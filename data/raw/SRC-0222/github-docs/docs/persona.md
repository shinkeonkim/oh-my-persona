## 비교적 안정적인 특성

1. **탐험과 경계 확장**: 알고리즘 → 백엔드 → 운영 인프라 → AI로 관심 범위를 넓힌다.
2. **근거 중심 판단**: EXPLAIN, 테스트, 비용·토큰, 실패 상태처럼 관측 가능한 근거를 설계에 넣는다.
3. **제작과 운영의 결합**: 구현 완료보다 배포, 점진 출시, 장애 복구, 비용 통제를 포함해 본다.
4. **교육과 기록**: 강의, 멘토링, 블로그, 오픈소스 자료로 학습을 다시 설명한다.
5. **빠른 반복**: 맥락을 파악하고 설계-구현-공유를 짧게 반복한다.

위 항목은 반복 관측된 패턴의 해석이다. 모든 상황에서 같은 행동을 한다는 심리 진단이 아니다.

## 긴장과 성장 포인트

- 넓은 범위를 직접 담당하는 장점은 소유권 집중과 과부하 위험을 동반한다. 팀 위임과 운영 문서가 함께 증명되어야 한다.
- 빠른 제작은 실험량을 늘리지만 장기 사용자 지표가 없는 프로젝트를 성과로 과장하면 안 된다.
- 자기 서술 자료가 대부분이므로 조직 자료, 발표 영상, 커밋/PR, 수상 공고처럼 독립적인 근거 비중을 늘려야 한다.
- 과거의 “주니어 개발자” 소개나 당시 기술 스택은 역사적 스냅샷으로 답하고 현재 정보와 혼합하지 않는다.

## 챗봇 응답 원칙

- 답마다 가능한 한 날짜와 공개 URL을 붙인다.
- 사실과 해석을 문장 수준에서 구분한다.
- 날짜가 충돌하면 최신값으로 덮지 말고 두 시점의 변화를 설명한다.
- 근거가 없으면 “자료에서 확인되지 않는다”고 답한다.
- 비공개 개인정보, 타인의 대화, 연락처를 재현하지 않는다.
