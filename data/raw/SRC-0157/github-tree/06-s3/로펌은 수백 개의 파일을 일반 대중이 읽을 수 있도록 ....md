## Question

로펌은 수백 개의 파일을 일반 대중이 읽을 수 있도록 만들어야 합니다. 로펌은 지정된 미래 날짜 전에 대중이 파일을 수정하거나 삭제하지 못하도록 해야 합니다.
이러한 요구 사항을 가장 안전하게 충족하는 솔루션은 무엇입니까?

- [ ] A. 정적 웹사이트 호스팅을 위해 구성된 Amazon S3 버킷에 파일을 업로드합니다. 지정된 날짜까지 S3 버킷에 액세스하는 모든 AWS 주체에게 읽기 전용 IAM 권한을 부여합니다.
- [ ] B. 새 Amazon S3 버킷을 만듭니다. S3 버전 관리를 활성화합니다. S3 객체 잠금을 사용하고 지정된 날짜를 기준으로 보관 기간을 설정합니다. 버킷에서 콘텐츠를 제공할 Amazon CloudFront 배포를 만듭니다. S3 버킷 정책을 사용하여 CloudFront 원본 액세스 제어(OAC)에 대한 액세스를 제한합니다.
- [ ] C. 새 Amazon S3 버킷을 만듭니다. S3 버전 관리를 활성화합니다. 사용자가 객체를 수정하거나 삭제하는 경우 AWS Lambda 함수를 실행하도록 이벤트 트리거를 구성합니다. Lambda 함수를 구성하여 수정되거나 삭제된 객체를 개인 S3 버킷의 객체의 원래 버전으로 바꿉니다.
- [ ] D. 정적 웹사이트 호스팅을 위해 구성된 Amazon S3 버킷에 파일을 업로드합니다. 파일이 들어 있는 폴더를 선택합니다. 지정된 날짜를 기준으로 보관 기간이 있는 S3 Object Lock을 사용합니다. S3 버킷에 액세스하는 모든 AWS 주체에게 읽기 전용 IAM 권한을 부여합니다.

## Answer

정답: B

## Explanation

S3 Versioning과 S3 Object Lock으로 보존 기간을 설정하면 지정된 날짜까지 파일 수정/삭제를 방지할 수 있습니다. CloudFront 배포와 OAC(Origin Access Control)를 사용하면 S3 버킷에 직접 접근을 차단하면서 일반 대중에게 읽기 전용 접근을 안전하게 제공할 수 있습니다.

오답 분석

A: IAM 권한으로 일반 대중에게 접근을 부여하는 것은 실용적이지 않으며, Object Lock 없이는 파일 수정/삭제를 완전히 방지할 수 없습니다.

C: Lambda 함수로 삭제/수정된 객체를 복원하는 방식은 복잡하고 신뢰성이 낮으며, Object Lock보다 보안이 취약합니다.

D: 정적 웹사이트 호스팅과 Object Lock을 함께 사용하는 것은 가능하지만, CloudFront OAC 없이는 S3 버킷이 직접 노출되어 보안이 취약합니다.
