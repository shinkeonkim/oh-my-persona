## Question

한 회사는 정기적으로 GB 크기의 파일을 Amazon S3에 업로드합니다. 회사는 파일을 업로드한 후 Amazon EC2 스팟 인스턴스 집합을 사용하여 파일 형식을 트랜스코딩합니다. 회사는 온프레미스 데이터 센터에서 Amazon S3로 데이터를 업로드할 때와 Amazon S3에서 EC2 인스턴스로 데이터를 다운로드할 때 처리량을 확장해야 합니다.
어떤 솔루션이 이러한 요구 사항을 충족합니까? (2개를 선택하세요.)

- [ ] A. S3 버킷에 직접 액세스하는 대신 S3 버킷 액세스 포인트를 사용합니다.
- [ ] B. 파일을 여러 S3 버킷에 업로드합니다.
- [ ] C. S3 멀티파트 업로드를 사용합니다.
- [ ] D. 객체의 여러 바이트 범위를 병렬로 가져옵니다.
- [ ] E. 파일을 업로드할 때 각 객체에 임의의 접두사를 추가합니다.

## Answer

정답: C, D

## Explanation

C와 D가 정답입니다. S3 멀티파트 업로드는 대용량 파일을 여러 파트(최소 5MB)로 나누어 병렬로 업로드하여 전체 처리량을 크게 향상시키며, AWS는 100MB 이상 파일에 멀티파트 업로드를 권장합니다. 바이트 범위 가져오기(Byte-Range Fetches)는 객체의 여러 바이트 범위를 병렬로 요청하여 다운로드 처리량을 확장합니다. 이 두 방법이 S3 업로드와 다운로드 모두에서 처리량을 확장하는 AWS 공식 모범 사례입니다.

오답 분석

A: S3 버킷 액세스 포인트는 대규모 데이터 세트에 대한 공유 액세스를 관리하는 기능으로, 각 액세스 포인트에 고유한 정책을 적용하여 접근을 제어합니다. 데이터 전송 처리량 향상과는 관련이 없습니다.

B: 여러 S3 버킷에 파일을 분산 업로드하는 것은 S3의 단일 버킷 성능이 이미 초당 5,500 GET 및 3,500 PUT 요청을 지원하므로 처리량 향상에 도움이 되지 않으며, 관리 복잡성만 증가시킵니다.

E: 2018년 S3 성능 개선 이후, S3는 접두사(prefix)별로 초당 5,500 GET/3,500 PUT을 자동 지원하므로 임의 접두사를 추가하여 성능을 분산할 필요가 없습니다.
