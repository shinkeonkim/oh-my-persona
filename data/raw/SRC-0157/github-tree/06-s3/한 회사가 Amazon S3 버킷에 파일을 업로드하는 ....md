## Question

한 회사가 Amazon S3 버킷에 파일을 업로드하는 데 사용되는 애플리케이션을 호스팅합니다. 업로드되면 파일을 처리하여 메타데이터를 추출하는데, 이 작업에는 5초도 채 걸리지 않습니다.
업로드의 양과 빈도는 매 시간 몇 개의 파일부터 수백 개의 동시 업로드까지 다양합니다. 회사는 솔루션 설계자에게 이러한 요구 사항을 충족할 수 있는 비용 효율적인 아키텍처를 설계하도록 요청했습니다.
솔루션 설계자는 무엇을 추천해야 합니까?

- [ ] A. S3 API 호출을 기록하도록 AWS CloudTrail 추적을 구성합니다. AWS AppSync를 사용하여 파일을 처리합니다.
- [ ] B. 파일을 처리하기 위해 AWS Lambda 함수를 호출하도록 S3 버킷 내에서 객체 생성 이벤트 알림을 구성합니다.
- [ ] C. 데이터를 처리하고 Amazon S3로 전송하도록 Amazon Kinesis Data Streams를 구성합니다. AWS Lambda 함수를 호출하여 파일을 처리합니다.
- [ ] D. Amazon S3에 업로드된 파일을 처리하도록 Amazon Simple 알림 서비스(Amazon SNS) 주제를 구성합니다. AWS Lambda 함수를 호출하여 파일을 처리합니다.

## Answer

정답: B

## Explanation

S3 버킷 내에서 객체 생성(s3:ObjectCreated:*) 이벤트 알림을 구성하여 AWS Lambda 함수를 직접 호출하는 것이 가장 비용 효율적이고 간단한 아키텍처입니다. Lambda는 5초 미만의 짧은 처리 시간에 최적화되어 있으며, 매 시간 몇 개부터 수백 개의 동시 업로드까지 자동으로 확장됩니다. 사용한 만큼만 비용을 지불하는 이벤트 기반 아키텍처로, 업로드가 없는 시간에는 비용이 발생하지 않습니다.

오답 분석

A: AWS CloudTrail은 API 호출 감사 추적 서비스이며 실시간 파일 처리 트리거로 적합하지 않습니다. AWS AppSync는 GraphQL API 서비스로 파일 메타데이터 추출 처리에 설계된 서비스가 아닙니다.

C: Amazon Kinesis Data Streams는 실시간 스트리밍 데이터 처리에 적합하지만, S3 파일 업로드 이벤트 처리에는 샤드 프로비저닝과 관리가 필요한 과도한 인프라이며 비용이 높습니다.

D: Amazon SNS 주제 자체는 파일을 처리하는 기능이 없으며, SNS를 중간 계층으로 추가하면 불필요한 아키텍처 복잡성이 증가합니다. S3 이벤트 알림에서 Lambda를 직접 호출하는 것이 더 간단하고 효율적입니다.
