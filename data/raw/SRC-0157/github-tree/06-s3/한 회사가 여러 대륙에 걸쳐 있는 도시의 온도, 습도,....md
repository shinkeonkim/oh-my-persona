## Question

한 회사가 여러 대륙에 걸쳐 있는 도시의 온도, 습도, 기압 데이터를 수집합니다. 사이트당 매일 수집되는 평균 데이터 양은 500GB입니다. 각 사이트는 고속 인터넷에 연결되어 있습니다. 회사의 기상 예보 애플리케이션은 단일 리전을 기반으로 하며 매일 데이터를 분석합니다. 이 모든 글로벌 사이트의 데이터를 집계하는 가장 빠른 방법은 무엇입니까?

- [ ] A. 대상 버킷에서 Amazon S3 Transfer Acceleration을 활성화합니다. 멀티파트 업로드를 사용하여 사이트 데이터를 대상 버킷에 직접 업로드합니다.
- [ ] B. 가장 가까운 AWS 리전의 Amazon S3 버킷에 사이트 데이터를 업로드합니다. S3 리전 간 복제를 사용하여 객체를 대상 버킷에 복사합니다.
- [ ] C. AWS Snowball 작업을 매일 예약하여 가장 가까운 AWS 리전으로 데이터를 전송합니다. S3 리전 간 복제를 사용하여 객체를 대상 버킷에 복사합니다.
- [ ] D. 가장 가까운 리전의 Amazon EC2 인스턴스에 데이터를 업로드합니다. Amazon Elastic Block Store(Amazon EBS) 볼륨에 데이터를 저장합니다. 하루에 한 번 EBS 스냅샷을 생성하여 중앙 리전에 복사합니다. 중앙 리전의 EBS 볼륨을 복원하고 매일 데이터에 대한 분석을 실행합니다.

## Answer

정답: A

## Explanation

S3 Transfer Acceleration은 Amazon CloudFront의 전 세계 엣지 로케이션을 활용하여 장거리 데이터 전송 속도를 크게 높입니다. 멀티파트 업로드와 결합하면 전 세계 여러 대륙의 사이트에서 단일 리전의 대상 버킷으로 500GB의 데이터를 가장 빠르게 집계할 수 있습니다.

오답 분석

B: 가장 가까운 리전에 업로드한 후 교차 리전 복제를 사용하면 추가 복제 시간이 필요하므로 직접 Transfer Acceleration으로 업로드하는 것보다 느립니다.

C: AWS Snowball은 매일 데이터를 전송해야 하는 경우 배송 시간 때문에 부적합하며, 일일 작업에는 사용할 수 없습니다.

D: EC2 인스턴스에 업로드 후 EBS 스냅샷을 복사하는 것은 복잡하고 시간이 많이 걸리며, 가장 빠른 방법이 아닙니다.
