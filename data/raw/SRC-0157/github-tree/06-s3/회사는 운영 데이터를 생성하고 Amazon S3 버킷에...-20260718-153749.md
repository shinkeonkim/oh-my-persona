## Question

회사는 운영 데이터를 생성하고 Amazon S3 버킷에 데이터를 저장합니다. 회사의 연간 감사를 위해 외부 컨설턴트는 S3 버킷에 저장된 연간 보고서에 액세스해야 합니다. 외부 컨설턴트는 7일 동안 보고서에 액세스해야 합니다.
회사는 외부 컨설턴트가 보고서에만 접근할 수 있도록 하는 솔루션을 구현해야 합니다.
가장 높은 운영 효율성으로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 공개 정적 웹 사이트를 호스팅하도록 구성된 새 S3 버킷을 생성합니다. 작업 데이터를 새 S3 버킷으로 마이그레이션합니다. S3 웹사이트 URL을 외부 컨설턴트와 공유합니다.
- [ ] B. 7일 동안 S3 버킷에 대한 공개 액세스를 활성화합니다. 외부 컨설턴트가 감사를 완료하면 S3 버킷에 대한 액세스 권한을 제거합니다.
- [ ] C. S3 버킷의 보고서에 액세스할 수 있는 새 IAM 사용자를 생성합니다. 외부 컨설턴트에게 액세스 키를 제공합니다. 7일 후에 액세스 키를 취소합니다.
- [ ] D. S3 버킷의 보고서 위치에 필요한 액세스 권한이 있는 미리 서명된 URL을 생성합니다. 미리 서명된 URL을 외부 컨설턴트와 공유합니다.

## Answer

정답: D

## Explanation

S3 미리 서명된(pre-signed) URL을 생성하면 S3 버킷의 특정 보고서 위치에 대한 임시 액세스를 안전하게 제공할 수 있습니다. IAM 사용자 자격 증명으로 생성한 pre-signed URL은 최대 7일(604,800초)까지 유효 기간을 설정할 수 있어 외부 컨설턴트의 7일 접근 요구 사항에 정확히 부합합니다(참고: IAM 역할이나 STS 임시 자격 증명으로 생성한 경우 세션 토큰 만료에 따라 최대 36시간으로 제한됩니다). URL에는 특정 객체(보고서)에 대한 GET 권한만 포함되므로 '보고서에만 접근' 요구 사항을 충족하며, IAM 사용자 생성이나 버킷 공개 설정 없이 URL 하나만 공유하면 되므로 운영 효율성이 가장 높습니다.

오답 분석

A: 정적 웹 사이트를 호스팅하고 운영 데이터를 새 버킷으로 마이그레이션하는 것은 불필요한 작업이며, 공개 웹사이트 URL을 통해 인터넷의 모든 사용자가 데이터에 접근할 수 있어 심각한 보안 위험이 발생합니다.

B: S3 버킷에 대한 공개 액세스(Public Access)를 활성화하면 보고서뿐만 아니라 버킷의 모든 운영 데이터가 인터넷에 노출됩니다. AWS는 S3 Block Public Access를 기본으로 활성화하도록 강력히 권장하며, 이를 비활성화하는 것은 모범 사례에 반합니다.

C: 외부 컨설턴트를 위한 IAM 사용자를 생성하고 액세스 키를 발급하는 것은 가능하지만, 외부 사용자에게 IAM 자격 증명을 제공하는 것은 보안 모범 사례에 반합니다. 또한 사용자 생성, 정책 할당, 액세스 키 발급, 7일 후 수동 취소 등의 관리 작업이 필요하여 운영 오버헤드가 높습니다.
