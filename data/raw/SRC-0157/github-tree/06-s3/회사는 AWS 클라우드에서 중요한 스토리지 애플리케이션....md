## Question

회사는 AWS 클라우드에서 중요한 스토리지 애플리케이션을 실행합니다. 애플리케이션은 두 AWS 리전에서 Amazon S3를 사용합니다. 회사는 애플리케이션이 공용 네트워크 정체 없이 원격 사용자 데이터를 가장 가까운 S3 버킷으로 보내기를 원합니다. 또한 회사는 최소한의 Amazon S3 관리로 애플리케이션 장애 조치를 원합니다.
이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 두 지역 간에 활성-활성 설계를 구현합니다. 사용자에게 가장 가까운 지역 S3 엔드포인트를 사용하도록 애플리케이션을 구성합니다.
- [ ] B. S3 다중 지역 액세스 포인트에 활성-수동 구성을 사용합니다. 각 지역에 대한 글로벌 엔드포인트를 생성합니다.
- [ ] C. 사용자에게 가장 가까운 지역 S3 엔드포인트로 사용자 데이터를 보냅니다. S3 버킷을 동기화된 상태로 유지하도록 S3 교차 계정 복제 규칙을 구성합니다.
- [ ] D. 단일 글로벌 엔드포인트가 있는 활성-활성 구성에서 다중 지역 액세스 포인트를 사용하도록 Amazon S3를 설정합니다. S3 교차 리전 복제를 구성합니다.

## Answer

정답: D

## Explanation

S3 Multi-Region Access Points(MRAP)를 활성-활성(active-active) 구성으로 설정하면 단일 글로벌 엔드포인트를 통해 사용자 요청이 네트워크 지연 시간에 기반하여 가장 가까운 S3 버킷으로 자동 라우팅됩니다. MRAP는 AWS Global Accelerator의 애니캐스트(anycast) IP 네트워크를 내부적으로 활용하여 공용 인터넷을 우회하고 AWS 글로벌 백본 네트워크를 통해 트래픽을 전송하므로 공용 네트워크 정체가 발생하지 않습니다. S3 교차 리전 복제(CRR)를 함께 구성하면 두 리전 간 데이터가 동기화되며, 한 리전에 장애가 발생해도 MRAP가 자동으로 정상 리전으로 트래픽을 전환하여 최소한의 S3 관리로 장애 조치가 이루어집니다. MRAP의 장애 조치 제어(failover controls)를 통해 활성/수동 상태를 리전별로 수동 또는 자동으로 조절할 수도 있습니다.

오답 분석

A: 활성-활성 설계에서 지역 S3 엔드포인트를 직접 사용하면 애플리케이션이 가장 가까운 리전을 판별하는 로직, 장애 감지 및 자동 장애 조치를 직접 구현해야 하므로 관리 부담이 크게 증가합니다. 또한 공용 인터넷을 통해 트래픽이 전송되므로 네트워크 정체를 피할 수 없습니다.

B: 활성-수동(active-passive) 구성은 하나의 리전만 트래픽을 수신하므로 항상 가장 가까운 버킷으로 데이터를 보내는 요구 사항을 충족하지 못합니다. 또한 MRAP는 단일 글로벌 엔드포인트를 제공하므로 '각 리전에 대한 글로벌 엔드포인트를 생성'한다는 설명은 MRAP의 동작 방식과 맞지 않습니다.

C: 교차 계정 복제(Cross-Account Replication)는 서로 다른 AWS 계정 간의 복제에 사용되며, 이 시나리오에서는 동일 회사의 두 리전 간 복제이므로 교차 리전 복제(CRR)가 적절합니다. 또한 자동 라우팅과 글로벌 엔드포인트 기능이 없어 최소 관리 장애 조치 요구 사항을 충족하지 못합니다.
