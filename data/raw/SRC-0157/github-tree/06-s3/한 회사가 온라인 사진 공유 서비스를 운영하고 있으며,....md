## Question

한 회사가 온라인 사진 공유 서비스를 운영하고 있으며, AWS 계정 A의 중앙 집중식 Amazon S3 버킷에 데이터를 저장하고 있습니다. 이 회사는 Account B라는 두 번째 AWS 계정에 중앙 집중식 S3 버킷에 대한 액세스 권한을 부여하고자 합니다. 이 회사는 Account B도 소유하고 있습니다.

- [ ] A. S3 Transfer Acceleration을 활성화하여 계정 B가 계정 A의 중앙 집중식 S3 버킷에 액세스할 수 있도록 합니다.
- [ ] B. 계정 A와 계정 B 간의 리전 간 복제를 활성화하여 S3 버킷 데이터를 공유합니다.
- [ ] C. Amazon CloudFront를 사용하여 S3 버킷 콘텐츠를 배포합니다. 서명된 URL을 통해 계정 B에 버킷 콘텐츠에 대한 액세스 권한을 부여합니다.
- [ ] D. 계정 B에 계정 A의 중앙 집중식 S3 버킷에 액세스할 수 있는 권한을 부여하는 버킷 정책을 생성합니다.

## Answer

정답: D

## Explanation

S3 버킷 정책에서 Principal에 Account B의 AWS 계정 ID를 지정하면 교차 계정 접근을 간단하게 구성할 수 있습니다. 버킷 정책은 리소스 기반 정책으로, 다른 계정의 IAM 사용자나 역할에 s3:GetObject, s3:PutObject 등 필요한 권한을 직접 부여할 수 있어 교차 계정 S3 접근의 가장 표준적인 방법입니다. 동일 회사가 소유한 계정 간 공유에 가장 직접적이고 관리가 용이합니다.

오답 분석

A: S3 Transfer Acceleration은 CloudFront 엣지 로케이션을 활용하여 장거리 파일 전송 속도를 높이는 기능이며, 접근 권한을 부여하는 메커니즘이 아닙니다.

B: 교차 리전 복제(CRR)는 버킷 간 데이터를 자동 복제하는 기능으로, 데이터 중복 저장 비용이 발생하며 단순 접근 권한 부여에는 불필요하게 복잡합니다.

C: CloudFront와 서명된 URL은 퍼블릭 콘텐츠 배포에 적합하며, 동일 회사 소유 AWS 계정 간 S3 버킷 접근 권한 부여에는 버킷 정책이 훨씬 더 간단하고 적절합니다.
