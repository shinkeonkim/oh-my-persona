## Question

한 회사는 매달 약 300TB의 Amazon S3 Standard 스토리지를 유지 관리합니다. S3 객체의 크기는 일반적으로 약 50GB이며 글로벌 애플리케이션에 의해 멀티파트 업로드로 자주 교체됩니다. S3 객체의 수와 크기는 일정하게 유지되지만 회사의 S3 스토리지 비용은 매달 증가하고 있습니다.
이 상황에서 솔루션 설계자는 어떻게 비용을 절감해야 합니까?

- [ ] A. 멀티파트 업로드에서 Amazon S3 Transfer Acceleration으로 전환합니다.
- [ ] B. 불완전한 멀티파트 업로드를 삭제하는 S3 수명 주기 정책을 활성화합니다.
- [ ] C. 객체가 너무 빨리 보관되지 않도록 S3 인벤토리를 구성합니다.
- [ ] D. Amazon S3에 저장되는 객체 수를 줄이도록 Amazon CloudFront를 구성합니다.

## Answer

정답: B

## Explanation

불완전한 멀티파트 업로드를 삭제하는 S3 수명 주기 정책(AbortIncompleteMultipartUpload)을 활성화하면 비용 증가 문제를 해결할 수 있습니다. 50GB 크기의 S3 객체가 자주 교체되면서 멀티파트 업로드의 불완전한 파트(업로드 실패, 중단, 취소된 파트)가 누적되어 보이지 않는 스토리지 비용을 발생시킵니다. 객체 수와 크기는 일정하지만 비용이 증가하는 것은 이러한 불완전한 업로드 파트가 원인이며, 수명 주기 정책으로 자동 정리됩니다.

오답 분석

A: S3 Transfer Acceleration은 CloudFront 엣지 로케이션을 활용하여 업로드 속도를 향상시키는 기능이며, 스토리지 비용 절감과는 관련이 없습니다. 오히려 전송 가속화에 대한 추가 비용이 발생합니다.

C: S3 Inventory는 버킷 내 객체 목록과 메타데이터(크기, 스토리지 클래스, 암호화 상태 등)를 정기적으로 생성하는 보고 도구이며, 객체 보관이나 스토리지 클래스 전환을 제어하는 기능이 아닙니다.

D: CloudFront는 엣지 로케이션에서 콘텐츠를 캐싱하고 배포하는 CDN 서비스로, S3에 저장되는 객체 수를 줄이는 기능이 없으며 스토리지 비용 최적화와 무관합니다.
