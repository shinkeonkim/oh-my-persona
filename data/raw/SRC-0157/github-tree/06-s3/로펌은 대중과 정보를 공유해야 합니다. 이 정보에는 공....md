## Question

로펌은 대중과 정보를 공유해야 합니다. 이 정보에는 공개적으로 읽을 수 있어야 하는 수백 개의 파일이 포함됩니다. 지정된 미래 날짜 이전에 누구든지 파일을 수정하거나 삭제하는 것은 금지됩니다.
가장 안전한 방식으로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 정적 웹 사이트 호스팅용으로 구성된 Amazon S3 버킷에 모든 파일을 업로드합니다. 지정된 날짜까지 S3 버킷에 액세스하는 모든 AWS 보안 주체에게 읽기 전용 IAM 권한을 부여합니다.
- [ ] B. S3 버전 관리가 활성화된 새 Amazon S3 버킷을 생성합니다. 지정된 날짜에 따라 보존 기간이 있는 S3 Object Lock을 사용합니다. 정적 웹 사이트 호스팅을 위해 S3 버킷을 구성합니다. 객체에 대한 읽기 전용 액세스를 허용하도록 S3 버킷 정책을 설정합니다.
- [ ] C. S3 버전 관리가 활성화된 새 Amazon S3 버킷을 생성합니다. 객체 수정 또는 삭제 시 AWS Lambda 함수를 실행하도록 이벤트 트리거를 구성합니다. 객체를 프라이빗 S3 버킷의 원래 버전으로 바꾸도록 Lambda 함수를 구성합니다.
- [ ] D. 정적 웹 사이트 호스팅용으로 구성된 Amazon S3 버킷에 모든 파일을 업로드합니다. 파일이 포함된 폴더를 선택합니다. 지정된 날짜에 따라 보존 기간이 있는 S3 Object Lock을 사용합니다. S3 버킷에 액세스하는 모든 AWS 보안 주체에게 읽기 전용 IAM 권한을 부여합니다.

## Answer

정답: B

## Explanation

S3 Versioning이 활성화된 새 버킷을 생성하고 S3 Object Lock을 지정된 날짜에 맞는 보존 기간으로 설정하면 파일의 수정 및 삭제를 방지합니다. 정적 웹 사이트 호스팅을 구성하고 S3 버킷 정책으로 읽기 전용 액세스를 허용하면 공개적으로 파일을 읽을 수 있습니다. Object Lock은 버전 관리가 활성화된 버킷에서만 사용 가능합니다.

오답 분석

A: IAM 권한을 사용한 읽기 전용 액세스는 AWS 보안 주체에게만 적용되며, Object Lock 없이는 수정이나 삭제를 완전히 방지할 수 없습니다.

C: Lambda 함수로 객체를 원래 버전으로 교체하는 것은 복잡하고 비효율적이며, 일시적으로 수정된 버전이 존재할 수 있어 보안이 완벽하지 않습니다.

D: S3 Object Lock은 폴더가 아닌 개별 객체 수준에서 적용됩니다. 폴더를 선택하여 Object Lock을 적용하는 것은 올바른 방법이 아닙니다. 또한 IAM 권한은 퍼블릭 액세스에 적합하지 않습니다.
