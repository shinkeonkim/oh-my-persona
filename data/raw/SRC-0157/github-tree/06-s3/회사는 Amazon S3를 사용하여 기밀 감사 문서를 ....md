## Question

회사는 Amazon S3를 사용하여 기밀 감사 문서를 저장합니다. S3 버킷은 버킷 정책을 사용하여 최소 권한 원칙에 따라 감사 팀 IAM 사용자 자격 증명에 대한 액세스를 제한합니다. 회사 관리자는 S3 버킷의 문서를 실수로 삭제하는 것에 대해 걱정하고 보다 안전한 솔루션을 원합니다.
솔루션 설계자는 감사 문서를 보호하기 위해 무엇을 해야 합니까?

- [ ] A. S3 버킷에서 버전 관리 및 MFA 삭제 기능을 활성화합니다.
- [ ] B. 각 감사 팀 IAM 사용자 계정의 IAM 사용자 자격 증명에서 다중 요소 인증(MFA)을 활성화합니다.
- [ ] C. 감사 날짜 동안 s3:DeleteObject 작업을 거부하도록 감사 팀의 IAM 사용자 계정에 S3 수명 주기 정책을 추가합니다.
- [ ] D. AWS Key Management Service(AWS KMS)를 사용하여 S3 버킷을 암호화하고 감사 팀 IAM 사용자 계정이 KMS 키에 액세스하지 못하도록 제한합니다.

## Answer

정답: A

## Explanation

S3 버킷에서 버전 관리(Versioning)와 MFA Delete를 활성화하면 기밀 감사 문서를 우발적 삭제로부터 강력하게 보호합니다. 버전 관리는 삭제된 객체의 이전 버전을 모두 유지하여 복구를 가능하게 하고, MFA Delete는 영구 삭제나 버전 관리 비활성화 시 루트 계정의 MFA 인증을 요구하여 추가 보안 계층을 제공합니다. 이 조합은 AWS Well-Architected Framework에서 권장하는 데이터 보호 모범 사례입니다.

오답 분석

B: IAM 사용자 계정에 MFA를 활성화하면 AWS 콘솔 로그인 시 보안이 강화되지만, S3 API 호출을 통한 객체 삭제 작업에 대한 MFA 인증을 직접 강제하지 않습니다. S3 객체 삭제 방지에는 MFA Delete가 필요합니다.

C: S3 수명 주기 정책은 IAM 사용자 계정에 추가하는 것이 아니라 S3 버킷에 구성하는 것이며, 삭제 작업을 거부하는 것은 IAM 정책의 Deny 문(statement) 기능입니다. 또한 특정 감사 기간만 보호하는 것은 영구적 문서 보호에 부적합합니다.

D: KMS 암호화로 S3 버킷을 암호화하고 KMS 키 접근을 제한하면 감사 팀이 문서를 복호화하여 읽을 수도 없게 되어 감사 업무 수행이 불가능해지며, 삭제 방지와는 다른 목적의 기능입니다.
