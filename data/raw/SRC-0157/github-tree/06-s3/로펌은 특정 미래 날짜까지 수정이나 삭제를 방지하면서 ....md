## Question

로펌은 특정 미래 날짜까지 수정이나 삭제를 방지하면서 파일을 공개적으로 읽을 수 있게 하려면 어떻게 해야 할까요?

- [ ] A. 정적 웹사이트 호스팅을 위해 구성된 Amazon S3 버킷에 파일을 업로드합니다. 모든 AWS 주체에게 읽기 전용 IAM 권한을 부여합니다.
- [ ] B. S3 버킷을 만듭니다. S3 버전 관리를 활성화합니다. 보관 기간이 있는 S3 객체 잠금을 사용합니다. CloudFront 배포를 만듭니다. 버킷 정책을 사용하여 액세스를 제한합니다.
- [ ] C. S3 버킷을 만듭니다. S3 버전 관리를 활성화합니다. AWS Lambda로 이벤트 트리거를 구성하여 개인 S3 버킷에서 수정된 객체를 복원합니다.
- [ ] D. 정적 웹사이트 호스팅을 위해 S3 버킷에 파일을 업로드합니다. 보관 기간이 있는 S3 객체 잠금을 사용합니다. 읽기 전용 IAM 권한을 부여합니다.

## Answer

정답: B

## Explanation

S3 버전 관리를 활성화한 후 S3 객체 잠금(Object Lock)으로 보관 기간(Retention Period)을 설정하면 WORM(Write Once Read Many) 방식으로 특정 날짜까지 객체의 수정과 삭제가 완전히 차단됩니다. CloudFront 배포로 HTTPS를 통한 공개 읽기 접근을 제공하면서 버킷 정책으로 S3에 대한 직접 접근을 차단합니다. CloudFront OAC를 통해 보안을 유지하면서 공개 배포가 가능합니다.

오답 분석

A: S3 정적 웹사이트 호스팅 엔드포인트는 HTTP만 지원하며 HTTPS를 제공하지 않습니다. IAM 권한만으로는 객체 잠금 수준의 수정/삭제 방지를 보장하기 어렵습니다.

C: Lambda 이벤트 트리거로 수정된 객체를 이전 버전으로 복원하는 것은 사후 대응 방식이며, 객체 잠금처럼 수정 자체를 원천적으로 차단하지 못합니다.

D: S3 정적 웹사이트 호스팅은 HTTPS를 지원하지 않습니다. CloudFront를 통해야 HTTPS 접근과 글로벌 배포가 가능합니다. 또한 IAM 읽기 전용 권한은 외부 공개 접근에 적합하지 않습니다.
