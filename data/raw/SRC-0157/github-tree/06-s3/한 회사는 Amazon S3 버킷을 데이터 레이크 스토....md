## Question

한 회사는 Amazon S3 버킷을 데이터 레이크 스토리지 플랫폼으로 사용합니다. S3 버킷에는 여러 팀과 수백 개의 애플리케이션에서 무작위로 액세스하는 엄청난 양의 데이터가 포함되어 있습니다. 회사는 S3 스토리지 비용을 절감하고 자주 액세스하는 객체에 대한 즉각적인 가용성을 제공하고자 합니다.
이러한 요구 사항을 충족하는 가장 운영 효율적인 솔루션은 무엇입니까?

- [ ] A. 객체를 S3 Intelligent-Tiering 스토리지 클래스로 전환하는 S3 수명 주기 규칙을 생성합니다.
- [ ] B. Amazon S3 Glacier에 객체를 저장합니다. S3 Select를 사용하여 애플리케이션에 데이터에 대한 액세스 권한을 제공합니다.
- [ ] C. S3 스토리지 클래스 분석의 데이터를 사용하여 객체를 S3 Standard-Infrequent Access(S3 Standard-IA) 스토리지 클래스로 자동 전환하는 S3 수명 주기 규칙을 생성합니다.
- [ ] D. 객체를 S3 Standard-Infrequent Access(S3 Standard-IA) 스토리지 클래스로 전환합니다. 애플리케이션에서 객체에 액세스할 때 객체를 S3 Standard 스토리지 클래스로 전환하는 AWS Lambda 함수를 생성합니다.

## Answer

정답: A

## Explanation

S3 Intelligent-Tiering으로 전환하는 수명 주기 규칙을 생성하면 무작위 액세스 패턴에 대해 자동으로 비용을 최적화합니다. 자주 액세스하는 객체는 빈번한 액세스 계층에 유지되어 즉각적인 가용성을 제공하고, 자주 액세스하지 않는 객체는 자동으로 저렴한 계층으로 이동됩니다. 수명 주기 규칙 하나만 생성하면 되므로 운영 효율성이 가장 높습니다.

오답 분석

B: S3 Glacier에 저장하면 즉시 접근이 불가능하며, S3 Select는 Glacier에 저장된 데이터에 직접 쿼리를 실행할 수 없습니다.

C: S3 스토리지 클래스 분석 데이터를 기반으로 수명 주기 규칙을 만드는 것은 수백 개의 애플리케이션에서 무작위로 액세스하는 환경에서 분석과 규칙 설정에 많은 운영 오버헤드가 발생합니다.

D: Lambda 함수로 객체 액세스 시 Standard로 전환하는 것은 각 액세스 시마다 Lambda가 호출되어 비용과 복잡성이 크게 증가하며, 운영 효율성이 매우 낮습니다.
