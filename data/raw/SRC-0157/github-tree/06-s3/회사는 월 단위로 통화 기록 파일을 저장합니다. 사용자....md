## Question

회사는 월 단위로 통화 기록 파일을 저장합니다. 사용자는 통화 후 1년 이내에 임의로 파일에 액세스하지만 1년 후에는 드물게 파일에 액세스합니다. 이 회사는 사용자에게 1년 미만의 파일을 가능한 한 빨리 쿼리하고 검색할 수 있는 기능을 제공하여 솔루션을 최적화하려고 합니다. 이전 파일 검색 지연은 허용됩니다.
이러한 요구 사항을 가장 비용 효율적으로 충족하는 솔루션은 무엇입니까?

- [ ] A. Amazon S3 Glacier Instant Retrieval에 태그가 있는 개별 파일을 저장합니다. 태그를 쿼리하여 S3 Glacier Instant Retrieval에서 파일을 검색합니다.
- [ ] B. Amazon S3 Intelligent-Tiering에 개별 파일을 저장합니다. S3 수명 주기 정책을 사용하여 1년 후 파일을 S3 Glacier Flexible Retrieval로 이동합니다. Amazon Athena를 사용하여 Amazon S3에 있는 파일을 쿼리하고 검색합니다. S3 Glacier Select를 사용하여 S3 Glacier에 있는 파일을 쿼리하고 검색합니다.
- [ ] C. Amazon S3 Standard 스토리지에 태그가 있는 개별 파일을 저장합니다. Amazon S3 Standard 스토리지의 각 아카이브에 대한 검색 메타데이터를 저장합니다. S3 수명 주기 정책을 사용하여 1년 후 파일을 S3 Glacier Instant Retrieval로 이동합니다. Amazon S3에서 메타데이터를 검색하여 파일을 쿼리하고 검색합니다.
- [ ] D. Amazon S3 Standard 스토리지에 개별 파일을 저장합니다. S3 수명 주기 정책을 사용하여 1년 후 파일을 S3 Glacier Deep Archive로 이동합니다. Amazon RDS에 검색 메타데이터를 저장합니다. Amazon RDS에서 파일을 쿼리합니다. S3 Glacier Deep Archive에서 파일을 검색합니다.

## Answer

정답: B

## Explanation

Amazon S3 Intelligent-Tiering은 액세스 패턴에 따라 자동으로 비용 최적화된 스토리지 계층으로 데이터를 이동합니다. 1년 이내의 임의 액세스 파일은 빈번한 액세스 계층에서 빠르게 검색 가능합니다. S3 Lifecycle 정책으로 1년 후 S3 Glacier Flexible Retrieval로 전환하면 장기 보관 비용을 절감합니다. Amazon Athena로 S3의 현재 데이터를 SQL로 쿼리하고, S3 Glacier Select로 아카이브된 데이터를 직접 쿼리할 수 있어, 전체 데이터에 대한 검색과 분석이 가능합니다.

오답 분석

A: S3 Glacier Instant Retrieval은 밀리초 단위 검색이 가능하지만, S3 태그만으로는 파일 내용을 쿼리하거나 복잡한 검색을 수행할 수 없습니다. 태그 기반 필터링은 제한적이며, Athena처럼 데이터 내용에 대한 SQL 쿼리를 지원하지 않습니다.

C: S3 Standard에 태그와 검색 메타데이터를 별도로 저장하고 관리하는 것은 수동 운영이 복잡합니다. Glacier Instant Retrieval은 즉시 검색이 가능하지만, 메타데이터 기반 수동 검색은 Athena의 자동화된 SQL 쿼리 대비 운영 효율성이 낮습니다.

D: S3 Glacier Deep Archive는 가장 저렴한 스토리지이지만 검색에 최대 12시간이 소요되어 지연 시간이 과도합니다. Amazon RDS에 별도로 검색 메타데이터를 저장하면 RDS 인스턴스 운영 비용과 관리 오버헤드가 추가됩니다.
