## Question

한 회사는 다중 테넌트 Amazon S3 버킷에 고객 데이터를 저장하고 있습니다. 각 고객의 데이터는 고객에게 고유한 접두사에 저장됩니다. 회사는 특정 고객의 데이터를 원본 버킷과 동일한 AWS 리전에 있는 새 전용 S3 버킷으로 마이그레이션해야 합니다. 회사는 생성 날짜 및 버전 ID와 같은 객체 메타데이터를 보존해야 합니다. 마이그레이션이 완료된 후, 회사는 원래 다중 테넌트 S3 버킷에서 마이그레이션된 고객의 원본 데이터를 삭제해야 합니다.
어떤 조합의 솔루션이 최소한의 오버헤드로 이러한 요구 사항을 충족할 수 있습니까? (세 가지를 선택합니다.)

- [ ] A. 대상 버킷으로 새로운 S3 버킷을 생성합니다. 새 버킷에서 버전 관리를 활성화합니다.
- [ ] B. S3 배치 작업을 사용하여 지정된 접두사에서 대상 버킷으로 객체를 복사합니다.
- [ ] C. S3 CopyObject API를 사용하고, 데이터를 대상 S3 버킷으로 복사하는 스크립트를 생성합니다.
- [ ] D. S3 동일 리전 복제(SRR)를 구성하여 원본 버킷의 지정된 접두사에서 대상 버킷으로 기존 데이터를 복제합니다.
- [ ] E. AWS DataSync를 구성하여 원본 버킷의 지정된 접두사에서 대상 버킷으로 데이터를 마이그레이션합니다.
- [ ] F. 데이터가 대상 버킷으로 마이그레이션된 후 원본 버킷에서 객체를 삭제하기 위해 S3 수명 주기 정책을 사용합니다.

## Answer

정답: A, B, F

## Explanation

A(새 S3 버킷 생성 및 버전 관리 활성화), B(S3 Batch Operations로 객체 복사), F(S3 Lifecycle 정책으로 원본 삭제)가 정답입니다. S3 Batch Operations는 대규모 객체 복사에 최적화되어 있으며 메타데이터를 보존합니다. 버전 관리를 활성화하면 버전 ID가 보존되고, Lifecycle 정책으로 마이그레이션 후 원본 데이터를 자동 삭제할 수 있어 운영 오버헤드가 가장 적습니다.

오답 분석

C: S3 CopyObject API로 스크립트를 직접 작성하는 것은 S3 Batch Operations보다 운영 오버헤드가 크고, 대규모 복사 작업 관리가 더 복잡합니다.

D: S3 Same-Region Replication(SRR)은 새로운 객체만 복제하며, 기존 객체를 복제하려면 추가 설정이 필요하여 오버헤드가 더 큽니다.

E: AWS DataSync는 데이터 마이그레이션에 사용할 수 있지만, 같은 리전 내 S3 간 복사에는 S3 Batch Operations가 더 효율적이고 메타데이터 보존이 더 확실합니다.
