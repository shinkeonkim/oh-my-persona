## Question

회사에서 Oracle 데이터베이스를 AWS로 마이그레이션하려고 합니다. 데이터베이스는 지리 코드로 식별되는 고해상도 지리 정보 시스템(GIS) 이미지 수백만 개가 포함된 단일 테이블로 구성됩니다.
자연 재해가 발생하면 몇 분마다 수만 개의 이미지가 업데이트됩니다. 각 지리적 코드에는 연결된 단일 이미지 또는 행이 있습니다. 회사는 이러한 이벤트 중에 가용성과 확장성이 뛰어난 솔루션을 원합니다.
이러한 요구 사항을 가장 비용 효율적으로 충족하는 솔루션은 무엇입니까?

- [ ] A. 이미지와 지리적 코드를 데이터베이스 테이블에 저장합니다. Amazon RDS 다중 AZ DB 인스턴스에서 실행되는 Oracle을 사용합니다.
- [ ] B. Amazon S3 버킷에 이미지를 저장합니다. 지리적 코드를 키로, 이미지 S3 URL을 값으로 사용하여 Amazon DynamoDB를 사용합니다.
- [ ] C. Amazon DynamoDB 테이블에 이미지와 지리적 코드를 저장합니다. 부하가 높은 시간 동안 DynamoDB Accelerator(DAX)를 구성합니다.
- [ ] D. Amazon S3 버킷에 이미지를 저장합니다. 지리 코드와 이미지 S3 URL을 데이터베이스 테이블에 저장합니다. Amazon RDS 다중 AZ DB 인스턴스에서 실행되는 Oracle을 사용합니다.

## Answer

정답: B

## Explanation

고해상도 GIS 이미지를 Amazon S3에 저장하고, DynamoDB에 지리적 코드(파티션 키)와 S3 URL(값)을 저장하는 아키텍처가 가장 비용 효율적이고 확장 가능합니다. DynamoDB는 키-값 조회에서 일관된 한 자릿수 밀리초 지연 시간을 제공하며, 자연 재해 시 수만 건의 동시 업데이트에도 자동으로 확장됩니다. S3는 99.999999999% 내구성으로 대용량 이미지를 저렴하게 저장하며, DynamoDB 항목 크기 제한(400KB)을 우회합니다.

오답 분석

A: Oracle RDS에 대용량 고해상도 이미지를 직접 저장하면 BLOB 데이터 관리가 복잡하고 스토리지 비용이 S3보다 훨씬 높습니다. 또한 RDS는 수만 건의 동시 업데이트 시 DynamoDB만큼의 자동 확장성을 제공하지 않으며, Oracle 라이선스 비용도 추가됩니다.

C: DynamoDB 테이블에 직접 고해상도 이미지를 저장하면 항목 크기 제한(400KB)에 걸릴 수 있으며, 대용량 이미지 저장 시 읽기/쓰기 비용이 매우 높아집니다. 이미지는 S3에 저장하고 메타데이터만 DynamoDB에 저장하는 것이 비용 효율적입니다.

D: Oracle RDS를 메타데이터 저장소로 사용하면 DynamoDB보다 관리 오버헤드가 높고, Oracle 라이선스 비용이 추가됩니다. 또한 RDS의 확장성은 DynamoDB보다 제한적이며, 자연 재해 시 급격한 부하 증가에 즉시 대응하기 어렵습니다.
