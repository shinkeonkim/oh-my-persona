## Question

회사는 중요한 보관 데이터 파일을 생성하는 애플리케이션을 AWS 클라우드에서 실행합니다. 회사는 애플리케이션의 데이터 스토리지를 재설계하려고 합니다. 회사는 데이터 파일을 암호화하고 데이터가 암호화되어 AWS로 전송되기 전에 제3자가 데이터에 액세스할 수 없도록 하고 싶어합니다. 회사는 이미 Amazon S3 버킷을 생성했습니다.
어떤 솔루션이 이러한 요구 사항을 충족합니까?

- [ ] A. Amazon S3 관리형 암호화 키로 클라이언트 측 암호화를 사용하도록 S3 버킷을 구성합니다. S3 버킷을 사용하여 아카이브 파일을 저장하도록 애플리케이션을 구성합니다.
- [ ] B. AWS KMS 키(SSE-KMS)로 서버 측 암호화를 사용하도록 S3 버킷을 구성합니다. S3 버킷을 사용하여 아카이브 파일을 저장하도록 애플리케이션을 구성합니다.
- [ ] C. AWS KMS 키(SSE-KMS)와 함께 이중 계층 서버 측 암호화를 사용하도록 S3 버킷을 구성합니다. S3 버킷을 사용하여 아카이브 파일을 저장하도록 애플리케이션을 구성합니다.
- [ ] D. AWS Key Management Service(AWS KMS)에 저장된 키로 클라이언트 측 암호화를 사용하도록 애플리케이션을 구성합니다. S3 버킷에 아카이브 파일을 저장하도록 애플리케이션을 구성합니다.

## Answer

정답: D

## Explanation

AWS KMS에 저장된 키로 클라이언트 측 암호화(CSE-KMS)를 사용하면 애플리케이션이 데이터를 S3로 전송하기 전에 로컬에서 암호화합니다. 이렇게 하면 전송 전에 데이터가 이미 암호화된 상태이므로 제3자가 암호화되지 않은 데이터에 접근할 수 없습니다. AWS KMS가 암호화 키의 생성, 순환, 폐기를 관리하여 키 관리 부담을 줄이면서도 보안이 강화되며, HTTPS 전송과 결합하여 이중 보호를 제공합니다.

오답 분석

A: 'S3 관리형 암호화 키로 클라이언트 측 암호화'라는 옵션은 AWS SDK에서 지원하는 표준 방식이 아닙니다. 클라이언트 측 암호화는 KMS 키 또는 클라이언트 제공 마스터 키(CSE-CMK)를 사용합니다.

B: SSE-KMS는 서버 측 암호화로, 데이터가 S3에 도착한 후에 암호화됩니다. 전송 중에 HTTPS로 보호되더라도 데이터가 AWS 인프라에 암호화되지 않은 상태로 전달되므로 '전송 전에 제3자가 접근할 수 없도록' 하는 요구 사항을 충족하지 못합니다.

C: 이중 계층 SSE-KMS(DSSE-KMS)는 두 개의 서버 측 암호화 레이어를 적용하지만 여전히 서버 측 암호화이므로, 데이터 전송 전 암호화 요구 사항을 충족하지 못합니다.
