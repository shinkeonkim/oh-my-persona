## Question

회사는 Amazon S3를 사용하여 고해상도 사진을 S3 버킷에 저장합니다. 애플리케이션 변경을 최소화하기 위해 회사는 사진을 S3 객체의 최신 버전으로 저장합니다. 회사는 사진의 가장 최근 버전 두 개만 유지하면 됩니다.
회사는 비용을 줄이고 싶어합니다. 회사는 S3 버킷을 큰 비용으로 식별했습니다.
최소한의 운영 오버헤드로 S3 비용을 줄이는 솔루션은 무엇입니까?

- [ ] A. S3 수명 주기를 사용하여 만료된 객체 버전을 삭제하고 가장 최근 버전 2개를 유지합니다.
- [ ] B. AWS Lambda 함수를 사용하여 이전 버전을 확인하고 가장 최근 버전 2개를 제외한 모든 버전을 삭제합니다.
- [ ] C. S3 배치 작업을 사용하여 최신이 아닌 객체 버전을 삭제하고 가장 최근 버전 2개만 유지합니다.
- [ ] D. S3 버킷에서 버전 관리를 비활성화하고 가장 최근 버전 2개를 유지합니다.

## Answer

정답: A

## Explanation

S3 수명 주기 정책의 NoncurrentVersionExpiration 작업을 사용하면 만료된 비현재(noncurrent) 객체 버전을 자동으로 삭제할 수 있습니다. NewerNoncurrentVersions 파라미터를 1로 설정하면 최신 현재 버전 외에 가장 최근 비현재 버전 1개만 유지하고 나머지를 자동 삭제하여, 현재 버전과 비현재 버전 1개를 합해 총 2개의 가장 최근 버전만 보관합니다. 이 방법은 한 번 구성하면 지속적으로 동작하므로 운영 오버헤드가 가장 적고, 추가 비용 없이 버전 관리 스토리지 비용을 효과적으로 절감합니다.

오답 분석

B: Lambda 함수를 사용하여 주기적으로 버전을 확인하고 삭제하는 것은 함수 코드 개발, 스케줄링(EventBridge), 오류 처리 등 수동 관리가 필요하며, S3 수명 주기 정책으로 해결할 수 있는 문제에 불필요한 복잡성을 추가합니다.

C: S3 배치 작업(Batch Operations)은 대량의 기존 객체에 대한 일회성 또는 수동 작업에 적합하지만, 지속적인 버전 관리에는 수명 주기 정책보다 운영 오버헤드가 높고 반복 실행을 위한 자동화가 별도로 필요합니다.

D: S3 버킷에서 버전 관리를 비활성화(Suspend)해도 기존의 비현재 버전은 삭제되지 않고 그대로 남아 스토리지 비용이 계속 발생하며, 향후 객체 복구 능력도 상실됩니다.
