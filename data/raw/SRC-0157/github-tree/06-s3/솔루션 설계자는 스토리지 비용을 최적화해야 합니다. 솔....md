## Question

솔루션 설계자는 스토리지 비용을 최적화해야 합니다. 솔루션 설계자는 더 이상 액세스하지 않거나 거의 액세스하지 않는 Amazon S3 버킷을 식별해야 합니다.
최소한의 운영 오버헤드로 이 목표를 달성할 수 있는 솔루션은 무엇입니까?

- [ ] A. 고급 활동 메트릭에 대한 S3 Storage Lens 대시보드를 사용하여 버킷 액세스 패턴을 분석합니다.
- [ ] B. AWS Management Console에서 S3 대시보드를 사용하여 버킷 액세스 패턴을 분석합니다.
- [ ] C. 버킷에 대한 Amazon CloudWatch BucketSizeBytes 지표를 켭니다. Amazon Athena에서 메트릭 데이터를 사용하여 버킷 액세스 패턴을 분석합니다.
- [ ] D. S3 객체 모니터링을 위해 AWS CloudTrail을 켭니다. Amazon CloudWatch Logs와 통합된 CloudTrail 로그를 사용하여 버킷 액세스 패턴을 분석합니다.

## Answer

정답: A

## Explanation

S3 Storage Lens 대시보드의 고급 활동 메트릭(Advanced Activity Metrics)을 사용하면 버킷별 GET/PUT 요청 수, 바이트 다운로드/업로드 등 상세한 액세스 패턴을 분석할 수 있습니다. 이를 통해 더 이상 액세스하지 않거나 거의 액세스하지 않는 버킷을 시각적으로 쉽게 식별할 수 있습니다. Storage Lens는 AWS가 메트릭을 자동 수집하고 대시보드로 시각화하므로 별도의 코드 개발이나 복잡한 분석 파이프라인 구축 없이 운영 오버헤드가 최소입니다.

오답 분석

B: AWS Management Console의 S3 대시보드는 기본적인 버킷 목록, 크기, 객체 수 등의 정보만 제공하며, 버킷별 액세스 빈도나 활동 트렌드 등 상세한 액세스 패턴 분석 기능이 제한적입니다.

C: CloudWatch BucketSizeBytes 지표는 버킷의 총 크기만 측정하며 액세스 패턴(요청 수, 다운로드/업로드)을 나타내지 않습니다. Athena로 분석하려면 별도의 데이터 파이프라인 구축과 SQL 쿼리 작성이 필요하여 운영 오버헤드가 높습니다.

D: CloudTrail로 S3 데이터 이벤트를 활성화하면 모든 객체 수준 API 호출이 기록되지만, 대량의 로그 데이터가 생성되어 비용이 높고, CloudWatch Logs와 통합하여 분석하려면 상당한 설정과 운영 노력이 필요합니다.
