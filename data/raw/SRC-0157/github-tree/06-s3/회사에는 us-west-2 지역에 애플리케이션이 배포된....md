## Question

회사에는 us-west-2 지역에 애플리케이션이 배포된 여러 AWS 계정이 있습니다. 애플리케이션 로그는 각 계정의 Amazon S3 버킷 내에 저장됩니다. 회사는 단일 S3 버킷을 사용하는 중앙 집중식 로그 분석 솔루션을 구축하려고 합니다. 로그는 us-west-2를 벗어나면 안 되며, 회사는 최소한의 운영 오버헤드를 원합니다.
이러한 요구 사항을 충족하고 가장 비용 효율적인 솔루션은 무엇입니까?

- [ ] A. 애플리케이션 S3 버킷 중 하나에서 중앙 집중식 S3 버킷으로 객체를 복사하는 S3 수명 주기 정책을 생성합니다.
- [ ] B. S3 동일 리전 복제를 사용하여 S3 버킷의 로그를 us-west-2의 다른 S3 버킷으로 복제합니다. 로그 분석을 위해 이 S3 버킷을 사용합니다.
- [ ] C. 매일 PutObject API 작업을 사용하여 버킷의 전체 콘텐츠를 us-west-2의 다른 S3 버킷에 복사하는 스크립트를 작성합니다. 로그 분석을 위해 이 S3 버킷을 사용합니다.
- [ ] D. 로그가 S3 버킷(s3:ObjectCreated:* 이벤트)으로 전달될 때마다 트리거되는 AWS Lambda 함수를 이러한 계정에 작성합니다. us-west-2의 다른 S3 버킷에 로그를 복사합니다. 로그 분석을 위해 이 S3 버킷을 사용합니다.

## Answer

정답: B

## Explanation

S3 동일 리전 복제(Same-Region Replication, SRR)를 사용하면 여러 계정의 S3 버킷에서 us-west-2 내의 중앙 집중식 S3 버킷으로 로그를 자동으로 복제할 수 있습니다. SRR은 동일 리전 내에서 복제되므로 로그 데이터가 us-west-2를 벗어나지 않아 데이터 거주 요구 사항을 충족합니다. 한 번 복제 규칙을 구성하면 새로 업로드되는 객체가 자동으로 복제되므로 운영 오버헤드가 최소화됩니다.

오답 분석

A: S3 수명 주기 정책은 객체를 다른 스토리지 클래스로 전환하거나 만료시키는 기능이며, 다른 S3 버킷으로 객체를 복사하거나 이동하는 기능을 제공하지 않습니다.

C: PutObject API로 매일 전체 콘텐츠를 복사하는 스크립트는 이미 복사된 파일도 다시 복사하여 API 호출 비용과 데이터 전송 비용이 불필요하게 높아지며, 스크립트 관리와 오류 처리에 운영 부담이 큽니다.

D: Lambda 함수를 S3 이벤트 알림으로 트리거하여 로그를 복사하는 것은 가능하지만, 함수 코드 개발, 오류 처리, IAM 역할 관리 등 SRR보다 운영 오버헤드가 높으며, SRR이 AWS 네이티브 기능으로 더 안정적입니다.
