## Question

한 회사가 여러 비즈니스 애플리케이션이 액세스해야 하는 데이터를 저장하기 위해 단일 Amazon S3 버킷을 사용합니다. 이 회사는 VPC에 있는 Amazon EC2 Windows 인스턴스에 애플리케이션을 호스팅합니다. 회사는 애플리케이션에 버킷 액세스 권한을 부여하기 위해 S3 버킷에 대한 버킷 정책을 구성했습니다. 이 회사는 환경에 더 많은 비즈니스 애플리케이션을 지속적으로 추가합니다. 비즈니스 애플리케이션 수가 증가함에 따라 정책 문서 관리가 더욱 어려워집니다. S3 버킷 정책 문서는 곧 정책 크기 할당량에 도달할 예정입니다. 이 회사는 더 많은 비즈니스 애플리케이션을 처리할 수 있도록 아키텍처를 확장할 솔루션이 필요합니다. 운영 효율성이 가장 높은 방식으로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. S3 버킷의 데이터를 Amazon EFS(Amazon Elastic File System) 볼륨으로 마이그레이션합니다. 모든 애플리케이션 소유자가 EFS 볼륨을 사용하도록 애플리케이션을 구성해야 합니다.
- [ ] B. 각 애플리케이션에 AWS Storage Gateway 어플라이언스를 배포합니다. S3 객체에 직접 액세스하는 대신 전용 Storage Gateway 어플라이언스를 사용하여 액세스하도록 애플리케이션을 재구성합니다.
- [ ] C. 각 애플리케이션에 대해 새 S3 버킷을 생성합니다. 새 버킷이 원본 S3 버킷과 동기화되도록 S3 복제를 구성합니다. 애플리케이션 소유자에게 각자의 S3 버킷을 사용하도록 안내합니다.
- [ ] D. 각 애플리케이션에 대한 S3 액세스 포인트를 생성합니다. 애플리케이션 소유자에게 각자의 S3 액세스 포인트를 사용하도록 안내합니다.

## Answer

정답: D

## Explanation

S3 Access Point는 각 애플리케이션에 대해 개별 접근 포인트를 생성하여 독립적인 접근 정책을 관리합니다. 단일 버킷 정책의 크기 제한(20KB) 문제를 해결하며, 새로운 애플리케이션이 추가될 때 새 Access Point만 생성하면 됩니다. 각 Access Point는 자체 정책을 가지므로 정책 관리가 분산되어 운영 효율성이 높고, VPC 제한 등 네트워크 수준 접근 제어도 지원합니다.

오답 분석

A: S3에서 EFS로 데이터를 마이그레이션하는 것은 대규모 아키텍처 변경이 필요하며, 모든 애플리케이션 소유자가 변경해야 하므로 운영 효율적이지 않습니다.

B: 각 애플리케이션에 Storage Gateway를 배포하는 것은 인프라 비용이 높고 관리가 복잡하여 운영 효율성이 가장 낮습니다.

C: 각 애플리케이션에 새 S3 버킷을 생성하고 복제를 구성하면 데이터 중복 저장 비용이 발생하고, 복제 지연 및 일관성 문제가 생길 수 있습니다.
