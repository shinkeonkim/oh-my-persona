## Question

한 회사가 AWS에서 애플리케이션을 호스팅하고 있습니다. 이 애플리케이션은 지난 12년 동안 약 2.5TB의 데이터를 생성했습니다. 회사는 현재 Amazon EBS 볼륨에 데이터를 저장하고 있습니다. 회사는 장기 보관을 위한 비용 효율적인 백업 솔루션을 원합니다. 회사는 감사에 필요할 경우 몇 분 내에 데이터를 검색할 수 있어야 합니다.
이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. EBS 스냅샷을 생성하여 데이터를 백업합니다.
- [ ] B. Amazon S3 버킷을 생성합니다. S3 Glacier Deep Archive 스토리지 클래스를 사용하여 데이터를 백업합니다.
- [ ] C. Amazon S3 버킷을 생성합니다. S3 Glacier Flexible Retrieval 스토리지 클래스를 사용하여 데이터를 백업합니다.
- [ ] D. Amazon Elastic File System(Amazon EFS) 파일 시스템을 생성하여 데이터를 백업합니다.

## Answer

정답: C

## Explanation

S3 Glacier Flexible Retrieval은 장기 보관에 최적화된 저비용 스토리지 클래스로, GB당 약 $0.0036/월의 비용으로 EBS 스냅샷보다 훨씬 경제적입니다. 긴급 검색(Expedited Retrieval) 옵션을 사용하면 1~5분 내에 데이터를 검색할 수 있어 감사 시 몇 분 이내 검색 요구사항을 충족합니다. 12년간 2.5TB의 데이터를 장기 보관하면서도 필요 시 빠른 접근이 가능한 최적의 솔루션입니다.

오답 분석

A: EBS 스냅샷은 S3에 저장되지만 Glacier보다 비용이 높아 장기 보관용 비용 효율적인 백업 솔루션으로 적합하지 않습니다. 또한 스냅샷은 복원 시 볼륨을 다시 생성해야 합니다.

B: S3 Glacier Deep Archive는 가장 저렴한 스토리지이지만 표준 검색에 12시간, 대량 검색에 48시간이 소요되어 '몇 분 내 검색' 요구사항을 충족하지 못합니다.

D: Amazon EFS는 활성 파일 시스템으로 비용이 높아 장기 보관용 백업 스토리지로 적합하지 않으며, 비용 효율적이지 않습니다.
