## Question

회사에는 각각 크기가 약 5MB인 많은 수의 파일을 생성하는 응용 프로그램이 있습니다. 파일은 Amazon S3에 저장됩니다. 회사 정책에 따라 파일은 삭제되기 전에 4년 동안 저장되어야 합니다. 파일에는 재현하기 어려운 중요한 비즈니스 데이터가 포함되어 있으므로 즉각적인 액세스 가능성이 항상 필요합니다. 파일은 객체 생성 후 처음 30일 동안 자주 액세스되지만 처음 30일 이후에는 거의 액세스되지 않습니다.
가장 비용 효율적인 스토리지 솔루션은 무엇입니까?

- [ ] A. 객체 생성 30일 후에 S3 Standard에서 S3 Glacier로 파일을 이동하는 S3 버킷 수명 주기 정책을 생성합니다. 객체 생성 후 4년이 지나면 파일을 삭제합니다.
- [ ] B. S3 Standard에서 S3 One Zone-Infrequent Access(S3 One Zone-IA)로 객체 생성 30일 후에 파일을 이동하는 S3 버킷 수명 주기 정책을 생성합니다. 객체 생성 후 4년이 지나면 파일을 삭제합니다.
- [ ] C. 객체 생성 30일 후에 S3 Standard에서 S3 Standard-Infrequent Access(S3 Standard-IA)로 파일을 이동하는 S3 버킷 수명 주기 정책을 생성합니다. 객체 생성 후 4년이 지나면 파일을 삭제합니다.
- [ ] D. 객체 생성 30일 후에 S3 Standard에서 S3 Standard-Infrequent Access(S3 Standard-IA)로 파일을 이동하는 S3 버킷 수명 주기 정책을 생성합니다. 객체 생성 4년 후 파일을 S3 Glacier로 이동합니다.

## Answer

정답: C

## Explanation

파일은 처음 30일간 자주 액세스되므로 S3 Standard에 저장하고, 30일 후에는 거의 액세스되지 않지만 즉각적인 접근이 필요하므로 S3 Standard-IA로 전환하는 것이 적합합니다. S3 Standard-IA는 S3 Standard와 동일한 밀리초 단위의 첫 바이트 접근 시간을 제공하면서 스토리지 비용이 약 45% 저렴합니다(GB당 $0.0125 vs $0.023). 파일 크기가 약 5MB로 S3 Standard-IA의 최소 과금 크기(128KB) 요구사항도 충족합니다. 4년 후 삭제하도록 만료(Expiration) 작업을 수명 주기 정책에 설정하면 모든 요구 사항을 충족합니다.

오답 분석

A: S3 Glacier(Flexible Retrieval)는 즉각적인 액세스를 제공하지 않습니다. 긴급 검색(Expedited)은 1-5분, 표준 검색(Standard)은 3-5시간이 소요되므로 '즉각적인 접근 가능성(immediate accessibility)이 항상 필요하다'는 요구 사항을 충족하지 못합니다.

B: S3 One Zone-IA는 단일 가용 영역에만 데이터를 저장하여 내구성이 S3 Standard-IA(99.999999999%)와 동일하지만 가용성이 99.5%로 낮습니다. '재현하기 어려운 중요한 비즈니스 데이터'에는 여러 AZ에 복제하여 AZ 장애에도 데이터가 보존되는 S3 Standard-IA가 적합합니다.

D: 4년 후 S3 Glacier로 이동하는 것은 회사 정책에서 '4년 후 삭제'를 요구하고 있으므로 요구 사항에 맞지 않습니다. Glacier로 이동하면 삭제가 아닌 보관이 되어 불필요한 스토리지 비용이 계속 발생합니다.
