## Question

한 회사가 회사의 지불자 AWS 계정에 있는 단일 Amazon S3 버킷에 여러 사업부의 데이터를 저장합니다. 데이터 격리를 유지하기 위해 사업부는 S3 버킷 정책을 사용하여 S3 버킷에 별도의 접두사로 데이터를 저장합니다. 이 회사는 많은 수의 동적 접두사를 추가할 계획입니다. 단일 S3 버킷 정책에 의존하여 대규모 데이터 액세스를 관리하고 싶지 않습니다. 이 회사는 접두사 수준의 데이터 격리를 시행하기 위해 버킷 정책 외에도 안전한 액세스 관리 솔루션을 개발할 계획입니다.

- [ ] A. 모든 사용자에 대한 s3:GetObject 권한을 거부하도록 S3 버킷 정책을 구성합니다. 개별 사업부에 대한 s3:* 액세스를 허용하도록 버킷 정책을 구성합니다.
- [ ] B. Amazon S3 관리 키(SSE-S3)를 사용하여 서버 측 암호화를 사용하여 S3 버킷에서 기본 암호화를 활성화합니다.
- [ ] C. 각 사업부에 대한 S3 액세스 포인트를 만들어 S3 버킷에서 리소스 기반 권한을 구성합니다.
- [ ] D. 미리 서명된 URL을 사용하여 S3 버킷에 대한 액세스를 제공합니다.

## Answer

정답: C

## Explanation

S3 Access Point는 단일 버킷에 대해 여러 개의 접근 포인트를 생성하여 각각 독립적인 접근 정책을 설정할 수 있습니다. 각 비즈니스 유닛에 대해 별도의 Access Point를 생성하면 접두사 수준의 데이터 격리를 시행하면서도 단일 버킷 정책의 크기 제한(20KB) 문제를 회피할 수 있습니다. 동적 접두사가 추가될 때 새 Access Point만 생성하면 되므로 확장성이 뛰어납니다.

오답 분석

A: 모든 사용자에 대해 s3:GetObject를 거부하고 개별적으로 허용하는 방식은 여전히 단일 버킷 정책에 의존하며, 정책 크기 제한 문제를 해결하지 못합니다.

B: SSE-S3 기본 암호화는 저장 데이터의 암호화 설정이며, 접두사 수준의 데이터 접근 격리 및 권한 관리와는 관련이 없습니다.

D: Pre-signed URL은 시간 제한이 있는 임시 접근 권한을 부여하는 방법으로, 지속적인 비즈니스 유닛 수준의 접근 관리에는 적합하지 않으며 운영 오버헤드가 큽니다.
