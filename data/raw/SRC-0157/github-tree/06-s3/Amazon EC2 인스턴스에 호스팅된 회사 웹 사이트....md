## Question

Amazon EC2 인스턴스에 호스팅된 회사 웹 사이트는 Amazon S3에 저장된 분류된 데이터를 처리합니다. 보안 문제로 인해 회사에서는 EC2 리소스와 Amazon S3 간에 비공개적이고 안전한 연결이 필요합니다.
이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. VPC 엔드포인트에서의 액세스를 허용하도록 S3 버킷 정책을 설정합니다.
- [ ] B. S3 버킷에 대한 읽기-쓰기 액세스 권한을 부여하도록 IAM 정책을 설정합니다.
- [ ] C. 프라이빗 서브넷 외부의 리소스에 액세스하기 위해 NAT 게이트웨이를 설정합니다.
- [ ] D. S3 버킷에 액세스하기 위한 액세스 키 ID와 보안 액세스 키를 설정합니다.

## Answer

정답: A

## Explanation

VPC Gateway 엔드포인트를 생성하고 S3 버킷 정책에서 VPC 엔드포인트(aws:sourceVpce 조건 키)를 통한 액세스만 허용하도록 설정하면, EC2 인스턴스와 S3 간의 트래픽이 공용 인터넷을 거치지 않고 AWS 내부 프라이빗 네트워크를 통해 전송됩니다. VPC Gateway 엔드포인트는 S3와 DynamoDB에 대해 무료로 제공되며, 추가 비용 없이 비공개적이고 안전한 연결을 보장합니다. NAT 게이트웨이나 인터넷 게이트웨이 없이도 프라이빗 서브넷에서 S3에 접근할 수 있습니다.

오답 분석

B: IAM 정책으로 읽기-쓰기 액세스 권한을 부여하는 것은 인증과 권한 관리(who can access)에 해당하며, 네트워크 경로의 프라이빗 보안(how data travels)을 보장하지 않습니다.

C: NAT 게이트웨이는 프라이빗 서브넷에서 인터넷으로의 아웃바운드 연결을 제공하지만, 트래픽이 공용 인터넷을 통과하므로 '비공개 연결' 요구 사항을 충족하지 못하며, GB당 데이터 처리 비용도 발생합니다.

D: 액세스 키 ID와 보안 액세스 키는 AWS API 호출의 인증 메커니즘(credentials)이며, 네트워크 연결의 프라이빗 보안 경로를 제공하지 않습니다.
