## Question

회사에는 Amazon S3 버킷에 수백만 개의 객체가 있는 서버리스 웹 사이트가 있습니다. 회사는 S3 버킷을 Amazon CloudFront 배포의 오리진으로 사용합니다. 회사는 객체가 로드되기 전에 S3 버킷에 암호화를 설정하지 않았습니다. 솔루션 설계자는 모든 기존 객체와 향후 S3 버킷에 추가되는 모든 객체에 대해 암호화를 활성화해야 합니다.
최소한의 노력으로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 새 S3 버킷을 생성합니다. 새 S3 버킷에 대한 기본 암호화 설정을 켭니다. 모든 기존 객체를 임시 로컬 저장소에 다운로드합니다. 새 S3 버킷에 객체를 업로드합니다.
- [ ] B. S3 버킷의 기본 암호화 설정을 켭니다. S3 Inventory 기능을 사용하여 암호화되지 않은 객체를 나열하는 .csv 파일을 생성합니다. 복사 명령을 사용하여 해당 객체를 암호화하는 S3 Batch Operations 작업을 실행합니다.
- [ ] C. AWS Key Management Service(AWS KMS)를 사용하여 새 암호화 키를 생성합니다. AWS KMS 관리형 암호화 키(SSE-KMS)로 서버 측 암호화를 사용하도록 S3 버킷의 설정을 변경합니다. S3 버킷에 대한 버전 관리를 켭니다.
- [ ] D. AWS Management Console에서 Amazon S3로 이동합니다. S3 버킷의 객체를 찾습니다. 암호화 필드를 기준으로 정렬합니다. 암호화되지 않은 각 객체를 선택합니다. 수정 버튼을 사용하여 S3 버킷의 모든 암호화되지 않은 객체에 기본 암호화 설정을 적용합니다.

## Answer

정답: B

## Explanation

S3 기본 암호화(Default Encryption) 설정을 켜면 이후 업로드되는 모든 새 객체가 자동으로 암호화됩니다(2023년 1월부터 AWS는 모든 새 S3 버킷에 SSE-S3 기본 암호화를 자동 적용합니다). 기존 암호화되지 않은 객체는 S3 Inventory를 사용하여 암호화 상태를 포함한 .csv 파일(또는 ORC/Parquet 형식)로 목록을 생성한 후, S3 Batch Operations의 복사(Copy) 명령으로 해당 객체를 동일 버킷 내에서 제자리 복사(in-place copy)하면 기본 암호화가 자동으로 적용됩니다. S3 Inventory는 매일 또는 매주 보고서를 생성하며, S3 Batch Operations는 단일 작업으로 수십억 개의 객체를 일괄 처리할 수 있어 수백만 개의 객체에 대해 최소한의 운영 노력으로 암호화를 적용할 수 있습니다.

오답 분석

A: 새 S3 버킷을 생성하고 수백만 개의 객체를 임시 로컬 저장소에 다운로드한 후 다시 업로드하는 것은 막대한 시간, 네트워크 대역폭, 로컬 스토리지 공간이 필요하며 실용적이지 않습니다. CloudFront 배포의 오리진 설정도 변경해야 합니다.

C: SSE-KMS로 암호화 설정을 변경하고 버전 관리를 켜는 것만으로는 기존에 이미 저장된 암호화되지 않은 객체가 소급하여 자동으로 암호화되지 않습니다. 기본 암호화 설정은 새로 업로드되는 객체에만 적용되며, 기존 객체는 S3 Batch Operations 등 별도의 조치가 필요합니다.

D: AWS 콘솔에서 수백만 개의 객체를 수동으로 탐색하고 선택하여 암호화 설정을 변경하는 것은 비현실적이며, S3 콘솔은 대규모 객체 목록 표시에 성능 한계가 있습니다. '최소한의 노력' 요구 사항에 전혀 부합하지 않습니다.
