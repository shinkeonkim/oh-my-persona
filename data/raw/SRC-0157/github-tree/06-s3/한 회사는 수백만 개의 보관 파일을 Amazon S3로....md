## Question

한 회사는 수백만 개의 보관 파일을 Amazon S3로 마이그레이션했습니다. 솔루션 설계자는 고객이 제공한 키를 사용하여 모든 보관 데이터를 암호화하는 솔루션을 구현해야 합니다. 솔루션은 암호화되지 않은 기존 객체와 향후 객체를 암호화해야 합니다.
어떤 솔루션이 이러한 요구 사항을 충족합니까?

- [ ] A. Amazon S3 인벤토리 보고서를 필터링하여 암호화되지 않은 객체 목록을 생성합니다. 고객 제공 키(SSE-C)를 사용한 서버 측 암호화를 통해 목록의 객체를 암호화하도록 S3 배치 작업 작업을 구성합니다. 고객 제공 키(SSE-C)로 서버 측 암호화를 사용하도록 S3 기본 암호화 기능을 구성합니다.
- [ ] B. S3 Storage Lens 지표를 사용하여 암호화되지 않은 S3 버킷을 식별합니다. AWS KMS 키(SSE-KMS)로 서버 측 암호화를 사용하도록 S3 기본 암호화 기능을 구성합니다.
- [ ] C. Amazon S3에 대한 AWS 사용 보고서를 필터링하여 암호화되지 않은 객체 목록을 생성합니다. AWS KMS 키(SSE-KMS)를 사용한 서버 측 암호화를 통해 목록의 객체를 암호화하도록 AWS Batch 작업을 구성합니다. AWS KMS 키(SSE-KMS)로 서버 측 암호화를 사용하도록 S3 기본 암호화 기능을 구성합니다.
- [ ] D. Amazon S3에 대한 AWS 사용 보고서를 필터링하여 암호화되지 않은 객체 목록을 생성합니다. 고객 제공 키(SSE-C)로 서버 측 암호화를 사용하도록 S3 기본 암호화 기능을 구성합니다.

## Answer

정답: A

## Explanation

Amazon S3 Inventory 보고서는 버킷 내 모든 객체의 메타데이터(크기, 스토리지 클래스, 암호화 상태, 복제 상태 등)를 CSV, ORC, 또는 Parquet 형식으로 매일 또는 매주 생성합니다. Inventory 보고서의 암호화 상태(EncryptionStatus) 필드를 필터링하면 암호화되지 않은 객체 목록을 정확하게 식별할 수 있습니다. S3 Batch Operations는 이 Inventory 보고서를 입력으로 받아 수백만 개의 객체에 대해 복사(COPY) 작업을 실행하여 SSE-C 암호화를 일괄 적용할 수 있습니다. SSE-C(고객 제공 키를 사용한 서버 측 암호화)는 업로드 시마다 고객이 암호화 키를 HTTP 헤더로 직접 제공해야 하며 AWS는 키를 저장하지 않습니다. 단, SSE-C는 S3 버킷의 기본 암호화(default encryption)로 설정할 수 없으며, 향후 업로드에도 각 요청 시 클라이언트가 키를 제공해야 합니다.

오답 분석

B: S3 Storage Lens는 버킷 수준의 집계 메트릭(암호화된 객체 비율 등)을 제공하지만, 개별 암호화되지 않은 객체 목록을 생성하지 못합니다. 또한 SSE-KMS는 AWS KMS가 관리하는 키를 사용하므로 '고객이 제공한 키(customer-provided key)'로 암호화하라는 요구사항을 충족하지 못합니다.

C: AWS 사용 보고서(Usage Report)는 S3 스토리지 사용량과 데이터 전송량의 과금 정보를 제공하며, 개별 객체의 암호화 상태를 포함하지 않습니다. 또한 AWS Batch는 EC2/Fargate 기반 배치 컴퓨팅 서비스로, S3 Batch Operations와는 완전히 다른 서비스입니다. SSE-KMS도 고객 제공 키 요구사항에 부합하지 않습니다.

D: AWS 사용 보고서만으로는 암호화되지 않은 개별 객체를 식별할 수 없으며, S3 기본 암호화 설정만으로는 기존에 이미 저장된 암호화되지 않은 객체에 소급적으로 암호화를 적용하지 않습니다. 기존 객체의 암호화에는 S3 Batch Operations를 통한 복사 작업이 필요합니다.
