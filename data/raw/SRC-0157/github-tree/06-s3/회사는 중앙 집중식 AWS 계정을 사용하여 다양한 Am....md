## Question

회사는 중앙 집중식 AWS 계정을 사용하여 다양한 Amazon S3 버킷에 로그 데이터를 저장합니다. 솔루션 설계자는 데이터가 S3 버킷에 업로드되기 전에 미사용 데이터가 암호화되었는지 확인해야 합니다. 또한 데이터는 전송 중에 암호화되어야 합니다.
어떤 솔루션이 이러한 요구 사항을 충족합니까?

- [ ] A. 클라이언트 측 암호화를 사용하여 S3 버킷에 업로드되는 데이터를 암호화합니다.
- [ ] B. 서버 측 암호화를 사용하여 S3 버킷에 업로드되는 데이터를 암호화합니다.
- [ ] C. S3 업로드를 위해 S3 관리형 암호화 키(SSE-S3)로 서버 측 암호화를 사용해야 하는 버킷 정책을 만듭니다.
- [ ] D. 기본 AWS Key Management Service(AWS KMS) 키를 사용하여 S3 버킷을 암호화하는 보안 옵션을 활성화합니다.

## Answer

정답: A

## Explanation

클라이언트 측 암호화(Client-Side Encryption)를 사용하면 데이터가 S3에 업로드되기 전에 클라이언트 애플리케이션에서 암호화됩니다. 따라서 전송 전에 데이터가 이미 암호화된 상태이므로 미사용 데이터 암호화 요구 사항을 충족합니다. 또한 S3로의 데이터 전송 시 HTTPS(TLS)를 사용하면 전송 중 암호화도 보장됩니다. 클라이언트 측 암호화는 AWS에 전달되는 데이터의 기밀성을 완전히 통제할 수 있는 가장 강력한 방법입니다.

오답 분석

B: 서버 측 암호화(SSE)는 데이터가 S3 서버에 도착한 후에 암호화하므로, 데이터가 S3에 '업로드되기 전에' 미사용 데이터가 암호화되어야 한다는 요구 사항을 충족하지 못합니다.

C: SSE-S3 버킷 정책으로 서버 측 암호화를 강제하더라도 데이터가 업로드되기 전에는 암호화되지 않습니다. 서버 측 암호화는 S3가 데이터를 수신한 후 저장 시점에 암호화합니다.

D: KMS 기본 키로 S3 버킷을 암호화하는 것도 서버 측 암호화(SSE-KMS)이며, 클라이언트에서 데이터가 암호화되지 않은 상태로 전송됩니다. HTTPS를 통한 전송 중 암호화는 가능하지만 업로드 전 미사용 데이터 암호화 요구 사항에 부합하지 않습니다.
