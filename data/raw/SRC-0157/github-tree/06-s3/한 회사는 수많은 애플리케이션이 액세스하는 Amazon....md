## Question

한 회사는 수많은 애플리케이션이 액세스하는 Amazon S3 버킷에서 데이터 레이크를 관리합니다. 버킷에는 각 애플리케이션에 대한 고유한 S3 접두사가 포함되어 있습니다. 회사는 각 애플리케이션을 특정 접두사로 제한하고 각 접두사 아래의 객체를 세부적으로 제어하기를 원합니다.
최소한의 운영 오버헤드로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 각 애플리케이션에 대한 전용 S3 액세스 포인트 및 액세스 포인트 정책을 생성합니다.
- [ ] B. S3 Batch Operations 작업을 생성하여 S3 버킷의 각 객체에 대한 ACL 권한을 설정합니다.
- [ ] C. S3 버킷의 객체를 각 애플리케이션의 새 S3 버킷에 복제합니다. 접두사별로 복제 규칙을 만듭니다.
- [ ] D. S3 버킷의 객체를 각 애플리케이션의 새 S3 버킷에 복제합니다. 각 애플리케이션에 대한 전용 S3 액세스 포인트를 생성합니다.

## Answer

정답: A

## Explanation

S3 액세스 포인트(Access Points)를 각 애플리케이션에 대해 생성하면 각 액세스 포인트에 고유한 정책을 적용하여 특정 S3 접두사(prefix)에 대한 접근을 세밀하게 제한할 수 있습니다. 단일 복잡한 버킷 정책 대신 각 애플리케이션별 독립적인 액세스 포인트 정책을 관리하므로 정책의 가독성과 유지보수성이 크게 향상됩니다. 각 액세스 포인트는 고유한 DNS 이름을 가지며, 버킷 데이터를 복제하지 않고도 세분화된 접근 제어를 제공하여 운영 오버헤드가 최소화됩니다.

오답 분석

B: S3 배치 작업으로 각 객체의 ACL을 설정하는 것은 객체 수가 많을수록 관리가 복잡해지며, ACL은 최대 100개의 권한 부여만 지원하고 접두사 기반 제어에 적합하지 않습니다. AWS는 ACL 대신 IAM/버킷 정책 사용을 권장합니다.

C: 각 애플리케이션을 위한 새 S3 버킷으로 복제하면 데이터가 중복되어 스토리지 비용이 배수로 증가하고, 복제 동기화 및 일관성 관리가 복잡해집니다.

D: 새 S3 버킷으로 복제하고 추가로 액세스 포인트를 생성하는 것은 불필요한 데이터 복제 비용과 복잡성을 추가합니다. 기존 단일 버킷에 직접 액세스 포인트를 생성하면 됩니다.
