## Question

한 회사에서 대량의 데이터를 병렬로 처리하는 애플리케이션을 배포하고 있습니다. 회사는 워크로드에 Amazon EC2 인스턴스를 사용할 계획입니다. 노드 그룹이 동일한 기본 하드웨어를 공유하지 못하도록 네트워크 아키텍처를 구성할 수 있어야 합니다.
이러한 요구 사항을 충족하는 네트워킹 솔루션은 무엇입니까?

- [ ] A. 분산 배치 그룹에서 EC2 인스턴스를 실행합니다.
- [ ] B. EC2 인스턴스를 별도의 계정으로 그룹화합니다.
- [ ] C. 전용 테넌시로 EC2 인스턴스를 구성합니다.
- [ ] D. 공유 테넌시로 EC2 인스턴스를 구성합니다.

## Answer

정답: A

## Explanation

분산 배치 그룹(Spread Placement Group)은 각 EC2 인스턴스를 서로 다른 기본 하드웨어(물리적 서버/랙)에 배치하여, 하드웨어 장애의 상관 관계(correlated failure)를 최소화합니다. 이는 노드 그룹이 동일한 기본 하드웨어를 공유하지 못하도록 해야 하는 요구 사항에 정확히 부합합니다. 분산 배치 그룹은 가용 영역당 최대 7개의 인스턴스를 배치할 수 있으며, 각 인스턴스는 고유한 랙에 위치합니다.

오답 분석

B: EC2 인스턴스를 별도의 AWS 계정으로 분리하는 것은 리소스 격리 및 청구 분리에 유용하지만, 하드웨어 수준의 격리를 보장하지 않습니다. AWS는 다른 계정의 인스턴스도 동일한 물리적 하드웨어에서 실행할 수 있으므로 요구 사항을 충족하지 못합니다.

C: 전용 테넌시(Dedicated Tenancy)는 자사 인스턴스가 다른 AWS 고객의 인스턴스와 물리적 하드웨어를 공유하지 않도록 합니다. 그러나 자사의 여러 인스턴스가 서로 같은 물리적 서버에 배치되는 것은 방지하지 않으므로, 노드 그룹 간 하드웨어 공유를 막는 요구 사항에 부합하지 않습니다.

D: 공유 테넌시(Shared Tenancy)는 EC2의 기본 설정으로, 자사 및 다른 고객의 인스턴스와 물리적 하드웨어를 공유할 수 있습니다. 이는 요구 사항의 정반대이며 하드웨어 격리를 전혀 제공하지 않습니다.
