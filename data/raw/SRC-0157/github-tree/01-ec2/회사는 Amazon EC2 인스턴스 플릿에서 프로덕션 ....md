## Question

회사는 Amazon EC2 인스턴스 플릿에서 프로덕션 애플리케이션을 실행합니다. 애플리케이션은 Amazon SQS 대기열에서 데이터를 읽고 병렬로 메시지를 처리합니다. 메시지 볼륨은 예측할 수 없으며 종종 트래픽이 간헐적으로 발생합니다. 이 애플리케이션은 다운타임 없이 지속적으로 메시지를 처리해야 합니다.
이러한 요구 사항을 가장 비용 효율적으로 충족하는 솔루션은 무엇입니까?

- [ ] A. 스팟 인스턴스를 독점적으로 사용하여 필요한 최대 용량을 처리합니다.
- [ ] B. 예약 인스턴스를 독점적으로 사용하여 필요한 최대 용량을 처리합니다.
- [ ] C. 기본 용량으로 예약 인스턴스를 사용하고 추가 용량을 처리하려면 스팟 인스턴스를 사용합니다.
- [ ] D. 기본 용량에는 예약 인스턴스를 사용하고 추가 용량을 처리하려면 온디맨드 인스턴스를 사용합니다.

## Answer

정답: D

## Explanation

예약 인스턴스로 기본 용량(상시 실행)을 확보하여 안정적인 메시지 처리를 보장하면서 비용을 절감하고, 예측 불가능한 간헐적 추가 트래픽에 대해서는 온디맨드 인스턴스를 사용하면 안정적이면서도 비용 효율적인 구성이 가능합니다. 프로덕션 애플리케이션은 '다운타임 없이 지속적으로 메시지를 처리'해야 하므로, 기본 용량과 추가 용량 모두에서 인스턴스 중단이 허용되지 않습니다. 온디맨드 인스턴스는 중단 없이 안정적으로 실행되므로 이 요구 사항에 적합합니다.

오답 분석

A: 스팟 인스턴스만 사용하면 AWS가 용량을 회수할 때 2분 전 알림으로 인스턴스가 중단됩니다. 모든 인스턴스가 스팟이면 대규모 중단 시 메시지 처리가 완전히 중단될 수 있어, 다운타임 없이 지속적으로 처리해야 하는 요구 사항을 충족하지 못합니다.

B: 예약 인스턴스만으로 최대 용량을 커버하면, 간헐적 트래픽(intermittent traffic)이 없는 대부분의 시간에 과도한 예약 용량에 대해 비용을 지불하게 되어 비용 효율적이지 않습니다.

C: 스팟 인스턴스는 비용이 매우 저렴하지만 중단 가능성이 있습니다. SQS 큐에서 메시지를 처리하는 경우 메시지 재처리가 가능하긴 하지만, 문제에서 '다운타임 없이 지속적으로' 처리해야 한다고 명시했으므로, 스팟 중단 시 처리 지연이 발생하여 요구 사항을 완벽히 충족하지 못합니다.
