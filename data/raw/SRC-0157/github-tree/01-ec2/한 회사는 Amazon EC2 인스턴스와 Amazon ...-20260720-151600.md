## Question

한 회사는 Amazon EC2 인스턴스와 Amazon Elastic Block Store(Amazon EBS)를 사용하여 자체 관리형 데이터베이스를 실행합니다. 이 회사는 모든 EBS 볼륨에 걸쳐 350TB의 데이터를 보유하고 있습니다. 회사는 매일 EBS 스냅샷을 생성하여 1개월간 보관합니다. 일일 변동률은 EBS 볼륨의 5%입니다.
새로운 규정으로 인해 회사는 월별 스냅샷을 7년 동안 보관해야 합니다. 회사는 새로운 규정을 준수하고 관리 노력을 최소화하면서 데이터를 사용할 수 있도록 백업 전략을 변경해야 합니다.
이러한 요구 사항을 가장 비용 효율적으로 충족하는 솔루션은 무엇입니까?

- [ ] A. EBS 스냅샷 표준 계층에 일일 스냅샷을 1개월 동안 보관합니다. 보존 기간이 7년인 월별 스냅샷을 Amazon S3 Glacier Deep Archive에 복사합니다.
- [ ] B. 현재 EBS 스냅샷 정책을 계속 유지합니다. 보존 기간이 7년인 Amazon EBS 스냅샷 아카이브로 월간 스냅샷을 이동하는 새 정책을 추가합니다.
- [ ] C. EBS 스냅샷 표준 계층에 일일 스냅샷을 1개월 동안 보관합니다. 월별 스냅샷을 7년 동안 표준 계층에 유지합니다. 증분 스냅샷을 사용합니다.
- [ ] D. EBS 스냅샷 표준 계층에 일일 스냅샷을 보관합니다. EBS 다이렉트 API를 사용하여 매달 모든 EBS 볼륨의 스냅샷을 찍습니다. Infrequent Access 계층의 Amazon S3 버킷에 스냅샷을 7년 동안 저장합니다.

## Answer

정답: B

## Explanation

현재 EBS 스냅샷 정책을 유지하면서 Amazon EBS Snapshots Archive로 월간 스냅샷을 이동하는 새 정책을 추가하는 것이 가장 비용 효율적인 솔루션입니다. EBS Snapshot Archive 계층은 표준 스냅샷 스토리지 대비 최대 75% 저렴하여, 350TB 데이터의 월별 스냅샷을 7년간 보관하는 비용을 크게 절감합니다. 아카이브된 스냅샷은 복원에 24~72시간이 걸리지만, 장기 보관 규정 준수 목적에는 충분합니다. DLM 정책으로 자동화하여 관리 노력을 최소화할 수 있습니다.

오답 분석

A: EBS 스냅샷을 Amazon S3 Glacier Deep Archive에 직접 복사하는 것은 지원되지 않습니다. EBS 스냅샷은 AWS 관리형 S3 스토리지에 저장되며, 사용자가 Glacier로 직접 복사할 수 없습니다.

C: 월별 스냅샷을 7년간 표준 계층에 유지하면 증분 스냅샷을 사용하더라도 Snapshot Archive 계층보다 비용이 훨씬 높습니다. 350TB 데이터의 7년치 월별 스냅샷을 표준 계층에 보관하는 것은 비용 효율적이지 않습니다.

D: EBS 다이렉트 API로 스냅샷을 찍어 S3 IA 버킷에 저장하는 것은 기술적으로 복잡하고, EBS 스냅샷의 증분 특성을 활용할 수 없어 저장 비용이 크게 증가합니다. 또한 관리 노력이 크게 늘어납니다.
