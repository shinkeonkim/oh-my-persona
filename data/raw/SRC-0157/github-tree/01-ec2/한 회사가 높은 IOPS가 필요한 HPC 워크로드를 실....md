## Question

한 회사가 높은 IOPS가 필요한 HPC 워크로드를 실행합니다.
이러한 요구 사항을 충족하는 단계 조합은 무엇입니까? (2개 선택)

- [ ] A. Amazon EFS를 고성능 파일 시스템으로 사용합니다.
- [ ] B. Amazon FSx for Lustre를 고성능 파일 시스템으로 사용합니다.
- [ ] C. EC2 인스턴스의 자동 확장 그룹을 만듭니다. 예약 인스턴스를 사용합니다. 분산 배치 그룹을 구성합니다. 분석에 AWS Batch를 사용합니다.
- [ ] D. Amazon S3의 Mountpoint를 고성능 파일 시스템으로 사용합니다.
- [ ] E. EC2 인스턴스의 자동 확장 그룹을 만듭니다. 혼합 인스턴스 유형과 클러스터 배치 그룹을 사용합니다. 분석에 Amazon EMR을 사용합니다.

## Answer

정답: B, E

## Explanation

B(Amazon FSx for Lustre)는 초당 수백만 IOPS와 수백 GB/s의 처리량으로 확장 가능한 고성능 병렬 파일 시스템으로 HPC 워크로드에 최적입니다. E(혼합 인스턴스 유형 + 클러스터 배치 그룹 + Amazon EMR)에서 클러스터 배치 그룹은 인스턴스를 물리적으로 가까이 배치하여 10Gbps 이상의 저지연 네트워크를 제공하며, EMR은 빅데이터 분석에 특화된 관리형 서비스입니다.

오답 분석

A: Amazon EFS는 범용 NFS 파일 시스템으로 최대 수만 IOPS 수준이며, HPC에 필요한 수백만 IOPS를 제공하지 못합니다.

C: 분산(Spread) 배치 그룹은 인스턴스를 별도 하드웨어에 분산 배치하므로 HPC에 필요한 저지연 인스턴스 간 통신에 적합하지 않습니다. 클러스터 배치 그룹이 필요합니다. AWS Batch는 배치 처리용이며 EMR보다 빅데이터 분석에 덜 적합합니다.

D: Mountpoint for Amazon S3는 S3 객체에 POSIX 파일 시스템 인터페이스를 제공하지만, 객체 스토리지 특성상 HPC에 필요한 수백만 IOPS의 고성능을 지원하지 않습니다.
