## Question

회사에서 기존 3계층 웹 아키텍처의 비용을 줄이고자 합니다. 웹, 애플리케이션 및 데이터베이스 서버는 개발, 테스트 및 프로덕션 환경을 위해 Amazon EC2 인스턴스에서 실행됩니다.
EC2 인스턴스는 사용량이 많은 시간에 평균 30%의 CPU 사용률을 보이고 사용량이 적은 시간에는 10%의 CPU 사용률을 보입니다.
프로덕션 EC2 인스턴스는 하루 24시간 실행됩니다. 개발 및 테스트 EC2 인스턴스는 매일 최소 8시간 동안 실행됩니다. 이 회사는 개발을 중지하고 사용하지 않는 EC2 인스턴스를 테스트하기 위해 자동화를 구현할 계획입니다.
어떤 EC2 인스턴스 구매 솔루션이 회사의 요구 사항을 가장 비용 효율적으로 충족합니까?

- [ ] A. 프로덕션 EC2 인스턴스에는 스팟 인스턴스를 사용합니다. 개발 및 테스트 EC2 인스턴스에 예약 인스턴스를 사용합니다.
- [ ] B. 프로덕션 EC2 인스턴스에 예약 인스턴스를 사용합니다. 개발 및 테스트 EC2 인스턴스에 온디맨드 인스턴스를 사용합니다.
- [ ] C. 프로덕션 EC2 인스턴스에 스팟 블록을 사용합니다. 개발 및 테스트 EC2 인스턴스에 예약 인스턴스를 사용합니다.
- [ ] D. 프로덕션 EC2 인스턴스에 온디맨드 인스턴스를 사용합니다. 개발 및 테스트 EC2 인스턴스에 스팟 블록을 사용합니다.

## Answer

정답: B

## Explanation

프로덕션 EC2 인스턴스는 하루 24시간 실행되므로 예약 인스턴스(Reserved Instances)를 사용하면 장기적으로 가장 큰 비용 절감(온디맨드 대비 최대 72%)을 얻을 수 있습니다. 개발 및 테스트 인스턴스는 하루 최소 8시간만 사용하고 자동화로 사용하지 않을 때 중지하므로, 온디맨드 인스턴스를 사용하고 중지(stop) 시 EBS 볼륨 비용만 발생하도록 하는 것이 가장 비용 효율적입니다. CPU 사용률이 낮으므로(피크 30%, 비피크 10%) 적절한 인스턴스 크기 조정(Right Sizing)도 추가로 고려해야 합니다.

오답 분석

A: 프로덕션에 스팟 인스턴스를 사용하면 2분 전 알림으로 인스턴스가 언제든 중단될 수 있어, 프로덕션 웹/애플리케이션/데이터베이스 서버에는 절대 부적합합니다. 프로덕션 안정성이 보장되지 않습니다.

C: 스팟 블록(Spot Blocks)은 1~6시간의 정해진 기간 동안 스팟 인스턴스를 중단 없이 사용하는 기능이었으나, AWS에서 2021년 이후 더 이상 새로운 스팟 블록 할당을 지원하지 않습니다. 또한 프로덕션에 스팟 기반 인스턴스를 사용하는 것은 안정성 면에서 부적합합니다.

D: 프로덕션에 온디맨드 인스턴스를 사용하면 24시간 실행 시 예약 인스턴스보다 비용이 최대 72% 더 높아 비용 최적화에 적합하지 않습니다. 스팟 블록은 더 이상 AWS에서 지원하지 않는 기능입니다.
