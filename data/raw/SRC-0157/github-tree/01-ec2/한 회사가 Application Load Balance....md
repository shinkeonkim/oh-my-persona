## Question

한 회사가 Application Load Balancer 뒤의 Amazon EC2 온디맨드 인스턴스 그룹에서 프로덕션 환경의 상태 비저장 웹 애플리케이션을 실행합니다. 애플리케이션은 각 영업일 8시간 동안 사용량이 많습니다. 애플리케이션 사용량은 밤 사이 중간 정도이며 안정적입니다. 주말에는 애플리케이션 사용량이 적습니다.
회사는 애플리케이션의 가용성에 영향을 미치지 않으면서 EC2 비용을 최소화하려고 합니다.
이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 전체 워크로드에 스팟 인스턴스를 사용합니다.
- [ ] B. 기준 사용 수준에 대해 예약 인스턴스를 사용합니다. 애플리케이션에 필요한 추가 용량에는 스팟 인스턴스를 사용합니다.
- [ ] C. 기본 사용 수준에 대해 온디맨드 인스턴스를 사용합니다. 애플리케이션에 필요한 추가 용량에는 스팟 인스턴스를 사용합니다.
- [ ] D. 기본 사용 수준에 전용 인스턴스를 사용합니다. 애플리케이션에 필요한 추가 용량에 대해서는 온디맨드 인스턴스를 사용합니다.

## Answer

정답: B

## Explanation

예약 인스턴스(Reserved Instances)를 야간의 안정적인 기준 사용량(moderate and steady)에 적용하면, 24/7 운영되는 기본 용량의 비용을 온디맨드 대비 최대 72%까지 절감할 수 있습니다. 업무 시간 동안의 추가 용량에는 스팟 인스턴스를 사용하면 온디맨드 대비 최대 90%까지 비용을 절약할 수 있습니다. 상태 비저장(stateless) 웹 애플리케이션은 Application Load Balancer 뒤에서 실행되므로, 스팟 인스턴스가 중단되어도 다른 인스턴스가 즉시 트래픽을 처리할 수 있어 가용성에 영향을 미치지 않습니다.

오답 분석

A: 전체 워크로드에 스팟 인스턴스만 사용하면, AWS가 용량을 회수할 때 모든 인스턴스가 동시에 또는 순차적으로 종료될 위험이 있습니다. 기본 용량에 대한 보장이 없으므로 애플리케이션 가용성이 보장되지 않습니다.

C: 기본 사용량에 온디맨드 인스턴스를 사용하면 예약 인스턴스에 비해 비용이 최대 72% 더 높아 비용 최소화 요구 사항을 충족하지 못합니다. 24/7 실행되는 기본 용량에는 RI가 훨씬 비용 효율적입니다.

D: 전용 인스턴스(Dedicated Instances)는 다른 고객과 하드웨어를 공유하지 않는 격리된 환경을 제공하지만, 특별한 규정 준수 요구 사항이 없는 한 일반 인스턴스보다 비용이 높습니다. 비용 최소화 목적에 전혀 적합하지 않습니다.
