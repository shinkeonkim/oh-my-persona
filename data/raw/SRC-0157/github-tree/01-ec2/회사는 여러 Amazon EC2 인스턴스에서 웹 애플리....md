## Question

회사는 여러 Amazon EC2 인스턴스에서 웹 애플리케이션을 호스팅합니다. EC2 인스턴스는 사용자 요구에 따라 확장되는 Auto Scaling 그룹에 있습니다. 회사는 장기적인 약정 없이 비용 절감을 최적화하기를 원합니다.
이러한 요구 사항을 충족하기 위해 솔루션 설계자가 권장해야 하는 EC2 인스턴스 구매 옵션은 무엇입니까?

- [ ] A. 전용 인스턴스만 해당
- [ ] B. 온디맨드 인스턴스 전용
- [ ] C. 온디맨드 인스턴스와 스팟 인스턴스의 혼합
- [ ] D. 온디맨드 인스턴스와 예약 인스턴스의 혼합

## Answer

정답: C

## Explanation

온디맨드 인스턴스와 스팟 인스턴스를 혼합(Mixed Instances Policy)하면, 장기적인 약정 없이 비용을 최적화할 수 있습니다. 온디맨드 인스턴스로 기본 가용성과 안정성을 보장하고, 스팟 인스턴스로 사용자 수요에 따라 탄력적으로 확장하여 비용을 크게 절감합니다. Auto Scaling 그룹에서 혼합 인스턴스 정책(Mixed Instances Policy)을 사용하면 온디맨드와 스팟의 비율을 자동으로 관리할 수 있습니다. 예약 인스턴스나 Savings Plan은 장기 약정이 필요하므로 조건에 부합하지 않습니다.

오답 분석

A: 전용 인스턴스(Dedicated Instances)는 물리적 하드웨어를 다른 고객과 공유하지 않는 격리된 환경을 제공하며, 일반 인스턴스보다 비용이 높습니다. 특별한 규정 준수 요구 사항이 없는 한 비용 최적화에 전혀 적합하지 않습니다.

B: 온디맨드 인스턴스만 사용하면 스팟 인스턴스를 활용한 비용 절감 기회(최대 90% 절감)를 놓치게 됩니다. 웹 애플리케이션의 스케일 아웃/인 용량에 스팟을 활용하면 상당한 비용 절감이 가능합니다.

D: 예약 인스턴스(Reserved Instances)는 1년 또는 3년의 장기 약정이 필요합니다. 문제에서 '장기적인 약정 없이' 비용을 최적화하라고 명시했으므로, 예약 인스턴스는 요구 사항에 부합하지 않습니다.
