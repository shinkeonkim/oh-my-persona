## Question

한 회사는 Amazon EC2 인스턴스에서 고성능 컴퓨팅 워크로드(HPC)를 실행할 계획입니다. 워크로드에는 긴밀하게 결합된 노드 간 통신을 통해 대기 시간이 짧은 네트워크 성능과 높은 네트워크 처리량이 필요합니다.
어떤 솔루션이 이러한 요구 사항을 충족합니까?

- [ ] A. 클러스터 배치 그룹의 일부가 되도록 EC2 인스턴스를 구성합니다.
- [ ] B. 전용 인스턴스 테넌시를 사용하여 EC2 인스턴스를 시작합니다.
- [ ] C. EC2 인스턴스를 스팟 인스턴스로 시작합니다.
- [ ] D. EC2 인스턴스가 시작될 때 온디맨드 용량 예약을 구성합니다.

## Answer

정답: A

## Explanation

클러스터 배치 그룹(Cluster Placement Group)은 EC2 인스턴스를 동일 가용 영역 내의 물리적으로 인접한 서버에 배치하여, 인스턴스 간 최저 지연 시간(마이크로초 수준)과 최대 네트워크 처리량(Enhanced Networking으로 최대 100Gbps)을 제공합니다. HPC 워크로드에서 요구하는 긴밀하게 결합된(tightly coupled) 노드 간 통신을 위해 설계된 유일한 배치 전략이며, MPI(Message Passing Interface) 등의 병렬 컴퓨팅 프레임워크에 최적화되어 있습니다.

오답 분석

B: 전용 인스턴스 테넌시(Dedicated Instance Tenancy)는 다른 AWS 고객과의 하드웨어 격리를 제공하지만, 자사 인스턴스 간의 물리적 근접성이나 네트워크 성능 최적화를 보장하지 않습니다. 라이선스 규정 준수에는 유용하지만 HPC 네트워크 성능과는 무관합니다.

C: 스팟 인스턴스(Spot Instances)는 여유 EC2 용량을 할인된 가격에 사용하는 비용 절감 옵션입니다. 네트워크 지연 시간이나 처리량을 개선하는 기능이 아니며, 2분 전 알림으로 언제든 중단될 수 있어 장기 실행 HPC 워크로드에는 부적합합니다.

D: 온디맨드 용량 예약(On-Demand Capacity Reservation)은 특정 AZ에서 인스턴스를 시작할 수 있는 용량을 사전에 확보하는 것입니다. 용량 가용성은 보장하지만, 인스턴스 간 물리적 배치나 네트워크 성능 최적화에는 영향을 주지 않습니다.
