## Question

회사는 Amazon EC2 온디맨드 인스턴스에서 사용자 지정 애플리케이션을 실행하고 있습니다. 애플리케이션에는 하루 24시간, 주 7일 실행해야 하는 프론트엔드 노드와 워크로드에 따라 짧은 시간 동안만 실행해야 하는 백엔드 노드가 있습니다. 백엔드 노드의 수는 하루 동안 다양합니다.
회사는 워크로드에 따라 더 많은 인스턴스를 스케일 아웃 및 스케일 인해야 합니다.
이러한 요구 사항을 가장 비용 효율적으로 충족하는 솔루션은 무엇입니까?

- [ ] A. 프론트엔드 노드에는 예약 인스턴스를 사용합니다. 백엔드 노드에 AWS Fargate를 사용합니다.
- [ ] B. 프론트엔드 노드에 예약 인스턴스를 사용합니다. 백엔드 노드에 스팟 인스턴스를 사용합니다.
- [ ] C. 프론트엔드 노드에 스팟 인스턴스를 사용합니다. 백엔드 노드에 예약 인스턴스를 사용합니다.
- [ ] D. 프론트엔드 노드에 스팟 인스턴스를 사용합니다. 백엔드 노드에 AWS Fargate를 사용합니다.

## Answer

정답: B

## Explanation

프론트엔드 노드는 24/7 상시 실행되어야 하므로 예약 인스턴스(Reserved Instances)를 사용하면 온디맨드 대비 최대 72%까지 비용을 절감할 수 있습니다. 백엔드 노드는 워크로드에 따라 짧은 시간만 실행되고 수가 가변적이므로, 스팟 인스턴스를 사용하면 온디맨드 대비 최대 90%까지 비용을 절약할 수 있습니다. 백엔드 작업이 중단되어도 재시작하면 되는 워크로드이므로 스팟 인스턴스의 중단 특성이 문제되지 않습니다. 이 조합이 가장 비용 효율적입니다.

오답 분석

A: 프론트엔드에 예약 인스턴스를 사용하는 것은 적절하지만, AWS Fargate는 컨테이너 기반 서버리스 컴퓨팅 서비스로 기존 EC2 기반 애플리케이션을 실행하려면 컨테이너화(Docker 이미지 생성 등)가 필요합니다. 문제에서 EC2 인스턴스 기반 사용자 지정 애플리케이션이라고 했으므로, 컨테이너화 없이 스팟 인스턴스가 더 간단하고 비용 효율적입니다.

C: 프론트엔드 노드에 스팟 인스턴스를 사용하면, 24/7 상시 실행이 필요한 서비스가 2분 전 알림으로 언제든 중단될 수 있어 서비스 안정성이 크게 저하됩니다. 프론트엔드는 항상 사용자 요청을 받아야 하므로 예약 인스턴스가 적합합니다.

D: 프론트엔드에 스팟 인스턴스를 사용하면 상시 실행 서비스의 안정성이 보장되지 않으며, Fargate는 EC2 기반 워크로드의 컨테이너화가 필요하여 추가 작업이 발생합니다.
