## Question

회사는 Amazon EC2 인스턴스의 비용을 최적화해야 합니다. 회사는 또한 2~3개월마다 EC2 인스턴스의 유형과 제품군을 변경해야 합니다.
이러한 요구 사항을 충족하기 위해 회사는 무엇을 해야 합니까?

- [ ] A. 3년 기간 동안 부분 선결제 예약 인스턴스를 구매합니다.
- [ ] B. 1년 기간 동안 선결제 없는 Compute Savings Plan을 구매합니다.
- [ ] C. 1년 기간 동안 전액 선결제 예약 인스턴스를 구매합니다.
- [ ] D. 1년 기간 동안 All Upfront EC2 Instance Savings Plan을 구매합니다.

## Answer

정답: B

## Explanation

Compute Savings Plan은 특정 인스턴스 유형이나 패밀리에 구속되지 않으므로, 2~3개월마다 EC2 인스턴스의 유형과 패밀리를 변경해야 하는 요구 사항에 완벽히 적합합니다. 선결제 없는(No Upfront) 옵션을 선택하면 초기 비용 부담 없이 온디맨드 대비 할인(약 20-30%)을 받을 수 있으며, 1년 약정 기간 동안 인스턴스 유형을 자유롭게 변경하면서도 지속적으로 할인이 적용됩니다. 인스턴스 패밀리, 크기, OS, 리전, 심지어 EC2에서 Fargate나 Lambda로 전환해도 할인이 유지됩니다.

오답 분석

A: 예약 인스턴스(Reserved Instances)는 특정 인스턴스 유형에 고정되므로, 2~3개월마다 유형과 패밀리를 변경하면 할인이 적용되지 않습니다. 3년 약정은 유연성을 더욱 제한하며, 변경하지 않을 인스턴스 유형에 장기간 묶이게 됩니다.

C: 예약 인스턴스는 인스턴스 유형 변경에 유연하지 않습니다. All Upfront으로 1년 전체 비용을 선결제하면, 인스턴스 유형 변경 시 이미 지불한 비용이 낭비됩니다. Standard RI는 패밀리 변경이 불가하고, Convertible RI도 변경 절차가 복잡합니다.

D: EC2 Instance Savings Plan은 특정 인스턴스 패밀리(예: M5)와 리전에 대한 약정이므로, 패밀리를 변경하면(예: M5에서 R6i로) 할인이 적용되지 않습니다. 인스턴스 패밀리 변경이 필요한 이 시나리오에서는 Compute Savings Plan이 적합합니다.
