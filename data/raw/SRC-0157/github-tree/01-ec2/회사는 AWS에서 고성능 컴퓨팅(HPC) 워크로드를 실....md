## Question

회사는 AWS에서 고성능 컴퓨팅(HPC) 워크로드를 실행합니다. 워크로드에는 대기 시간이 짧은 네트워크 성능과 긴밀하게 연결된 노드 간 통신을 통한 높은 네트워크 처리량이 필요합니다. Amazon EC2 인스턴스는 컴퓨팅 및 스토리지 용량에 맞게 적절한 크기로 지정되며 기본 옵션을 사용하여 시작됩니다.
워크로드의 성능을 개선하기 위해 솔루션 설계자는 무엇을 제안해야 합니까?

- [ ] A. Amazon EC2 인스턴스를 시작하는 동안 클러스터 배치 그룹을 선택합니다.
- [ ] B. Amazon EC2 인스턴스를 시작하는 동안 전용 인스턴스 테넌시를 선택합니다.
- [ ] C. Amazon EC2 인스턴스를 시작하는 동안 Elastic Inference 액셀러레이터를 선택합니다.
- [ ] D. Amazon EC2 인스턴스를 시작하는 동안 필요한 용량 예약을 선택합니다.

## Answer

정답: A

## Explanation

클러스터 배치 그룹(Cluster Placement Group)은 EC2 인스턴스를 단일 가용 영역 내에서 물리적으로 인접한 서버 랙에 배치하여, 인스턴스 간 최저 지연 시간(마이크로초 수준)과 최대 네트워크 처리량(최대 100Gbps Enhanced Networking)을 제공합니다. HPC 워크로드에서 요구하는 긴밀하게 결합된(tightly coupled) 노드 간 통신에 최적화된 배치 전략이며, 인스턴스가 기본 옵션으로 시작되었다면 배치 그룹이 적용되지 않아 성능이 최적화되지 않았을 것입니다.

오답 분석

B: 전용 인스턴스 테넌시(Dedicated Instance Tenancy)는 다른 AWS 고객과 물리적 하드웨어를 공유하지 않도록 격리하는 것입니다. 이는 규정 준수나 라이선스 요구 사항을 위한 것으로, 인스턴스 간 네트워크 지연 시간이나 처리량을 개선하는 것과는 무관합니다.

C: Elastic Inference 액셀러레이터는 EC2 인스턴스에 GPU 추론 가속을 추가하여 딥 러닝 추론 비용을 줄이는 서비스입니다. HPC 워크로드의 네트워크 성능과는 전혀 관련이 없으며, 2023년 이후 신규 사용이 중단되었습니다.

D: 용량 예약(Capacity Reservation)은 특정 AZ에서 인스턴스를 시작할 수 있는 용량을 사전에 확보하는 것이지, 인스턴스 간 물리적 배치나 네트워크 성능에 영향을 주지 않습니다.
