## Question

회사에는 Amazon EC2 인스턴스에서 실행 중인 애플리케이션이 있습니다. 솔루션 설계자는 회사의 현재 요구 사항을 기반으로 특정 인스턴스 제품군 및 다양한 인스턴스 크기로 회사를 표준화했습니다.
회사는 향후 3년 동안 애플리케이션의 비용 절감을 극대화하고자 합니다. 회사는 애플리케이션 인기도 및 사용량에 따라 향후 6개월 내에 인스턴스 패밀리 및 크기를 변경할 수 있어야 합니다.
이러한 요구 사항을 가장 비용 효율적으로 충족하는 솔루션은 무엇입니까?

- [ ] A. Compute Savings Plan
- [ ] B. EC2 Instance Savings Plan
- [ ] C. 영역 예약 인스턴스
- [ ] D. 표준 예약 인스턴스

## Answer

정답: A

## Explanation

Compute Savings Plan은 특정 인스턴스 패밀리, 크기, OS, 테넌시, 리전에 관계없이 EC2, Lambda, Fargate 등 모든 컴퓨팅 서비스에 유연하게 적용됩니다. 향후 6개월 내에 인스턴스 패밀리와 크기를 변경해야 하는 요구 사항이 있으므로, 인스턴스 유형 변경에 완전히 유연한 Compute Savings Plan이 가장 비용 효율적입니다. EC2 Instance Savings Plan보다 할인율은 약간 낮지만, 유연성이 중요한 이 시나리오에서는 Compute Savings Plan이 적합합니다.

오답 분석

B: EC2 Instance Savings Plan은 특정 인스턴스 패밀리(예: M5)와 리전에 대한 약정입니다. 동일 패밀리 내에서 크기, OS, 테넌시는 유연하게 변경할 수 있지만, 인스턴스 패밀리 자체를 변경(예: M5에서 C6i로)하면 할인이 적용되지 않습니다. 문제에서 패밀리 변경 가능성을 명시했으므로 부적합합니다.

C: 영역 예약 인스턴스(Zonal Reserved Instances)는 특정 인스턴스 유형, 특정 가용 영역에 고정되며 1년 또는 3년 약정이 필요합니다. 인스턴스 패밀리나 크기 변경이 불가능하고, 용량 예약이 특정 AZ에 묶이므로 유연성이 가장 낮습니다.

D: 표준 예약 인스턴스(Standard Reserved Instances)는 특정 인스턴스 유형에 고정되며, 동일 패밀리 내에서 크기 변경만 제한적으로 가능합니다(Convertible RI와 달리 패밀리 변경 불가). 인스턴스 패밀리를 변경해야 하는 요구 사항을 충족하지 못합니다.
