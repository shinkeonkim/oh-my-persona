## Question

회사는 AWS Cost Explorer를 사용하여 AWS 비용을 모니터링합니다. 회사는 Amazon Elastic Block Store(Amazon EBS) 스토리지 및 스냅샷 비용이 매달 증가한다는 사실을 알아냈습니다. 그러나 회사는 매달 EBS 스토리지를 추가로 구매하지 않습니다. 회사는 현재 스토리지 사용량에 맞게 월별 비용을 최적화하려고 합니다.
최소한의 운영 오버헤드로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. Amazon CloudWatch Logs의 로그를 사용하여 Amazon EBS의 스토리지 활용도를 모니터링합니다. Amazon EBS 탄력적 볼륨을 사용하여 EBS 볼륨의 크기를 줄입니다.
- [ ] B. 사용자 정의 스크립트를 사용하여 공간 사용량을 모니터링합니다. Amazon EBS 탄력적 볼륨을 사용하여 EBS 볼륨의 크기를 줄입니다.
- [ ] C. 만료되거나 사용되지 않은 모든 스냅샷을 삭제하여 스냅샷 비용을 줄입니다.
- [ ] D. 중요하지 않은 스냅샷을 모두 삭제합니다. Amazon Data Lifecycle Manager를 사용하여 회사의 스냅샷 정책 요구 사항에 따라 스냅샷을 생성하고 관리합니다.

## Answer

정답: D

## Explanation

불필요한 스냅샷을 모두 삭제하고 Amazon Data Lifecycle Manager(DLM)를 사용하여 스냅샷 정책에 따라 스냅샷을 생성/관리하는 것이 최소 운영 오버헤드로 월별 비용을 최적화하는 솔루션입니다. EBS 스냅샷은 증분 방식이지만, 시간이 지남에 따라 스냅샷 수가 누적되면 비용이 증가합니다. 기존 불필요한 스냅샷을 삭제하여 즉시 비용을 절감하고, DLM으로 자동 생성/삭제 정책을 설정하면 향후 스냅샷 비용 증가를 방지할 수 있습니다.

오답 분석

A: CloudWatch Logs로 스토리지 활용도를 모니터링하고 Elastic Volumes로 볼륨 크기를 줄이는 것은 EBS 볼륨 스토리지 비용에 초점을 맞추지만, 문제에서 스냅샷 비용이 증가한다고 명시했으므로 스냅샷 관리가 핵심입니다.

B: 사용자 정의 스크립트로 공간을 모니터링하는 것은 운영 오버헤드가 DLM보다 크며, 스냅샷 비용 문제를 직접 해결하지 않습니다.

C: 만료되거나 사용되지 않은 스냅샷을 삭제하는 것만으로는 일시적인 비용 절감이 되지만, DLM 같은 자동화 정책 없이는 스냅샷이 다시 누적되어 비용이 재증가합니다.
