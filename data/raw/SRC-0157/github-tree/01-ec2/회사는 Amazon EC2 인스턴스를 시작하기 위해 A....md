## Question

회사는 Amazon EC2 인스턴스를 시작하기 위해 AWS 계정에 여러 Amazon 머신 이미지(AMI)를 저장합니다. AMI에는 회사 운영에 필요한 중요한 데이터와 구성이 포함되어 있습니다.
회사는 실수로 삭제된 AMI를 빠르고 효율적으로 복구하는 솔루션을 구현하려고 합니다.
최소한의 운영 오버헤드로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. AMI의 Amazon Elastic Block Store(Amazon EBS) 스냅샷을 생성합니다. 스냅샷을 별도의 AWS 계정에 저장합니다.
- [ ] B. 모든 AMI를 주기적으로 다른 AWS 계정에 복사합니다.
- [ ] C. 휴지통 보관 규칙을 생성합니다.
- [ ] D. 교차 리전 복제 기능이 있는 Amazon S3 버킷에 AMI를 업로드합니다.

## Answer

정답: C

## Explanation

Amazon Recycle Bin(휴지통)에 보관 규칙을 생성하면, 실수로 삭제된 AMI를 빠르고 효율적으로 복구할 수 있습니다. Recycle Bin은 삭제된 AMI와 관련 EBS 스냅샷을 지정된 보관 기간 동안 보관하여, 필요할 때 즉시 복원할 수 있습니다. 이 솔루션은 AWS 콘솔에서 몇 번의 클릭만으로 설정할 수 있어 최소한의 운영 오버헤드로 요구 사항을 충족합니다.

오답 분석

A: AMI의 EBS 스냅샷을 별도의 AWS 계정에 저장하면 보호가 되지만, 교차 계정 스냅샷 복사 프로세스를 구현하고 관리해야 하므로 운영 오버헤드가 큽니다. 또한 복구 시 별도 계정에서 스냅샷을 복사하고 AMI를 재생성해야 합니다.

B: 모든 AMI를 주기적으로 다른 AWS 계정에 복사하면 백업이 되지만, 정기적인 복사 프로세스를 자동화하고 관리해야 하며, 복구 시 다른 계정에서 AMI를 복사해 와야 합니다. Recycle Bin보다 운영 오버헤드가 큽니다.

D: AMI를 S3 버킷에 업로드하는 것은 표준적인 AMI 백업 방법이 아닙니다. AMI는 AWS에서 관리하는 리소스이며, S3에 직접 저장할 수 없습니다. 교차 리전 복제(CRR)도 AMI 복구와는 무관합니다.
