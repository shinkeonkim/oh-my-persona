## Question

회사는 로컬로 연결된 스토리지를 사용하여 온프레미스에서 대기 시간에 민감한 애플리케이션을 실행합니다. 이 회사는 애플리케이션을 AWS 클라우드로 옮기기 위해 리프트 앤 시프트 방식을 사용하고 있습니다. 회사는 애플리케이션 아키텍처를 변경하기를 원하지 않습니다.
이러한 요구 사항을 가장 비용 효율적으로 충족하는 솔루션은 무엇입니까?

- [ ] A. Amazon EC2 인스턴스로 Auto Scaling 그룹을 구성합니다. Amazon FSx for Lustre 파일 시스템을 사용하여 애플리케이션을 실행합니다.
- [ ] B. Amazon EC2 인스턴스에서 애플리케이션을 호스팅합니다. Amazon Elastic Block Store(Amazon EBS) gp2 볼륨을 사용하여 애플리케이션을 실행합니다.
- [ ] C. Amazon EC2 인스턴스로 Auto Scaling 그룹을 구성합니다. Amazon FSx for OpenZFS 파일 시스템을 사용하여 애플리케이션을 실행합니다.
- [ ] D. Amazon EC2 인스턴스에서 애플리케이션을 호스팅합니다. Amazon Elastic Block Store(Amazon EBS) gp3 볼륨을 사용하여 애플리케이션을 실행합니다.

## Answer

정답: D

## Explanation

Amazon EBS gp3 볼륨은 EC2 인스턴스에 로컬로 연결되는 블록 스토리지로, 일관된 낮은 지연 시간(한 자릿수 밀리초)을 제공합니다. gp3는 기본 3,000 IOPS와 125MB/s 처리량을 제공하며, gp2보다 GB당 비용이 약 20% 저렴합니다. 리프트 앤 시프트(Lift and Shift) 마이그레이션은 애플리케이션 아키텍처를 변경하지 않고 그대로 클라우드로 이전하는 방식이므로, 온프레미스에서 로컬 스토리지를 사용하던 환경을 EC2 + EBS 조합으로 동일하게 재현할 수 있습니다. IOPS와 처리량을 독립적으로 프로비저닝할 수 있어 비용 최적화에도 유리합니다.

오답 분석

A: Amazon FSx for Lustre는 HPC(고성능 컴퓨팅), ML 훈련, 미디어 처리 등 대규모 병렬 파일 시스템이 필요한 워크로드에 적합합니다. 단순 리프트 앤 시프트에 사용하기에는 과도한 솔루션이며, EBS보다 비용이 훨씬 높습니다. Auto Scaling 그룹도 요구 사항에 언급되지 않았습니다.

B: EBS gp2 볼륨도 지연 시간에 민감한 애플리케이션에 사용할 수 있지만, gp2는 IOPS가 볼륨 크기에 비례하여 자동 할당되며 gp3보다 GB당 비용이 약 20% 높습니다. 동일한 성능을 더 낮은 가격에 제공하는 gp3가 가장 비용 효율적인 선택입니다.

C: Amazon FSx for OpenZFS는 NFS 프로토콜을 지원하는 완전 관리형 공유 파일 시스템으로, 여러 인스턴스 간 데이터 공유가 필요한 경우에 적합합니다. 단일 인스턴스의 로컬 연결 스토리지 대체에는 과도하며 비용이 EBS보다 높습니다.
