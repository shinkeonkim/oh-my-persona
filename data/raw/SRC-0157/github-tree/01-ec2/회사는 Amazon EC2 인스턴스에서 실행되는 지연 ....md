## Question

회사는 Amazon EC2 인스턴스에서 실행되는 지연 시간에 민감한 애플리케이션을 위해 인 메모리 데이터베이스를 실행하려고 합니다. 애플리케이션은 분당 100,000개 이상의 트랜잭션을 처리하며 높은 네트워크 처리량이 필요합니다. 솔루션 설계자는 데이터 전송 비용을 최소화하는 비용 효율적인 네트워크 설계를 제공해야 합니다.
어떤 솔루션이 이러한 요구 사항을 충족합니까?

- [ ] A. 동일한 AWS 리전 내의 동일한 가용 영역에서 모든 EC2 인스턴스를 시작합니다. EC2 인스턴스를 시작할 때 클러스터 전략으로 배치 그룹을 지정합니다.
- [ ] B. 동일한 AWS 리전 내의 다른 가용 영역에서 모든 EC2 인스턴스를 시작합니다. EC2 인스턴스를 시작할 때 파티션 전략으로 배치 그룹을 지정합니다.
- [ ] C. Auto Scaling 그룹을 배포하여 네트워크 활용 목표에 따라 다른 가용 영역에서 EC2 인스턴스를 시작합니다.
- [ ] D. 서로 다른 가용 영역에서 EC2 인스턴스를 시작하기 위해 단계 조정 정책으로 Auto Scaling 그룹을 배포합니다.

## Answer

정답: A

## Explanation

동일한 가용 영역에서 클러스터 배치 그룹(Cluster Placement Group)을 사용하면, 모든 EC2 인스턴스가 물리적으로 인접한 위치에 배치되어 마이크로초 수준의 낮은 지연 시간과 최대 100Gbps의 높은 네트워크 처리량을 제공합니다. 동일 가용 영역 내 EC2 인스턴스 간 데이터 전송은 무료이므로 데이터 전송 비용이 최소화됩니다. 인 메모리 데이터베이스에서 분당 100,000건 이상의 트랜잭션을 처리하려면 이러한 고성능 네트워크가 필수적입니다.

오답 분석

B: 다른 가용 영역에 인스턴스를 분산하면 AZ 간 데이터 전송 비용(GB당 약 $0.01)이 발생하며, AZ 간 네트워크 지연 시간이 동일 AZ 내보다 높습니다. 파티션 배치 그룹(Partition Placement Group)은 대규모 분산 워크로드(HDFS, HBase, Cassandra)의 장애 격리를 위한 것으로, 낮은 지연 시간 통신에 최적화되지 않습니다.

C: 다른 가용 영역에 Auto Scaling으로 인스턴스를 분산하면 AZ 간 데이터 전송 비용이 발생하고, 네트워크 지연 시간이 증가하여 인 메모리 데이터베이스의 성능에 부정적 영향을 줍니다.

D: 다른 가용 영역에 인스턴스를 분산하면 동일한 데이터 전송 비용 및 지연 시간 문제가 발생합니다. 단계 조정 정책(Step Scaling)은 스케일링 방식에 관한 것으로, 네트워크 성능이나 데이터 전송 비용 최적화와 직접적인 관련이 없습니다.
