## Question

한 회사에 AWS Lambda 함수로 구성된 서버리스 웹 애플리케이션이 있습니다. 이 애플리케이션은 콜드 스타트로 인해 지연 시간이 증가하는 트래픽 급증을 경험합니다. 이 회사는 애플리케이션의 트래픽 급증 처리 기능을 개선하고 지연 시간을 최소화하고자 합니다. 이 솔루션은 트래픽이 적은 기간 동안 비용을 최적화해야 합니다.
어떤 솔루션이 이러한 요구 사항을 충족할까요?

- [ ] A. Lambda 함수에 대한 프로비저닝된 동시성을 구성합니다. AWS Application Auto Scaling을 사용하여 프로비저닝된 동시성을 조정합니다.
- [ ] B. Auto Scaling 그룹에서 Amazon EC2 인스턴스를 시작합니다. 예약된 확장 정책을 추가하여 트래픽이 많은 기간 동안 추가 EC2 인스턴스를 시작합니다.
- [ ] C. Lambda 함수에 대한 프로비저닝된 동시성을 구성합니다. 최대 예상 트래픽을 처리하도록 고정된 동시성 수준을 설정합니다.
- [ ] D. Amazon EventBridge Scheduler에서 반복 일정을 만듭니다. 이 일정을 사용하여 Lambda 함수를 주기적으로 호출하여 함수를 워밍업합니다.

## Answer

정답: A

## Explanation

Lambda 함수에 프로비저닝된 동시성(Provisioned Concurrency)을 구성하면 사전 초기화된 실행 환경을 유지하여 콜드 스타트를 제거합니다. AWS Application Auto Scaling을 사용하여 트래픽 패턴에 따라 프로비저닝된 동시성 수준을 동적으로 조정하면, 피크 시 충분한 용량을 확보하고 비활동 시 비용을 최적화합니다.

오답 분석

B: EC2 인스턴스와 Auto Scaling 그룹을 사용하면 서버리스 아키텍처의 이점을 잃고, 서버 관리 오버헤드가 발생합니다.

C: 고정된 프로비저닝된 동시성 수준은 트래픽이 적은 기간에도 동일한 비용이 발생하여 비용 최적화 요구사항을 충족하지 못합니다.

D: EventBridge Scheduler로 Lambda를 주기적으로 호출하는 워밍업 방식은 타이밍 불일치로 콜드 스타트를 완전히 제거하지 못하며 안정적이지 않습니다.
