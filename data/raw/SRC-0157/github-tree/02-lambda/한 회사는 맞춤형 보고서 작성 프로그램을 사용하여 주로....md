## Question

한 회사는 맞춤형 보고서 작성 프로그램을 사용하여 주로 매월 마지막 주에 수행되는 모바일 앱 사용을 추적하는 보고서를 효율적으로 생성하는 것을 목표로 합니다. 프로그램의 생성 프로세스는 각 보고서당 10분 미만이 소요될 정도로 신속합니다. 이 기간 외에는 거의 사용되지 않으므로, 회사는 요청 시 신속한 보고서 생성을 위한 비용 효율적인 솔루션을 찾고 있습니다.
이러한 요구 사항을 가장 잘 충족하는 솔루션은 무엇입니까?

- [ ] A. Amazon EC2 온디맨드 인스턴스를 사용하여 프로그램을 실행합니다. 보고서가 요청될 때 EC2 인스턴스를 트리거하는 Amazon EventBridge 규칙을 설정합니다. 매월 마지막 주에만 EC2 인스턴스를 지속적으로 운영합니다.
- [ ] B. AWS Lambda를 사용하여 프로그램을 실행합니다. 보고서가 요청되면 Lambda 함수를 트리거하는 Amazon EventBridge 규칙을 생성합니다.
- [ ] C. Amazon Elastic Container Service(Amazon ECS) 내에서 프로그램을 운영하고 보고서 요청 시 실행되도록 예약합니다.
- [ ] D. Amazon EC2 스팟 인스턴스를 활용하여 프로그램을 실행합니다. 보고서가 요청되면 EC2 인스턴스를 시작하는 Amazon EventBridge 규칙을 생성합니다. 매월 마지막 주 동안 EC2 인스턴스를 지속적으로 실행하도록 유지합니다.

## Answer

정답: B

## Explanation

AWS Lambda로 보고서 생성 프로그램을 실행하고, Amazon EventBridge 스케줄 규칙으로 월말에만 트리거합니다. Lambda는 실행 시에만 과금되므로 월 대부분 사용하지 않는 패턴에서 비용이 최소화됩니다. EventBridge의 cron 표현식으로 '매월 마지막 주'에만 실행하도록 정확한 스케줄링이 가능합니다. 서버리스 아키텍처로 인프라 프로비저닝, 관리, 패칭이 불필요하며 보고서 생성이 끝나면 자동으로 리소스가 해제됩니다.

오답 분석

A: EC2 On-Demand 인스턴스는 월말 보고서 생성 기간이 아닌 나머지 시간에도 비용이 발생합니다(중지하더라도 EBS 비용). Lambda의 pay-per-execution 대비 비용 비효율적이며 인스턴스 관리 오버헤드도 존재합니다.

C: Amazon ECS는 컨테이너 기반 서비스로, 태스크 정의, 클러스터 관리, 이미지 관리 등 추가적인 운영 복잡성이 있습니다. 월 1회 실행되는 간단한 보고서 생성에는 Lambda가 더 적합합니다.

D: EC2 Spot 인스턴스는 저렴하지만 언제든 중단될 수 있어 보고서 생성 안정성이 보장되지 않습니다. 또한 EC2 인스턴스 관리 오버헤드가 존재하며, Lambda 대비 시작 시간이 깁니다.
