## Question

한 회사에 직원이 15명 있습니다. 회사는 직원 시작 날짜를 Amazon DynamoDB 테이블에 저장합니다. 회사에서는 직원의 입사 기념일에 각 직원에게 이메일 메시지를 보내려고 합니다.
가장 효율적인 운영 효율성으로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. DynamoDB 테이블을 스캔하고 Amazon Simple Notification Service(Amazon SNS)를 사용하여 필요할 때 직원에게 이메일 메시지를 보내는 스크립트를 생성합니다. cron 작업을 사용하여 Amazon EC2 인스턴스에서 매일 이 스크립트를 실행합니다.
- [ ] B. DynamoDB 테이블을 스캔하고 Amazon Simple Queue Service(Amazon SQS)를 사용하여 필요할 때 직원에게 이메일 메시지를 보내는 스크립트를 만듭니다. cron 작업을 사용하여 Amazon EC2 인스턴스에서 매일 이 스크립트를 실행합니다.
- [ ] C. DynamoDB 테이블을 스캔하고 필요할 때 Amazon Simple Notification Service(Amazon SNS)를 사용하여 직원에게 이메일 메시지를 보내는 AWS Lambda 함수를 생성합니다. 이 Lambda 함수가 매일 실행되도록 예약합니다.
- [ ] D. DynamoDB 테이블을 스캔하고 Amazon Simple Queue Service(Amazon SQS)를 사용하여 필요할 때 직원에게 이메일 메시지를 보내는 AWS Lambda 함수를 생성합니다. 이 Lambda 함수가 매일 실행되도록 예약합니다.

## Answer

정답: C

## Explanation

AWS Lambda 함수가 DynamoDB 테이블을 스캔하여 오늘 날짜와 입사 기념일이 일치하는 직원을 조회하고, Amazon SNS 토픽의 이메일 구독을 통해 축하 이메일을 전송합니다. EventBridge 스케줄 규칙으로 매일 Lambda 함수를 자동 호출합니다. 15명의 소규모 조직에서 완전 서버리스 아키텍처는 최소한의 운영 오버헤드와 비용으로 이메일 자동화를 구현합니다. Lambda + EventBridge + SNS 조합은 추가 인프라 없이 스케줄 기반 알림을 처리하는 AWS 표준 패턴입니다.

오답 분석

A: EC2 인스턴스에서 스크립트로 DynamoDB를 스캔하고 SNS로 이메일을 보내는 방식은 기능적으로 가능하지만, EC2 인스턴스의 상시 운영 비용과 관리(패칭, 모니터링, cron 설정)가 필요합니다. Lambda 서버리스 대비 비용과 운영 오버헤드가 큽니다.

B: SQS는 메시지 큐 서비스로 이메일 전송 기능을 제공하지 않습니다. SQS에 메시지를 넣어도 직원에게 이메일이 전달되지 않으며, 별도의 이메일 전송 로직이 추가로 필요합니다.

D: Lambda + SQS 조합에서 SQS는 B와 동일하게 이메일 전송을 지원하지 않습니다. 이메일 알림에는 SNS 토픽의 이메일 프로토콜 구독 또는 Amazon SES를 사용해야 합니다.
