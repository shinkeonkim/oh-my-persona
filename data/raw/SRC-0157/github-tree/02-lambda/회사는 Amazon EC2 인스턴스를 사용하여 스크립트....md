## Question

회사는 Amazon EC2 인스턴스를 사용하여 스크립트를 실행하여 Amazon Simple Queue Service (Amazon SQS) 대기열에서 메시지를 폴링하고 처리합니다. 이 회사는 대기열에 추가되는 점점 더 많은 수의 메시지를 처리할 수 있는 능력을 유지하면서 운영 비용을 절감하고자 합니다.
이러한 요구 사항을 충족하기 위해 솔루션 설계자는 무엇을 권장해야 합니까?

- [ ] A. EC2 인스턴스의 크기를 늘려 메시지를 더 빠르게 처리합니다.
- [ ] B. 인스턴스가 충분히 활용되지 않을 때 Amazon EventBridge를 사용하여 EC2 인스턴스를 끕니다.
- [ ] C. EC2 인스턴스의 스크립트를 적절한 런타임이 있는 AWS Lambda 함수로 마이그레이션합니다.
- [ ] D. AWS Systems Manager Run Command를 사용하여 요청 시 스크립트를 실행합니다.

## Answer

정답: C

## Explanation

EC2 인스턴스에서 실행 중인 SQS 폴링 스크립트를 AWS Lambda 함수로 마이그레이션하면 서버리스 아키텍처의 장점을 얻을 수 있습니다. Lambda는 SQS를 이벤트 소스로 직접 지원하여 메시지가 큐에 도착하면 자동으로 Lambda 함수가 호출됩니다. 메시지 수에 따라 Lambda가 자동 확장되어 처리량이 탄력적으로 조정되고, 메시지가 없을 때는 비용이 발생하지 않습니다. EC2 인스턴스의 상시 운영 비용, OS 패칭, 모니터링 등 관리 오버헤드가 완전히 제거됩니다.

오답 분석

A: EC2 인스턴스 크기를 늘리면(수직 확장) 처리 속도는 향상될 수 있지만 비용이 증가하며, 메시지 수에 따른 탄력적 확장이 불가능합니다. 기본적인 비용 비효율성 문제를 해결하지 못합니다.

B: EventBridge로 EC2 인스턴스를 저사용 시 종료하면 메시지 처리가 중단됩니다. SQS 큐에 메시지가 쌓여도 EC2가 꺼져 있으면 처리되지 않는 문제가 발생합니다.

D: AWS Systems Manager Run Command는 EC2 인스턴스에서 명령을 원격 실행하는 도구입니다. 수동 또는 이벤트 기반 실행이 가능하지만 여전히 EC2 인스턴스가 필요하며, 서버리스 전환의 비용 절감 효과를 얻을 수 없습니다.
