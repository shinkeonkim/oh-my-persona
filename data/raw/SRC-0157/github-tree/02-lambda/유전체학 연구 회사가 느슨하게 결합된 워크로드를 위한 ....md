## Question

유전체학 연구 회사가 느슨하게 결합된 워크로드를 위한 확장 가능한 아키텍처를 설계하고 있습니다. 워크로드의 각 작업은 독립적이며 병렬로 처리될 수 있습니다. 아키텍처는 관리 오버헤드를 최소화하고 수요에 따라 자동 확장을 제공해야 합니다.

- [ ] A. Amazon EC2 인스턴스 클러스터를 사용합니다. AWS Systems Manager를 사용하여 워크로드를 관리합니다.
- [ ] B. AWS Lambda 함수를 사용하는 서버리스 아키텍처를 구현합니다.
- [ ] C. AWS ParallelCluster를 사용하여 전용 고성능 클러스터를 배포합니다.
- [ ] D. 각 워크로드 작업에 대한 수직 확장을 구현합니다.

## Answer

정답: B

## Explanation

AWS Lambda 함수를 사용한 서버리스 아키텍처는 각 독립적인 작업을 개별 Lambda 함수 호출로 병렬 처리할 수 있으며, 수요에 따라 수천 개의 동시 실행으로 즉시 자동 확장됩니다. 서버 프로비저닝이나 클러스터 관리가 완전히 불필요하여 관리 오버헤드가 최소화되며, 실행 시간에 따른 과금으로 비용 효율적입니다.

오답 분석

A: EC2 인스턴스 클러스터와 Systems Manager를 사용하면 서버 패치, 용량 관리 등 지속적인 관리 오버헤드가 높습니다.

C: AWS ParallelCluster는 HPC(고성능 컴퓨팅) 클러스터 배포 도구로, 클러스터 인프라 관리가 필요하여 관리 오버헤드가 높습니다.

D: 수직 확장(Vertical Scaling)은 단일 인스턴스의 크기를 늘리는 방식으로, 독립적인 병렬 작업의 수평 처리와 자동 확장에 적합하지 않습니다.
