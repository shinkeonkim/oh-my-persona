## Question

솔루션 설계자는 건물 내 비즈니스 테넌트의 시간당 에너지 소비량을 저장할 워크로드를 설계하고 있습니다. 센서는 각 테넌트의 사용량을 합산하는 HTTP 요청을 통해 데이터베이스에 공급합니다. 솔루션 설계자는 가능한 경우 관리 서비스를 사용해야 합니다. 워크로드는 솔루션 설계자가 독립적인 구성 요소를 추가함에 따라 향후 더 많은 기능을 받게 됩니다.
최소한의 운영 오버헤드로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. AWS Lambda 함수와 함께 Amazon API Gateway를 사용하여 센서에서 데이터를 수신하고, 데이터를 처리하고, Amazon DynamoDB 테이블에 데이터를 저장합니다.
- [ ] B. Amazon EC2 인스턴스의 Auto Scaling 그룹에서 지원하는 Elastic Load Balancer를 사용하여 센서에서 데이터를 수신하고 처리합니다. Amazon S3 버킷을 사용하여 처리된 데이터를 저장합니다.
- [ ] C. AWS Lambda 함수와 함께 Amazon API Gateway를 사용하여 센서에서 데이터를 수신하고, 데이터를 처리하고, Amazon EC2 인스턴스의 Microsoft SQL Server Express 데이터베이스에 데이터를 저장합니다.
- [ ] D. Amazon EC2 인스턴스의 Auto Scaling 그룹에서 지원하는 Elastic Load Balancer를 사용하여 센서에서 데이터를 수신하고 처리합니다. Amazon Elastic File System(Amazon EFS) 공유 파일 시스템을 사용하여 처리된 데이터를 저장합니다.

## Answer

정답: A

## Explanation

API Gateway로 센서의 HTTP 데이터를 수신하고, Lambda 함수로 데이터를 처리한 후, DynamoDB에 저장합니다. 이 완전 서버리스 조합은 관리형 서비스로만 구성되어 운영 오버헤드가 최소화됩니다. DynamoDB는 시간별 에너지 소비 데이터의 key-value 저장에 적합하며, 단일 자릿수 밀리초 응답으로 빠른 읽기/쓰기를 제공합니다. 향후 요구사항 변경 시 각 구성 요소를 독립적으로 교체하거나 확장할 수 있는 유연한 아키텍처입니다.

오답 분석

B: ELB + EC2 Auto Scaling + S3 조합은 EC2 인스턴스의 관리(패칭, 모니터링, 장애 대응)가 필요하여 서버리스 대비 운영 오버헤드가 큽니다.

C: API Gateway + Lambda는 서버리스이지만, Amazon EC2 인스턴스에서 Microsoft SQL Server Express를 운영하면 데이터베이스 인스턴스 관리, 소프트웨어 설치 및 패칭 등의 오버헤드가 발생합니다. EC2 기반 SQL Server는 관리형 서비스가 아니며, 시계열 에너지 소비 데이터 저장에 관계형 DB는 과도합니다.

D: ELB + EC2 Auto Scaling + EFS 조합은 EC2 인스턴스 관리와 EFS 공유 파일 시스템 관리가 모두 필요한 높은 운영 오버헤드 구성입니다. 서버리스 대안 대비 비용과 관리 부담이 크게 증가합니다.
