## Question

회사는 타사 데이터 피드와 통합해야 합니다. 데이터 피드는 웹후크를 보내 새 데이터를 사용할 준비가 되면 외부 서비스에 알립니다. 개발자는 회사에서 웹후크 콜백을 수신할 때 데이터를 검색하는 AWS Lambda 함수를 작성했습니다. 개발자는 제3자가 호출할 수 있도록 Lambda 함수를 제공해야 합니다.
이러한 요구 사항을 가장 효율적으로 충족하는 솔루션은 무엇입니까?

- [ ] A. Lambda 함수에 대한 함수 URL을 생성합니다. Webhook에 대한 Lambda 함수 URL을 타사에 제공합니다.
- [ ] B. Lambda 함수 앞에 ALB(Application Load Balancer)를 배포합니다. Webhook에 대한 ALB URL을 타사에 제공합니다.
- [ ] C. Amazon Simple Notification Service(Amazon SNS) 주제를 생성합니다. Lambda 함수에 주제를 연결합니다. Webhook에 대한 제3자에게 SNS 주제의 공개 호스트 이름을 제공합니다.
- [ ] D. Amazon Simple Queue Service(Amazon SQS) 대기열을 생성합니다. 대기열을 Lambda 함수에 연결합니다. Webhook에 대해 타사에 SQS 대기열의 공개 호스트 이름을 제공합니다.

## Answer

정답: A

## Explanation

Lambda function URL은 Lambda 함수에 대한 전용 HTTPS 엔드포인트를 자동으로 생성합니다. 형식은 https://<url-id>.lambda-url.<region>.on.aws이며, 생성 후 URL이 변경되지 않습니다. 서드파티 webhook이 이 URL로 HTTP POST 요청을 보내면 Lambda 함수가 직접 호출됩니다. API Gateway나 ALB 같은 중간 계층 없이 Lambda 함수를 직접 노출하므로 가장 간단하고 운영 효율적인 솔루션입니다. AWS_IAM 또는 NONE 인증 타입을 지원합니다.

오답 분석

B: ALB(Application Load Balancer)를 Lambda 앞에 배치하면 동일한 기능을 제공하지만, ALB 자체의 프로비저닝, 관리, 시간당 비용이 추가됩니다. 단일 Lambda webhook에 ALB는 과도한 인프라입니다.

C: Amazon SNS 토픽은 pub/sub 메시징 서비스로, 외부 서드파티가 직접 호출할 수 있는 webhook HTTP 엔드포인트를 제공하지 않습니다. SNS는 구독자에게 메시지를 푸시하는 방식이지, 외부에서 메시지를 수신하는 방식이 아닙니다.

D: Amazon SQS 큐는 외부에서 직접 webhook URL로 호출할 수 있는 HTTP 엔드포인트를 제공하지 않습니다. SQS에 메시지를 전송하려면 AWS SDK나 API를 사용해야 하며, 서드파티 webhook 콜백에는 부적합합니다.
