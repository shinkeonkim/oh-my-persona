## Question

회사는 고객이 재무 정보를 검색할 수 있도록 고객에게 API 인터페이스를 제공합니다. 회사는 연중 사용량이 가장 많은 시간에 더 많은 수의 요청을 예상합니다.
회사는 API가 고객 만족을 보장하기 위해 낮은 대기 시간으로 일관되게 응답하도록 요구합니다. 회사는 API에 컴퓨팅 호스트를 제공해야 합니다.
최소한의 운영 오버헤드로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. Application Load Balancer 및 Amazon Elastic Container Service(Amazon ECS)를 사용합니다.
- [ ] B. 프로비저닝된 동시성과 함께 Amazon API Gateway 및 AWS Lambda 함수를 사용합니다.
- [ ] C. Application Load Balancer 및 Amazon Elastic Kubernetes Service(Amazon EKS) 클러스터를 사용합니다.
- [ ] D. 예약된 동시성과 함께 Amazon API Gateway 및 AWS Lambda 함수를 사용합니다.

## Answer

정답: B

## Explanation

Amazon API Gateway와 AWS Lambda 함수에 provisioned concurrency를 설정하면 일관된 저지연 응답을 보장할 수 있습니다. Provisioned concurrency는 Lambda 실행 환경을 사전 초기화하여 cold start를 완전히 제거하고, 한 자릿수 밀리초 응답 시간을 보장합니다. 금융 정보 API는 일관된 성능이 중요하며, year-end 등 peak 시간에도 사전 프로비저닝된 환경이 즉시 응답합니다. 서버리스 아키텍처로 인프라 관리가 불필요하면서도 성능 요구사항을 충족합니다.

오답 분석

A: ALB + ECS는 컨테이너 기반으로 일관된 성능은 제공할 수 있으나, ECS 태스크 관리, 컨테이너 이미지 관리, Auto Scaling 구성 등 운영 오버헤드가 서버리스 대비 상당합니다.

C: ALB + EKS는 Kubernetes 클러스터 관리, 노드 그룹 관리, pod 오토스케일링 구성 등 가장 높은 운영 복잡성을 수반합니다. 관리형 서비스이지만 서버리스 대비 관리 부담이 큽니다.

D: Reserved concurrency는 Lambda 함수의 최대 동시 실행 수를 제한하는 설정으로, 다른 함수가 리소스를 소진하는 것을 방지합니다. 하지만 실행 환경을 사전 초기화하지 않으므로 cold start 문제가 여전히 발생하며, 일관된 저지연 응답을 보장하지 못합니다.
