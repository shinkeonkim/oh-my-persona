## Question

회사에서 새로운 동적 주문 웹사이트를 구축하고 있습니다. 회사는 서버 유지 관리 및 패치를 최소화하려고 합니다. 웹 사이트는 가용성이 높아야 하며 사용자 요구의 변화를 충족하기 위해 가능한 한 빨리 읽기 및 쓰기 용량을 확장해야 합니다.
이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. Amazon S3에서 정적 콘텐츠를 호스팅합니다. Amazon API Gateway 및 AWS Lambda를 사용하여 동적 콘텐츠를 호스팅합니다. 데이터베이스에 대한 온디맨드 용량과 함께 Amazon DynamoDB를 사용합니다. 웹 사이트 콘텐츠를 제공하도록 Amazon CloudFront를 구성합니다.
- [ ] B. Amazon S3에서 정적 콘텐츠를 호스팅합니다. Amazon API Gateway 및 AWS Lambda를 사용하여 동적 콘텐츠를 호스팅합니다. 데이터베이스에는 Aurora Auto Scaling과 함께 Amazon Aurora를 사용합니다. 웹 사이트 콘텐츠를 제공하도록 Amazon CloudFront를 구성합니다.
- [ ] C. Amazon EC2 인스턴스에서 모든 웹 사이트 콘텐츠를 호스팅합니다. Auto Scaling 그룹을 생성하여 EC2 인스턴스를 확장합니다. Application Load Balancer를 사용하여 트래픽을 분산합니다. 데이터베이스에 대해 프로비저닝된 쓰기 용량과 함께 Amazon DynamoDB를 사용합니다.
- [ ] D. Amazon EC2 인스턴스에서 모든 웹 사이트 콘텐츠를 호스팅합니다. Auto Scaling 그룹을 생성하여 EC2 인스턴스를 확장합니다. Application Load Balancer를 사용하여 트래픽을 분산합니다. 데이터베이스에는 Aurora Auto Scaling과 함께 Amazon Aurora를 사용합니다.

## Answer

정답: A

## Explanation

S3에 정적 콘텐츠를 호스팅하고 CloudFront로 글로벌 캐싱하며, API Gateway + Lambda로 동적 주문 처리를 구현합니다. DynamoDB on-demand 모드로 자동 확장과 고가용성을 보장합니다. 이 완전 서버리스 아키텍처는 서버 유지보수와 패칭이 불필요하고, CloudFront의 엣지 로케이션을 통한 고가용성이 기본 제공됩니다. Amazon DynamoDB는 자동으로 세 개의 가용 영역에 걸쳐 데이터를 복제하여 내구성과 가용성을 보장합니다.

오답 분석

B: Aurora Serverless가 아닌 일반 Aurora는 데이터베이스 인스턴스 관리가 필요합니다. Lambda + API Gateway는 서버리스이지만, Aurora의 인스턴스 크기 조정, 유지보수 윈도우 관리 등이 필요하여 '서버 유지보수 최소화' 요구사항에 DynamoDB보다 부적합합니다.

C: EC2 인스턴스 기반 아키텍처는 OS 패칭, 보안 업데이트, Auto Scaling 구성 등 서버 유지보수가 필요하여 서버리스 방식 대비 운영 부담이 큽니다. 또한 DynamoDB에서 프로비저닝된 쓰기 용량은 Auto Scaling 정책을 사용하여 수 분간의 스케일링 지연이 발생하므로, 읽기 및 쓰기 용량을 가능한 한 빠르게 확장해야 하는 요구사항을 충족하지 못합니다. DynamoDB 온디맨드 모드(옵션 A)는 사전 프로비저닝 없이 트래픽 급증에 즉시 대응합니다.

D: C 옵션과 동일하게 EC2 인스턴스의 서버 유지보수가 필요합니다. Amazon Aurora는 DynamoDB 대비 관리 오버헤드가 있으며, 전체적으로 서버리스 아키텍처 대비 운영 오버헤드가 크게 증가합니다.
