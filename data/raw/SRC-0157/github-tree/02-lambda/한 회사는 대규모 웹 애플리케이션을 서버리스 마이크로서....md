## Question

한 회사는 대규모 웹 애플리케이션을 서버리스 마이크로서비스 아키텍처로 재설계하려고 합니다. 애플리케이션은 Amazon EC2 인스턴스를 사용하며 Python으로 작성되었습니다.
회사는 마이크로서비스로 테스트하기 위해 웹 애플리케이션의 한 구성 요소를 선택했습니다. 구성 요소는 초당 수백 개의 요청을 지원합니다. 회사는 Python을 지원하는 AWS 솔루션에서 마이크로서비스를 생성하고 테스트하려고 합니다. 또한 솔루션은 자동으로 확장되어야 하며 최소한의 인프라와 최소한의 운영 지원이 필요합니다.
어떤 솔루션이 이러한 요구 사항을 충족합니까?

- [ ] A. 최신 Amazon Linux 운영 체제를 실행하는 EC2 인스턴스의 자동 확장 기능이 있는 스팟 집합을 사용합니다.
- [ ] B. 고가용성이 구성된 AWS Elastic Beanstalk 웹 서버 환경을 사용합니다.
- [ ] C. Amazon Elastic Kubernetes Service(Amazon EKS)를 사용합니다. 자체 관리형 EC2 인스턴스의 Auto Scaling 그룹을 시작합니다.
- [ ] D. 사용자 정의 개발 코드를 실행하는 AWS Lambda 함수를 사용합니다.

## Answer

정답: D

## Explanation

AWS Lambda 함수는 Python을 포함한 다양한 런타임을 지원하며, 서버리스 마이크로서비스 아키텍처에 가장 적합합니다. Lambda는 수백 req/sec을 처리할 수 있고, 요청량에 따라 자동으로 확장됩니다. 인프라 프로비저닝이나 서버 관리가 완전히 불필요하여 '최소 인프라 지원' 요구사항을 충족합니다. API Gateway와 통합하면 기존 RESTful 인터페이스를 유지하면서 EC2 기반 모놀리식 애플리케이션을 서버리스 마이크로서비스로 현대화할 수 있습니다.

오답 분석

A: EC2 Spot Fleet은 비용 효율적이지만 여전히 EC2 인스턴스의 관리(AMI 관리, Auto Scaling 구성, Spot 중단 처리)가 필요합니다. 서버리스가 아니므로 최소 인프라 지원 요구사항에 부합하지 않습니다.

B: AWS Elastic Beanstalk는 배포와 스케일링을 자동화하지만, 내부적으로 EC2 인스턴스가 사용되며 플랫폼 업데이트와 환경 관리가 필요합니다. Lambda 대비 운영 오버헤드가 큽니다.

C: Amazon EKS + EC2 Auto Scaling은 Kubernetes 클러스터 관리, 워커 노드 관리, pod 배포 등 상당한 인프라 관리가 필요합니다. 서버리스 대비 가장 높은 운영 복잡성을 수반합니다.
