## Question

IoT 회사는 사용자의 수면에 대한 데이터를 수집하는 센서가 있는 매트리스를 출시하고 있습니다. 센서는 데이터를 Amazon S3 버킷으로 보냅니다. 센서는 각 매트리스에 대해 매일 밤 약 2MB의 데이터를 수집합니다. 회사는 각 매트리스에 대한 데이터를 처리하고 요약해야 합니다. 결과는 가능한 한 빨리 제공되어야 합니다. 데이터 처리에는 1GB의 메모리가 필요하며 30초 이내에 완료됩니다.
이러한 요구 사항을 가장 비용 효율적으로 충족하는 솔루션은 무엇입니까?

- [ ] A. Scala 작업과 함께 AWS Glue를 사용합니다.
- [ ] B. Apache Spark 스크립트와 함께 Amazon EMR을 사용합니다.
- [ ] C. Python 스크립트와 함께 AWS Lambda를 사용합니다.
- [ ] D. PySpark 작업과 함께 AWS Glue를 사용합니다.

## Answer

정답: C

## Explanation

AWS Lambda + Python 스크립트는 센서당 최대 2MB, 처리 시간 30초 이내의 소규모 데이터 처리에 최적입니다. Lambda는 S3 이벤트 트리거로 새 데이터가 업로드될 때마다 자동 실행되며, 최대 10GB 메모리와 15분 실행 시간을 지원하므로 요구사항을 충분히 충족합니다. 밤마다 수천 개의 매트리스 센서 데이터가 업로드되어도 Lambda의 자동 확장으로 병렬 처리가 가능하며, pay-per-request 과금으로 비용 효율적입니다. 서버리스로 인프라 관리가 불필요합니다.

오답 분석

A: AWS Glue + Scala는 대규모 ETL 작업을 위한 분산 처리 엔진(Apache Spark 기반)입니다. 센서당 2MB의 소규모 데이터에 Glue job을 사용하는 것은 과도하며, Glue job 시작 시간(수 분의 warm-up)으로 비효율적입니다.

B: Amazon EMR + Apache Spark는 대규모 빅데이터 분석을 위한 분산 클러스터 서비스입니다. 2MB 데이터 처리에 EMR 클러스터를 사용하는 것은 비용과 복잡성 면에서 과도합니다.

D: AWS Glue + PySpark도 A 옵션과 동일하게 대규모 ETL용 서비스입니다. 소규모 데이터에 Spark 클러스터를 사용하는 오버헤드가 크며, Lambda의 직관적인 Python 스크립트 대비 복잡합니다.
