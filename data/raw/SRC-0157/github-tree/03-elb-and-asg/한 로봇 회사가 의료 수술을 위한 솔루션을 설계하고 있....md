## Question

한 로봇 회사가 의료 수술을 위한 솔루션을 설계하고 있습니다. 로봇은 고급 센서, 카메라 및 AI 알고리즘을 사용하여 환경을 인식하고 수술을 완료합니다.
회사에는 백엔드 서비스와의 원활한 통신을 보장할 AWS 클라우드의 공용 로드 밸런서가 필요합니다. 로드 밸런서는 쿼리 문자열을 기반으로 트래픽을 다른 대상 그룹으로 라우팅할 수 있어야 합니다. 트래픽도 암호화되어야 합니다.
어떤 솔루션이 이러한 요구 사항을 충족합니까?

- [ ] A. ACM(AWS Certificate Manager)에서 첨부된 인증서와 함께 Application Load Balancer를 사용합니다. 쿼리 매개변수 기반 라우팅을 사용합니다.
- [ ] B. Network Load Balancer를 사용합니다. AWS Identity and Access Management(IAM)에서 생성된 인증서를 가져옵니다. 인증서를 로드 밸런서에 연결합니다. 쿼리 매개변수 기반 라우팅을 사용합니다.
- [ ] C. 게이트웨이 로드 밸런서를 사용합니다. AWS Identity and Access Management(IAM)에서 생성된 인증서를 가져옵니다. 인증서를 로드 밸런서에 연결합니다. HTTP 경로 기반 라우팅을 사용합니다.
- [ ] D. ACM(AWS Certificate Manager)에서 첨부된 인증서와 함께 Network Load Balancer를 사용합니다. 쿼리 매개변수 기반 라우팅을 사용합니다.

## Answer

정답: A

## Explanation

Application Load Balancer(ALB)는 OSI 모델 7계층에서 작동하며, 리스너 규칙에서 다양한 조건 기반 라우팅을 지원합니다. 쿼리 매개변수(Query String Parameter) 기반 라우팅을 통해 URL의 쿼리 문자열 값(예: ?version=v2)에 따라 트래픽을 서로 다른 대상 그룹으로 라우팅할 수 있습니다. ALB가 지원하는 조건 유형은 쿼리 문자열, 호스트 헤더, HTTP 메서드, 경로 패턴, 소스 IP, HTTP 헤더의 총 6가지입니다. ACM(AWS Certificate Manager)에서 발급한 SSL/TLS 인증서를 ALB에 무료로 연결하여 HTTPS 리스너를 구성하면 트래픽 암호화 요구 사항도 충족됩니다. ACM 인증서는 자동 갱신이 지원되어 운영 부담이 줄어듭니다.

오답 분석

B: NLB(Network Load Balancer)는 OSI 4계층(전송 계층)에서 작동하므로 HTTP 요청의 URL이나 쿼리 문자열을 파싱할 수 없습니다. 쿼리 매개변수 기반 라우팅은 HTTP 요청 내용을 분석해야 하므로 7계층에서 작동하는 ALB에서만 가능합니다. 또한 IAM에서 인증서를 가져오는 방식은 ACM 사용보다 관리가 복잡하고, ACM과 달리 자동 갱신이 지원되지 않아 수동으로 인증서를 교체해야 합니다.

C: Gateway Load Balancer(GWLB)는 OSI 3계층(네트워크 계층)에서 작동하며, 모든 IP 패킷을 모든 포트에서 수신합니다. GENEVE 프로토콜(포트 6081)을 사용하여 보안 가상 어플라이언스로 트래픽을 전달하는 용도로 설계되었습니다. HTTP 경로 기반이나 쿼리 매개변수 기반 라우팅을 지원하지 않으며, TLS 종료 기능도 없습니다.

D: NLB는 ACM 인증서를 TLS 리스너에 연결하여 TLS 종료를 지원할 수 있지만, 4계층에서 작동하므로 HTTP 요청의 쿼리 문자열을 검사하거나 이를 기반으로 라우팅할 수 없습니다. 쿼리 매개변수 기반 라우팅은 HTTP 헤더와 URL을 파싱하는 7계층 ALB에서만 사용 가능한 기능입니다.
