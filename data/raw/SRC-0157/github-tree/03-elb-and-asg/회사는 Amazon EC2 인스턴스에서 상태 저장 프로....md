## Question

회사는 Amazon EC2 인스턴스에서 상태 저장 프로덕션 애플리케이션을 실행합니다. 애플리케이션을 항상 실행하려면 최소 2개의 EC2 인스턴스가 필요합니다.
솔루션 설계자는 애플리케이션을 위한 고가용성 및 내결함성 아키텍처를 설계해야 합니다. 솔루션 설계자는 EC2 인스턴스의 Auto Scaling 그룹을 생성합니다.
이러한 요구 사항을 충족하기 위해 솔루션 설계자가 수행해야 하는 추가 단계는 무엇입니까?

- [ ] A. Auto Scaling 그룹의 최소 용량을 2로 설정합니다. 하나의 가용 영역에 하나의 온디맨드 인스턴스를 배포하고 두 번째 가용 영역에 하나의 온디맨드 인스턴스를 배포합니다.
- [ ] B. Auto Scaling 그룹의 최소 용량을 4개로 설정합니다. 하나의 가용 영역에 2개의 온디맨드 인스턴스를 배포하고 두 번째 가용 영역에 2개의 온디맨드 인스턴스를 배포합니다.
- [ ] C. Auto Scaling 그룹의 최소 용량을 2로 설정합니다. 하나의 가용 영역에 4개의 스팟 인스턴스를 배포합니다.
- [ ] D. Auto Scaling 그룹의 최소 용량을 4로 설정합니다. 하나의 가용 영역에 2개의 온디맨드 인스턴스를 배포하고 두 번째 가용 영역에 2개의 스팟 인스턴스를 배포합니다.

## Answer

정답: B

## Explanation

상태 저장(stateful) 프로덕션 애플리케이션의 고가용성과 내결함성을 위해, 최소 용량을 4개로 설정하고 2개의 가용 영역에 각 2개의 온디맨드 인스턴스를 배포해야 합니다. 이렇게 구성하면 한 가용 영역이 완전히 장애가 발생해도 다른 가용 영역에 2개의 인스턴스가 남아 '최소 2개 인스턴스 항상 실행'이라는 요구 사항을 충족합니다. 온디맨드 인스턴스는 중단 없이 안정적으로 실행되므로 프로덕션 환경에 적합합니다.

오답 분석

A: 최소 용량 2개에 각 AZ에 1개 인스턴스만 배포하면, 한 AZ 장애 시 1개 인스턴스만 남아 '최소 2개' 요구 사항을 충족하지 못합니다. Auto Scaling이 새 인스턴스를 시작할 수 있지만, 시작 시간 동안 1개만 운영되어 내결함성이 부족합니다.

C: 단일 가용 영역에 4개의 스팟 인스턴스를 배포하면 두 가지 문제가 있습니다. 첫째, 단일 AZ 장애 시 모든 인스턴스가 중단됩니다. 둘째, 스팟 인스턴스는 2분 전 알림으로 언제든 중단될 수 있어, 상태 저장 프로덕션 애플리케이션에는 부적합합니다.

D: 스팟 인스턴스는 언제든 중단될 수 있으므로, 상태 저장 프로덕션 애플리케이션에 스팟을 사용하면 세션 데이터 손실 위험이 있습니다. 한 AZ의 2개 스팟 인스턴스가 동시에 중단되면 해당 AZ에 인스턴스가 없어지며, 최소 2개 요구 사항을 안정적으로 보장할 수 없습니다.
