## Question

회사가 AWS에서 애플리케이션을 시작하고 있습니다. 애플리케이션은 Application Load Balancer(ALB)를 사용하여 단일 대상 그룹에 있는 최소 2개의 Amazon EC2 인스턴스로 트래픽을 보냅니다. 인스턴스는 각 환경의 Auto Scaling 그룹에 있습니다. 회사는 개발 환경과 생산 환경이 필요합니다. 프로덕션 환경에는 트래픽이 많은 기간이 있습니다.
개발 환경을 가장 비용 효율적으로 구성하는 솔루션은 무엇입니까?

- [ ] A. 하나의 EC2 인스턴스만 대상으로 하도록 개발 환경에서 대상 그룹을 재구성합니다.
- [ ] B. ALB 밸런싱 알고리즘을 최소 미해결 요청으로 변경합니다.
- [ ] C. 두 환경 모두에서 EC2 인스턴스의 크기를 줄입니다.
- [ ] D. 개발 환경의 Auto Scaling 그룹에서 최대 EC2 인스턴스 수를 줄입니다.

## Answer

정답: A

## Explanation

개발 환경에서 대상 그룹의 대상을 하나의 EC2 인스턴스로 재구성하면, 최소 2개 대신 1개의 인스턴스만 실행하여 인스턴스 비용을 50% 절감할 수 있습니다. 개발 환경은 프로덕션처럼 높은 트래픽이 발생하지 않으므로, 단일 인스턴스로 개발 및 테스트 목적에 충분합니다. ALB 대상 그룹의 최소 등록 대상 수에는 제한이 없으므로 1개의 인스턴스만으로도 정상 운영이 가능합니다. 문제에서 개발 환경의 비용 최적화만 요구하므로, 프로덕션 환경에 영향을 주지 않으면서 개발 환경의 리소스를 줄이는 것이 가장 직접적인 비용 절감 방법입니다.

오답 분석

B: ALB 밸런싱 알고리즘을 최소 미해결 요청(Least Outstanding Requests)으로 변경하는 것은 기존 인스턴스 간의 트래픽 분배 효율을 개선할 뿐, 실행되는 인스턴스 수를 줄이지 않습니다. 라우팅 알고리즘 변경으로는 EC2 인스턴스 비용이 절감되지 않습니다.

C: 두 환경 모두에서 EC2 인스턴스 크기를 줄이면 개발 환경뿐 아니라 프로덕션 환경의 성능에도 영향을 줍니다. 문제에서 프로덕션에 높은 트래픽 기간이 있다고 했으므로, 프로덕션 인스턴스 크기를 줄이면 피크 시간에 성능 문제가 발생할 수 있습니다. 문제는 '개발 환경'의 비용 최적화만 요구합니다.

D: Auto Scaling 그룹의 최대 인스턴스 수를 줄이면 확장 가능한 상한선만 낮아질 뿐, 현재 실행 중인 최소 인스턴스 수에는 영향을 주지 않습니다. 최소 용량이 2개로 설정되어 있다면 최대 값을 줄여도 여전히 최소 2개가 실행됩니다. 비용 절감을 위해서는 실제 실행 인스턴스 수를 줄여야 합니다.
