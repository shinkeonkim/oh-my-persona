## Question

회사는 사용자 디바이스에서 센서 데이터를 수집하는 3계층 애플리케이션을 AWS에 보유하고 있습니다. 트래픽은 NLB(Network Load Balancer)를 거쳐 웹 계층용 Amazon EC2 인스턴스로 이동한 다음 마지막으로 애플리케이션 계층용 EC2 인스턴스로 이동합니다. 애플리케이션 계층은 데이터베이스를 호출합니다.
솔루션 설계자는 전송 중인 데이터의 보안을 개선하기 위해 무엇을 해야 합니까?

- [ ] A. TLS 수신기를 구성합니다. NLB에 서버 인증서를 배포합니다.
- [ ] B. AWS Shield Advanced를 구성합니다. NLB에서 AWS WAF를 활성화합니다.
- [ ] C. 로드 밸런서를 Application Load Balancer(ALB)로 변경합니다. ALB에서 AWS WAF를 활성화합니다.
- [ ] D. AWS Key Management Service(AWS KMS)를 사용하여 EC2 인스턴스에서 Amazon Elastic Block Store(Amazon EBS) 볼륨을 암호화합니다.

## Answer

정답: A

## Explanation

NLB에 TLS 리스너를 구성하고 서버 인증서를 배포하면, 클라이언트와 로드 밸런서 간의 모든 통신이 TLS(Transport Layer Security)로 암호화됩니다. TLS는 데이터의 기밀성과 무결성을 보장하여 전송 중(in transit) 데이터의 보안을 직접적으로 향상시킵니다. NLB는 TLS 종료(TLS Termination)를 기본적으로 지원하며, AWS Certificate Manager(ACM)에서 무료로 발급한 SSL/TLS 인증서를 사용할 수 있습니다.

오답 분석

B: AWS Shield Advanced는 DDoS 공격 방어 서비스이고, AWS WAF는 웹 애플리케이션 방화벽으로 SQL 인젝션, XSS 등의 공격을 방어합니다. 이들은 공격 방어 서비스이며 전송 중 데이터 암호화 문제를 해결하지 않습니다. 특히 WAF는 NLB에 직접 연결할 수 없으며, ALB, CloudFront, API Gateway, AppSync, Cognito 사용자 풀, App Runner, Verified Access에서만 사용 가능합니다.

C: ALB(Application Load Balancer)로 변경하고 WAF를 활성화하면 7계층 웹 공격 방어가 가능하지만, WAF는 전송 중 데이터 암호화가 아닌 요청 패턴 필터링을 수행합니다. 전송 중 데이터 보안에는 TLS 리스너 구성이 직접적인 해결책입니다.

D: AWS KMS로 EBS 볼륨을 암호화하는 것은 디스크에 저장된 데이터(at rest)를 보호합니다. 네트워크를 통해 전송되는 데이터(in transit)의 보안과는 완전히 별개의 문제이며, 이 질문의 요구 사항을 충족하지 못합니다.
