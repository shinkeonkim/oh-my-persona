## Question

회사에는 동적 트래픽 부하를 처리하는 웹사이트가 있습니다. 웹사이트 아키텍처는 예약된 스케일링을 사용하도록 구성된 Auto Scaling 그룹의 Amazon EC2 인스턴스를 기반으로 합니다. 각 EC2 인스턴스는 Amazon Elastic File System(Amazon EFS) 볼륨에서 코드를 실행하고 공유 데이터를 동일한 볼륨에 다시 저장합니다.
회사는 웹사이트 비용을 최적화하려고 합니다. 이 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. Auto Scaling 그룹을 재구성하여 원하는 인스턴스 수를 설정합니다. 예약된 스케일링을 끕니다.
- [ ] B. 더 큰 EC2 인스턴스를 사용하는 Auto Scaling 그룹에 대한 새 시작 템플릿 버전을 만듭니다.
- [ ] C. 대상 추적 스케일링 정책을 사용하도록 Auto Scaling 그룹을 재구성합니다.
- [ ] D. EFS 볼륨을 인스턴스 스토어 볼륨으로 바꿉니다.

## Answer

정답: C

## Explanation

대상 추적 스케일링 정책(Target Tracking Scaling Policy)은 지정된 메트릭(예: 평균 CPU 사용률, 요청 수)의 목표 값을 유지하도록 Auto Scaling 그룹의 인스턴스 수를 자동으로 조정합니다. 동적 트래픽 부하에서 예약된 스케일링보다 실시간으로 정확하게 대응하며, 트래픽이 줄어들면 자동으로 인스턴스를 축소하여 비용을 최적화합니다.

오답 분석

A: 원하는 인스턴스 수를 고정값으로 설정하고 예약된 스케일링을 끄면 동적 트래픽 변화에 전혀 대응할 수 없습니다. 트래픽이 증가하면 용량 부족이, 감소하면 과잉 프로비저닝이 발생합니다.

B: 더 큰 EC2 인스턴스 유형으로 변경하는 수직 확장은 트래픽 변동에 따른 동적 조정이 이루어지지 않으며, 피크에 맞춘 큰 인스턴스를 항상 실행하면 비용이 최적화되지 않습니다.

D: 인스턴스 스토어 볼륨은 인스턴스에 물리적으로 연결된 임시 스토리지로, EFS처럼 여러 인스턴스 간에 데이터를 공유할 수 없습니다. 기존 아키텍처의 공유 파일 시스템 요구사항을 충족하지 못합니다.
