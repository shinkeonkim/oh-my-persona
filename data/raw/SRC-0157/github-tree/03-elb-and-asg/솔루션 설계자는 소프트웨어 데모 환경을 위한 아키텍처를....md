## Question

솔루션 설계자는 소프트웨어 데모 환경을 위한 아키텍처를 설계하고 있습니다. 환경은 Application Load Balancer(ALB) 뒤에 있는 Auto Scaling 그룹의 Amazon EC2 인스턴스에서 실행됩니다. 시스템은 근무 시간 동안 트래픽이 크게 증가하지만 주말에는 작동하지 않아도 됩니다.
수요에 맞게 시스템을 확장할 수 있도록 하기 위해 솔루션 설계자는 어떤 조치 조합을 취해야 합니까? (두 가지를 선택하세요.)

- [ ] A. AWS Auto Scaling을 사용하여 요청 속도에 따라 ALB 용량을 조정합니다.
- [ ] B. AWS Auto Scaling을 사용하여 VPC 인터넷 게이트웨이의 용량을 확장합니다.
- [ ] C. 여러 AWS 지역에서 EC2 인스턴스를 시작하여 여러 지역에 로드를 분산합니다.
- [ ] D. 대상 추적 조정 정책을 사용하여 인스턴스 CPU 사용률을 기반으로 Auto Scaling 그룹을 조정합니다.
- [ ] E. 예약된 조정을 사용하여 Auto Scaling 그룹의 최소, 최대 및 원하는 용량을 주말 동안 0으로 변경합니다. 주의 시작 시 기본값으로 되돌립니다.

## Answer

정답: D, E

## Explanation

D와 E가 정답입니다. 대상 추적 조정 정책(D)은 인스턴스 CPU 사용률(ASGAverageCPUUtilization) 같은 메트릭에 대해 목표 값을 설정하면, Auto Scaling이 자동으로 CloudWatch 경보를 생성하고 관리하여 해당 메트릭 값을 목표에 가깝게 유지합니다. 마치 온도 조절기(thermostat)처럼 작동하여 근무 시간의 트래픽 증가에 자동 대응합니다. 사전 정의된 메트릭으로는 ASGAverageCPUUtilization, ASGAverageNetworkIn, ASGAverageNetworkOut, ALBRequestCountPerTarget 4가지가 있습니다. 예약된 조정(E)은 cron 표현식을 사용하여 주말에 Auto Scaling 그룹의 최소, 최대, 원하는 용량을 0으로 설정하고, 주 시작 시 기본값으로 복원하는 반복 일정을 설정할 수 있습니다. 두 정책을 함께 사용하면 동적 수요 대응과 예약된 비용 절감을 동시에 달성합니다.

오답 분석

A: ALB(Application Load Balancer)는 AWS 완전 관리형 서비스로 트래픽에 따라 자동으로 확장됩니다. ALB에는 사용자가 조정할 수 있는 '용량' 개념이 없으며, AWS Auto Scaling으로 ALB 용량을 별도로 조정하는 것은 불가능합니다. ALB는 내부적으로 수요에 맞게 자동 스케일링됩니다.

B: VPC 인터넷 게이트웨이(IGW)는 완전 관리형 AWS 구성 요소로, 대역폭 제한 없이 수평적으로 자동 확장됩니다. IGW는 고가용성과 중복성이 내장되어 있어 별도의 스케일링이 필요하지 않으며, Auto Scaling으로 IGW 용량을 조정하는 것은 기술적으로 불가능합니다.

C: 여러 AWS 리전에 EC2 인스턴스를 분산하는 것은 글로벌 재해 복구(DR)나 지리적 지연 시간 최적화를 위한 것입니다. 소프트웨어 데모 환경의 근무 시간 트래픽 처리에는 단일 리전 내 다중 AZ와 Auto Scaling으로 충분하며, 멀티 리전은 과도하게 복잡하고 비용이 많이 드는 솔루션입니다.
