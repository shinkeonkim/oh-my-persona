## Question

한 회사는 최근 Amazon EC2 인스턴스에 대해 운영 체제 버전 패치 및 설치된 소프트웨어에 대한 정보를 중앙 집중화하기 위해 새로운 감사 시스템을 배포했습니다. 솔루션 설계자는 EC2 Auto Scaling 그룹을 통해 프로비저닝된 모든 인스턴스가 시작 및 종료되는 즉시 성공적으로 감사 시스템에 보고서를 보내도록 해야 합니다.
이러한 목표를 가장 효율적으로 달성하는 솔루션은 무엇입니까?

- [ ] A. 예약된 AWS Lambda 함수를 사용하고 모든 EC2 인스턴스에서 원격으로 스크립트를 실행하여 데이터를 감사 시스템으로 보냅니다.
- [ ] B. EC2 Auto Scaling 수명 주기 후크를 사용하여 인스턴스가 시작되고 종료될 때 감사 시스템에 데이터를 보내는 사용자 지정 스크립트를 실행합니다.
- [ ] C. EC2 Auto Scaling 시작 구성을 사용하여 사용자 데이터를 통해 사용자 지정 스크립트를 실행하여 인스턴스가 시작되고 종료될 때 감사 시스템에 데이터를 보냅니다.
- [ ] D. 인스턴스 운영 체제에서 사용자 지정 스크립트를 실행하여 데이터를 감사 시스템으로 보냅니다. 인스턴스가 시작되고 종료될 때 EC2 Auto Scaling 그룹에서 호출할 스크립트를 구성합니다.

## Answer

정답: B

## Explanation

EC2 Auto Scaling 수명 주기 후크(Lifecycle Hooks)를 사용하면 인스턴스가 시작(launching) 또는 종료(terminating)되는 시점에 사용자 정의 작업을 수행할 수 있습니다. 수명 주기 후크는 인스턴스 상태 전환 시 대기(Pending:Wait 또는 Terminating:Wait) 상태를 생성하여, 감사 시스템에 보고서를 보내는 스크립트를 실행할 충분한 시간을 확보합니다. 이 방식은 인스턴스 시작과 종료 모두에서 자동으로 트리거되므로 가장 효율적입니다.

오답 분석

A: 예약된 Lambda 함수로 원격 스크립트를 실행하면 인스턴스 시작/종료 시점을 정확히 포착할 수 없으며, 스케줄 간격 사이에 생성되고 종료된 인스턴스를 놓칠 수 있습니다.

C: 인스턴스 시작 시 사용자 데이터(User Data)로 스크립트를 실행하면 시작 시점은 처리할 수 있지만, 종료 시점에는 보고서를 보낼 수 없습니다.

D: 인스턴스 OS에서 사용자 지정 스크립트를 실행하는 방식은 시작 시(User Data 등) 스크립트를 실행할 수 있지만, 인스턴스 종료 시점에는 OS가 이미 종료 절차에 진입하므로 스크립트 완료를 보장하기 어렵습니다. 수명 주기 후크와 달리 종료를 지연시키는 메커니즘이 없어 감사 보고서 전송이 보장되지 않습니다.
