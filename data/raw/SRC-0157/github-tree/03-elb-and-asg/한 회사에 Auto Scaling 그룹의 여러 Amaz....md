## Question

한 회사에 Auto Scaling 그룹의 여러 Amazon EC2 인스턴스에 배포된 다중 계층 애플리케이션이 있습니다. Amazon RDS for Oracle 인스턴스는 Oracle 관련 PL/SQL 기능을 사용하는 애플리케이션의 데이터 계층입니다. 애플리케이션에 대한 트래픽은 꾸준히 증가하고 있습니다. 이로 인해 EC2 인스턴스가 과부하되고 RDS 인스턴스의 스토리지가 부족해집니다. Auto Scaling 그룹에는 조정 지표가 없으며 최소 정상 인스턴스 수만 정의합니다. 이 회사는 트래픽이 안정되기 전에 꾸준하지만 예측할 수 없는 속도로 계속 증가할 것이라고 예측합니다.
증가된 트래픽에 대해 시스템이 자동으로 확장될 수 있도록 하려면 솔루션 설계자가 무엇을 해야 합니까? (두 가지를 선택하세요.)

- [ ] A. RDS for Oracle 인스턴스에서 스토리지 Auto Scaling을 구성합니다.
- [ ] B. Auto Scaling 스토리지를 사용하려면 데이터베이스를 Amazon Aurora로 마이그레이션합니다.
- [ ] C. 사용 가능한 저장 공간 부족에 대해 Oracle 인스턴스용 RDS에서 경보를 구성합니다.
- [ ] D. 평균 CPU를 조정 지표로 사용하도록 Auto Scaling 그룹을 구성합니다.
- [ ] E. 평균 여유 메모리를 조정 지표로 사용하도록 Auto Scaling 그룹을 구성합니다.

## Answer

정답: A, D

## Explanation

A와 D가 정답입니다. RDS for Oracle에서 스토리지 Auto Scaling(A)을 활성화하면, 데이터베이스 스토리지가 부족해질 때 자동으로 스토리지를 확장하여 문제를 해결합니다. Oracle 관련 PL/SQL 기능을 사용하므로 Oracle 호환 DB를 유지해야 합니다. EC2 Auto Scaling 그룹에 평균 CPU를 조정 지표(D)로 추가하면, EC2 인스턴스 과부하 시 자동으로 인스턴스를 추가하여 트래픽 증가에 대응합니다. CPU 사용률은 기본 CloudWatch 메트릭으로 추가 설정 없이 사용 가능합니다.

오답 분석

B: Amazon Aurora는 MySQL 및 PostgreSQL과 호환되는 관계형 데이터베이스이며, Oracle PL/SQL과는 호환되지 않습니다. Oracle 고유의 PL/SQL 함수, 패키지, 트리거를 사용하는 애플리케이션을 Aurora로 마이그레이션하면 코드 변경이 필요하고 호환성 문제가 발생합니다.

C: 스토리지 부족에 대한 CloudWatch 경보만 설정하면 알림(이메일, SNS 등)만 제공하고, 스토리지를 자동으로 확장하지 않습니다. 문제에서 '자동으로 확장'해야 한다고 했으므로, 경보만으로는 요구 사항을 충족하지 못합니다.

E: 평균 여유 메모리(FreeableMemory)는 EC2의 기본 CloudWatch 메트릭이 아닙니다. EC2에서 메모리 메트릭을 모니터링하려면 CloudWatch Agent를 설치하여 커스텀 메트릭을 수집해야 합니다. CPU 사용률이 인스턴스 과부하의 더 보편적이고 직접적인 지표이며, 별도 에이전트 설치 없이 기본 메트릭으로 바로 사용할 수 있습니다.
