## Question

회사에서 내부 브라우저 기반 애플리케이션을 실행합니다. 애플리케이션은 Application Load Balancer 뒤의 Amazon EC2 인스턴스에서 실행됩니다. 인스턴스는 여러 가용 영역에 걸쳐 Amazon EC2 Auto Scaling 그룹에서 실행됩니다. Auto Scaling 그룹은 근무 시간 동안 최대 20개의 인스턴스로 확장되지만 밤에는 2개의 인스턴스로 축소됩니다. 직원들은 하루가 시작될 때 애플리케이션이 매우 느리지만 오전 중반쯤에는 정상적으로 동작한다고 불평하고 있습니다.
직원 불만을 해결하고 비용을 최소화하기 위해 확장을 어떻게 변경해야 합니까?

- [ ] A. 사무실이 열리기 직전에 원하는 용량을 20개로 설정하는 예약 작업을 구현합니다.
- [ ] B. 더 낮은 CPU 임계값에서 트리거되는 단계 조정 작업을 구현하고 휴지 기간을 줄입니다.
- [ ] C. 더 낮은 CPU 임계값에서 트리거되는 대상 추적 작업을 구현하고 휴지 기간을 줄입니다.
- [ ] D. 사무실이 열리기 직전에 최소 및 최대 용량을 20개로 설정하는 예약 조치를 구현합니다.

## Answer

정답: C

## Explanation

대상 추적(Target Tracking) 스케일링에서 더 낮은 CPU 임계값을 설정하고 휴지 기간을 줄이면, 아침 시간대의 애플리케이션 속도 저하 문제를 가장 비용 효율적으로 해결할 수 있습니다. 대상 추적은 지정된 CPU 사용률 목표를 유지하도록 인스턴스 수를 자동으로 조정합니다. 더 낮은 CPU 임계값을 설정하면 성능이 저하되기 전에 더 일찍 스케일링이 시작됩니다. 휴지 기간을 줄이면 Auto Scaling 그룹이 증가하는 수요에 더 빠르게 대응할 수 있습니다. 원하는 용량을 20으로 설정하는 예약 작업과 달리(과도한 프로비저닝으로 비용 낭비), 대상 추적은 실제 수요에 비례하여 확장하므로 비용을 최소화합니다.

오답 분석

A: 사무실이 열리기 전에 예약 작업으로 원하는 용량을 20으로 설정하면, 전체 용량이 아직 필요하지 않은 초기 시간대에 인스턴스를 과도하게 프로비저닝하여 불필요한 비용이 발생합니다.

B: 단계 조정(Step Scaling)은 임계값 초과에 따라 단계적으로 반응하지만, 대상 추적이 일반적으로 목표 지표 값을 유지하는 데 더 반응적이고 구성이 간단합니다. 단계 조정은 여러 스케일링 조정을 정의해야 합니다.

D: 최소 및 최대 용량을 모두 20으로 설정하면 Auto Scaling이 완전히 제거되어, 수요가 적은 기간을 포함하여 항상 20개의 인스턴스가 실행되므로 비용이 크게 증가합니다.
