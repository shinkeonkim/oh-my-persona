## Question

한 회사에서 새로운 가구 재고 애플리케이션을 구축하고 있습니다. 이 회사는 여러 가용 영역에 걸쳐 Amazon EC2 인스턴스 집합에 애플리케이션을 배포했습니다. EC2 인스턴스는 VPC의 ALB(Application Load Balancer) 뒤에서 실행됩니다.
솔루션 설계자는 수신 트래픽이 하나의 EC2 인스턴스를 선호하는 것으로 보이며 이로 인해 일부 요청에 대한 지연 시간이 발생하는 것으로 나타났습니다.
이 문제를 해결하려면 솔루션 아키텍트가 무엇을 해야 합니까?

- [ ] A. ALB에서 세션 선호도(고정 세션)를 비활성화합니다.
- [ ] B. ALB를 Network Load Balancer로 교체합니다.
- [ ] C. 각 가용 영역의 EC2 인스턴스 수를 늘립니다.
- [ ] D. ALB 대상 그룹에 대한 상태 확인 빈도를 조정합니다.

## Answer

정답: A

## Explanation

수신 트래픽이 하나의 EC2 인스턴스를 선호하는 현상은 ALB에서 세션 선호도(Sticky Sessions/Session Affinity)가 활성화되어 있기 때문입니다. 고정 세션이 활성화되면 ALB는 쿠키를 사용하여 동일 클라이언트의 요청을 동일한 인스턴스로 계속 라우팅합니다. 특정 클라이언트가 많은 요청을 보내거나, 세션 쿠키의 만료 시간이 길면 트래픽이 특정 인스턴스에 집중됩니다. 세션 선호도를 비활성화하면 ALB가 라운드 로빈 또는 최소 미해결 요청(Least Outstanding Requests) 알고리즘으로 트래픽을 균등하게 분산합니다.

오답 분석

B: ALB를 NLB로 교체하는 것은 트래픽 편중의 근본 원인(고정 세션 설정)을 해결하지 않으며, ALB의 7계층 기능(경로 기반 라우팅, 호스트 기반 라우팅 등)을 잃게 됩니다. NLB로 교체해도 고정 세션이 설정되어 있으면 동일한 문제가 발생할 수 있습니다.

C: 각 가용 영역의 EC2 인스턴스 수를 늘리면 전체 처리 용량은 증가하지만, 고정 세션으로 인해 여전히 특정 인스턴스로 트래픽이 집중되는 근본 문제가 해결되지 않습니다. 추가 인스턴스가 유휴 상태로 남아 비용만 증가합니다.

D: 상태 확인(Health Check) 빈도를 조정하는 것은 비정상(unhealthy) 인스턴스를 더 빨리 또는 느리게 감지하는 것에 영향을 줍니다. 정상 인스턴스 간 트래픽 분배 불균형 문제와는 직접적인 관련이 없습니다.
