## Question

회사에는 ALB(Application Load Balancer) 뒤의 단일 가용 영역에 있는 Amazon EC2 Auto Scaling 그룹에서 6개의 프런트 엔드 웹 서버를 실행하는 다중 계층 애플리케이션이 있습니다. 솔루션 설계자는 애플리케이션을 수정하지 않고 인프라를 고가용성으로 수정해야 합니다.
고가용성을 제공하는 솔루션 설계자는 어떤 아키텍처를 선택해야 합니까?

- [ ] A. 두 리전 각각에서 세 개의 인스턴스를 사용하는 Auto Scaling 그룹을 만듭니다.
- [ ] B. 2개의 가용 영역 각각에서 3개의 인스턴스를 사용하도록 Auto Scaling 그룹을 수정합니다.
- [ ] C. 다른 리전에서 더 많은 인스턴스를 빠르게 생성하는 데 사용할 수 있는 Auto Scaling 템플릿을 생성합니다.
- [ ] D. Amazon EC2 인스턴스 앞의 ALB를 라운드 로빈 구성으로 변경하여 웹 계층에 대한 트래픽의 균형을 맞춥니다.

## Answer

정답: B

## Explanation

Auto Scaling 그룹을 2개의 가용 영역에 걸쳐 각 3개의 인스턴스(총 6개)를 실행하도록 수정하면, 한 가용 영역에 장애가 발생해도 다른 가용 영역의 3개 인스턴스가 서비스를 계속 제공할 수 있어 고가용성을 확보합니다. Auto Scaling 그룹은 지정된 가용 영역 간에 인스턴스를 균등하게 분산하려고 시도하며(AZ Rebalancing), 불균형이 감지되면 먼저 새 인스턴스를 시작한 후 기존 인스턴스를 종료하여 가용성을 유지합니다. ALB는 자동으로 두 가용 영역에 걸쳐 트래픽을 분산하며, 교차 영역 로드 밸런싱(Cross-Zone Load Balancing)을 통해 모든 AZ의 인스턴스에 균등하게 요청을 분배합니다. 기존의 6개 프런트 엔드 웹 서버를 유지하면서 인프라 수준에서만 변경하므로 애플리케이션 수정이 필요 없습니다.

오답 분석

A: Auto Scaling 그룹은 단일 AWS 리전 내에서만 작동하며, 두 리전에 걸쳐 Auto Scaling 그룹을 생성할 수 없습니다. 멀티 리전 배포에는 각 리전에 별도의 Auto Scaling 그룹, ALB, 그리고 Route 53 DNS 기반 라우팅 구성이 필요하며, 이는 단순 고가용성 확보에 비해 과도하게 복잡하고 비용이 높습니다.

C: Auto Scaling 템플릿(시작 템플릿)만 생성하면 다른 리전에서 인스턴스를 빠르게 시작할 수 있는 준비만 되는 것이며, 장애 발생 시 자동 장애 조치를 제공하지 않습니다. 수동 개입이 필요하므로 고가용성 요구 사항을 충족하지 않으며, AMI와 시작 템플릿은 리전 간 복사가 별도로 필요합니다.

D: ALB는 기본적으로 라운드 로빈 방식으로 트래픽을 분산하고 있으며, 분산 알고리즘 변경만으로는 단일 가용 영역 장애 시 서비스 중단을 방지할 수 없습니다. 고가용성의 핵심은 여러 AZ에 걸친 인스턴스 분산이며, 로드 밸런싱 알고리즘 조정은 근본적인 해결책이 아닙니다.
