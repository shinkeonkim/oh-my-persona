## Question

애플리케이션은 여러 가용 영역의 Amazon EC2 인스턴스에서 실행됩니다. 인스턴스는 Application Load Balancer 뒤의 Amazon EC2 Auto Scaling 그룹에서 실행됩니다. 애플리케이션은 EC2 인스턴스의 CPU 사용률이 40% 또는 거의 40%일 때 최상의 성능을 발휘합니다.
솔루션 설계자는 그룹의 모든 인스턴스에서 원하는 성능을 유지하기 위해 무엇을 해야 합니까?

- [ ] A. 간단한 조정 정책을 사용하여 Auto Scaling 그룹을 동적으로 조정합니다.
- [ ] B. 대상 추적 정책을 사용하여 Auto Scaling 그룹을 동적으로 확장합니다.
- [ ] C. AWS Lambda 함수를 사용하여 원하는 Auto Scaling 그룹 용량을 업데이트합니다.
- [ ] D. 예약된 조정 작업을 사용하여 Auto Scaling 그룹을 확장 및 축소합니다.

## Answer

정답: B

## Explanation

대상 추적(Target Tracking) 조정 정책은 지정된 메트릭의 목표 값을 자동으로 유지하도록 Auto Scaling 그룹의 인스턴스 수를 동적으로 조정합니다. CPU 사용률 40%를 목표로 설정하면, Auto Scaling이 지속적으로 실제 CPU 사용률을 모니터링하고 목표에 가깝게 유지하기 위해 인스턴스를 추가하거나 제거합니다. 대상 추적 정책은 CloudWatch 경보를 자동 생성하고 관리하므로 설정이 간단하며, 특정 메트릭 값을 유지해야 하는 요구 사항에 가장 적합한 스케일링 방식입니다.

오답 분석

A: 단순 조정 정책(Simple Scaling)은 단일 CloudWatch 경보에 기반하여 고정된 수의 인스턴스를 추가/제거합니다. 특정 CPU 사용률 목표치(40%)를 정밀하게 유지하는 데는 대상 추적 정책보다 효과적이지 않으며, 스케일링 후 쿨다운(cooldown) 기간 동안 추가 조정이 불가능합니다.

C: Lambda 함수를 사용하여 Auto Scaling 그룹의 원하는 용량을 수동으로 업데이트하는 것은 커스텀 스케일링 로직을 구현하는 것으로, 운영 오버헤드가 크고 Lambda 함수의 개발/유지 관리가 필요합니다. Auto Scaling의 내장 대상 추적 정책으로 동일한 결과를 더 간단하게 달성할 수 있습니다.

D: 예약된 조정(Scheduled Scaling)은 트래픽 패턴이 시간적으로 예측 가능한 경우(예: 매일 오전 9시에 증가)에 사용합니다. 실시간 CPU 사용률을 특정 값(40%)으로 유지하는 동적 요구 사항에는 적합하지 않습니다.
