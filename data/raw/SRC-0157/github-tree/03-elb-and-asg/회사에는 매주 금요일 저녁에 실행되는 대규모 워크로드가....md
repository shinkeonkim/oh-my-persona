## Question

회사에는 매주 금요일 저녁에 실행되는 대규모 워크로드가 있습니다. 워크로드는 us-east-1 리전의 두 가용 영역에 있는 Amazon EC2 인스턴스에서 실행됩니다. 일반적으로 회사는 항상 두 개 이상의 인스턴스를 실행하지 않아야 합니다. 그러나 회사는 정기적으로 반복되는 증가된 워크로드를 처리하기 위해 금요일마다 최대 6개의 인스턴스로 확장하려고 합니다.
최소한의 운영 오버헤드로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. Amazon EventBridge에서 미리 알림을 생성하여 인스턴스를 확장합니다.
- [ ] B. 예약된 작업이 있는 Auto Scaling 그룹을 생성합니다.
- [ ] C. 수동 조정을 사용하는 Auto Scaling 그룹을 생성합니다.
- [ ] D. 자동 조정을 사용하는 Auto Scaling 그룹을 생성합니다.

## Answer

정답: B

## Explanation

예약된 작업(Scheduled Action)이 있는 Auto Scaling 그룹은 매주 금요일 저녁에 인스턴스를 6개로 확장하고, 워크로드 완료 후 2개로 축소하는 반복 일정(cron 표현식)을 설정할 수 있습니다. 예측 가능하고 정기적으로 반복되는 워크로드 패턴에 가장 적합하며, 설정 후 수동 개입이 전혀 필요 없어 운영 오버헤드가 최소화됩니다. 예약된 작업은 Auto Scaling 그룹의 최소, 최대, 원하는 용량을 지정된 시간에 자동으로 변경합니다.

오답 분석

A: Amazon EventBridge에서 '미리 알림'을 생성하는 것은 이벤트 알림만 제공하며, 실제로 인스턴스를 자동 확장하는 기능이 아닙니다. 알림을 받은 후 수동으로 인스턴스를 확장해야 하므로 운영 오버헤드가 높습니다.

C: 수동 조정(Manual Scaling)은 관리자가 매주 금요일마다 직접 AWS 콘솔 또는 CLI로 Auto Scaling 그룹의 용량을 변경하고, 워크로드 완료 후 다시 축소해야 합니다. 반복적인 수동 작업이 필요하여 운영 오버헤드가 가장 큽니다.

D: 자동 조정(Dynamic Scaling)은 실시간 메트릭에 반응하여 확장하므로, 워크로드가 시작되고 CPU/메모리가 증가한 후에야 인스턴스가 추가됩니다. 정확한 시간에 사전 확장하는 예약 조정보다 반응 시간이 느려, 워크로드 초기에 성능 저하가 발생할 수 있습니다.
