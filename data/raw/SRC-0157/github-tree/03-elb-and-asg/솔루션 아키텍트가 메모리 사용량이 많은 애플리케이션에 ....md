## Question

솔루션 아키텍트가 메모리 사용량이 많은 애플리케이션에 대한 Auto Scaling 그룹을 생성합니다. 솔루션 아키텍트는 메모리 사용량에 따라 확장 및 축소하려고 합니다. 이 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. AWS Systems Manager 에이전트(SSM 에이전트)를 설치하고 구성합니다. 메모리 사용량 추세에 따라 단계적으로 조정되는 단계적 확장 정책을 생성합니다.
- [ ] B. Amazon CloudWatch 에이전트를 설치하고 구성합니다. CloudWatch 지표(mem_used_percent)를 기준으로 확장하는 대상 추적 정책을 생성합니다.
- [ ] C. AWS Systems Manager 에이전트(SSM 에이전트)를 설치하고 구성합니다. Amazon CloudWatch 지표(mem_used_percent)를 기준으로 확장하는 대상 추적 정책을 생성합니다.
- [ ] D. Amazon CloudWatch 에이전트를 설치하고 구성합니다. 메모리 사용량 추세에 따라 확장하는 예약된 확장 정책을 생성합니다.

## Answer

정답: B

## Explanation

Amazon CloudWatch 에이전트를 설치하면 메모리 사용량(mem_used_percent)과 같은 커스텀 메트릭을 CloudWatch에 전송할 수 있으며, 대상 추적 정책(Target Tracking Policy)을 사용하여 해당 메트릭 기반으로 Auto Scaling 그룹을 자동 확장할 수 있습니다.

오답 분석

A: SSM Agent는 메모리 사용량 메트릭을 CloudWatch에 전송하는 기능이 없습니다. CloudWatch 에이전트가 필요합니다.

C: SSM Agent는 시스템 관리용이며 메모리 메트릭 수집 기능이 없습니다. CloudWatch 에이전트를 사용해야 합니다.

D: CloudWatch 에이전트는 올바르지만, 예약된 스케일링 정책은 메모리 사용량 추세에 따라 동적으로 조정하지 못하며 대상 추적 정책이 더 적합합니다.
