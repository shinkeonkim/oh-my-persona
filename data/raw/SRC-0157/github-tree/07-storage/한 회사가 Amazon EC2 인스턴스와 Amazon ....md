## Question

한 회사가 Amazon EC2 인스턴스와 Amazon Elastic Block Store(Amazon EBS) 볼륨을 사용하여 애플리케이션을 실행합니다. 이 회사는 매일 각 EBS 볼륨의 스냅샷을 하나씩 생성합니다. 이 회사는 사용자가 실수로 EBS 볼륨 스냅샷을 삭제하는 것을 방지해야 합니다. 솔루션은 스토리지 관리자의 관리 권한을 변경해서는 안 됩니다. 관리 부담을 최소화하면서 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 스냅샷 삭제 권한이 있는 IAM 역할을 생성합니다. 이 역할을 새 EC2 인스턴스에 연결합니다. 새 EC2 인스턴스에서 AWS CLI를 사용하여 스냅샷을 삭제합니다.
- [ ] B. 스냅샷 삭제를 거부하는 IAM 정책을 생성합니다. 이 정책을 스토리지 관리자 사용자에게 연결합니다.
- [ ] C. 스냅샷에 태그를 추가합니다. EBS 스냅샷에 대한 태그 수준 보존 규칙을 휴지통에 생성합니다. 보존 규칙에 대한 규칙 잠금 설정을 구성합니다.
- [ ] D. EBS Direct API를 사용하여 EBS 스냅샷을 생성합니다. 스냅샷을 Amazon S3 버킷에 복사합니다. 버킷에 S3 버전 관리 및 객체 잠금을 구성합니다.

## Answer

정답: C

## Explanation

EBS 스냅샷에 태그를 추가하고 Amazon EBS Recycle Bin의 태그 수준 보존 규칙을 구성하면, 실수로 삭제된 스냅샷이 지정된 기간 동안 Recycle Bin에 보존되어 복구할 수 있습니다. 규칙 잠금(Rule Lock)을 설정하면 보존 규칙 자체를 수정하거나 삭제할 수 없어, 스토리지 관리자의 기존 관리 권한을 변경하지 않고도 스냅샷이 영구 삭제되는 것을 방지합니다.

오답 분석

A: 스냅샷 삭제 권한이 있는 IAM 역할을 생성하는 것은 삭제를 허용하는 것이며, 실수로 삭제하는 것을 방지하지 못합니다.

B: 스냅샷 삭제를 거부하는 IAM 정책을 스토리지 관리자에게 연결하면 관리자의 관리 권한이 변경되므로 요구사항에 위배됩니다.

D: EBS direct API로 스냅샷을 생성하여 S3에 복사하는 것은 워크플로가 복잡하며, 기존 스냅샷 관리 방식을 크게 변경해야 하여 관리 부담이 큽니다.
