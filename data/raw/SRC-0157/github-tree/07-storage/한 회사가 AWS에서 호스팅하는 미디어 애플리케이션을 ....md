## Question

한 회사가 AWS에서 호스팅하는 미디어 애플리케이션을 위한 공유 스토리지 솔루션을 구현하고 있습니다. 회사는 SMB 클라이언트를 사용하여 저장된 데이터에 액세스할 수 있는 기능이 필요합니다.
최소한의 관리 오버헤드로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. AWS Storage Gateway 볼륨 게이트웨이를 생성합니다. 필요한 클라이언트 프로토콜을 사용하는 파일 공유를 만듭니다. 응용 프로그램 서버를 파일 공유에 연결합니다.
- [ ] B. AWS Storage Gateway 테이프 게이트웨이를 생성합니다. Amazon S3를 사용하도록 테이프를 구성합니다. 애플리케이션 서버를 테이프 게이트웨이에 연결합니다.
- [ ] C. Amazon EC2 Windows 인스턴스를 생성합니다. 인스턴스에 Windows 파일 공유 역할을 설치하고 구성합니다. 응용 프로그램 서버를 파일 공유에 연결합니다.
- [ ] D. Windows 파일 서버 파일 시스템용 Amazon FSx를 생성합니다. 원본 서버에 파일 시스템을 연결합니다. 애플리케이션 서버를 파일 시스템에 연결합니다.

## Answer

정답: D

## Explanation

Amazon FSx for Windows File Server는 완전관리형 Windows 파일 시스템으로 SMB(Server Message Block) 프로토콜을 기본 지원합니다. AWS에서 파일 시스템의 프로비저닝, 패치, 백업, 모니터링을 자동으로 관리하므로 관리 오버헤드가 최소화됩니다. Multi-AZ 배포 옵션으로 고가용성을 제공하며, 여러 EC2 인스턴스에서 동시에 마운트하여 공유 스토리지로 사용할 수 있습니다.

오답 분석

A: Storage Gateway 볼륨 게이트웨이는 iSCSI 블록 스토리지를 제공하며, SMB 파일 공유 프로토콜을 직접 지원하지 않습니다. SMB 클라이언트를 사용한 데이터 접근이 요구되므로 볼륨 게이트웨이는 부적합합니다.

B: Storage Gateway 테이프 게이트웨이는 백업 애플리케이션과의 VTL 인터페이스를 위한 것이며, 파일 공유나 SMB 접근을 제공하지 않습니다. 테이프 게이트웨이는 백업/아카이브 용도에만 적합합니다.

C: EC2 인스턴스에 Windows 파일 공유 역할을 수동으로 설치하고 구성하면 '완전관리형' 요구사항을 충족하지 못합니다. OS 패치, 파일 서버 관리, 용량 계획, 백업 등의 모든 관리를 직접 수행해야 합니다.
