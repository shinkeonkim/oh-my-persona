## Question

일기 예보 회사는 밀리초 미만의 대기 시간으로 수백 기가바이트의 데이터를 처리해야 합니다. 이 회사는 데이터 센터에 HPC(고성능 컴퓨팅) 환경을 보유하고 있으며 예측 기능을 확장하려고 합니다.
솔루션 설계자는 대량의 지속적인 처리량을 처리할 수 있는 고가용성 클라우드 스토리지 솔루션을 식별해야 합니다. 솔루션에 저장된 파일은 전체 데이터 세트에 동시에 액세스하고 처리하는 수천 개의 컴퓨팅 인스턴스에 액세스할 수 있어야 합니다.
솔루션 설계자는 이러한 요구 사항을 충족하기 위해 무엇을 해야 합니까?

- [ ] A. Lustre 스크래치 파일 시스템에는 Amazon FSx를 사용합니다.
- [ ] B. Lustre 영구 파일 시스템에는 Amazon FSx를 사용합니다.
- [ ] C. 버스팅 처리량 모드와 함께 Amazon Elastic File System(Amazon EFS)을 사용합니다.
- [ ] D. 프로비저닝된 처리량 모드와 함께 Amazon Elastic File System(Amazon EFS)을 사용합니다.

## Answer

정답: B

## Explanation

Amazon FSx for Lustre 영구(Persistent) 파일 시스템은 데이터를 동일 AZ 내에서 자동으로 복제하여 고가용성을 제공하며, 하드웨어 장애 시 투명하게 데이터를 복구합니다. 밀리초 미만의 지연 시간과 수백 GB/s의 처리량을 제공하여 HPC 워크로드에 최적이며, 수천 개의 컴퓨팅 인스턴스에서 POSIX 호환 병렬 접근이 가능합니다. 영구 파일 시스템은 장기 저장이 필요한 데이터에 적합한 반면, 스크래치는 임시 데이터에 적합합니다.

오답 분석

A: FSx for Lustre 스크래치(Scratch) 파일 시스템은 임시 스토리지로, 데이터 복제를 제공하지 않습니다. 서버 장애 시 데이터가 손실될 수 있어 고가용성 요구사항을 충족하지 못합니다. 스크래치는 임시 처리에만 적합합니다.

C: Amazon EFS Bursting Throughput 모드는 크레딧 기반으로 처리량을 제공하며, FSx for Lustre보다 최대 처리량이 낮습니다. HPC 워크로드에 필요한 수백 GB/s의 지속적인 처리량과 밀리초 미만의 지연 시간을 보장하지 못합니다.

D: Amazon EFS Provisioned Throughput 모드는 일정한 처리량을 제공하지만, FSx for Lustre의 병렬 파일 시스템 아키텍처보다 처리량이 낮으며 밀리초 미만의 지연 시간을 보장하지 않습니다. HPC에 최적화된 Lustre 파일 시스템이 더 적합합니다.
