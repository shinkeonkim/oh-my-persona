## Question

주로 온프레미스에서 애플리케이션 서버를 실행하는 회사가 AWS로 마이그레이션하기로 결정했습니다. 회사는 온프레미스에서 iSCSI(Internet Small Computer Systems Interface) 스토리지를 확장해야 할 필요성을 최소화하려고 합니다. 회사는 최근에 액세스한 데이터만 로컬에 저장하기를 원합니다.
회사는 이러한 요구 사항을 충족하기 위해 어떤 AWS 솔루션을 사용해야 합니까?

- [ ] A. Amazon S3 파일 게이트웨이
- [ ] B. AWS Storage Gateway 테이프 게이트웨이
- [ ] C. AWS Storage Gateway 볼륨 게이트웨이 저장 볼륨
- [ ] D. AWS Storage Gateway 볼륨 게이트웨이 캐시 볼륨

## Answer

정답: D

## Explanation

AWS Storage Gateway 볼륨 게이트웨이 캐시 볼륨(Cached Volume)은 iSCSI(Internet Small Computer Systems Interface) 프로토콜을 지원하여 기존 온프레미스 iSCSI 스토리지와 호환됩니다. 전체 데이터는 S3에 저장하면서 자주 액세스하는 데이터만 로컬에 캐시하므로, 온프레미스 iSCSI 스토리지 확장 필요성을 최소화하면서도 최근 데이터에 대한 저지연 로컬 액세스를 유지합니다. 볼륨당 최대 32TB, 게이트웨이당 최대 1PB를 지원합니다.

오답 분석

A: Amazon S3 파일 게이트웨이는 NFS와 SMB 파일 공유 프로토콜을 사용하며, iSCSI 블록 스토리지를 지원하지 않습니다. 기존 iSCSI 스토리지 인프라와 호환되지 않아 인프라 변경이 필요합니다.

B: Storage Gateway 테이프 게이트웨이는 기존 백업 소프트웨어의 물리적 테이프를 가상 테이프(VTL)로 대체하기 위한 서비스입니다. 일반적인 블록 스토리지 액세스 용도가 아닌 백업/아카이브 전용이므로 부적합합니다.

C: 저장 볼륨(Stored Volume)은 전체 데이터를 로컬에 저장하고 S3에 비동기적으로 스냅샷을 백업합니다. 모든 데이터가 로컬에 있으므로 온프레미스 스토리지 확장 필요성이 줄어들지 않아 요구사항에 부합하지 않습니다.
