## Question

의학 연구실에서 새로운 연구와 관련된 데이터를 생성합니다. 연구소는 온프레미스 파일 기반 애플리케이션을 위해 전국의 클리닉에 최소한의 대기 시간으로 데이터를 제공하고자 합니다. 데이터 파일은 각 클리닉에 대한 읽기 전용 권한이 있는 Amazon S3 버킷에 저장됩니다.
이러한 요구 사항을 충족하기 위해 솔루션 설계자는 무엇을 권장해야 합니까?

- [ ] A. 각 클리닉에서 온프레미스로 AWS Storage Gateway 파일 게이트웨이를 가상 머신(VM)으로 배포합니다.
- [ ] B. 처리를 위해 AWS DataSync를 사용하여 각 클리닉의 온프레미스 애플리케이션으로 파일을 마이그레이션합니다.
- [ ] C. 각 클리닉에서 온프레미스로 AWS Storage Gateway 볼륨 게이트웨이를 가상 머신(VM)으로 배포합니다.
- [ ] D. Amazon Elastic File System(Amazon EFS) 파일 시스템을 각 클리닉의 온프레미스 서버에 연결합니다.

## Answer

정답: A

## Explanation

AWS Storage Gateway 파일 게이트웨이를 각 클리닉에 온프레미스 VM으로 배포하면, S3 버킷의 연구 데이터를 NFS 또는 SMB 파일 공유로 로컬에서 제공합니다. 파일 게이트웨이는 자주 액세스하는 데이터를 로컬 캐시에 저장하여 최소 지연 시간으로 접근 가능하게 하며, 클리닉의 기존 파일 기반 애플리케이션이 코드 변경 없이 데이터에 접근할 수 있습니다. 읽기 전용 S3 버킷 권한이 파일 게이트웨이를 통해 적용됩니다.

오답 분석

B: AWS DataSync는 데이터 전송/마이그레이션 도구로, 온프레미스 애플리케이션에 파일 시스템 인터페이스(NFS/SMB 공유)를 제공하지 않습니다. 데이터를 전송한 후에도 애플리케이션이 S3 데이터에 실시간으로 접근하는 메커니즘이 없습니다.

C: Storage Gateway 볼륨 게이트웨이는 iSCSI 블록 스토리지를 제공하며, S3 버킷의 읽기 전용 파일 공유 용도에는 적합하지 않습니다. 파일 기반 애플리케이션에는 파일 게이트웨이(NFS/SMB)가 더 적합합니다.

D: Amazon EFS를 전국 각 클리닉의 온프레미스 서버에 직접 연결하려면 각 클리닉에서 AWS까지 VPN이나 Direct Connect가 필요하며, 물리적 거리에 따른 네트워크 지연이 발생합니다. 로컬 캐시가 없어 파일 게이트웨이보다 지연 시간이 높습니다.
