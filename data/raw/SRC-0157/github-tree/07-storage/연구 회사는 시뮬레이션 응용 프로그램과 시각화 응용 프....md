## Question

연구 회사는 시뮬레이션 응용 프로그램과 시각화 응용 프로그램으로 구동되는 실험을 실행합니다. 시뮬레이션 애플리케이션은 Linux에서 실행되며 5분마다 NFS 공유에 중간 데이터를 출력합니다. 시각화 응용 프로그램은 시뮬레이션 출력을 표시하고 SMB 파일 시스템이 필요한 Windows 데스크톱 응용 프로그램입니다.
회사는 두 개의 동기화된 파일 시스템을 유지 관리합니다. 이 전략은 데이터 중복 및 비효율적인 리소스 사용을 유발합니다. 회사는 애플리케이션에 코드를 변경하지 않고 애플리케이션을 AWS로 마이그레이션해야 합니다.
이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 두 애플리케이션을 모두 AWS Lambda로 마이그레이션합니다. 애플리케이션 간에 데이터를 교환할 Amazon S3 버킷을 생성합니다.
- [ ] B. 두 애플리케이션을 모두 Amazon Elastic Container Service(Amazon ECS)로 마이그레이션합니다. 스토리지용 Amazon FSx 파일 게이트웨이를 구성합니다.
- [ ] C. 시뮬레이션 애플리케이션을 Linux Amazon EC2 인스턴스로 마이그레이션합니다. 시각화 애플리케이션을 Windows EC2 인스턴스로 마이그레이션합니다. 애플리케이션 간에 데이터를 교환하도록 Amazon Simple Queue Service(Amazon SQS)를 구성합니다.
- [ ] D. 시뮬레이션 애플리케이션을 Linux Amazon EC2 인스턴스로 마이그레이션합니다. 시각화 애플리케이션을 Windows EC2 인스턴스로 마이그레이션합니다. 스토리지용 NetApp ONTAP용 Amazon FSx를 구성합니다.

## Answer

정답: D

## Explanation

FSx for NetApp ONTAP은 NFS와 SMB를 동시에 지원하는 다중 프로토콜 파일 시스템이므로, Linux EC2의 시뮬레이션 애플리케이션이 NFS로 데이터를 출력하고 Windows EC2의 시각화 애플리케이션이 SMB로 동일한 데이터에 접근할 수 있습니다. 이를 통해 두 개의 동기화된 파일 시스템을 하나의 파일 시스템으로 통합하여 데이터 중복을 제거하고 리소스 사용을 효율화합니다. 코드 변경 없이 프로토콜 호환성만으로 마이그레이션이 가능합니다.

오답 분석

A: Lambda는 최대 실행 시간이 15분으로 제한되어 5분마다 중간 데이터를 출력하는 장시간 실행 시뮬레이션에 적합하지 않습니다. 또한 S3는 파일 시스템이 아니므로 기존 NFS/SMB 기반 애플리케이션의 코드 변경이 필요합니다.

B: ECS 컨테이너화는 애플리케이션 패키징 변경이 필요하여 '코드 변경 없이'라는 요구사항에 위배됩니다. FSx 파일 게이트웨이는 온프레미스 환경을 위한 것이며, AWS 내 EC2 인스턴스 간 파일 공유에는 FSx를 직접 사용하는 것이 적합합니다.

C: Amazon SQS는 메시지 큐 서비스로, 파일 기반 데이터를 공유하는 파일 시스템이 아닙니다. 시뮬레이션 출력 파일을 시각화 애플리케이션과 공유하려면 공유 파일 시스템이 필요하며, SQS는 이 목적에 부적합합니다.
