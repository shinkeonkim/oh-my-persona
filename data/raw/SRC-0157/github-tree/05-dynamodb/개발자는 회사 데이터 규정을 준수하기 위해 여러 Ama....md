## Question

개발자는 회사 데이터 규정을 준수하기 위해 여러 Amazon DynamoDB 테이블의 내용을 Amazon S3 버킷으로 내보내야 합니다. 개발자는 AWS CLI를 사용하여 각 테이블에서 적절한 S3 버킷으로 내보내는 명령을 실행합니다. 개발자는 AWS 자격 증명을 올바르게 설정하고 리소스에 적절한 권한을 부여합니다. 그러나 일부 테이블의 내보내기가 실패합니다.
개발자는 이 문제를 해결하기 위해 무엇을 해야 합니까?

- [ ] A. DynamoDB 테이블에서 특정 시점 복구가 활성화되어 있는지 확인합니다.
- [ ] B. 대상 S3 버킷이 DynamoDB 테이블과 동일한 AWS 리전에 있는지 확인합니다.
- [ ] C. 테이블에 DynamoDB 스트리밍이 활성화되어 있는지 확인합니다.
- [ ] D. DynamoDB Accelerator(DAX)가 활성화되어 있는지 확인합니다.

## Answer

정답: A

## Explanation

DynamoDB에서 Amazon S3로 데이터를 내보내기(Export to S3) 위해서는 해당 테이블에 시점 복구(Point-in-Time Recovery, PITR)가 반드시 활성화되어 있어야 합니다. 내보내기 기능은 PITR의 연속 백업 데이터를 기반으로 작동하기 때문에, PITR이 비활성화된 테이블에서는 내보내기가 실패합니다. 일부 테이블만 실패하는 이유는 해당 테이블에 PITR이 활성화되지 않았기 때문입니다.

오답 분석

B: DynamoDB S3 내보내기는 테이블과 대상 S3 버킷이 서로 다른 AWS 리전에 있어도 정상적으로 작동합니다. 크로스 리전 내보내기가 지원되므로 리전 불일치가 실패 원인이 아닙니다.

C: DynamoDB Streams는 테이블 데이터 변경 이벤트를 캡처하는 기능으로, S3 내보내기 기능과는 완전히 별개의 기능입니다. Streams 활성화 여부는 내보내기 성공에 영향을 주지 않습니다.

D: DynamoDB Accelerator(DAX)는 읽기 성능을 향상시키는 인메모리 캐싱 서비스이며, S3 내보내기 기능과는 관련이 없습니다.
