## Question

전자상거래 회사가 단일 AWS 리전에서 Amazon DynamoDB 테이블을 사용하는 애플리케이션을 실행합니다. 이 회사는 애플리케이션을 두 번째 리전에 배포하려고 합니다. 이 회사는 두 리전에서 기존 DynamoDB 테이블에 대한 낮은 지연 시간 읽기 및 쓰기를 통해 다중 활성 복제를 지원해야 합니다. 가장 운영 효율적인 방식으로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 기존 테이블에 대한 DynamoDB 글로벌 보조 인덱스(GSI)를 만듭니다. 두 번째 리전에 새 테이블을 만듭니다. 기존 DynamoDB 테이블을 글로벌 테이블로 변환합니다. 새 테이블을 보조 테이블로 지정합니다.
- [ ] B. 기존 테이블에 대해 Amazon DynamoDB Streams를 활성화합니다. 두 번째 리전에 새 테이블을 만듭니다. DynamoDB Streams Kinesis Adapter와 Amazon Kinesis Client Library(KCL)를 사용하는 새 애플리케이션을 만듭니다. 새 애플리케이션을 구성하여 첫 번째 리전의 DynamoDB 테이블에서 데이터를 읽고 두 번째 리전의 새 테이블에 데이터를 씁니다.
- [ ] C. 기존 DynamoDB 테이블을 글로벌 테이블로 변환합니다. 두 리전에서 모두 활성-활성 쓰기 기능을 구현하려면 적절한 두 번째 리전을 선택합니다.
- [ ] D. 기존 테이블에 Amazon DynamoDB Streams를 활성화합니다. 두 번째 리전에 새 테이블을 만듭니다. 첫 번째 리전에서 첫 번째 리전의 테이블에서 데이터를 읽고 두 번째 리전의 새 테이블에 데이터를 쓰는 AWS Lambda 함수를 만듭니다. DynamoDB 스트림을 Lambda 함수의 입력 트리거로 설정합니다.

## Answer

정답: C

## Explanation

기존 DynamoDB 테이블을 글로벌 테이블로 변환하면 두 리전에서 활성-활성(Active-Active) 읽기와 쓰기가 자동으로 지원됩니다. 글로벌 테이블은 리전 간 데이터 복제를 자동으로 처리하며, 일반적으로 1초 이내의 복제 지연으로 낮은 지연 시간을 제공합니다. 별도의 복제 로직이나 추가 인프라가 필요 없어 가장 운영 효율적입니다.

오답 분석

A: 글로벌 보조 인덱스(GSI)는 테이블 내 쿼리 패턴을 지원하는 기능으로 리전 간 복제와는 관련이 없습니다. 글로벌 테이블을 만들기 위해 GSI를 생성할 필요가 없으며, 보조 테이블 지정이라는 개념도 올바르지 않습니다.

B: DynamoDB Streams + Kinesis Adapter + KCL을 사용하여 수동으로 리전 간 복제를 구현하면 애플리케이션 코드 작성과 관리가 필요하여 글로벌 테이블보다 운영 오버헤드가 훨씬 큽니다.

D: DynamoDB Streams + Lambda로 수동 복제하는 것도 Lambda 함수 작성, 오류 처리, 모니터링 등의 운영 부담이 크며, 글로벌 테이블의 자동 충돌 해결 기능을 제공하지 않습니다.
