## Question

한 회사가 최대 48시간 동안 세션 데이터(최대 256KB)를 저장하는 모바일 게임 앱을 운영하고 있습니다. 데이터는 자주 업데이트되며 만료 후 자동으로 삭제되어야 합니다. 또한 복원성이 필요합니다.

- [ ] A. Amazon DynamoDB 테이블을 사용하여 세션 데이터를 저장합니다. 특정 시점 복구(PITR) 및 TTL을 활성화합니다.
- [ ] B. Amazon MemoryDB를 사용하고 PITR 및 TTL을 활성화합니다.
- [ ] C. S3 Standard에 세션 데이터를 저장합니다. 버전 관리 및 수명 주기 규칙을 사용하여 48시간 후 객체가 만료되도록 합니다.
- [ ] D. 버전 관리 및 48시간 후 만료되는 수명 주기 규칙을 사용하여 S3 Intelligent-Tiering에 데이터를 저장합니다.

## Answer

정답: A

## Explanation

Amazon DynamoDB는 최대 400KB 항목을 지원하므로 256KB 세션 데이터에 적합하며, TTL(Time to Live) 기능으로 48시간 후 자동 삭제가 가능합니다. PITR(시점 복구)을 활성화하면 최대 35일 전 시점으로 테이블을 복원할 수 있어 복원성 요구를 충족합니다. 서버리스이며 한 자릿수 밀리초 응답 시간으로 빈번한 업데이트에 최적화되어 있습니다.

오답 분석

B: Amazon MemoryDB는 Redis 호환 인메모리 데이터베이스로 세션 데이터에 사용 가능하지만, DynamoDB보다 비용이 상당히 높고 256KB 세션 데이터 저장에는 과도한 솔루션입니다. 인메모리 특성상 비용 대비 효율이 낮습니다.

C: Amazon S3는 객체 스토리지로 빈번한 업데이트(하루에 여러 번 수정)에 적합하지 않습니다. S3 수명 주기 규칙의 최소 전환/만료 단위가 1일이므로 정확한 48시간 만료를 구현하기 어렵습니다.

D: S3 Intelligent-Tiering은 접근 빈도에 따라 스토리지 클래스를 자동 전환하는 기능으로, 빈번하게 업데이트되는 세션 데이터에는 부적합하며 정밀한 만료 제어가 어렵습니다.
