## Question

전자상거래 회사가 VPC에 3티어 웹 애플리케이션을 호스팅합니다. 웹 티어는 두 개의 가용 영역에 있는 Amazon EC2 인스턴스에서 실행됩니다. 이 회사는 제품 카탈로그와 고객 판매 정보를 Amazon DynamoDB에 저장합니다. 회사의 재무팀은 보고 애플리케이션을 사용하여 일일 제품 판매 보고서를 생성합니다. 재무팀이 일일 보고서를 실행할 때 갑작스러운 성능 저하가 웹사이트 고객에게 영향을 미칩니다. 회사는 시스템 성능을 개선하고자 합니다.
현재 아키텍처를 최소한으로 변경하면서 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 애플리케이션을 더 큰 EC2 인스턴스로 마이그레이션합니다. 데이터베이스를 Amazon RDS for MySQL로 마이그레이션합니다. 두 번째 가용 영역에 데이터베이스의 읽기 복제본을 구성합니다.
- [ ] B. EC2 인스턴스의 컴퓨팅 용량을 늘립니다. 데이터베이스를 Amazon ElastiCache(Memcached)로 마이그레이션합니다.
- [ ] C. DynamoDB Accelerator(DAX)를 구현합니다.
- [ ] D. DynamoDB Streams를 구성합니다.

## Answer

정답: C

## Explanation

DynamoDB Accelerator(DAX)는 DynamoDB 앞에 위치하는 완전 관리형 인메모리 캐시로, 읽기 응답 시간을 밀리초에서 마이크로초로 단축합니다. 재무팀의 보고서 실행으로 인한 대량 읽기 요청을 DAX가 캐시에서 처리하므로 DynamoDB 테이블의 읽기 부하가 크게 줄어들어 웹사이트 고객 경험에 영향을 주지 않습니다. 기존 아키텍처 변경이 최소화됩니다.

오답 분석

A: EC2를 더 큰 인스턴스로 마이그레이션하고 DynamoDB를 RDS for MySQL로 전환하는 것은 대규모 아키텍처 변경이 필요하며, 데이터베이스 마이그레이션 비용과 위험이 큽니다.

B: DynamoDB를 ElastiCache(Memcached)로 완전 대체하는 것은 전체 데이터베이스를 마이그레이션하는 것이며, Memcached는 영구 스토리지가 아니므로 데이터 내구성이 보장되지 않습니다.

D: DynamoDB Streams는 테이블 데이터 변경 사항을 실시간으로 캡처하는 변경 데이터 캡처(CDC) 서비스이며, 읽기 성능을 개선하는 기능이 아닙니다.
