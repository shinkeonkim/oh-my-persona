## Question

한 회사에서 Amazon DynamoDB를 데이터베이스 계층으로 사용하는 서버리스 애플리케이션을 배포했습니다. 애플리케이션의 사용자가 크게 증가했습니다. 이 회사는 데이터베이스 응답 시간을 밀리초에서 마이크로초로 개선하고 데이터베이스에 대한 요청을 캐시하기를 원합니다.
최소한의 운영 오버헤드로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. DynamoDB Accelerator(DAX)를 사용합니다.
- [ ] B. 데이터베이스를 Amazon Redshift로 마이그레이션합니다.
- [ ] C. 데이터베이스를 Amazon RDS로 마이그레이션합니다.
- [ ] D. Redis용 Amazon ElastiCache를 사용합니다.

## Answer

정답: A

## Explanation

DynamoDB Accelerator(DAX)는 DynamoDB 전용 완전관리형 인메모리 캐시 서비스로, 읽기 응답 시간을 밀리초에서 마이크로초(일반적으로 수백 마이크로초) 수준으로 개선합니다. DAX 클러스터는 완전관리형으로 노드 관리, 패치, 장애 복구가 자동화되어 운영 오버헤드가 최소화됩니다. DynamoDB API와 완전히 호환되므로 기존 애플리케이션 코드에서 엔드포인트만 변경하면 즉시 캐싱 효과를 얻을 수 있습니다.

오답 분석

B: Amazon Redshift는 페타바이트 규모의 데이터 웨어하우스로 OLAP(온라인 분석 처리) 워크로드에 최적화되어 있습니다. DynamoDB의 OLTP(온라인 트랜잭션 처리) 워크로드를 Redshift로 마이그레이션하면 아키텍처가 완전히 변경되며, 마이크로초 수준의 캐싱 성능을 제공하지 않습니다.

C: Amazon RDS로의 마이그레이션은 NoSQL에서 관계형 DB로의 전환을 의미하며, 서버리스 애플리케이션의 스키마와 쿼리 패턴을 완전히 재설계해야 합니다. 또한 마이크로초 수준의 응답 시간이나 요청 캐싱 기능을 기본 제공하지 않습니다.

D: ElastiCache for Redis는 강력한 범용 캐시이지만, DynamoDB와 통합하려면 캐시 관리 로직(캐시 적중/미스 처리, 캐시 무효화, 데이터 직렬화)을 직접 구현해야 합니다. DAX는 이러한 로직이 내장되어 있어 운영 오버헤드가 훨씬 적습니다.
