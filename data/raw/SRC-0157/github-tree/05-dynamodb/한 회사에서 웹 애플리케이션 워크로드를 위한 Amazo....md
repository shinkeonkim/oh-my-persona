## Question

한 회사에서 웹 애플리케이션 워크로드를 위한 Amazon DynamoDB Accelerator(DAX) 클러스터가 저장 데이터를 암호화하지 않는다는 사실을 발견했습니다. 회사는 이 보안 문제를 해결해야 합니다. 
이 요구 사항을 충족하는 해결책은 무엇입니까?

- [ ] A. 기존 DAX 클러스터를 중지합니다. 기존 DAX 클러스터에 저장 데이터 암호화를 활성화한 후 클러스터를 다시 시작합니다.
- [ ] B. 기존 DAX 클러스터를 삭제합니다. DAX 클러스터를 다시 생성하고 저장 데이터를 암호화하도록 새 클러스터를 구성합니다.
- [ ] C. 저장 데이터를 암호화하도록 기존 DAX 클러스터의 구성을 업데이트합니다.
- [ ] D. 기존 DAX 클러스터를 AWS Security Hub와 통합하여 저장 데이터 암호화를 자동으로 활성화합니다.

## Answer

정답: B

## Explanation

DAX 클러스터의 저장 데이터 암호화(Encryption at Rest)는 클러스터 생성 시에만 설정할 수 있으며, 생성 후에는 변경할 수 없습니다. 따라서 기존 비암호화 클러스터를 삭제하고 저장 데이터 암호화가 활성화된 새 DAX 클러스터를 생성해야 합니다. 새 클러스터는 동일한 노드 유형, 서브넷 그룹, 파라미터 그룹으로 구성할 수 있습니다.

오답 분석

A: DAX 클러스터는 EC2 인스턴스처럼 중지/시작(Stop/Start) 기능을 지원하지 않습니다. 또한 실행 중인 클러스터에서 저장 데이터 암호화 설정을 변경하는 것은 불가능합니다.

C: 기존 DAX 클러스터의 암호화 구성을 런타임에 업데이트할 수 없습니다. 암호화 설정은 클러스터 생성 시에만 가능한 불변(immutable) 속성입니다.

D: AWS Security Hub는 보안 모범 사례 위반을 탐지하고 알림하는 서비스이며, DAX 클러스터의 저장 데이터 암호화를 자동으로 활성화하는 자동 수정(remediation) 기능은 제공하지 않습니다.
