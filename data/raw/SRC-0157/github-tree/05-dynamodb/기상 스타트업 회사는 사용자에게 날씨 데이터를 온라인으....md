## Question

기상 스타트업 회사는 사용자에게 날씨 데이터를 온라인으로 판매하는 맞춤형 웹 애플리케이션을 보유하고 있습니다. 이 회사는 Amazon DynamoDB를 사용하여 데이터를 저장하고 새로운 날씨 이벤트가 기록될 때마다 4개의 내부 팀 관리자에게 경고를 보내는 새로운 서비스를 구축하려고 합니다. 회사는 이 새로운 서비스가 현재 애플리케이션의 성능에 영향을 미치는 것을 원하지 않습니다.
최소한의 운영 오버헤드로 이러한 요구 사항을 충족하려면 솔루션 설계자가 무엇을 해야 합니까?

- [ ] A. DynamoDB 트랜잭션을 사용하여 새 이벤트 데이터를 테이블에 씁니다. 내부 팀에 알리도록 트랜잭션을 구성합니다.
- [ ] B. 현재 애플리케이션이 4개의 Amazon Simple Notification Service(Amazon SNS) 주제에 메시지를 게시하도록 합니다. 각 팀이 하나의 주제를 구독하도록 합니다.
- [ ] C. 테이블에서 Amazon DynamoDB 스트림을 활성화합니다. 트리거를 사용하여 팀이 구독할 수 있는 단일 Amazon Simple Notification Service(Amazon SNS) 주제에 씁니다.
- [ ] D. 각 레코드에 사용자 정의 속성을 추가하여 새 항목에 플래그를 지정합니다. 새 항목이 있는지 매분 테이블을 스캔하고 팀이 구독할 수 있는 Amazon Simple Queue Service(Amazon SQS) 대기열에 알리는 cron 작업을 작성합니다.

## Answer

정답: C

## Explanation

Amazon DynamoDB Streams를 활성화하면 테이블의 항목 수준 변경사항(INSERT, MODIFY, DELETE)이 실시간으로 캡처됩니다. 이 스트림에 AWS Lambda 트리거를 연결하여 새 날씨 이벤트가 기록될 때 자동으로 단일 SNS 주제에 알림을 게시하면, 4개 내부 팀이 모두 해당 주제를 구독하여 동시에 알림을 받을 수 있습니다. DynamoDB Streams는 기본 테이블의 읽기/쓰기 용량과 별도로 동작하므로 현재 애플리케이션 성능에 영향을 미치지 않습니다.

오답 분석

A: DynamoDB 트랜잭션은 여러 항목 또는 테이블에 걸친 원자적(ACID) 읽기/쓰기 작업을 보장하기 위한 기능입니다. 트랜잭션 자체에는 알림 전송 기능이 없으며, 이 목적으로 사용할 수 없습니다.

B: 현재 애플리케이션이 직접 SNS 주제에 메시지를 게시하도록 수정하면, 애플리케이션의 쓰기 경로에 SNS 호출이 추가되어 지연 시간이 증가하고 성능에 영향을 미칩니다. 또한 4개의 별도 SNS 주제를 관리하는 것은 불필요한 복잡성입니다. DynamoDB Streams를 사용하면 비동기적으로 처리되어 성능 영향이 없습니다.

D: 매분 테이블을 스캔하는 cron 작업은 전체 테이블 스캔이 필요하여 대량의 읽기 용량을 소비하고 비용이 증가합니다. 또한 실시간 알림이 아닌 최대 1분 지연이 있으며, SQS는 팀에 이메일이나 SMS 알림을 직접 보내는 데 적합하지 않습니다(SNS가 더 적합합니다).
