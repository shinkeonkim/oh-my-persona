## Question

게임 회사는 Amazon DynamoDB를 사용하여 지리적 위치, 플레이어 데이터 및 순위표와 같은 사용자 정보를 저장합니다. 회사는 최소한의 코딩으로 Amazon S3 버킷에 지속적인 백업을 구성해야 합니다. 백업은 애플리케이션의 가용성에 영향을 미치지 않아야 하며 테이블에 대해 정의된 읽기 용량 단위(RCU)에 영향을 주지 않아야 합니다.
어떤 솔루션이 이러한 요구 사항을 충족합니까?

- [ ] A. Amazon EMR 클러스터를 사용합니다. Apache Hive 작업을 생성하여 Amazon S3에 데이터를 백업합니다.
- [ ] B. 연속 백업을 통해 DynamoDB에서 Amazon S3로 직접 데이터를 내보냅니다. 테이블에 대해 특정 시점 복구를 설정합니다.
- [ ] C. Amazon DynamoDB 스트림을 구성합니다. 스트림을 사용하고 데이터를 Amazon S3 버킷으로 내보내는 AWS Lambda 함수를 생성합니다.
- [ ] D. 정기적으로 데이터베이스 테이블에서 Amazon S3로 데이터를 내보내는 AWS Lambda 함수를 생성합니다. 테이블에 대해 특정 시점 복구를 설정합니다.

## Answer

정답: B

## Explanation

DynamoDB는 S3로의 직접 테이블 내보내기(Export to S3) 기능과 PITR(Point-in-Time Recovery, 특정 시점 복구)을 기본 지원합니다. PITR을 활성화하면 테이블에 대한 연속적인 백업이 자동으로 수행되며, 이 과정은 테이블의 프로비저닝된 RCU를 소비하지 않습니다. S3로의 테이블 내보내기도 테이블의 읽기 용량에 영향을 주지 않는 별도의 경로를 사용합니다. 최소한의 코딩으로 AWS 콘솔이나 CLI에서 간단히 설정할 수 있어 운영 오버헤드가 최소화됩니다.

오답 분석

A: Amazon EMR 클러스터에서 Apache Hive 작업을 실행하여 DynamoDB 데이터를 S3로 백업하려면 EMR 클러스터 관리, Hive 스크립트 작성 등 상당한 코딩과 인프라 관리가 필요합니다. 또한 EMR 클러스터 운영 비용이 추가로 발생합니다.

C: DynamoDB Streams + Lambda를 사용하면 변경 데이터를 실시간으로 캡처하여 S3로 내보낼 수 있지만, Lambda 함수를 작성하고 관리해야 하므로 '최소한의 코딩' 요구사항에 부합하지 않습니다. Streams 처리 자체는 RCU에 영향을 주지 않지만 구현 복잡도가 높습니다.

D: Lambda 함수로 정기적으로 테이블을 스캔하여 S3로 내보내면 전체 테이블 스캔이 필요하여 대량의 RCU를 소비합니다. 이는 '테이블에 대해 정의된 RCU에 영향을 주지 않아야' 하는 요구사항에 위배됩니다. 또한 연속 백업이 아닌 주기적 백업입니다.
