## Question

회사는 회사 AWS 계정의 Amazon DynamoDB 테이블에 중요한 데이터를 저장합니다. IT 관리자가 실수로 DynamoDB 테이블을 삭제했습니다. 삭제로 인해 상당한 데이터 손실이 발생하고 회사 운영이 중단되었습니다. 회사는 앞으로 이러한 유형의 중단을 방지하기를 원합니다.
최소한의 운영 오버헤드로 이 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. AWS CloudTrail에서 추적을 구성합니다. 삭제 작업에 대한 Amazon EventBridge 규칙을 생성합니다. 삭제된 DynamoDB 테이블을 자동으로 복원하는 AWS Lambda 함수를 생성합니다.
- [ ] B. DynamoDB 테이블에 대한 백업 및 복원 계획을 생성합니다. DynamoDB 테이블을 수동으로 복구합니다.
- [ ] C. DynamoDB 테이블에 대한 삭제 방지를 구성합니다.
- [ ] D. DynamoDB 테이블에서 특정 시점 복구를 활성화합니다.

## Answer

정답: C

## Explanation

DynamoDB 삭제 방지(Deletion Protection) 기능은 테이블에 대한 실수로의 삭제를 사전에 차단하는 가장 직접적이고 효과적인 방법입니다. 이 기능을 활성화하면 DeleteTable API 호출이 거부되므로, IT 관리자가 실수로 삭제를 시도해도 테이블이 보호됩니다. 삭제 방지를 해제하려면 명시적으로 비활성화해야 하므로, 의도적인 삭제와 실수를 구분할 수 있습니다. 추가 비용이나 운영 오버헤드 없이 즉시 적용 가능합니다.

오답 분석

A: CloudTrail + EventBridge + Lambda를 조합하여 삭제된 테이블을 자동 복원하는 방식은 구현이 복잡하고, 삭제를 '방지'하는 것이 아니라 삭제 후 '복구'하는 사후 대응입니다. 삭제와 복원 사이에 데이터 손실이 발생할 수 있으며, Lambda 함수의 오류 처리도 필요합니다.

B: 백업 및 복원 계획을 생성하고 수동으로 복구하는 것은 삭제를 방지하지 못하며, 복구 과정에서 다운타임과 데이터 손실이 발생합니다. 수동 복구는 운영 오버헤드가 높고, 복구 완료까지 서비스 중단이 지속됩니다.

D: PITR(특정 시점 복구)은 테이블 내 데이터의 특정 시점 복원에 유용하지만, 테이블 자체가 삭제되면 PITR 설정도 함께 사라집니다. PITR은 데이터 손상 복구에는 적합하지만 테이블 삭제 방지 기능은 제공하지 않습니다.
