## Question

회사에는 Amazon EC2 인스턴스에서 실행되는 비즈니스에 중요한 애플리케이션이 있습니다. 애플리케이션은 Amazon DynamoDB 테이블에 데이터를 저장합니다. 회사는 지난 24시간 내의 어느 시점으로든 테이블을 되돌릴 수 있어야 합니다.
최소한의 운영 오버헤드로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 테이블에 대한 특정 시점 복구를 구성합니다.
- [ ] B. 테이블에 AWS Backup을 사용합니다.
- [ ] C. AWS Lambda 함수를 사용하여 매시간 테이블의 주문형 백업을 만듭니다.
- [ ] D. 테이블에서 스트림을 켜서 지난 24시간 동안 테이블에 대한 모든 변경 사항에 대한 로그를 캡처합니다. Amazon S3 버킷에 스트림 복사본을 저장합니다.

## Answer

정답: A

## Explanation

DynamoDB의 Point-in-Time Recovery(PITR)를 활성화하면 최근 35일 이내의 어느 시점으로든 테이블을 복원할 수 있으며, 이는 24시간 이내 복원 요구사항을 충분히 충족합니다. PITR은 테이블 설정에서 토글하기만 하면 연속 백업이 자동으로 수행되므로 운영 오버헤드가 거의 없습니다. 초 단위 정밀도로 복원 시점을 지정할 수 있습니다.

오답 분석

B: AWS Backup으로 DynamoDB 테이블을 백업하는 것은 가능하지만, 백업 스케줄 설정과 관리가 필요하여 PITR의 자동 연속 백업보다 운영 오버헤드가 큽니다.

C: Lambda로 매시간 온디맨드 백업을 생성하면 Lambda 함수 개발, 스케줄 관리, 오류 처리 등 커스텀 솔루션의 운영 부담이 발생합니다. 또한 백업 간격 사이의 데이터 손실 가능성이 있습니다.

D: DynamoDB Streams로 변경 사항을 로깅하고 S3에 저장하는 것은 복잡한 커스텀 복원 메커니즘을 구축해야 하며, 스트림 데이터를 원본 테이블로 재적용하는 로직 개발이 필요하여 운영 오버헤드가 가장 큽니다.
