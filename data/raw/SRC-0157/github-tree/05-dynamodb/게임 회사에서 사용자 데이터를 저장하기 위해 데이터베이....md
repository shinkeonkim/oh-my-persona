## Question

게임 회사에서 사용자 데이터를 저장하기 위해 데이터베이스를 사용하는 애플리케이션을 구축하고 있습니다. 이 회사는 보조 AWS 리전에 데이터를 쓸 수 있는 활성-활성 구성을 데이터베이스에 적용하고자 합니다. 데이터베이스는 1초 미만의 복구 지점 목표 (RPO)를 달성해야 합니다. 솔루션 아키텍트는 이러한 요구 사항을 충족하기 위해 무엇을 해야 합니까?

- [ ] A. Amazon ElastiCache(Redis OSS) 클러스터를 배포합니다. 재해 복구를 위한 글로벌 데이터 저장소를 구성합니다. 기본 리전에 배포된 Amazon RDS 데이터베이스의 데이터를 캐시하도록 ElastiCache 클러스터를 구성합니다.
- [ ] B. 기본 리전과 보조 리전에 Amazon DynamoDB 테이블을 배포합니다. Amazon DynamoDB Streams를 구성하여 AWS Lambda 함수를 호출하여 기본 리전의 테이블에서 보조 리전의 테이블에 변경 사항을 씁니다.
- [ ] C. 기본 리전에 Amazon Aurora MySQL 데이터베이스를 배포합니다. 보조 리전에 글로벌 데이터베이스를 구성합니다.
- [ ] D. 기본 리전에 Amazon DynamoDB 테이블을 배포합니다. 보조 리전에 글로벌 테이블을 구성합니다.

## Answer

정답: D

## Explanation

DynamoDB 글로벌 테이블은 여러 AWS 리전에서 활성-활성(Active-Active) 읽기/쓰기를 지원하며, 리전 간 복제 지연이 일반적으로 1초 미만이므로 RPO(복구 지점 목표) 1초 미만을 달성합니다. 보조 리전에서도 직접 쓰기가 가능하여 게임 사용자 데이터의 다중 리전 접근 요구를 완전히 충족합니다.

오답 분석

A: ElastiCache(Redis OSS) 글로벌 데이터 저장소는 캐시 레이어로 주 데이터베이스가 아니며, RDS 데이터베이스의 활성-활성 다중 리전 쓰기를 지원하지 않습니다.

B: DynamoDB Streams + Lambda로 수동 리전 간 복제를 구현하면 Lambda 실행 지연과 오류 처리 등으로 인해 1초 미만의 RPO를 안정적으로 보장하기 어렵습니다. 또한 단방향 복제이므로 활성-활성이 아닙니다.

C: Amazon Aurora 글로벌 데이터베이스는 보조 리전에서 읽기만 가능하고 쓰기는 기본 리전에서만 수행되므로, 활성-활성 구성이 아닙니다. 보조 리전에 데이터를 쓸 수 있는 요구사항을 충족하지 못합니다.
