## Question

전자 상거래 회사는 Amazon RDS 기반 웹 애플리케이션의 성능 저하를 발견했습니다. 성능 저하의 원인은 비즈니스 분석가가 트리거하는 읽기 전용 SQL 쿼리 수가 증가했기 때문입니다.
솔루션 설계자는 기존 웹 애플리케이션에 대한 최소한의 변경으로 문제를 해결해야 합니다.
솔루션 설계자는 무엇을 추천해야 합니까?

- [ ] A. 데이터를 Amazon DynamoDB로 내보내고 비즈니스 분석가가 쿼리를 실행하도록 합니다.
- [ ] B. Amazon ElastiCache에 데이터를 로드하고 비즈니스 분석가가 쿼리를 실행하도록 합니다.
- [ ] C. 기본 데이터베이스의 읽기 복제본을 생성하고 비즈니스 분석가가 쿼리를 실행하도록 합니다.
- [ ] D. 데이터를 Amazon Redshift 클러스터로 복사하고 비즈니스 분석가가 쿼리를 실행하도록 합니다.

## Answer

정답: C

## Explanation

기본 데이터베이스의 읽기 복제본을 생성하여 비즈니스 분석가의 읽기 전용 SQL 쿼리를 복제본에서 실행하도록 하면, 기존 웹 애플리케이션에 대한 최소한의 변경으로 성능 저하 문제를 해결할 수 있습니다. 읽기 복제본은 기본 RDS 인스턴스와 동일한 SQL 인터페이스를 제공하므로, 분석가들이 기존 쿼리를 그대로 사용할 수 있습니다.

오답 분석

A: Amazon DynamoDB는 NoSQL 데이터베이스로, 기존 SQL 쿼리를 그대로 사용할 수 없으며 데이터 마이그레이션과 쿼리 재작성이 필요합니다.

B: Amazon ElastiCache에 전체 데이터를 로드하는 것은 적절하지 않습니다. ElastiCache는 인메모리 캐시로, 복잡한 SQL 보고 쿼리를 실행하는 데 적합하지 않습니다.

D: Amazon Redshift 클러스터로 데이터를 복사하면 분석 쿼리에는 효과적이지만, 데이터 동기화 프로세스를 설정해야 하고 기존 웹 애플리케이션에 대한 변경이 더 필요합니다.
