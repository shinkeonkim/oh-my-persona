## Question

회사는 애플리케이션과 함께 Amazon Aurora PostgreSQL 프로비저닝 클러스터를 사용합니다. 애플리케이션의 최대 트래픽은 30분에서 몇 시간 동안 하루에 여러 번 발생합니다. 애플리케이션의 최대 트래픽을 처리하기 위해 데이터베이스 용량이 프로비저닝되었지만 피크가 아닌 시간 동안 데이터베이스에서 용량이 낭비되었습니다. 회사는 데이터베이스 비용을 절감하려고 합니다.
최소한의 운영 노력으로 이러한 요구 사항을 충족할 수 있는 솔루션은 무엇입니까?

- [ ] A. Amazon CloudWatch 경보를 설정하여 데이터베이스 활용도를 모니터링합니다. 트래픽 양에 따라 데이터베이스 용량을 확장하거나 축소합니다.
- [ ] B. 데이터베이스를 Auto Scaling 그룹의 Amazon EC2 인스턴스로 마이그레이션합니다. 트래픽 양에 따라 인스턴스 수를 늘리거나 줄입니다.
- [ ] C. 데이터베이스를 Amazon Aurora Serverless DB 클러스터로 마이그레이션하여 트래픽 양에 따라 용량을 확장하거나 축소합니다.
- [ ] D. 매일 시작 시 필요한 데이터베이스 용량을 프로비저닝하도록 AWS Lambda 함수를 예약합니다. 하루가 끝날 때 용량을 줄이기 위해 다른 Lambda 함수를 예약합니다.

## Answer

정답: C

## Explanation

Amazon Aurora Serverless DB 클러스터로 마이그레이션하면 트래픽 양에 따라 자동으로 용량을 확장하고 축소할 수 있습니다. 하루에 여러 번 30분에서 몇 시간 동안 발생하는 피크 트래픽과 비피크 시간 동안의 낮은 트래픽 패턴에 Aurora Serverless가 자동으로 대응하여, 비피크 시간에 낭비되는 용량을 줄이고 비용을 절감할 수 있습니다. 운영 노력도 최소화됩니다.

오답 분석

A: Amazon CloudWatch 경보로 데이터베이스 활용도를 모니터링하고 수동으로 용량을 조정하는 것은 운영 노력이 많이 필요합니다. 하루에 여러 번 발생하는 트래픽 변동에 수동으로 대응하는 것은 비효율적입니다.

B: EC2 Auto Scaling 그룹은 데이터베이스에 적합하지 않습니다. 데이터베이스는 상태를 유지해야 하므로 일반적인 EC2 Auto Scaling으로는 관리할 수 없으며, 데이터 일관성 문제가 발생합니다.

D: Lambda 함수로 하루 시작과 끝에 용량을 프로비저닝하고 줄이는 것은 하루 중 여러 번 발생하는 불규칙한 피크 트래픽에 대응하지 못합니다. 또한 Lambda 함수의 개발과 유지 관리가 필요하여 운영 노력이 증가합니다.
