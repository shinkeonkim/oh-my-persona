## Question

전자상거래 애플리케이션은 Amazon EC2 인스턴스에서 실행되는 PostgreSQL 데이터베이스를 사용합니다. 월별 판매 이벤트 중에 데이터베이스 사용량이 증가하고 애플리케이션에 대한 데이터베이스 연결 문제가 발생합니다. 후속 월별 판매 이벤트에 대한 트래픽은 예측할 수 없으며 이는 판매 예측에 영향을 미칩니다. 회사는 예측할 수 없는 트래픽 증가가 있을 때 성능을 유지해야 합니다.
가장 비용 효과적인 방법으로 이 문제를 해결하는 솔루션은 무엇입니까?

- [ ] A. PostgreSQL 데이터베이스를 Amazon Aurora Serverless v2로 마이그레이션합니다.
- [ ] B. 증가된 사용량을 수용하기 위해 EC2 인스턴스의 PostgreSQL 데이터베이스에 대한 자동 크기 조정을 활성화합니다.
- [ ] C. 더 큰 인스턴스 유형을 사용하여 PostgreSQL 데이터베이스를 PostgreSQL용 Amazon RDS로 마이그레이션합니다.
- [ ] D. 증가된 사용량을 수용하기 위해 PostgreSQL 데이터베이스를 Amazon Redshift로 마이그레이션합니다.

## Answer

정답: A

## Explanation

Amazon Aurora Serverless v2는 예측 불가능한 트래픽 증가에 자동으로 대응할 수 있는 가장 비용 효율적인 솔루션입니다. Aurora Serverless v2는 0.5 ACU 단위로 세밀하게 자동 확장되며, 트래픽이 줄어들면 자동으로 축소되어 사용한 만큼만 비용을 지불합니다. PostgreSQL 호환이므로 기존 PostgreSQL 데이터베이스에서 마이그레이션이 용이하며, 연결 관리도 자동으로 처리됩니다.

오답 분석

B: EC2 인스턴스의 PostgreSQL 데이터베이스에 대한 자동 크기 조정은 EC2 인스턴스 수준에서 직접 지원되지 않습니다. 데이터베이스 계층에서 자동 확장을 구현하려면 복잡한 사용자 정의 구성이 필요합니다.

C: 더 큰 인스턴스 유형의 Amazon RDS for PostgreSQL로 마이그레이션하면 고정된 용량이므로 트래픽이 적을 때 비용이 낭비됩니다. 예측 불가능한 트래픽에 자동으로 대응할 수 없어 비용 효율적이지 않습니다.

D: Amazon Redshift는 데이터 웨어하우스 서비스로, OLTP(온라인 트랜잭션 처리) 워크로드인 전자상거래 애플리케이션에 적합하지 않습니다. 트랜잭션 처리보다는 대규모 분석 쿼리에 최적화되어 있습니다.
