## Question

한 회사가 Amazon Aurora 데이터베이스에 연결되는 Amazon EC2 인스턴스 그룹을 실행할 계획입니다. 이 회사는 EC2 인스턴스와 Aurora DB 클러스터를 배포하기 위해 AWS CloudFormation 템플릿을 구축했습니다. 회사는 인스턴스가 안전한 방식으로 데이터베이스에 인증되도록 허용하려고 합니다. 회사는 정적 데이터베이스 자격 증명을 유지하고 싶지 않습니다.
최소한의 운영 노력으로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 사용자 이름과 비밀번호를 사용하여 데이터베이스 사용자를 생성합니다. CloudFormation 템플릿에 데이터베이스 사용자 이름과 비밀번호에 대한 매개변수를 추가합니다. 인스턴스가 시작될 때 매개변수를 EC2 인스턴스에 전달합니다.
- [ ] B. 사용자 이름과 비밀번호를 사용하여 데이터베이스 사용자를 생성합니다. AWS Systems Manager Parameter Store에 사용자 이름과 암호를 저장합니다. Parameter Store에서 데이터베이스 자격 증명을 검색하도록 EC2 인스턴스를 구성합니다.
- [ ] C. IAM 데이터베이스 인증을 사용하도록 DB 클러스터를 구성합니다. IAM 인증에 사용할 데이터베이스 사용자를 생성합니다. 인스턴스의 애플리케이션이 데이터베이스에 액세스할 수 있도록 역할을 EC2 인스턴스와 연결합니다.
- [ ] D. IAM 사용자와 함께 IAM 데이터베이스 인증을 사용하도록 DB 클러스터를 구성합니다. IAM 사용자와 일치하는 이름을 가진 데이터베이스 사용자를 생성합니다. IAM 사용자를 EC2 인스턴스와 연결하여 인스턴스의 애플리케이션이 데이터베이스에 액세스할 수 있도록 합니다.

## Answer

정답: C

## Explanation

IAM 데이터베이스 인증을 사용하면 정적 자격 증명 없이 Aurora DB에 안전하게 인증할 수 있습니다. EC2 인스턴스에 IAM 역할을 연결하면 임시 보안 토큰을 통해 데이터베이스에 접속할 수 있어 비밀번호 관리가 불필요합니다. IAM 데이터베이스 인증은 AWS Signature Version 4를 사용하여 15분 수명의 인증 토큰을 생성하며, CloudFormation 템플릿에서도 역할 연결을 자동화할 수 있어 운영 부담이 최소화됩니다.

오답 분석

A: CloudFormation 매개변수로 사용자 이름과 비밀번호를 전달하면 템플릿에 정적 자격 증명이 포함되어 보안 위험이 있으며, '정적 자격 증명을 유지하고 싶지 않다'는 요구 사항에 위배됩니다.

B: AWS Systems Manager Parameter Store에 자격 증명을 저장하면 정적 사용자 이름과 비밀번호를 계속 유지 관리해야 하므로 요구 사항에 맞지 않으며, 자격 증명 교체도 별도로 관리해야 합니다.

D: IAM 사용자를 EC2 인스턴스에 연결하는 것은 올바른 방법이 아닙니다. EC2 인스턴스에는 IAM 역할(인스턴스 프로파일)을 사용해야 하며, IAM 사용자의 액세스 키를 사용하면 장기 자격 증명이 되어 보안 모범 사례에 어긋납니다.
