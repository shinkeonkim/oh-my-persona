## Question

한 회사가 최근 글로벌 전자 상거래 애플리케이션을 위한 데이터 저장소로 Amazon Aurora를 사용하기 시작했습니다. 대규모 보고서가 실행될 때 개발자는 전자 상거래 애플리케이션이 제대로 작동하지 않는다고 보고합니다. 솔루션 설계자는 Amazon CloudWatch에서 지표를 검토한 후 월별 보고서를 실행할 때 ReadIOPS 및 CPUUtilization 지표가 급증하고 있음을 발견했습니다.
가장 비용 효율적인 솔루션은 무엇입니까?

- [ ] A. 월별 보고를 Amazon Redshift로 마이그레이션합니다.
- [ ] B. 월간 보고를 Aurora 복제본으로 마이그레이션합니다.
- [ ] C. Aurora 데이터베이스를 더 큰 인스턴스 클래스로 마이그레이션합니다.
- [ ] D. Aurora 인스턴스에서 프로비저닝된 IOPS를 늘립니다.

## Answer

정답: B

## Explanation

Aurora 복제본(Replica)으로 월별 보고 워크로드를 오프로드하는 것이 가장 비용 효율적인 솔루션입니다. Aurora 복제본은 기본 인스턴스와 동일한 스토리지 볼륨을 공유하므로 추가 스토리지 비용이 없으며, 읽기 트래픽을 복제본으로 분리하면 기본 전자상거래 애플리케이션의 성능에 영향을 주지 않습니다. Aurora 복제본은 일반적으로 기본 인스턴스와 100ms 이내의 복제 지연만 발생합니다.

오답 분석

A: Amazon Redshift로 마이그레이션하면 데이터 파이프라인 구축, ETL 프로세스 설정 등 추가 비용과 복잡성이 발생하며, 단순 월별 보고를 위해서는 과도한 솔루션입니다.

C: 더 큰 인스턴스 클래스로 마이그레이션하면 보고와 OLTP 워크로드가 여전히 동일 인스턴스에서 경합하며, 항상 더 큰 인스턴스 비용을 지불해야 합니다.

D: Amazon Aurora는 RDS와 달리 별도의 스토리지 파라미터로 Provisioned IOPS를 구성하는 것을 지원하지 않습니다. Aurora는 스토리지 I/O 성능을 자동으로 관리하며 Provisioned IOPS 스토리지 타입을 제공하지 않습니다. 따라서 옵션 D는 Aurora에 적용할 수 없는 기능을 설명하고 있으며, IOPS 증가로는 보고 워크로드와 기본 인스턴스 간 CPU 경합 문제를 해결할 수 없습니다.
