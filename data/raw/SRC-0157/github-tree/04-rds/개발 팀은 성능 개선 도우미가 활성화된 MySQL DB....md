## Question

개발 팀은 성능 개선 도우미가 활성화된 MySQL DB 인스턴스용 범용 Amazon RDS에서 매월 리소스 집약적인 테스트를 실행합니다. 테스트는 한 달에 한 번 48시간 동안 진행되며 데이터베이스를 사용하는 유일한 프로세스입니다. 팀은 DB 인스턴스의 컴퓨팅 및 메모리 속성을 줄이지 않고 테스트 실행 비용을 줄이려고 합니다.
이러한 요구 사항을 가장 비용 효율적으로 충족하는 솔루션은 무엇입니까?

- [ ] A. 테스트가 완료되면 DB 인스턴스를 중지합니다. 필요한 경우 DB 인스턴스를 다시 시작합니다.
- [ ] B. DB 인스턴스와 함께 Auto Scaling 정책을 사용하여 테스트가 완료되면 자동으로 조정합니다.
- [ ] C. 테스트가 완료되면 스냅샷을 생성합니다. 필요한 경우 DB 인스턴스를 종료하고 스냅샷을 복원합니다.
- [ ] D. 테스트가 완료되면 DB 인스턴스를 저용량 인스턴스로 수정합니다. 필요한 경우 DB 인스턴스를 다시 수정합니다.

## Answer

정답: C

## Explanation

월 48시간만 사용하는 DB 인스턴스의 경우, 테스트 완료 후 스냅샷을 생성하고 DB 인스턴스를 종료한 뒤, 필요할 때 스냅샷에서 복원하는 것이 가장 비용 효율적입니다. RDS 인스턴스를 중지하면 최대 7일까지만 중지 상태를 유지할 수 있으며 그 이후 자동으로 시작됩니다. 월 1회 48시간만 사용하므로 7일 제한에 걸리며, 스냅샷/종료/복원 방식이 더 적합합니다. 스냅샷 스토리지 비용만 발생하므로 비용이 크게 절감됩니다.

오답 분석

A: RDS DB 인스턴스를 중지하면 최대 7일까지만 중지 상태를 유지할 수 있습니다. 7일이 지나면 자동으로 다시 시작되어 비용이 발생합니다. 월 1회 48시간만 사용하므로 나머지 기간(약 3주)에 자동 시작이 반복될 수 있습니다.

B: RDS는 EC2의 Auto Scaling과 같은 인스턴스 자동 확장/축소 기능을 제공하지 않습니다.

D: 저용량 인스턴스로 수정하면 비용이 일부 절감되지만, 문제에서 컴퓨팅 및 메모리 속성을 줄이지 않겠다고 했으므로 요구 사항에 부합하지 않습니다.
