## Question

한 회사가 여러 가용 영역에 배포된 Amazon RDS 인스턴스에서 실행되는 데이터베이스를 호스팅합니다. 주기적 스크립트는 데이터베이스를 쿼리하여 중요한 애플리케이션에 부정적인 영향을 미칩니다. 최소한의 비용으로 애플리케이션 성능을 개선하려면 어떻게 해야 합니까?

- [ ] A. 스크립트에 기능을 추가하여 활성 연결이 가장 적은 인스턴스를 식별하고 해당 인스턴스를 쿼리합니다.
- [ ] B. 데이터베이스의 읽기 복제본을 만들고 읽기 복제본만 쿼리하도록 스크립트를 구성합니다.
- [ ] C. 개발 팀에 하루가 끝나면 새 항목을 수동으로 내보내도록 지시합니다.
- [ ] D. Amazon ElastiCache를 사용하여 스크립트가 실행하는 일반적인 쿼리를 캐시합니다.

## Answer

정답: B

## Explanation

읽기 전용 복제본(Read Replica)을 생성하고 주기적 스크립트의 쿼리를 복제본으로 리디렉션하면, 기본 데이터베이스 인스턴스의 중요한 애플리케이션 성능에 영향을 주지 않습니다. Multi-AZ 배포 환경에 읽기 복제본을 추가하는 것은 비교적 저비용이며 구성이 간단하여 최소 비용으로 성능 문제를 해결합니다.

오답 분석

A: Multi-AZ RDS 배포에서는 표준 엔드포인트를 통해 기본 인스턴스만 액세스할 수 있습니다. 스크립트가 대기 인스턴스로 쿼리를 라우팅할 수 없으므로, 연결 수 기반 로직을 추가해도 실질적인 부하 분산이 이루어지지 않으며 기본 인스턴스의 성능 영향을 해결하지 못합니다.

C: 하루 끝에 수동으로 데이터를 내보내는 것은 비효율적이며 자동화되지 않아 운영 오버헤드가 높습니다.

D: ElastiCache를 사용하면 캐시 레이어 구현의 추가 복잡성이 발생하고, 읽기 복제본보다 구현 비용이 높을 수 있습니다.
