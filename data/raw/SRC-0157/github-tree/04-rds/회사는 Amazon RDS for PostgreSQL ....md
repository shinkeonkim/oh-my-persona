## Question

회사는 Amazon RDS for PostgreSQL DB 인스턴스를 사용하여 웹 서버 플릿을 실행합니다. 일상적인 규정 준수 검사 후 회사는 모든 프로덕션 데이터베이스에 대해 1초 미만의 복구 지점 목표(RPO)를 요구하는 표준을 설정합니다.
어떤 솔루션이 이러한 요구 사항을 충족합니까?

- [ ] A. DB 인스턴스에 대해 다중 AZ 배포를 활성화합니다.
- [ ] B. 하나의 가용 영역에서 DB 인스턴스에 대해 Auto Scaling을 활성화합니다.
- [ ] C. 하나의 가용 영역에서 DB 인스턴스를 구성하고 별도의 가용 영역에서 여러 읽기 전용 복제본을 생성합니다.
- [ ] D. 하나의 가용 영역에서 DB 인스턴스를 구성하고 AWS DMS(AWS Database Migration Service) 변경 데이터 캡처(CDC) 작업을 구성합니다.

## Answer

정답: A

## Explanation

RDS 다중 AZ 배포는 동기식 복제(synchronous replication)를 사용하여 기본 인스턴스의 모든 변경 사항이 대기 인스턴스에 즉시 복제됩니다. 이를 통해 1초 미만의 RPO(복구 시점 목표)를 달성할 수 있습니다. 기본 인스턴스에 장애가 발생하면 대기 인스턴스가 최신 데이터를 가지고 있으므로 데이터 손실이 거의 발생하지 않습니다.

오답 분석

B: 하나의 가용 영역에서 Auto Scaling을 활성화하는 것은 RDS 데이터베이스에 적용되는 기능이 아닙니다. RDS Auto Scaling은 스토리지 자동 확장이며, 컴퓨팅 인스턴스 자동 확장과는 다릅니다. RPO와도 관련이 없습니다.

C: 읽기 전용 복제본은 비동기식 복제를 사용하므로 복제 지연(replication lag)이 발생할 수 있어 1초 미만의 RPO를 보장하지 못합니다. 읽기 전용 복제본은 읽기 부하 분산을 위한 것이지 RPO 요구 사항을 충족하기 위한 것이 아닙니다.

D: AWS DMS CDC(변경 데이터 캡처)는 데이터 마이그레이션 및 복제를 위한 서비스로, 비동기식으로 작동하므로 1초 미만의 RPO를 보장하지 못하며, 고가용성 솔루션이 아닙니다.
