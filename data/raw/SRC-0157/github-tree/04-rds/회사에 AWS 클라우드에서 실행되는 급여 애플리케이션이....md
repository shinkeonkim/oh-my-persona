## Question

회사에 AWS 클라우드에서 실행되는 급여 애플리케이션이 있습니다. 이 애플리케이션은 데이터 저장을 위해 Amazon Aurora MySQL 데이터베이스 클러스터를 사용합니다. 회사의 감사팀은 최근 90일간의 급여 데이터를 검토해야 합니다. 솔루션 아키텍트는 감사팀이 급여 데이터에 액세스할 수 있도록 솔루션을 설계해야 합니다.
어떤 솔루션이 이러한 요구 사항을 가장 높은 운영 효율성으로 충족할까요?

- [ ] A. Aurora 자동 백업을 사용합니다. 지정 시점 복구를 사용하여 데이터베이스를 복원합니다.
- [ ] B. 지정 시점 복구를 사용하여 AWS Backup을 사용하여 백업 계획을 만듭니다. 백업 볼트의 백업을 사용하여 데이터베이스를 복원합니다.
- [ ] C. 최근 90일간 Aurora 클러스터의 일일 수동 백업을 만듭니다. 백업을 사용하여 데이터베이스를 복원합니다. 스크립트 CLI 호출을 사용하여 이전 백업 파일을 삭제합니다.
- [ ] D. 일일 백업 옵션을 사용하여 AWS Backup을 사용하여 백업 계획을 만듭니다. 보존 기간을 90일로 설정합니다. 백업 볼트의 백업을 사용하여 데이터베이스를 복원합니다.

## Answer

정답: D

## Explanation

AWS Backup의 일일 백업 옵션으로 백업 계획을 생성하고 보존 기간을 90일로 설정하면, 매일 자동으로 Aurora 백업이 생성되고 90일이 지난 백업은 자동 삭제됩니다. Aurora 자동 백업은 최대 35일까지만 보존 가능하지만 AWS Backup은 이보다 훨씬 긴 보존 기간을 지원하여, 감사팀이 90일 이내 데이터를 복원할 수 있어 가장 운영 효율적입니다.

오답 분석

A: Aurora 자동 백업의 최대 보존 기간은 35일이므로 90일 보존 요구사항을 충족할 수 없습니다.

B: AWS Backup의 PITR 옵션은 지속적 백업용으로, 일일 백업과 90일 보존에는 일일 스냅샷 백업 계획이 더 직접적입니다.

C: 90일간 매일 수동 백업을 생성하고 CLI 스크립트로 이전 백업을 관리하면 자동화가 부족하고 운영 오버헤드가 높습니다.
