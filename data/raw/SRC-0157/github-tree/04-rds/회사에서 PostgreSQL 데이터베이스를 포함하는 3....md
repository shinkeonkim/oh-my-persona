## Question

회사에서 PostgreSQL 데이터베이스를 포함하는 3계층 웹 애플리케이션을 호스팅합니다. 데이터베이스는 문서의 메타데이터를 저장합니다. 회사는 매달 보고서에서 회사가 검토하는 문서를 조회하기 위해 핵심 용어에 대한 메타데이터를 검색합니다. 문서는 Amazon S3에 저장됩니다. 문서는 일반적으로 한 번만 작성되지만 자주 업데이트됩니다.
보고 프로세스는 관계형 쿼리를 사용하여 몇 시간이 걸립니다. 보고 프로세스는 문서 수정 또는 새 문서 추가를 방해해서는 안 됩니다.
이러한 요구 사항을 충족하는 운영상 가장 효율적인 솔루션은 무엇입니까? (2개 선택)

- [ ] A. 읽기 전용 복제본이 포함된 새로운 Amazon DocumentDB(MongoDB 호환) 클러스터를 설정합니다. 읽기 복제본을 확장하여 보고서를 생성합니다.
- [ ] B. 예약 인스턴스용 새 PostgreSQL Amazon RDS 및 온디맨드 읽기 전용 복제본을 설정합니다. 읽기 전용 복제본을 확장하여 보고서를 생성합니다.
- [ ] C. Aurora 복제본이 포함된 새로운 Amazon Aurora PostgreSQL DB 클러스터를 설정합니다. Aurora 복제본에 쿼리를 실행하여 보고서를 생성합니다.
- [ ] D. PostgreSQL 다중 AZ DB 인스턴스용 새 Amazon RDS를 설정합니다. 보고 모듈이 기본 노드에 영향을 주지 않도록 보조 RDS 노드를 쿼리하도록 보고 모듈을 구성합니다.
- [ ] E. 문서를 저장할 새 Amazon DynamoDB 테이블을 설정합니다. 새 문서 항목을 지원하기 위해 고정된 쓰기 용량을 사용합니다. 보고서를 지원하기 위해 읽기 용량을 자동으로 확장합니다.

## Answer

정답: B, C

## Explanation

(B) Amazon RDS for PostgreSQL 예약 인스턴스와 온디맨드 읽기 전용 복제본을 사용하면 프로덕션 DB에 영향 없이 보고서를 생성할 수 있으며, 예약 인스턴스로 비용을 절감할 수 있습니다. (C) Amazon Aurora PostgreSQL DB 클러스터의 Aurora 복제본을 사용하면 프로덕션 기본 인스턴스와 동일한 스토리지를 공유하면서 읽기 전용 쿼리를 처리할 수 있어 보고 프로세스가 문서 수정이나 새 문서 추가를 방해하지 않습니다. 두 솔루션 모두 관계형 쿼리를 지원하며 읽기 워크로드를 기본 인스턴스에서 분리합니다.

오답 분석

A: Amazon DocumentDB는 MongoDB 호환 문서 데이터베이스로, PostgreSQL 관계형 쿼리를 직접 사용할 수 없습니다. 기존 PostgreSQL 스키마와 쿼리를 변환해야 하므로 운영 효율성이 떨어집니다.

D: RDS 다중 AZ DB 인스턴스의 보조(대기) 노드는 읽기 트래픽을 처리할 수 없습니다. 대기 인스턴스는 장애 조치 목적으로만 사용되며 쿼리를 실행할 수 없습니다.

E: Amazon DynamoDB는 NoSQL 데이터베이스로, 관계형 쿼리를 사용하여 메타데이터를 검색하는 기존 보고 프로세스와 호환되지 않습니다. 또한 문서를 S3에 저장하고 있으므로 DynamoDB에 문서를 저장할 필요가 없습니다.
