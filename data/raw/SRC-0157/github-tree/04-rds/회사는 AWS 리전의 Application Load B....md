## Question

회사는 AWS 리전의 Application Load Balancer 뒤에 있는 Amazon Elastic Kubernetes Service(Amazon EKS)에 애플리케이션을 배포합니다. 애플리케이션은 PostgreSQL 데이터베이스 엔진에 데이터를 저장해야 합니다. 회사는 데이터베이스의 데이터가 가용성이 높기를 원합니다. 회사는 또한 읽기 워크로드를 위한 증가된 용량이 필요합니다.
이러한 요구 사항을 가장 효율적으로 충족하는 솔루션은 무엇입니까?

- [ ] A. 전역 테이블로 구성된 Amazon DynamoDB 데이터베이스 테이블을 생성합니다.
- [ ] B. 다중 AZ 배포로 Amazon RDS 데이터베이스를 생성합니다.
- [ ] C. 다중 AZ DB 클러스터 배포로 Amazon RDS 데이터베이스를 생성합니다.
- [ ] D. 리전 간 읽기 전용 복제본으로 구성된 Amazon RDS 데이터베이스를 생성합니다.

## Answer

정답: C

## Explanation

Amazon RDS 다중 AZ DB 클러스터 배포는 PostgreSQL을 지원하며, 1개의 쓰기 인스턴스와 2개의 읽기 가능한 대기 인스턴스를 3개의 가용 영역에 배치합니다. 이를 통해 고가용성과 읽기 워크로드 용량 증가를 동시에 제공합니다. 리더 엔드포인트를 통해 읽기 트래픽을 분산할 수 있으며, 자동 장애 조치도 지원하여 운영 효율성이 가장 높습니다.

오답 분석

A: Amazon DynamoDB는 NoSQL 데이터베이스로, PostgreSQL 데이터베이스 엔진이 필요하다는 요구 사항에 맞지 않습니다. 또한 기존 애플리케이션의 SQL 쿼리를 DynamoDB API로 변환해야 합니다.

B: 다중 AZ 배포(인스턴스)는 고가용성을 제공하지만, 대기 인스턴스에서 읽기 트래픽을 처리할 수 없습니다. 읽기 워크로드 용량 증가 요구 사항을 충족하지 못합니다.

D: 리전 간 읽기 전용 복제본은 다른 리전에 복제본을 생성하는 것으로, 동일 리전 내 고가용성과 읽기 용량 증가에는 불필요한 오버헤드입니다. 또한 리전 간 복제로 인한 추가 비용과 지연 시간이 발생합니다.
