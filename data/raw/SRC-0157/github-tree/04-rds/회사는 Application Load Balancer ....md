## Question

회사는 Application Load Balancer 뒤의 Amazon EC2 인스턴스에서 비즈니스 크리티컬 웹 애플리케이션을 실행하고 있습니다. EC2 인스턴스는 Auto Scaling 그룹에 있습니다. 애플리케이션은 단일 가용 영역에 배포된 Amazon Aurora PostgreSQL 데이터베이스를 사용합니다. 회사는 가동 중지 시간을 최소화하고 데이터 손실을 최소화하면서 애플리케이션의 가용성을 높이길 원합니다.
최소한의 운영 노력으로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 다른 AWS 리전에 EC2 인스턴스를 배치합니다. Amazon Route 53 상태 확인을 사용하여 트래픽을 리디렉션합니다. Aurora PostgreSQL 교차 리전 복제를 사용합니다.
- [ ] B. 여러 가용 영역을 사용하도록 Auto Scaling 그룹을 구성합니다. 데이터베이스를 다중 AZ로 구성합니다. 데이터베이스에 대한 Amazon RDS Proxy 인스턴스를 구성합니다.
- [ ] C. 하나의 가용 영역을 사용하도록 Auto Scaling 그룹을 구성합니다. 데이터베이스의 시간별 스냅샷을 생성합니다. 장애 발생 시 스냅샷에서 데이터베이스를 복구합니다.
- [ ] D. 여러 AWS 리전을 사용하도록 Auto Scaling 그룹을 구성합니다. 애플리케이션의 데이터를 Amazon S3에 씁니다. S3 이벤트 알림을 사용하여 데이터베이스에 데이터를 쓰는 AWS Lambda 함수를 시작합니다.

## Answer

정답: B

## Explanation

Auto Scaling 그룹을 여러 가용 영역에 걸쳐 구성하면 EC2 인스턴스의 고가용성을 확보할 수 있습니다. Aurora PostgreSQL 데이터베이스를 Multi-AZ로 구성하면 자동 장애 조치를 통해 데이터베이스의 고가용성을 보장하며, Amazon RDS Proxy를 사용하면 데이터베이스 연결을 효율적으로 관리하고 장애 조치 시 애플리케이션 중단 시간을 크게 줄일 수 있습니다. 이 조합은 최소한의 운영 노력으로 가동 중지 시간과 데이터 손실을 최소화합니다.

오답 분석

A: 교차 리전 복제는 재해 복구에는 유용하지만, 단순 고가용성 요구 사항에 비해 과도한 솔루션이며 운영 오버헤드가 매우 큽니다. Route 53 상태 확인을 통한 트래픽 리디렉션은 복잡한 구성이 필요합니다.

C: 하나의 가용 영역만 사용하면 해당 AZ 장애 시 전체 애플리케이션이 중단되므로 고가용성 요구 사항을 충족하지 못합니다. 시간별 스냅샷 복구는 데이터 손실과 긴 복구 시간을 초래합니다.

D: Auto Scaling 그룹은 여러 리전에 걸쳐 구성할 수 없습니다. 또한 S3에 데이터를 쓰고 Lambda를 통해 데이터베이스에 기록하는 방식은 불필요하게 복잡하고 지연 시간이 발생합니다.
