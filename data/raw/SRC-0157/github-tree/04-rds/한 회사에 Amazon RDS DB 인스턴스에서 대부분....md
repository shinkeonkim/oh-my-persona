## Question

한 회사에 Amazon RDS DB 인스턴스에서 대부분의 메타데이터를 읽는 모바일 게임이 있습니다. 게임의 인기가 높아짐에 따라 개발자들은 게임의 메타데이터 로드 시간과 관련된 속도 저하를 발견했습니다. 성능 지표는 단순히 데이터베이스를 확장하는 것만으로는 도움이 되지 않음을 나타냅니다. 솔루션 설계자는 스냅샷, 복제, 밀리초 미만의 응답 시간을 포함하는 모든 옵션을 탐색해야 합니다.
이러한 문제를 해결하기 위해 솔루션 설계자는 무엇을 권장해야 합니까?

- [ ] A. Aurora 복제본을 사용하여 데이터베이스를 Amazon Aurora로 마이그레이션합니다.
- [ ] B. 글로벌 테이블을 사용하여 데이터베이스를 Amazon DynamoDB로 마이그레이션합니다.
- [ ] C. 데이터베이스 앞에 Redis용 Amazon ElastiCache 계층을 추가합니다.
- [ ] D. 데이터베이스 앞에 Memcached용 Amazon ElastiCache 계층을 추가합니다.

## Answer

정답: C

## Explanation

Amazon ElastiCache for Redis는 밀리초 미만의 응답 시간, 스냅샷을 통한 백업, 복제 기능을 모두 제공합니다. 모바일 게임의 메타데이터는 읽기가 주로 발생하는 패턴이므로, Redis 캐시를 데이터베이스 앞에 배치하면 RDS의 CPU 부하를 줄이고 빠른 데이터 접근이 가능합니다. Redis는 스냅샷과 복제 기능을 기본 지원하여 문제에서 요구하는 모든 조건을 충족합니다.

오답 분석

A: Aurora 복제본은 읽기 트래픽을 분산시킬 수 있지만, 밀리초 미만의 응답 시간을 제공하지 않습니다. 문제에서 단순히 확장으로는 도움이 되지 않는다고 명시했습니다.

B: DynamoDB 글로벌 테이블은 밀리초 수준의 응답을 제공하지만, 기존 RDS 데이터베이스에서의 마이그레이션이 필요하고 관계형 쿼리를 지원하지 않습니다.

D: Memcached는 밀리초 미만의 응답 시간을 제공하지만, 스냅샷과 복제 기능을 지원하지 않아 문제의 요구 사항을 충족하지 못합니다.
