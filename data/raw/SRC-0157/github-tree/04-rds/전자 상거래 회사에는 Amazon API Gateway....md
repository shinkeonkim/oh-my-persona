## Question

전자 상거래 회사에는 Amazon API Gateway 및 AWS Lambda 함수를 사용하는 주문 처리 애플리케이션이 있습니다. 애플리케이션은 Amazon Aurora PostgreSQL 데이터베이스에 데이터를 저장합니다. 최근 판매 행사 중에 고객 주문이 갑자기 급증했습니다. 일부 고객은 시간 초과를 경험했고 애플리케이션은 해당 고객의 주문을 처리하지 않았습니다.
솔루션 설계자는 많은 수의 열린 연결로 인해 데이터베이스에서 CPU 사용률과 메모리 사용률이 높다고 판단했습니다. 솔루션 설계자는 애플리케이션을 최소한으로 변경하면서 시간 초과 오류를 방지해야 합니다.
이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. Lambda 함수에 대해 프로비저닝된 동시성을 구성합니다. 여러 AWS 리전에서 글로벌 데이터베이스가 되도록 데이터베이스를 수정합니다.
- [ ] B. Amazon RDS 프록시를 사용하여 데이터베이스에 대한 프록시를 생성합니다. 데이터베이스 엔드포인트 대신 RDS 프록시 엔드포인트를 사용하도록 Lambda 함수를 수정합니다.
- [ ] C. 다른 AWS 리전에서 데이터베이스에 대한 읽기 전용 복제본을 생성합니다. API Gateway에서 쿼리 문자열 파라미터를 사용하여 트래픽을 읽기 전용 복제본으로 라우팅합니다.
- [ ] D. AWS Database Migration Service(AWS DMS)를 사용하여 Aurora PostgreSQL에서 Amazon DynamoDB로 데이터를 마이그레이션합니다. DynamoDB 테이블을 사용하도록 Lambda 함수를 수정합니다.

## Answer

정답: B

## Explanation

Amazon RDS Proxy는 많은 수의 열린 연결로 인한 데이터베이스 과부하 문제를 해결하는 최적의 솔루션입니다. RDS Proxy는 연결 풀링을 제공하여 Lambda 함수의 동시 연결을 효율적으로 관리하며, Lambda 함수의 엔드포인트만 RDS Proxy로 변경하면 되므로 애플리케이션 변경이 최소화됩니다. 주문이 급증할 때에도 RDS Proxy가 연결을 대기열에 넣고 관리하여 데이터베이스의 CPU 및 메모리 사용률을 안정적으로 유지합니다.

오답 분석

A: 프로비저닝된 동시성은 Lambda의 콜드 스타트 문제를 해결하지만, 데이터베이스 연결 과부하 문제는 해결하지 못합니다. 글로벌 데이터베이스는 교차 리전 복제를 위한 것으로 연결 관리와는 관련이 없습니다.

C: 다른 리전에 읽기 전용 복제본을 생성하면 읽기 부하를 분산할 수 있지만, API Gateway에서 쿼리 문자열 파라미터로 트래픽을 라우팅하는 것은 적절한 방법이 아니며 연결 관리 문제를 해결하지 못합니다.

D: DynamoDB로 마이그레이션하면 연결 문제는 해결될 수 있지만, 기존 관계형 데이터 모델과 쿼리를 완전히 재설계해야 하므로 애플리케이션 변경이 최소한이 아닙니다.
