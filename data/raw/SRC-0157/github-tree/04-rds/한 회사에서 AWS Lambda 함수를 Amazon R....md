## Question

한 회사에서 AWS Lambda 함수를 Amazon RDS for MySQL DB 인스턴스에 연결하는 애플리케이션을 설계하고 있습니다. DB 인스턴스는 여러 연결을 관리합니다. 회사는 연결 및 복구를 개선하기 위해 애플리케이션을 수정해야 합니다.
운영 오버헤드를 최소화하면서 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 연결 풀링에 Amazon RDS 프록시를 사용합니다. DB 인스턴스 연결에 RDS 프록시를 사용하도록 애플리케이션을 수정합니다.
- [ ] B. 연결 풀링을 위해 새 RDS 인스턴스를 생성합니다. 연결에 새 RDS 인스턴스를 사용하도록 애플리케이션을 수정합니다.
- [ ] C. DB 인스턴스의 부하를 분산하기 위해 읽기 전용 복제본을 생성합니다. 네트워크 로드 밸런서를 생성하여 부하를 읽기 전용 복제본에 분산합니다.
- [ ] D. DB 인스턴스 성능을 높이기 위해 RDS for MySQL DB 인스턴스를 Amazon Aurora MySQL로 마이그레이션합니다.

## Answer

정답: A

## Explanation

Amazon RDS Proxy는 데이터베이스 연결 풀링을 제공하여 많은 Lambda 함수 동시 실행 시 발생하는 연결 과다 문제를 해결합니다. RDS Proxy는 장애 조치 시 자동으로 연결을 재설정하여 복구 성능도 향상시키며, 운영 오버헤드가 가장 적습니다.

오답 분석

B: 연결 풀링을 위한 새 RDS 인스턴스를 생성하는 것은 RDS Proxy가 제공하는 기능을 수동으로 구현하는 것이며, 추가 관리가 필요합니다.

C: 읽기 전용 복제본과 NLB는 읽기 부하를 분산하지만, Lambda의 연결 관리 문제와 장애 복구를 직접 해결하지 않습니다.

D: Aurora MySQL로 마이그레이션하면 성능이 향상될 수 있지만, 연결 관리 문제의 근본 원인을 해결하지 않으며, RDS Proxy가 더 직접적인 솔루션입니다.
