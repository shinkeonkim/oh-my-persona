## Question

금융 서비스 회사가 민감한 금융 거래를 처리하기 위해 AWS에서 새로운 애플리케이션을 출시할 계획입니다. 이 회사는 Amazon EC2 인스턴스에 애플리케이션을 배포합니다. 이 회사는 데이터베이스로 Amazon RDS for MySQL을 사용합니다. 이 회사의 보안 정책에 따라 데이터는 저장 시와 전송 시 암호화되어야 합니다.
어떤 솔루션이 이러한 요구 사항을 최소한의 운영 오버헤드로 충족할까요?

- [ ] A. AWS KMS 관리 키를 사용하여 Amazon RDS for MySQL에 대한 저장 시 암호화를 구성합니다. 전송 중 암호화를 위해 AWS Certificate Manager(ACM) SSL/TLS 인증서를 구성합니다.
- [ ] B. AWS KMS 관리 키를 사용하여 Amazon RDS for MySQL에 대한 저장 시 암호화를 구성합니다. 전송 중 암호화를 위한 IPsec 터널을 구성합니다.
- [ ] C. Amazon RDS for MySQL에 데이터를 저장하기 전에 타사 애플리케이션 수준 데이터 암호화를 구현합니다. 전송 중 암호화를 위해 AWS Certificate Manager(ACM) SSL/TLS 인증서를 구성합니다.
- [ ] D. AWS KMS 관리 키를 사용하여 Amazon RDS for MySQL에 대한 저장 시 암호화를 구성합니다. VPN 연결을 구성하여 전송 중인 데이터를 암호화하기 위한 개인 연결을 활성화합니다.

## Answer

정답: A

## Explanation

Amazon RDS for MySQL에 AWS KMS 관리형 키로 저장 데이터 암호화(Encryption at Rest)를 구성하면 최소한의 운영 오버헤드로 미사용 데이터를 보호합니다. 전송 중 암호화를 위해 RDS는 RDS 관리형 서버 인증서(ACM 인증서가 아닌 RDS 자체 내장 인증 기관)를 사용하는 SSL/TLS 암호화를 기본적으로 지원합니다. 옵션 A에서 'ACM SSL/TLS 인증서'를 언급하고 있지만, RDS는 연결 수준에서 적용 가능한 RDS CA 인증서를 통해 SSL/TLS로 연결되며 운영 오버헤드가 최소화됩니다. 제시된 옵션 중에서 A는 두 가지 암호화 계층(저장 시: KMS, 전송 중: TLS)을 정확히 식별하며 운영 복잡성이 가장 낮습니다.

오답 분석

B: IPsec 터널은 네트워크 레이어의 암호화로, RDS 데이터베이스 연결에는 SSL/TLS가 더 표준적이고 간단한 방법입니다.

C: 타사 애플리케이션 수준 암호화는 추가 복잡성을 유발하며, RDS의 기본 KMS 암호화가 더 운영 오버헤드가 적습니다.

D: VPN 연결은 네트워크 레이어 암호화로, 데이터베이스 전송 중 암호화에는 SSL/TLS가 더 직접적이고 효율적입니다.
