## Question

한 회사가 Amazon RDS for PostgreSQL 테이블에 대량의 중요 데이터를 저장하고 있습니다. 이 회사는 곧 출시될 제품 출시를 위해 여러 가지 새로운 기능을 개발하고 있습니다. 일부 새로운 기능을 사용하려면 테이블 수정이 많이 필요합니다. 이 회사는 수정된 테이블을 며칠 동안 테스트할 솔루션이 필요합니다. 테스트 후, 솔루션은 프로덕션 환경에서 고객에게 새로운 기능을 제공해야 합니다. 어떤 솔루션이 이러한 요구 사항을 가장 높은 가용성으로 충족할 수 있을까요?

- [ ] A. RDS for PostgreSQL에 새 데이터베이스 인스턴스를 생성하여 새 기능을 테스트합니다. 테스트가 완료되면 테스트 데이터베이스를 백업하고 테스트 데이터베이스를 프로덕션 데이터베이스에 복원합니다.
- [ ] B. 프로덕션 데이터베이스에 새 데이터베이스 테이블을 생성하여 새 기능을 테스트합니다. 테스트가 완료되면 이전 테이블의 데이터를 새 테이블로 복사합니다. 이전 테이블을 삭제하고 새 테이블의 이름을 적절하게 변경합니다.
- [ ] C. Amazon RDS 읽기 전용 복제본을 생성하여 새 데이터베이스 인스턴스를 배포합니다. 복제본 인스턴스의 데이터베이스 테이블을 업데이트합니다. 테스트가 완료되면 복제본 인스턴스를 새 프로덕션 인스턴스로 승격합니다.
- [ ] D. Amazon RDS 블루/그린 배포를 사용하여 데이터베이스의 새 테스트 인스턴스를 배포합니다. 테스트 인스턴스에서 데이터베이스 테이블을 업데이트합니다. 테스트가 완료되면 테스트 인스턴스를 새 프로덕션 인스턴스로 승격합니다.

## Answer

정답: D

## Explanation

Amazon RDS 블루/그린 배포는 프로덕션 데이터베이스(블루)와 동일한 테스트 환경(그린)을 자동으로 생성하고, 블루에서 그린으로 지속적으로 복제합니다. 그린 환경에서 테이블을 수정하고 테스트한 후 전환(switchover)하면 약 1분 미만의 다운타임으로 프로덕션에 반영됩니다. 데이터 동기화가 자동으로 유지되어 가용성이 가장 높습니다.

오답 분석

A: 새 데이터베이스 인스턴스를 생성하고 테스트 후 백업/복원하면 프로덕션 데이터와 동기화되지 않으며, 테스트 중 프로덕션에 추가된 데이터가 유실될 위험이 있습니다.

B: 프로덕션 데이터베이스에서 직접 새 테이블을 생성하고 테스트하면 프로덕션 워크로드에 영향을 줄 수 있으며, 문제 발생 시 롤백이 복잡합니다.

C: 읽기 전용 복제본은 쓰기 작업(테이블 수정)이 불가능하므로, 복제본에서 테이블 수정 테스트를 수행할 수 없습니다. 승격하면 원본과의 복제가 중단됩니다.
