## Question

회사는 AWS에서 서버리스 애플리케이션을 호스팅합니다. 이 애플리케이션은 Amazon API Gateway, AWS Lambda 및 Amazon RDS for PostgreSQL 데이터베이스를 사용합니다. 회사는 최대 트래픽 또는 예측할 수 없는 트래픽 시간 동안 데이터베이스 연결 시간 초과로 인해 발생하는 애플리케이션 오류의 증가를 확인했습니다. 회사는 최소한의 코드 변경으로 애플리케이션 오류를 줄이는 솔루션이 필요합니다.
솔루션 설계자는 이러한 요구 사항을 충족하기 위해 무엇을 해야 합니까?

- [ ] A. Lambda 동시성 비율을 줄입니다.
- [ ] B. RDS DB 인스턴스에서 RDS 프록시를 활성화합니다.
- [ ] C. 더 많은 연결을 허용하도록 RDS DB 인스턴스 클래스의 크기를 조정합니다.
- [ ] D. 온디맨드 확장을 통해 데이터베이스를 Amazon DynamoDB로 마이그레이션합니다.

## Answer

정답: B

## Explanation

RDS Proxy를 RDS DB 인스턴스에 활성화하면 Lambda 함수의 동시 실행으로 인한 데이터베이스 연결 시간 초과 문제를 해결할 수 있습니다. RDS Proxy는 연결 풀링을 제공하여 Lambda 함수가 데이터베이스 연결을 효율적으로 재사용하도록 하며, 최소한의 코드 변경(엔드포인트 변경)만으로 구현 가능합니다. 피크 트래픽이나 예측할 수 없는 트래픽 시에도 안정적인 연결 관리를 보장합니다.

오답 분석

A: Lambda 동시성 비율을 줄이면 연결 시간 초과는 줄어들 수 있지만, 애플리케이션의 처리량이 감소하여 사용자 경험이 저하됩니다. 이는 근본적인 해결책이 아닙니다.

C: RDS DB 인스턴스 클래스의 크기를 조정하면 더 많은 연결을 처리할 수 있지만, 서버리스 환경에서의 급격한 연결 수 변동에 대한 연결 풀링 기능은 제공하지 않으므로 근본적인 해결이 되지 않습니다.

D: Amazon DynamoDB로 마이그레이션하면 연결 문제는 해결되지만, PostgreSQL 기반의 기존 관계형 쿼리를 NoSQL 모델로 전환해야 하므로 코드 변경이 최소화되지 않습니다.
