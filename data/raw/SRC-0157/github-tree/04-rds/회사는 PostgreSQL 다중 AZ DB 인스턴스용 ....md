## Question

회사는 PostgreSQL 다중 AZ DB 인스턴스용 Amazon RDS에 데이터를 저장하는 애플리케이션을 관리합니다. 트래픽 증가로 인해 성능 문제가 발생합니다. 회사에서는 데이터베이스 쿼리가 성능 저하의 주요 원인이라고 판단합니다.
솔루션 아키텍트는 애플리케이션 성능을 향상시키기 위해 무엇을 해야 합니까?

- [ ] A. 다중 AZ 대기 복제본에서 읽기 트래픽을 제공합니다.
- [ ] B. Transfer Acceleration을 사용하도록 DB 인스턴스를 구성합니다.
- [ ] C. 원본 DB 인스턴스에서 읽기 전용 복제본을 생성합니다. 읽기 복제본에서 읽기 트래픽을 제공합니다.
- [ ] D. 애플리케이션과 Amazon RDS 사이에 Amazon Kinesis Data Firehose를 사용하여 데이터베이스 요청의 동시성을 높입니다.

## Answer

정답: C

## Explanation

원본 DB 인스턴스에서 읽기 전용 복제본을 생성하고 읽기 트래픽을 복제본으로 전환하면 기본 인스턴스의 부하를 효과적으로 줄일 수 있습니다. 읽기 전용 복제본은 비동기식으로 데이터를 복제하며, 읽기 쿼리를 처리하여 기본 인스턴스가 쓰기 작업에 집중할 수 있게 합니다. 이는 데이터베이스 쿼리로 인한 성능 저하를 해결하는 표준적인 방법입니다.

오답 분석

A: 다중 AZ 대기 복제본에서 읽기 트래픽을 제공하는 것은 불가능합니다. RDS 다중 AZ DB 인스턴스 배포의 대기 인스턴스는 장애 조치 목적으로만 사용되며, 읽기 쿼리를 처리할 수 없습니다.

B: Transfer Acceleration은 Amazon S3의 기능으로, 지리적으로 분산된 클라이언트에서 S3 버킷으로의 파일 전송 속도를 높이는 데 사용됩니다. RDS DB 인스턴스에는 적용할 수 없는 기능입니다.

D: Amazon Kinesis Data Firehose는 실시간 스트리밍 데이터를 수집하고 전달하는 서비스입니다. 애플리케이션과 RDS 사이에 배치하여 데이터베이스 요청의 동시성을 높이는 용도로 설계되지 않았으며, SQL 데이터베이스 쿼리를 처리하는 기능이 없습니다.
