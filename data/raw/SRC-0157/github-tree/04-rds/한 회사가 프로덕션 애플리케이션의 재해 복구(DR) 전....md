## Question

한 회사가 프로덕션 애플리케이션의 재해 복구(DR) 전략을 설계하고 있습니다. 애플리케이션은 us-east-1 리전의 Amazon Aurora 클러스터에 있는 MySQL 데이터베이스의 지원을 받습니다. 회사는 us-west-1 리전을 DR 리전으로 선택했습니다.
회사의 복구 지점 목표(RPO)는 5분이고 복구 시간 목표(RTO)는 20분입니다. 회사에서는 구성 변경을 최소화하려고 합니다.
가장 효율적인 운영 효율성으로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 프로덕션 애플리케이션의 Aurora MySQL 클러스터 라이터 인스턴스와 비슷한 크기로 us-west-1에 Aurora 읽기 전용 복제본을 생성합니다.
- [ ] B. Aurora 클러스터를 Aurora 글로벌 데이터베이스로 변환합니다. 관리형 장애 조치를 구성합니다.
- [ ] C. 교차 리전 복제 기능이 있는 us-west-1에 새 Aurora 클러스터를 생성합니다.
- [ ] D. us-west-1에 새 Aurora 클러스터를 생성합니다. AWS Database Migration Service(AWS DMS)를 사용하여 두 클러스터를 모두 동기화합니다.

## Answer

정답: B

## Explanation

Aurora 글로벌 데이터베이스는 기본 리전에서 보조 리전으로 일반적으로 1초 미만의 복제 지연으로 데이터를 복제하므로, 5분의 RPO 요구 사항을 충분히 충족합니다. 관리형 장애 조치(Managed Failover)를 구성하면 장애 발생 시 자동으로 보조 리전을 기본 리전으로 승격하여 20분의 RTO 요구 사항도 충족할 수 있습니다. Aurora 글로벌 데이터베이스로 변환하면 기존 Aurora 클러스터의 구성을 최소한으로 변경하면서 교차 리전 DR을 구현할 수 있습니다.

오답 분석

A: 교차 리전 Aurora 읽기 전용 복제본은 수동 장애 조치가 필요하며, 관리형 장애 조치 기능이 없어 RTO가 더 길어질 수 있고 운영 효율성이 떨어집니다.

C: 교차 리전 복제 기능이 있는 새 Aurora 클러스터를 별도로 생성하는 것은 Aurora 글로벌 데이터베이스보다 구성이 복잡하며, 관리형 장애 조치를 지원하지 않습니다.

D: AWS DMS를 사용한 동기화는 추가적인 DMS 인스턴스 관리가 필요하며, Aurora 글로벌 데이터베이스에 비해 운영 오버헤드가 크고 복제 지연도 더 클 수 있습니다.
