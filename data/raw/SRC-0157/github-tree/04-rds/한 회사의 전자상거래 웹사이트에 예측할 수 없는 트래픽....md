## Question

한 회사의 전자상거래 웹사이트에 예측할 수 없는 트래픽이 있으며 AWS Lambda 함수를 사용하여 PostgreSQL용 프라이빗 Amazon RDS DB 인스턴스에 직접 액세스합니다. 회사는 예측 가능한 데이터베이스 성능을 유지하고 Lambda 호출이 너무 많은 연결로 인해 데이터베이스에 과부하가 걸리지 않도록 하려고 합니다.
솔루션 설계자는 이러한 요구 사항을 충족하기 위해 무엇을 해야 합니까?

- [ ] A. RDS 사용자 지정 엔드포인트에서 클라이언트 드라이버를 가리킵니다. VPC 내부에 Lambda 함수를 배포합니다.
- [ ] B. RDS 프록시 엔드포인트에서 클라이언트 드라이버를 가리킵니다. VPC 내부에 Lambda 함수를 배포합니다.
- [ ] C. RDS 사용자 지정 엔드포인트에서 클라이언트 드라이버를 가리킵니다. VPC 외부에 Lambda 함수를 배포합니다.
- [ ] D. RDS 프록시 엔드포인트에서 클라이언트 드라이버를 가리킵니다. VPC 외부에 Lambda 함수를 배포합니다.

## Answer

정답: B

## Explanation

RDS Proxy 엔드포인트를 사용하면 Lambda 함수의 연결 풀링을 통해 예측 가능한 데이터베이스 성능을 유지하고 과부하를 방지할 수 있습니다. Lambda 함수를 VPC 내부에 배포해야 하는 이유는 프라이빗 RDS DB 인스턴스가 VPC 내부에 있으므로, Lambda 함수도 같은 VPC에서 실행되어야 프라이빗 네트워크를 통해 RDS Proxy에 접근할 수 있기 때문입니다.

오답 분석

A: RDS 사용자 지정 엔드포인트는 Aurora 클러스터의 특정 DB 인스턴스 그룹을 지정하는 데 사용되며, 연결 풀링 기능을 제공하지 않습니다. VPC 내부 배포는 올바르지만 엔드포인트 유형이 적절하지 않습니다.

C: RDS 사용자 지정 엔드포인트는 연결 풀링을 제공하지 않으며, VPC 외부에서 Lambda를 배포하면 프라이빗 RDS 인스턴스에 접근할 수 없습니다.

D: RDS Proxy 엔드포인트는 올바른 선택이지만, VPC 외부에 Lambda 함수를 배포하면 프라이빗 RDS DB 인스턴스와 RDS Proxy에 네트워크 연결이 불가능합니다.
