## Question

회사에서 새로운 게임 애플리케이션을 출시합니다. 이 회사는 Amazon EC2 Auto Scaling 그룹을 사용하여 애플리케이션을 배포합니다. 이 애플리케이션은 관계형 데이터베이스에 사용자 데이터를 저장합니다. 이 회사는 전 세계에 사무실이 있으며, 이 사무실에서 데이터베이스의 사용자 데이터에 대한 분석을 실행해야 합니다. 이 회사는 AWS 리전에서 저지연 읽기 성능으로 리전 간 재해 복구를 제공하는 비용 효율적인 데이터베이스 솔루션이 필요합니다.
어떤 솔루션이 이러한 요구 사항을 충족할까요?

- [ ] A. 애플리케이션이 배포된 리전에 Amazon ElastiCache for Redis 클러스터를 만듭니다. 회사 사무실이 있는 리전에 읽기 복제본을 만듭니다. 회사 사무실에서 읽기 복제본 인스턴스에서 읽도록 합니다.
- [ ] B. Amazon DynamoDB 글로벌 테이블을 만듭니다. 회사 사무실이 있는 리전과 애플리케이션이 배포된 리전에 테이블을 배포합니다. 각 회사 사무실에서 사무실과 같은 리전에 있는 테이블에서 읽도록 합니다.
- [ ] C. Amazon Aurora 글로벌 데이터베이스를 만듭니다. 애플리케이션이 배포된 리전에 기본 클러스터를 구성합니다. 보조 Aurora 복제본을 회사 사무실이 있는 리전에 있도록 구성합니다. 회사 사무실이 Aurora 복제본에서 읽도록 합니다.
- [ ] D. 애플리케이션이 배포된 리전에 Amazon RDS Multi-AZ DB 클러스터 배포를 만듭니다. 회사 사무실이 읽기 복제본 인스턴스에서 읽도록 합니다.

## Answer

정답: C

## Explanation

Amazon Aurora 글로벌 데이터베이스는 기본 클러스터를 애플리케이션 배포 리전에, 보조 Aurora 복제본을 전 세계 사무실이 있는 리전에 배포합니다. 전용 복제 인프라를 통해 1초 미만의 복제 지연으로 저지연 읽기를 제공하며, 관계형 데이터베이스 요구사항을 충족하면서 리전 간 재해 복구도 지원합니다.

오답 분석

A: ElastiCache for Redis는 인메모리 캐싱 솔루션이며, 관계형 데이터를 저장하고 분석 쿼리를 실행하는 데이터베이스로 사용할 수 없습니다.

B: DynamoDB 글로벌 테이블은 NoSQL 데이터베이스이므로 관계형 데이터 요구사항을 충족하지 못합니다.

D: RDS Multi-AZ DB 클러스터는 단일 리전 내에서만 작동하므로, 다른 리전의 사무실에서 저지연 읽기를 제공할 수 없습니다.
