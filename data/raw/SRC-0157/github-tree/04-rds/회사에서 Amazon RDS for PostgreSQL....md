## Question

회사에서 Amazon RDS for PostgreSQL DB 클러스터를 사용하여 프로덕션 데이터베이스 워크로드에 대한 시간 소모적인 데이터베이스 관리 작업을 단순화하려고 합니다. 회사는 데이터베이스의 고가용성을 보장하고 대부분의 시나리오에서 40초 이내에 자동 장애 조치 지원을 제공하기를 원합니다. 회사는 기본 인스턴스에서 읽기를 오프로드하고 비용을 가능한 한 낮게 유지하려고 합니다.
이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. Amazon RDS 다중 AZ DB 인스턴스 배포를 사용합니다. 하나의 읽기 복제본을 만들고 읽기 워크로드를 읽기 복제본으로 지정합니다.
- [ ] B. Amazon RDS 다중 AZ DB 클러스터 배포를 사용합니다. 2개의 읽기 전용 복제본을 생성하고 읽기 워크로드를 읽기 전용 복제본으로 지정합니다.
- [ ] C. Amazon RDS 다중 AZ DB 인스턴스 배포를 사용합니다. 읽기 워크로드가 다중 AZ 쌍의 보조 인스턴스를 가리키도록 합니다.
- [ ] D. Amazon RDS 다중 AZ DB 클러스터 배포를 사용합니다. 읽기 워크로드를 리더 엔드포인트로 지정합니다.

## Answer

정답: D

## Explanation

Amazon RDS 다중 AZ DB 클러스터 배포는 1개의 쓰기 인스턴스와 2개의 읽기 가능한 대기 인스턴스를 3개의 가용 영역에 걸쳐 배치합니다. 대부분의 시나리오에서 35초 이내에 자동 장애 조치를 지원하며, 리더 엔드포인트를 통해 읽기 워크로드를 2개의 리더 인스턴스로 오프로드할 수 있습니다. 별도의 읽기 복제본을 추가로 생성할 필요가 없으므로 비용이 가장 낮습니다.

오답 분석

A: 다중 AZ DB 인스턴스 배포에 별도의 읽기 복제본을 추가하면 추가 비용이 발생합니다. 다중 AZ DB 인스턴스의 대기 인스턴스는 읽기 트래픽을 처리할 수 없으므로 별도의 읽기 복제본이 필요하여 비용이 증가합니다.

B: 다중 AZ DB 클러스터 배포에는 이미 2개의 리더 인스턴스가 포함되어 있으므로, 추가로 2개의 읽기 전용 복제본을 생성하면 불필요한 비용이 발생합니다.

C: 다중 AZ DB 인스턴스 배포의 보조(대기) 인스턴스는 읽기 트래픽을 처리할 수 없습니다. 대기 인스턴스는 장애 조치 목적으로만 사용되므로 읽기 오프로드 요구 사항을 충족할 수 없습니다.
