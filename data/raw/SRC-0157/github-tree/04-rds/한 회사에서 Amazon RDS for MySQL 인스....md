## Question

한 회사에서 Amazon RDS for MySQL 인스턴스를 사용합니다. 연말 처리를 준비하기 위해 이 회사는 회사의 보고 도구에서 추가 읽기 전용 쿼리를 수용하기 위해 읽기 복제본을 추가했습니다. 읽기 복제본 CPU 사용량은 60%이고 기본 인스턴스 CPU 사용량은 60%였습니다. 연말 활동이 완료된 후 읽기 복제본의 CPU 사용량은 일정하게 25%입니다. 기본 인스턴스의 CPU 사용량은 여전히 일정하게 60%입니다. 이 회사는 데이터베이스 크기를 조정하고 향후 성장에 충분한 성능을 제공하고자 합니다.
어떤 솔루션이 이러한 요구 사항을 충족할까요?

- [ ] A. 읽기 전용 복제본을 삭제합니다. 기본 인스턴스는 변경하지 마세요.
- [ ] B. 읽기 전용 복제본을 더 작은 인스턴스 크기로 조정합니다. 기본 인스턴스는 변경하지 마세요.
- [ ] C. 읽기 전용 복제본을 더 큰 인스턴스 크기로 조정합니다. 기본 인스턴스를 더 작은 인스턴스 크기로 조정합니다.
- [ ] D. 읽기 전용 복제본을 삭제합니다. 기본 인스턴스를 더 큰 인스턴스로 조정합니다.

## Answer

정답: B

## Explanation

연말 처리 후 읽기 전용 복제본의 CPU 사용률이 60%에서 25%로 크게 감소하여 현재 인스턴스가 과도하게 프로비저닝되었으므로, 더 작은 인스턴스 크기로 리사이징하면 불필요한 용량에 대한 비용을 상당히 절감할 수 있습니다. 기본 인스턴스는 CPU 60%로 적절하게 활용되고 있어 변경이 필요 없으며, 향후 보고 쿼리 증가에 대비하여 복제본 자체는 유지합니다.

오답 분석

A: 읽기 전용 복제본을 완전히 삭제하면 향후 보고 도구의 읽기 쿼리를 처리할 수 없으며, 기본 인스턴스에 부하가 집중됩니다.

C: 복제본을 더 크게 조정하면 비용이 더 증가하고, 기본 인스턴스를 축소하면 60% 사용률에서 성능 문제가 발생합니다.

D: 복제본을 삭제하고 기본 인스턴스를 확대하면 보고 쿼리가 기본 인스턴스에 집중되어 프로덕션 성능에 영향을 줍니다.
