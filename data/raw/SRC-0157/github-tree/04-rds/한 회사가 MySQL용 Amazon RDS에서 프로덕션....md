## Question

한 회사가 MySQL용 Amazon RDS에서 프로덕션 데이터베이스를 실행하고 있습니다. 회사에서는 보안 규정 준수를 위해 데이터베이스 버전을 업그레이드하려고 합니다. 데이터베이스에는 중요한 데이터가 포함되어 있으므로 회사에서는 데이터 손실 없이 기능을 업그레이드하고 테스트할 수 있는 빠른 솔루션을 원합니다.
최소한의 운영 오버헤드로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. RDS 수동 스냅샷을 생성합니다. MySQL용 Amazon RDS의 새 버전으로 업그레이드합니다.
- [ ] B. 기본 백업 및 복원을 사용합니다. 업그레이드된 새 버전의 MySQL용 Amazon RDS로 데이터를 복원합니다.
- [ ] C. AWS Database Migration Service(AWS DMS)를 사용하여 업그레이드된 새 버전의 MySQL용 Amazon RDS에 데이터를 복제합니다.
- [ ] D. Amazon RDS 블루/그린 배포를 사용하여 프로덕션 변경 사항을 배포하고 테스트합니다.

## Answer

정답: D

## Explanation

Amazon RDS 블루/그린 배포를 사용하면 프로덕션(블루) 환경의 복사본인 스테이징(그린) 환경을 생성하여 데이터베이스 버전 업그레이드를 안전하게 테스트할 수 있습니다. 그린 환경에서 업그레이드된 버전을 테스트한 후, 준비가 되면 1분 이내의 다운타임으로 전환(switchover)할 수 있습니다. 중요한 데이터가 포함된 데이터베이스에서 데이터 손실 없이 업그레이드하고 기능을 테스트할 수 있어 운영 오버헤드가 최소화됩니다.

오답 분석

A: RDS 수동 스냅샷을 생성한 후 직접 업그레이드하면 업그레이드 후 문제가 발생할 경우 롤백이 복잡합니다. 스냅샷은 백업 용도로는 좋지만, 업그레이드 전에 기능을 테스트하는 메커니즘을 제공하지 않습니다.

B: 네이티브 백업 및 복원으로 새 버전에 데이터를 복원하면 별도의 인스턴스를 수동으로 생성하고 관리해야 하며, 데이터 동기화가 자동으로 이루어지지 않아 운영 오버헤드가 높습니다.

C: AWS DMS를 사용하여 새 버전으로 데이터를 복제하면 DMS 태스크의 설정, 모니터링 및 관리가 필요하여 운영 오버헤드가 증가합니다. 블루/그린 배포가 이 과정을 자동화합니다.
