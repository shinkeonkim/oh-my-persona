## Question

한 회사는 AWS에서 서버리스 애플리케이션을 운영하며, 이 애플리케이션은 백엔드 데이터베이스로 Amazon RDS를 사용합니다. 애플리케이션은 때때로 예측할 수 없는 급격한 트래픽 증가를 겪습니다. 트래픽이 증가할 때마다 애플리케이션은 데이터베이스에 대해 자주 연결을 열고 닫으며, 이로 인해 데이터베이스로부터 오류를 받거나 연결이 부족해지는 문제가 발생합니다.
회사는 애플리케이션이 항상 확장 가능하고 고가용성을 유지할 수 있도록 해야 합니다.
어떤 해결책이 이러한 요구사항을 충족시키며 애플리케이션의 코드 변경 없이 가능할까요?

- [ ] A. 서버리스 애플리케이션의 RDS 데이터베이스의 옵션 그룹에서 최대 연결 수를 증가시킵니다.
- [ ] B. RDS DB 인스턴스의 인스턴스 크기를 최대 부하 트래픽에 맞게 증가시킵니다.
- [ ] C. 서버리스 애플리케이션과 Amazon RDS 사이에 Amazon RDS 프록시를 배포합니다.
- [ ] D. Amazon RDS에 대한 예약 인스턴스를 구매하여 최대 부하 트래픽 시에도 데이터베이스를 고가용성으로 유지합니다.

## Answer

정답: C

## Explanation

Amazon RDS Proxy를 서버리스 애플리케이션과 Amazon RDS 사이에 배포하면 연결 풀링을 통해 데이터베이스 연결을 효율적으로 관리할 수 있습니다. 예측할 수 없는 트래픽 급증 시에도 RDS Proxy가 연결을 재사용하고 대기열에 넣어 데이터베이스가 오류를 반환하거나 연결이 부족해지는 문제를 방지합니다. RDS Proxy는 애플리케이션 코드 변경 없이 엔드포인트만 변경하면 되므로 요구 사항을 충족합니다.

오답 분석

A: 옵션 그룹에서 최대 연결 수를 증가시키는 것만으로는 서버리스 환경의 급격한 연결 수 변동을 효과적으로 처리할 수 없으며, 연결 풀링 기능을 제공하지 않습니다.

B: RDS DB 인스턴스의 크기를 증가시키면 더 많은 동시 연결을 허용할 수 있지만, 서버리스 애플리케이션의 급격한 스케일링으로 인한 연결 관리 문제를 근본적으로 해결하지 못하며 비용 효율적이지 않습니다.

D: 예약 인스턴스 구매는 비용 절감을 위한 것이며, 데이터베이스의 고가용성이나 연결 관리 문제와는 관련이 없습니다.
