## Question

금융 서비스 회사는 Amazon RDS for MySQL 데이터베이스를 사용하는 새로운 애플리케이션을 출시했습니다. 회사는 애플리케이션을 사용하여 주식 시장 추세를 추적합니다. 회사는 매주 말 2시간 동안만 애플리케이션을 작동하면 됩니다. 회사는 데이터베이스 실행 비용을 최적화해야 합니다.
이러한 요구 사항을 가장 비용 효율적으로 충족하는 솔루션은 무엇입니까?

- [ ] A. 기존 RDS for MySQL 데이터베이스를 Aurora Serverless v2 MySQL 데이터베이스 클러스터로 마이그레이션합니다.
- [ ] B. 기존 RDS for MySQL 데이터베이스를 Aurora MySQL 데이터베이스 클러스터로 마이그레이션합니다.
- [ ] C. 기존 RDS for MySQL 데이터베이스를 MySQL을 실행하는 Amazon EC2 인스턴스로 마이그레이션합니다. EC2 인스턴스에 대한 인스턴스 예약을 구매합니다.
- [ ] D. 기존 RDS for MySQL 데이터베이스를 MySQL 컨테이너 이미지를 사용하여 작업을 실행하는 Amazon Elastic Container Service(Amazon ECS) 클러스터로 마이그레이션합니다.

## Answer

정답: A

## Explanation

Aurora Serverless v2 MySQL 데이터베이스 클러스터로 마이그레이션하면 주당 2시간만 사용하는 워크로드에서 비용을 크게 절감할 수 있습니다. Aurora Serverless v2는 사용하지 않는 시간에 최소 ACU로 자동 축소되어 초 단위로 비용이 청구됩니다. MySQL 호환이므로 기존 RDS for MySQL에서 마이그레이션이 용이하며, 사용 패턴에 자동으로 적응합니다.

오답 분석

B: Aurora MySQL 데이터베이스 클러스터(프로비저닝)는 고정 인스턴스 비용이 지속적으로 발생하므로, 주당 2시간만 사용하는 워크로드에서는 나머지 166시간 동안 비용이 낭비됩니다.

C: MySQL을 실행하는 EC2 인스턴스에 인스턴스 예약을 구매하면 관리형 서비스의 이점을 잃으며, 주당 2시간만 사용하는 워크로드에 예약 인스턴스는 비용 효율적이지 않습니다. 또한 EC2 인스턴스 관리 오버헤드가 발생합니다.

D: Amazon ECS에서 MySQL 컨테이너를 실행하면 데이터베이스 관리의 복잡성이 크게 증가합니다. 데이터 영속성, 백업, 고가용성 등을 직접 구성해야 하며, 관리형 데이터베이스 서비스의 이점을 활용할 수 없습니다.
