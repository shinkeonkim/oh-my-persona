## Question

한 회사가 최근 모놀리식 애플리케이션을 Amazon EC2 인스턴스와 Amazon RDS로 마이그레이션했습니다. 이 애플리케이션에는 밀접하게 결합된 모듈이 있습니다. 애플리케이션의 기존 설계는 애플리케이션이 단일 EC2 인스턴스에서만 실행될 수 있는 기능을 제공합니다. 이 회사는 피크 사용 시간 동안 EC2 인스턴스에서 높은 CPU 사용률을 발견했습니다. 높은 CPU 사용률은 읽기 요청에 대한 Amazon RDS의 성능 저하에 해당합니다. 이 회사는 높은 CPU 사용률을 줄이고 읽기 요청 성능을 개선하고자 합니다.
어떤 솔루션이 이러한 요구 사항을 충족할까요?

- [ ] A. EC2 인스턴스를 CPU 용량이 더 많은 EC2 인스턴스 유형으로 크기 조정합니다. 최소 및 최대 크기가 1인 Auto Scaling 그룹을 구성합니다. 읽기 요청에 대한 RDS 읽기 복제본을 구성합니다.
- [ ] B. EC2 인스턴스의 크기를 CPU 용량이 더 많은 EC2 인스턴스 유형으로 조정합니다. 최소 및 최대 크기가 1인 Auto Scaling 그룹을 구성합니다. RDS 읽기 복제본을 추가하고 모든 읽기/쓰기 트래픽을 복제본으로 리디렉션합니다.
- [ ] C. 최소 크기 1, 최대 크기 2로 Auto Scaling 그룹을 구성합니다. CPU 용량이 더 많은 인스턴스 유형으로 RDS DB 인스턴스 크기를 조정합니다.
- [ ] D. EC2 인스턴스를 CPU 용량이 더 많은 EC2 인스턴스 유형으로 크기 조정합니다. 최소 및 최대 크기가 1인 Auto Scaling 그룹을 구성합니다. RDS DB 인스턴스를 CPU 용량이 더 많은 인스턴스 유형으로 크기 조정합니다.

## Answer

정답: A

## Explanation

모놀리식 애플리케이션은 단일 EC2 인스턴스에서만 실행 가능하므로, CPU 용량이 더 큰 인스턴스 유형으로 리사이징하여 CPU 사용률을 줄입니다. Auto Scaling 그룹의 최소/최대를 1로 설정하면 인스턴스 장애 시 자동 복구가 됩니다. RDS 읽기 전용 복제본으로 읽기 요청 성능을 개선합니다.

오답 분석

B: 모든 읽기/쓰기 트래픽을 읽기 전용 복제본으로 리디렉션하면 쓰기 작업이 실패하며, 복제본은 읽기 전용입니다.

C: Auto Scaling 최대 2로 설정해도 모놀리식 애플리케이션이 단일 인스턴스에서만 실행 가능하므로 확장이 불가능하며, RDS 인스턴스 크기 변경은 읽기 성능 문제를 직접 해결하지 않습니다.

D: 이 옵션은 EC2 및 RDS 인스턴스 모두를 더 큰 CPU 용량으로 리사이징하지만, 읽기 전용 복제본을 추가하지 않습니다. 별도의 인스턴스로 읽기 트래픽을 분산하지 않으면 기본 데이터베이스의 읽기 요청 성능 저하 문제가 해결되지 않습니다.
