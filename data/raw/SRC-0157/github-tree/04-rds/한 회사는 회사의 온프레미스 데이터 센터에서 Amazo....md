## Question

한 회사는 회사의 온프레미스 데이터 센터에서 Amazon RDS for MySQL DB 인스턴스로 MySQL 데이터베이스를 마이그레이션했습니다. 회사는 회사의 일일 평균 워크로드를 충족하도록 RDS DB 인스턴스의 크기를 조정했습니다. 한 달에 한 번 회사에서 보고서에 대한 쿼리를 실행할 때 데이터베이스 성능이 느려집니다. 회사는 보고서를 실행하고 일일 작업 부하의 성능을 유지 관리할 수 있는 기능을 원합니다.
어떤 솔루션이 이러한 요구 사항을 충족합니까?

- [ ] A. 데이터베이스의 읽기 전용 복제본을 생성합니다. 쿼리를 읽기 전용 복제본으로 보냅니다.
- [ ] B. 데이터베이스 백업을 생성합니다. 백업을 다른 DB 인스턴스로 복원합니다. 쿼리를 새 데이터베이스로 보냅니다.
- [ ] C. 데이터를 Amazon S3로 내보냅니다. Amazon Athena를 사용하여 S3 버킷을 쿼리합니다.
- [ ] D. 추가 워크로드를 수용할 수 있도록 DB 인스턴스의 크기를 조정합니다.

## Answer

정답: A

## Explanation

데이터베이스의 읽기 전용 복제본을 생성하고 보고서 쿼리를 복제본으로 보내면, 한 달에 한 번 실행되는 보고서가 일일 작업 부하의 성능에 영향을 주지 않습니다. 읽기 복제본은 기본 인스턴스에서 비동기식으로 데이터를 복제하므로, 보고 쿼리의 부하가 기본 인스턴스에 전달되지 않아 일일 워크로드의 성능을 유지할 수 있습니다.

오답 분석

B: 데이터베이스 백업을 복원하여 별도의 DB 인스턴스를 생성하는 방식은 매번 수동으로 복원 작업을 수행해야 하며, 복원 시점 이후의 데이터 변경 사항이 반영되지 않습니다.

C: 데이터를 Amazon S3로 내보내고 Athena를 사용하는 방식은 데이터 변환 및 내보내기 프로세스가 필요하며, 관계형 쿼리와 동일한 결과를 얻기 위해 추가 작업이 필요합니다.

D: DB 인스턴스의 크기를 조정하면 비용이 증가하고, 월 1회 보고서를 위해 항상 큰 인스턴스를 유지하는 것은 비용 효율적이지 않습니다.
