## Question

회사에는 Oracle 데이터베이스를 사용하여 고객 정보를 처리하고 저장하는 온프레미스 서버가 있습니다. 이 회사는 AWS 데이터베이스 서비스를 사용하여 더 높은 가용성을 달성하고 애플리케이션 성능을 개선하고자 합니다. 회사는 또한 기본 데이터베이스 시스템에서 보고를 오프로드하려고 합니다.
운영상 가장 효율적인 방식으로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. AWS Database Migration Service(AWS DMS)를 사용하여 여러 AWS 리전에서 Amazon RDS DB 인스턴스를 생성합니다. 보고 기능은 기본 DB 인스턴스와 별도의 DB 인스턴스를 가리킵니다.
- [ ] B. 단일 AZ 배포에서 Amazon RDS를 사용하여 Oracle 데이터베이스를 생성합니다. 기본 DB 인스턴스와 동일한 영역에 읽기 전용 복제본을 생성합니다. 보고 기능을 읽기 전용 복제본으로 지정합니다.
- [ ] C. 다중 AZ 클러스터 배포에 배포된 Amazon RDS를 사용하여 Oracle 데이터베이스를 생성합니다. 클러스터 배포에서 리더 인스턴스를 사용하도록 보고 기능에 지시합니다.
- [ ] D. 다중 AZ 인스턴스 배포에 배포된 Amazon RDS를 사용하여 Amazon Aurora 데이터베이스를 생성합니다. 보고 기능을 리더 인스턴스로 지시합니다.

## Answer

정답: D

## Explanation

Amazon Aurora는 분산 스토리지 아키텍처를 통해 기본적으로 여러 가용 영역에 걸쳐 고가용성을 제공합니다. Aurora는 자체적으로 세 개의 AZ에 걸쳐 데이터를 복제하므로 별도의 'Multi-AZ 인스턴스 배포' 구성이 필요하지 않습니다. Aurora 리더 인스턴스(Aurora Replica)는 보고 워크로드를 기본 인스턴스에서 분리할 수 있으며, AWS DMS를 통해 Oracle 데이터를 Aurora로 마이그레이션할 수 있습니다. 참고: 옵션 D의 'Multi-AZ 인스턴스 배포로 배포'라는 표현은 Aurora에 기술적으로 정확하지 않지만(Aurora는 RDS Multi-AZ 인스턴스 배포 모델이 아닌 자체 클러스터 아키텍처를 사용), 리더 인스턴스를 활용한 고가용성 및 보고 목적의 Aurora 사용이라는 의도는 정확하며 가장 운영 효율적입니다.

오답 분석

A: 여러 AWS 리전에 RDS DB 인스턴스를 생성하면 불필요한 복잡성과 비용이 증가합니다. 보고 기능을 분리하기 위해 다른 리전까지 사용할 필요는 없습니다.

B: 단일 AZ 배포는 고가용성을 제공하지 않으며, 동일 영역의 읽기 전용 복제본은 가용 영역 장애 시 보호를 제공하지 않습니다.

C: RDS Multi-AZ 클러스터 배포에서 Oracle은 지원되지 않습니다. Multi-AZ 클러스터 배포는 MySQL과 PostgreSQL에서만 사용 가능합니다.
