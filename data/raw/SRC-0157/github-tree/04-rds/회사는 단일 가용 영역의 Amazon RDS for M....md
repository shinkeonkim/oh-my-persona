## Question

회사는 단일 가용 영역의 Amazon RDS for MySQL DB 인스턴스에 저장된 온라인 광고 비즈니스용 대규모 데이터 세트를 보유하고 있습니다. 회사는 프로덕션 DB 인스턴스에 대한 쓰기 작업에 영향을 주지 않고 비즈니스 보고 쿼리를 실행하기를 원합니다.
어떤 솔루션이 이러한 요구 사항을 충족합니까?

- [ ] A. RDS 읽기 복제본을 배포하여 비즈니스 보고 쿼리를 처리합니다.
- [ ] B. DB 인스턴스를 Elastic Load Balancer 뒤에 배치하여 수평으로 확장합니다.
- [ ] C. DB 인스턴스를 더 큰 인스턴스 유형으로 확장하여 쓰기 작업 및 쿼리를 처리합니다.
- [ ] D. 비즈니스 보고 쿼리를 처리하기 위해 여러 가용 영역에 DB 인스턴스를 배포합니다.

## Answer

정답: A

## Explanation

RDS 읽기 복제본을 배포하면 비즈니스 보고 쿼리를 프로덕션 DB 인스턴스의 쓰기 작업에 영향을 주지 않고 실행할 수 있습니다. 읽기 복제본은 기본 인스턴스에서 비동기식으로 데이터를 복제하며, 보고 쿼리를 읽기 복제본으로 분리하면 기본 인스턴스는 쓰기 작업에만 집중할 수 있습니다. 이는 AWS에서 권장하는 읽기-쓰기 워크로드 분리 패턴입니다.

오답 분석

B: DB 인스턴스를 Elastic Load Balancer 뒤에 배치하여 수평 확장하는 것은 RDS에서 지원되지 않는 아키텍처입니다. ELB는 EC2 인스턴스나 컨테이너의 로드 밸런싱에 사용됩니다.

C: DB 인스턴스를 더 큰 인스턴스 유형으로 확장하면 전체 성능은 향상되지만, 보고 쿼리가 여전히 같은 인스턴스에서 실행되므로 쓰기 작업에 영향을 줄 수 있습니다.

D: Multi-AZ 배포는 고가용성을 위한 것이며, 대기 인스턴스는 보고 쿼리를 처리할 수 없습니다. Multi-AZ DB 인스턴스 배포에서 보조 인스턴스는 장애 조치 시에만 활성화됩니다.
