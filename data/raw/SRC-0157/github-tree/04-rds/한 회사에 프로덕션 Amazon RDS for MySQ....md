## Question

한 회사에 프로덕션 Amazon RDS for MySQL 데이터베이스가 있습니다. 이 회사는 데이터베이스의 전반적인 성능에 미치는 영향을 최소화하면서 자주 변경되는 데이터를 데이터베이스에서 읽어오는 새로운 애플리케이션을 만들어야 합니다. 이 애플리케이션은 동일한 쿼리를 두 번 이상 수행하는 경우가 거의 없습니다.
솔루션 아키텍트는 이러한 요구 사항을 충족하기 위해 무엇을 해야 합니까?

- [ ] A. Amazon ElastiCache 클러스터를 설정합니다. 클러스터에서 결과를 쿼리합니다.
- [ ] B. 애플리케이션 로드 밸런서(ALB)를 설정합니다. ALB에서 결과를 쿼리합니다.
- [ ] C. 데이터베이스에 대한 읽기 전용 복제본을 설정합니다. 읽기 전용 복제본을 쿼리합니다.
- [ ] D. 데이터베이스 스냅샷 쿼리를 설정합니다. 데이터베이스 스냅샷을 쿼리합니다.

## Answer

정답: C

## Explanation

RDS for MySQL의 읽기 전용 복제본(Read Replica)을 설정하면 새 애플리케이션의 읽기 쿼리를 복제본으로 분리하여 기본 데이터베이스의 성능에 최소한의 영향을 줍니다. 데이터가 자주 변경되므로 복제본은 거의 실시간으로 데이터를 동기화하며, 동일한 쿼리를 거의 반복하지 않으므로 캐싱보다 복제본이 적합합니다.

오답 분석

A: ElastiCache는 동일한 쿼리를 반복 실행할 때 효과적이지만, 거의 같은 쿼리를 반복하지 않으면 캐시 히트율이 매우 낮아 효과가 없습니다.

B: Application Load Balancer는 HTTP/HTTPS 트래픽 분산용이며, 데이터베이스 쿼리 분산과는 관련이 없습니다.

D: 데이터베이스 스냅샷은 특정 시점의 정적 복사본이므로 자주 변경되는 데이터를 실시간으로 쿼리하는 데 적합하지 않습니다.
