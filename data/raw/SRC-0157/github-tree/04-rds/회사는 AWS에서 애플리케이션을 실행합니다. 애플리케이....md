## Question

회사는 AWS에서 애플리케이션을 실행합니다. 애플리케이션이 일관되지 않은 사용량을 수신합니다. 애플리케이션은 AWS Direct Connect를 사용하여 온프레미스 MySQL 호환 데이터베이스에 연결합니다. 온프레미스 데이터베이스는 지속적으로 최소 2GiB의 메모리를 사용합니다.
회사는 온프레미스 데이터베이스를 관리형 AWS 서비스로 마이그레이션하려고 합니다. 회사는 자동 확장 기능을 사용하여 예기치 않은 작업 부하 증가를 관리하려고 합니다.
최소한의 관리 오버헤드로 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

- [ ] A. 기본 읽기 및 쓰기 용량 설정으로 Amazon DynamoDB 데이터베이스를 프로비저닝합니다.
- [ ] B. 최소 용량이 1 Aurora 용량 단위(ACU)인 Amazon Aurora 데이터베이스를 프로비저닝합니다.
- [ ] C. 최소 용량이 1 Aurora 용량 단위(ACU)인 Amazon Aurora Serverless v2 데이터베이스를 프로비저닝합니다.
- [ ] D. 2GiB의 메모리로 Amazon RDS for MySQL 데이터베이스를 프로비저닝합니다.

## Answer

정답: C

## Explanation

Amazon Aurora Serverless v2는 0.5 ACU 단위로 세밀하게 자동 확장이 가능하며, 최소 1 ACU(약 2GiB 메모리)를 설정하면 온프레미스 데이터베이스의 최소 2GiB 메모리 요구 사항을 충족합니다. Aurora Serverless v2는 MySQL 호환이므로 기존 MySQL 데이터베이스에서 마이그레이션이 용이하며, 예기치 않은 워크로드 증가에 자동으로 대응할 수 있어 관리 오버헤드가 최소화됩니다.

오답 분석

A: Amazon DynamoDB는 NoSQL 데이터베이스로, MySQL 호환 데이터베이스에서의 마이그레이션에 적합하지 않습니다. 스키마와 쿼리 패턴을 완전히 재설계해야 하며, 이는 관리 오버헤드를 증가시킵니다.

B: Amazon Aurora 데이터베이스(프로비저닝)는 자동 확장 기능이 Aurora Serverless v2만큼 유연하지 않습니다. ACU 기반 자동 확장이 아닌 인스턴스 크기 변경이 필요하여 예기치 않은 워크로드 변동에 즉각적으로 대응하기 어렵습니다.

D: Amazon RDS for MySQL은 고정 인스턴스 크기를 사용하며 자동 확장 기능이 없어 예기치 않은 워크로드 증가에 자동으로 대응할 수 없습니다.
