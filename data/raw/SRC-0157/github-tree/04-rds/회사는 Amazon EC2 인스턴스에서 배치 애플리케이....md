## Question

회사는 Amazon EC2 인스턴스에서 배치 애플리케이션을 실행하고 있습니다. 애플리케이션은 여러 Amazon RDS 데이터베이스가 있는 백엔드로 구성됩니다. 애플리케이션으로 인해 데이터베이스에서 많은 수의 읽기가 발생하고 있습니다. 솔루션 설계자는 고가용성을 보장하면서 데이터베이스 읽기 수를 줄여야 합니다.
솔루션 설계자는 이 요구 사항을 충족하기 위해 무엇을 해야 합니까?

- [ ] A. Amazon RDS 읽기 전용 복제본을 추가합니다.
- [ ] B. Redis용 Amazon ElastiCache를 사용합니다.
- [ ] C. Amazon Route 53 DNS 캐싱을 사용합니다.
- [ ] D. Memcached용 Amazon ElastiCache를 사용합니다.

## Answer

정답: A

## Explanation

Amazon RDS 읽기 전용 복제본을 추가하면 배치 애플리케이션의 높은 읽기 부하를 분산할 수 있습니다. 읽기 전용 복제본은 기본 DB 인스턴스에서 비동기식으로 복제되며, 읽기 트래픽을 복제본으로 분산하여 기본 인스턴스의 부하를 줄입니다. 읽기 복제본은 여러 가용 영역에 걸쳐 배포할 수 있어 고가용성도 보장됩니다.

오답 분석

B: Redis용 Amazon ElastiCache는 캐싱 솔루션으로 자주 액세스되는 데이터를 캐시하는 데 유용하지만, 배치 애플리케이션의 다양한 읽기 쿼리 패턴에서는 캐시 적중률이 낮을 수 있으며, 데이터 일관성 관리가 복잡해집니다.

C: Amazon Route 53 DNS 캐싱은 DNS 쿼리를 캐시하는 것으로, 데이터베이스 읽기 부하를 줄이는 것과는 무관합니다.

D: Memcached용 Amazon ElastiCache도 캐싱 솔루션이지만, Redis에 비해 데이터 지속성이나 복제 기능이 부족하여 고가용성 보장에 적합하지 않습니다.
