## Question

패키지 배송 회사에는 Amazon EC2 인스턴스와 Amazon Aurora MySQL DB 클러스터를 사용하는 애플리케이션이 있습니다. 애플리케이션이 대중화되면서 EC2 인스턴스 사용량은 약간만 증가합니다. DB 클러스터 사용량이 훨씬 빠른 속도로 증가합니다.
회사에서는 단기간 동안 DB 클러스터 사용량을 줄이는 읽기 전용 복제본을 추가합니다. 그러나 부하가 계속 증가합니다. DB 클러스터 사용량을 증가시키는 작업은 모두 전송 세부 사항과 관련된 반복 읽기 명령문입니다. 회사에서는 DB 클러스터에 대한 반복 읽기의 영향을 완화해야 합니다.
이러한 요구 사항을 가장 비용 효율적으로 충족하는 솔루션은 무엇입니까?

- [ ] A. 애플리케이션과 DB 클러스터 사이에 Redis용 Amazon ElastiCache 클러스터를 구현합니다.
- [ ] B. DB 클러스터에 추가 읽기 전용 복제본을 추가합니다.
- [ ] C. Aurora 읽기 전용 복제본을 위한 Aurora Auto Scaling을 구성합니다.
- [ ] D. 여러 개의 라이터 인스턴스를 갖도록 DB 클러스터를 수정합니다.

## Answer

정답: A

## Explanation

Amazon ElastiCache for Redis를 애플리케이션과 DB 클러스터 사이에 구현하면, 반복적인 읽기 요청(배송 세부 사항 조회)을 캐시에서 처리하여 데이터베이스 부하를 크게 줄일 수 있습니다. 읽기 전용 복제본을 추가해도 부하가 계속 증가한다는 것은 동일한 데이터에 대한 반복 읽기가 근본적인 문제이며, 이는 캐싱으로 가장 효과적으로 해결됩니다. ElastiCache는 인메모리 캐시로 밀리초 미만의 응답 시간을 제공하여 가장 비용 효율적인 솔루션입니다.

오답 분석

B: 추가 읽기 전용 복제본은 이미 단기간만 효과가 있었으며, 반복 읽기 패턴에서는 근본적인 해결책이 되지 않습니다. 복제본 추가 비용도 계속 증가합니다.

C: Aurora Auto Scaling으로 복제본을 자동 확장할 수 있지만, 반복 읽기는 캐싱이 더 효과적이며 비용 효율적입니다. 복제본 확장은 비용이 더 많이 듭니다.

D: 여러 라이터 인스턴스는 쓰기 성능 향상을 위한 것이며, 읽기 반복 문제를 해결하지 않습니다.
