## Question

회사는 Amazon RDS에서 지원하는 웹 애플리케이션을 실행합니다. 새로운 데이터베이스 관리자가 실수로 데이터베이스 테이블의 정보를 편집하여 데이터 손실을 일으켰습니다. 이러한 유형의 사고에서 복구하는 데 도움이 되도록 회사는 지난 30일 동안 변경이 발생하기 5분 전의 상태로 데이터베이스를 복원할 수 있는 기능을 원합니다.
이 요구 사항을 충족하기 위해 솔루션 설계자는 어떤 기능을 디자인에 포함해야 합니까?

- [ ] A. 읽기 복제본
- [ ] B. 수동 스냅샷
- [ ] C. 자동 백업
- [ ] D. 다중 AZ 배포

## Answer

정답: C

## Explanation

Amazon RDS 자동 백업(Automated Backups)은 특정 시점 복구(Point-in-Time Recovery, PITR)를 지원합니다. RDS는 트랜잭션 로그를 5분마다 Amazon S3에 업로드하므로, 백업 보존 기간(최대 35일) 내에서 변경이 발생하기 5분 전의 상태로 데이터베이스를 복원할 수 있습니다. 자동 백업의 보존 기간을 30일로 설정하면 지난 30일 동안 5분 이내의 정밀도로 데이터베이스를 복원할 수 있어 요구 사항을 정확히 충족합니다.

오답 분석

A: 읽기 복제본은 기본 인스턴스의 읽기 부하를 분산하기 위한 것이며, 과거 특정 시점으로 데이터베이스를 복원하는 기능을 제공하지 않습니다.

B: 수동 스냅샷은 특정 시점의 전체 백업을 생성하지만, 스냅샷 생성 시점 사이의 특정 시점으로 복원하는 기능(PITR)은 제공하지 않습니다. 5분 전 상태로 복원하려면 자동 백업이 필요합니다.

D: 다중 AZ 배포는 고가용성과 자동 장애 조치를 제공하지만, 과거 특정 시점으로 데이터를 복원하는 기능은 제공하지 않습니다. 실수로 인한 데이터 손실 복구와는 다른 목적의 기능입니다.
