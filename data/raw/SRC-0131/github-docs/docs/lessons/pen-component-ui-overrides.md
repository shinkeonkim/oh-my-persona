# .pen 컴포넌트 UI 오버라이드 시 배운 점

계좌 관리 페이지에서 사이드바 메뉴 **「계좌 관리」에만 하이라이트**가 들어가도록 수정하는 과정에서 정리한 내용입니다.

---

## 1. 상황 요약

- **목표**: 계좌 관리 화면의 좌측 메뉴에서 「계좌 관리」만 활성(하이라이트)으로 보이게 하기.
- **문제**: 복사된 페이지에서는 그대로 **「대시보드」가 활성**으로 남아 있었고, `ref`만 바꿔서 해결하려 했으나 원하는 대로 동작하지 않음.

---

## 2. Pencil에서 인스턴스 속성 변경 규칙

### 2.1 `ref`는 Update로 바꿀 수 없음

- `batch_design`의 **Update(U)** 로는 노드의 **`ref` 속성을 변경할 수 없음**이 명시되어 있음.
- 따라서 「이 아이템을 Active 컴포넌트로 바꿀게요」처럼 **인스턴스가 가리키는 컴포넌트(ref)를 U()로 바꾸는 방식은 불가**.

### 2.2 인스턴스 단위 오버라이드로 “보이는 UI”만 바꾸기

- **ref는 그대로 두고**, 해당 **인스턴스 노드에만** 적용되는 속성을 덮어쓰는 방식이 유효함.
- 인스턴스( ref 노드 )에 줄 수 있는 것:
  - **인스턴스 자신의 속성**  
    예: `fill` → 이 인스턴스만 배경색/배경 없음을 지정.
  - **descendants**  
    예: `TXca3`, `xGT5g` 등 **컴포넌트 내부 노드 id**에 대한 오버라이드 → 텍스트/아이콘 색 등.

즉, **「어떤 컴포넌트를 쓰는지(ref)」는 그대로 두고, 「이 인스턴스만 어떻게 보일지」를 `fill` + `descendants`로 조정**하는 패턴이 안전하고 재현 가능함.

---

## 3. 이번 케이스: Active vs Default 스타일 차이

| 항목 | Active (dOLzc) | Default (X6nwq) |
|------|-----------------|-----------------|
| **fill** | `$--sidebar-accent` (#2a2a30) | `[]` (배경 없음) |
| **cornerRadius** | 100 (pill) | 동일 |
| **stroke** | 있음 | 동일 |
| **텍스트/아이콘 fill** | `$--sidebar-accent-foreground` | `$--sidebar-foreground` |

- **시각적 차이의 핵심**: Active는 **배경색(fill)** 이 있고, Default는 **fill: []** 로 배경이 없음.
- 따라서 「어떤 메뉴를 활성으로 보이게 할지」는 **해당 인스턴스의 `fill`(와 필요 시 텍스트/아이콘 색)** 만 바꿔도 구현 가능.

---

## 4. 적용한 해결 방법

- **대시보드 항목 (j7jVD)**  
  - `U("j7jVD", { fill: [] })`  
  - `U("j7jVD", { descendants: { TXca3: { fill: "$--sidebar-foreground" }, xGT5g: { fill: "$--sidebar-foreground" } } })`  
  → 배경 제거 + 기본 텍스트/아이콘 색 (Default처럼 보이게).

- **계좌 관리 항목 (8cBS3)**  
  - `U("8cBS3", { fill: "$--sidebar-accent" })`  
  - `U("8cBS3", { descendants: { TXca3: { fill: "$--sidebar-accent-foreground" }, xGT5g: { fill: "$--sidebar-accent-foreground" } } })`  
  → 배경 + 강조 텍스트/아이콘 (Active처럼 보이게).

- **Replace(R)** 로 ref를 바꾸는 시도는 이 환경에서 오류(예: parent 관련)가 나서 사용하지 않음. **인스턴스 속성/descendants 오버라이드만** 사용.

---

## 5. 다른 컴포넌트에 적용할 때 체크리스트

1. **스타일 차이 분석**  
   - Active/Default(또는 variant) 컴포넌트 정의를 `batch_get`으로 비교.  
   - **fill, stroke, cornerRadius, 텍스트/아이콘 fill** 등 실제로 다른 속성만 정리.

2. **ref 변경 여부**  
   - “이 인스턴스를 다른 컴포넌트로 바꾸고 싶다”면 **U()로는 불가** → R() 또는 다른 구조 변경이 필요할 수 있음.  
   - “이 인스턴스만 같은 컴포넌트인데 다르게 보이게 하고 싶다”면 **인스턴스 `fill` + `descendants`** 가 적합.

3. **오버라이드 경로**  
   - **descendants** 키는 **컴포넌트 정의 쪽 노드 id** (예: TXca3, xGT5g).  
   - **컴포넌트 루트 자신의 속성**(예: dOLzc의 fill)을 descendants로 넘길 때는, 툴/스키마에 따라 경로가 다를 수 있음.  
     → 이번 경우에는 **인스턴스 노드에 직접 `fill`** 을 주는 방식이 동작함.

4. **변수 사용**  
   - 색은 가능하면 `$--sidebar-accent`, `$--sidebar-foreground` 같은 **디자인 변수**로 맞추면 테마/다크모드와 일관되게 유지하기 쉬움.

---

## 6. 요약

| 배운 점 | 내용 |
|--------|------|
| ref 변경 | **Update로는 불가**. 인스턴스가 참조하는 컴포넌트를 바꾸려면 Replace 등 다른 방법 필요. |
| 인스턴스만 다르게 보이게 하기 | **인스턴스의 `fill` + `descendants`(텍스트/아이콘 fill 등)** 로 “이 인스턴스만” 스타일 오버라이드. |
| 스타일 분석 | Active/Default 차이는 **fill 유무·색·타이포** 등 정의를 비교해 명확히 한 뒤, 그에 맞춰 오버라이드할 속성만 선택. |
| descendants 경로 | 컴포넌트 **내부** 노드 id 사용. 루트 속성은 인스턴스 노드에 직접 주는 방식이 안정적일 수 있음. |

이 문서는 **특정 컴포넌트(사이드바 아이템)의 UI만 바꾸는 과정**에서의 경험을 정리한 것이며, 다른 .pen 컴포넌트를 수정할 때도 같은 원칙을 참고하면 됩니다.
