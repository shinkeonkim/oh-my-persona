## 구현 내용

| 문제 | 제목 | 구현 위치 | 요점 |
|---|---|---|---|
| 6-1 | 폰트 | `INHERITED_PROPERTIES`, `font_for` | `font-family` 를 상속 속성에 넣고, `<code>`/`<pre>` 는 기본 스타일시트에서 고정폭으로 |
| 6-2 | 너비/높이 | `parse_px`, `BlockLayout.layout` | `width`/`height` 를 픽셀로 읽고, `auto` 면 지금까지대로 |
| 6-3 | 클래스 선택자 | `ClassSelector` | 우선순위 10 — 태그 선택자(1)보다 큽니다 |
| 6-4 | `display` | `is_block`, `BROWSER_CSS` | 하드코딩하던 블록 태그 목록을 CSS 규칙으로 옮겼습니다 |
| 6-5 | 단축 속성 | `expand_shorthand` | `font: italic bold 100% Times` 를 네 속성으로 폅니다 |
| 6-6 | 인라인 스타일시트 | `Browser.load` | `<style>` 안의 글자를 규칙으로 읽어 뒤에 붙입니다 |
| 6-7 | 빠른 자손 선택자 | `DescendantSelector` | 조상들을 목록으로 들고 사슬을 한 번만 거슬러 올라갑니다 |
| 6-8 | 선택자 시퀀스 | `SelectorSequence`, `ident` | `span.announce` — 우선순위는 합 |
| 6-9 | `!important` | `ImportantSelector` | 같은 선언을 우선순위 +10000 으로 한 벌 더 |
| 6-10 | `:has` 선택자 | `HasSelector.prepare` | 스타일 적용 전에 트리를 한 번 훑어 조상 집합을 만듭니다 |

## 복잡도에 대한 답

**6-7 자손 선택자.** 원래 코드는 선택자 하나가 안 맞을 때마다 조상 사슬을 처음부터
다시 훑어서 O(n·d) 였습니다. 조상 선택자들을 목록으로 들고 **안쪽부터 맞춰 가며**
조상을 한 칸씩만 올리면, 사슬은 한 번만 지나가므로 O(n + d) 입니다.
`test_walks_ancestors_only_once` 가 깊이 200 짜리 트리에서 호출 횟수를 세어
확인합니다.

**6-10 `:has`.** 매칭할 때마다 서브트리를 뒤지면 요소당 O(서브트리) 라 전체가
최악 O(n²) 이 됩니다. 대신 스타일을 입히기 **전에** 트리를 한 번 훑어서, 안쪽
선택자에 맞는 노드마다 조상들을 표시해 둡니다. 이미 표시된 조상을 만나면 거기서
멈추므로 각 노드는 많아야 한 번 표시되고, 준비 단계 전체가 O(n) — 요소당 상각
O(1) 입니다. 그 뒤 `matches` 는 집합 조회 한 번이라 O(1) 입니다.

## 설계 메모

**`!important` 를 우선순위로만 풀었습니다.** 선언을 두 벌(보통/`!important`)로
나눠 두고, `!important` 쪽은 원래 선택자를 감싼 `ImportantSelector` 로 우선순위만
+10000 해서 규칙 목록에 한 번 더 넣습니다. `style()` 은 손대지 않아도 됩니다.

**6-4 가 3장의 흔적을 하나 걷어냈습니다.** `</p>` 에서 무조건 줄을 끊던 코드가
`display: inline` 을 무시했습니다. 이제 문단의 줄바꿈은 태그 이름이 아니라
`is_block(node)` 이 정합니다. `test_display_inline_joins_lines` 가 이 버그를
잡았습니다.

**6-8 때문에 낱말 읽기를 둘로 나눴습니다.** `word()` 는 값에 쓰이느라 `.` 을
삼키는데, 그러면 `span.announce` 가 통째로 태그 이름이 됩니다. 선택자 전용
`ident()` 를 따로 두어 `.` 앞에서 멈추게 했습니다.
