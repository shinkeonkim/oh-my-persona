[이전 장](https://browser.engineering/layout.html)에서 우리는 각 `pre` 요소에 회색 배경을 주었습니다. 보기에 괜찮고 기본값이 있다는 것은 _좋은_ 일이지만, 사이트들은 자신의 모습에 대해 발언권을 갖고 싶어 합니다. 웹사이트는 _캐스케이딩 스타일 시트_([CSS](https://developer.mozilla.org/en-US/docs/Web/CSS))로 그렇게 하는데, CSS는 웹 작성자가 (그리고 앞으로 보게 되겠지만 브라우저 개발자가) 웹 페이지가 어떻게 보여야 하는지 정의할 수 있게 해 줍니다.

## 함수로 파싱하기

웹 페이지가 자신의 모습을 바꾸는 한 가지 방법은 `style` 속성입니다. 예를 들어 다음은 요소의 배경색을 바꿉니다.

```
<div style="background-color:lightblue">Blue background</div>
```

그러면 다음과 같이 렌더링됩니다.

> **데모**
>
> Blue background (연한 파란색 배경 위의 텍스트)

좀 더 일반적으로 말하면, `style` 속성에는 세미콜론으로 구분된 속성–값 쌍들이 들어 있습니다. 브라우저는 이 CSS 속성–값 쌍들을 보고 요소가 어떻게 보일지, 예를 들어 배경색이 무엇일지 결정합니다.

이를 브라우저에 추가하려면 먼저 이 속성–값 쌍들을 파싱하는 것부터 시작해야 합니다. 저는 재귀적인 _파싱 함수_ 를 사용하겠습니다. 이는 복잡한 파서를 한 단계씩 쌓아 올리는 좋은 방법입니다. 핵심 아이디어는 각 파싱 함수가 파싱 중인 텍스트를 따라 나아가면서 자신이 파싱한 데이터를 반환한다는 것입니다. 데이터 종류마다 서로 다른 함수를 두고, 이들을 `CSSParser` 클래스로 정리하겠습니다. 이 클래스는 파싱 중인 텍스트와 그 안에서의 파서의 현재 위치를 저장합니다.

```python
class CSSParser:
    def __init__(self, s):
        self.s = s
        self.i = 0
```

작은 것부터 시작해 쌓아 올립시다. 공백을 위한 파싱 함수는 모든 공백 문자를 지나 인덱스 `i`를 증가시킵니다.

```python
def whitespace(self):
    while self.i < len(self.s) and self.s[self.i].isspace():
        self.i += 1
```

공백에는 의미가 없으므로 반환할 파싱 데이터가 없습니다. 하지만 속성 이름을 파싱할 때는 그것을 반환하고 싶습니다.

```python
def word(self):
    start = self.i
    while self.i < len(self.s):
        if self.s[self.i].isalnum() or self.s[self.i] in "#-.%":
            self.i += 1
        else:
            break
    if not (self.i > start):
        raise Exception("Parsing error")
    return self.s[start:self.i]
```

이 함수는 `whitespace`와 비슷하게 단어 문자[^1]를 지나며 `i`를 증가시킵니다. 다만 파싱한 데이터를 반환하기 위해 시작 위치를 저장해 두었다가 자신이 지나온 부분 문자열을 뽑아냅니다.

파싱 함수는 실패할 수 있습니다. 방금 작성한 `word` 함수는 `i`가 최소 한 글자도 나아가지 않았으면 예외를 던집니다. 그렇지 않았다면 애초에 단어를 가리키고 있지 않았다는 뜻이니까요.[^2] 마찬가지로 리터럴 콜론(또는 다른 문장 부호 문자)을 확인하려면 다음과 같이 합니다.

```python
def literal(self, literal):
    if not (self.i < len(self.s) and self.s[self.i] == literal):
        raise Exception("Parsing error")
    self.i += 1
```

파싱 함수의 훌륭한 점은 서로를 기반으로 쌓아 올릴 수 있다는 것입니다. 예를 들어 속성–값 쌍은 속성, 콜론, 값으로 이루어지며[^3] 그 사이사이에 공백이 들어갑니다.

```python
def pair(self):
    prop = self.word()
    self.whitespace()
    self.literal(":")
    self.whitespace()
    val = self.word()
    return prop.casefold(), val
```

파싱 함수를 루프 안에서 호출하면 시퀀스를 파싱할 수 있습니다. 예를 들어 `style` 속성은 속성–값 쌍의 시퀀스입니다.

```python
def body(self):
    pairs = {}
    while self.i < len(self.s):
        prop, val = self.pair()
        pairs[prop] = val
        self.whitespace()
        self.literal(";")
        self.whitespace()
    return pairs
```

이제 브라우저에서는 항상 오류 처리를 생각해야 합니다. 웹 페이지 작성자가 실수를 할 때도 있고, 우리 브라우저가 다른 브라우저는 지원하는 기능을 지원하지 않을 때도 있습니다. 그러니 파싱되지 않는 속성–값 쌍은 건너뛰고 파싱되는 것만 남겨야 합니다.

다음의 작은 함수로 건너뛸 수 있습니다. 이 함수는 주어진 문자 집합 중 하나를 만나면 멈추고 그 문자를 반환합니다(파일 끝 때문에 멈췄다면 `None`을 반환합니다).

```python
def ignore_until(self, chars):
    while self.i < len(self.s):
        if self.s[self.i] in chars:
            return self.s[self.i]
        else:
            self.i += 1
    return None
```

속성–값 쌍을 파싱하는 데 실패하면 다음 세미콜론이나 문자열 끝까지 건너뜁니다.

```python
def body(self):
    # ...
    while self.i < len(self.s):
        try:
            # ...
        except Exception:
            why = self.ignore_until([";"])
            if why == ";":
                self.literal(";")
                self.whitespace()
            else:
                break
    # ...
```

파싱 오류를 건너뛰는 것은 양날의 검입니다. 오류 메시지를 감추기 때문에 작성자가 스타일 시트를 디버깅하기 어려워지고, 파서를 디버깅하기도 어려워집니다.[^4] 그래서 대부분의 프로그래밍 상황에서 이런 "모두 잡아내는" 오류 처리는 코드 냄새입니다.

하지만 "모두 잡아내는" 오류 처리는 웹에서 특별한 이점을 갖습니다. 웹은 많은 브라우저로 이루어진 생태계이고,[^5] 그 브라우저들은 (예를 들어) 서로 다른 종류의 속성 값을 지원합니다.[^6] 어떤 브라우저에서 파싱되는 CSS가 다른 브라우저에서는 파싱되지 않을 수 있습니다. 파싱 오류를 조용히 넘기면 브라우저는 자신이 이해하지 못하는 것을 그냥 무시하고, 웹 페이지는 모든 브라우저에서 대체로 잘 동작합니다. 이 원칙은 ("포스텔의 법칙",[^7] "디지털 원칙",[^8] "견고성 원칙" 등 여러 이름으로 불리는데) 다음과 같습니다. 최대한 규격에 맞는 출력을 만들되, 최소한만 규격에 맞는 입력이라도 받아들여라.

### 더 알아보기

이 파싱 방법은 형식적으로 [LL(1)](https://en.wikipedia.org/wiki/LL_parser) 언어에 대한 재귀 하강 파싱이라고 불립니다. 이 방법을 사용하는 파서는 (많은 노력을 들인다면) [정말, 정말 빠를 수 있습니다](https://simdjson.org/). 브라우저에서 파싱이 빨라진다는 것은 페이지가 더 빨리 로드된다는 뜻입니다.

## `style` 속성

이제 `style` 속성이 파싱되었으니, 그 파싱된 정보를 브라우저의 나머지 부분에서 사용할 수 있습니다. 파싱된 `style` 속성을 노드의 `style` 필드에 저장하는 `style` 함수 안에서 그 일을 해 봅시다.

```python
def style(node):
    node.style = {}
    if isinstance(node, Element) and "style" in node.attributes:
        pairs = CSSParser(node.attributes["style"]).body()
        for property, value in pairs.items():
            node.style[property] = value
```

이 메서드는 HTML 트리를 재귀적으로 순회하면서 모든 요소가 스타일을 갖도록 할 수 있습니다.

```python
def style(node):
    # ...
    for child in node.children:
        style(child)
```

브라우저의 `load` 메서드에서 HTML을 파싱한 뒤 레이아웃을 하기 전에 `style`을 호출하세요. 각 요소에 `style` 정보가 저장되어 있으면, 브라우저는 페인트 중에 스타일 정보를 얻기 위해 그것을 참조할 수 있습니다.

```python
class BlockLayout:
    def paint(self):
        # ...
        bgcolor = self.node.style.get("background-color",
                                      "transparent")
        if bgcolor != "transparent":
            x2, y2 = self.x + self.width, self.y + self.height
            rect = DrawRect(self.x, self.y, x2, y2, bgcolor)
            cmds.append(rect)
        # ...
```

지금은 `pre` 요소의 기본 회색 배경을 제거했지만, 곧 다시 넣을 것입니다.

[이 장의 웹 버전](https://browser.engineering/styles.html)을 여러분의 브라우저로 열어 코드를 시험해 보세요. 장 앞부분의 코드 블록이 이제 연한 파란색 배경을 가져야 합니다.

이것이 웹 페이지가 자신의 모습을 바꾸는 한 가지 방법입니다. 그리고 웹 초창기에는[^9] 이런 방식이 _유일한_ 방법이었습니다. 하지만 솔직히 말해 이것은 번거롭습니다. 각 요소마다 `style` 속성을 설정해야 하고, 페이지를 다시 디자인하면 고쳐야 할 속성이 아주 많아집니다. CSS는 바로 이런 상황을 개선하기 위해 발명되었습니다.

- 하나의 CSS 파일로 여러 웹 페이지에 일관되게 스타일을 줄 수 있습니다.

- CSS 한 줄로 여러 요소에 일관되게 스타일을 줄 수 있습니다.

- CSS는 미래에도 통하며, 서로 다른 기능을 가진 브라우저들을 지원합니다.

이 목표를 이루기 위해 CSS는 `style` 속성을 서로 관련된 두 아이디어로 확장합니다. _선택자(selector)_ 와 _캐스케이딩(cascading)_ 입니다. 선택자는 속성–값 쌍 목록이 어떤 HTML 요소에 적용되는지를 나타냅니다.[^10] 이 둘을 합친 것을 _규칙(rule)_ 이라고 하며, 그림 1에 나와 있습니다.

우리 브라우저에 CSS 지원을 추가합시다. CSS 파일을 선택자와 속성–값 쌍으로 파싱하고, 페이지의 어떤 요소가 각 선택자에 맞는지 알아내고, 그 속성 값들을 요소의 `style` 필드에 복사해야 합니다.

### 더 알아보기

사실 CSS 이전에는 [`font`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/font)나 [`center`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/center) 같은 전용 _표현용 태그_ 로 페이지에 스타일을 주었습니다(이미 살펴본 `<b>`와 `<i>` 태그는 말할 것도 없고요). 구현하기는 쉬웠지만 페이지를 일관되게 유지하기는 어려웠습니다. 주로 링크를 위해 텍스트 색을 일관되게 설정할 수 있는 [`text`와 `vlink`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/body#attributes) 같은 `<body>` 속성도 있었습니다.

## 선택자

선택자에는 여러 종류가 있지만, 우리 브라우저에서는 두 가지를 지원하겠습니다. 태그 선택자(`p`는 모든 `<p>` 요소를, `ul`은 모든 `<ul>` 요소를 선택)와 자손 선택자(`article div`는 `article` 조상을 가진 모든 `div` 요소를 선택)입니다.[^11]

선택자의 내용, 예를 들어 태그 선택자의 태그 이름을 저장하기 위해 종류마다 클래스를 하나씩 두겠습니다.

```python
class TagSelector:
    def __init__(self, tag):
        self.tag = tag
```

각 선택자 클래스는 그 선택자가 요소에 매치되는지도 검사합니다.

```python
class TagSelector:
    def matches(self, node):
        return isinstance(node, Element) and self.tag == node.tag
```

자손 선택자도 비슷하게 동작합니다. 이 선택자는 두 부분으로 이루어지는데, 두 부분 모두 그 자체로 선택자입니다.

```python
class DescendantSelector:
    def __init__(self, ancestor, descendant):
        self.ancestor = ancestor
        self.descendant = descendant
```

그러면 `matches` 메서드는 재귀적이 됩니다.

```python
class DescendantSelector:
    def matches(self, node):
        if not self.descendant.matches(node): return False
        while node.parent:
            if self.ancestor.matches(node.parent): return True
            node = node.parent
        return False
```

이제 이 선택자 객체들을 만들려면 파서가 필요합니다. 이 경우 그것은 그저 또 하나의 파싱 함수일 뿐입니다.[^12]

```python
class CSSParser:
    def selector(self):
        out = TagSelector(self.word().casefold())
        self.whitespace()
        while self.i < len(self.s) and self.s[self.i] != "{":
            tag = self.word()
            descendant = TagSelector(tag.casefold())
            out = DescendantSelector(out, descendant)
            self.whitespace()
        return out
```

CSS 파일은 그저 선택자와 블록의 시퀀스입니다.

```python
def parse(self):
    rules = []
    while self.i < len(self.s):
        self.whitespace()
        selector = self.selector()
        self.literal("{")
        self.whitespace()
        body = self.body()
        self.literal("}")
        rules.append((selector, body))
    return rules
```

다시 한번 오류 처리에 대해 생각해 봅시다. 첫째, CSS를 파싱하면서 `body`를 호출할 때는 닫는 중괄호에 도달하면 멈춰야 합니다.

```python
def body(self):
    # ...
    while self.i < len(self.s) and self.s[self.i] != "}":
        try:
            # ...
        except Exception:
            why = self.ignore_until([";", "}"])
            if why == ";":
                self.literal(";")
                self.whitespace()
            else:
                break
    # ...
```

둘째, 선택자를 파싱하는 도중에도 파싱 오류가 생길 수 있습니다. 그런 경우에는 규칙 전체를 건너뛰고 싶습니다.

```python
def parse(self):
    # ...
    while self.i < len(self.s):
        try:
            # ...
        except Exception:
            why = self.ignore_until(["}"])
            if why == "}":
                self.literal("}")
                self.whitespace()
            else:
                break
    # ...
```

오류 처리는 제대로 하기가 어려우니, [4장](https://browser.engineering/html.html)의 HTML 파서와 마찬가지로 파서를 반드시 테스트하세요. 다음은 마주칠 수 있는 오류들입니다.

- 출력에 일부 규칙이나 속성이 빠져 있다면, 오류 처리에 가려진 버그일 가능성이 큽니다. `try` 블록을 몇 개 제거해 보고 해당 오류를 고칠 수 있는지 확인하세요.

- 올바른 것이 뭉개진 형태의 여분 규칙이나 속성이 보인다면, 어딘가에서 `i`를 갱신하는 것을 잊었을 가능성이 큽니다.

- 무한 루프가 보인다면, 오류 처리 코드가 항상 `i`를 증가시키는지 확인하세요. (`whitespace`를 제외한) 각 파싱 함수는 항상 `i`를 증가시켜야 합니다.

각 파싱 함수의 시작과 끝[^13]에 파싱 함수의 이름,[^14] 인덱스 `i`,[^15] 그리고 파싱된 데이터를 출력하는 `print` 문을 넣어 볼 수도 있습니다. 출력이 많아지긴 하지만, 정말 복잡한 버그를 찾아내는 확실한 방법입니다.

### 더 알아보기

파서는 임의의 바이트를 입력으로 받으므로, 파서 버그는 보통 악의적인 행위자가 악용하기 쉽습니다. [수많은](https://nvd.nist.gov/vuln/detail/CVE-2010-3971) [파서](https://nvd.nist.gov/vuln/detail/CVE-2007-0943) [버그](https://nvd.nist.gov/vuln/detail/CVE-2010-1663)가 보여 주었듯이, 파서의 정확성은 브라우저 보안에 매우 중요합니다. 요즘 브라우저 개발자들은 그런 버그를 찾아 고치기 위해 [퍼징(fuzzing)](https://hacks.mozilla.org/2021/02/browser-fuzzing-at-mozilla/)을 사용합니다.

## 스타일 시트 적용하기

파서를 디버깅했으니 다음 단계는 파싱된 스타일 시트를 웹 페이지에 적용하는 것입니다. 각 CSS 규칙이 페이지의 여러 요소에 스타일을 줄 수 있으므로, 모든 요소 _와_ 모든 규칙에 대해 반복해야 합니다. 규칙이 적용되면 그 속성–값 쌍들이 요소의 스타일 정보로 복사됩니다.

```python
def style(node, rules):
    # ...
    for selector, body in rules:
        if not selector.matches(node): continue
        for property, value in body.items():
            node.style[property] = value
    # ...
```

이 루프를 `style` 속성을 파싱하는 루프 앞에 두어야 한다는 점을 잊지 마세요. `style` 속성은 스타일 시트의 값을 덮어써야 합니다.

이를 시험해 보려면 스타일 시트가 필요합니다. 모든 브라우저에는 _브라우저 스타일 시트_[^16] 가 함께 들어 있는데, 이는 여러 HTML 요소에 대한 기본 스타일을 정의합니다. 우리 브라우저의 것은 다음과 같은 모습일 수 있습니다.

```css
pre { background-color: gray; }
```

이것을 `browser.css`라는 새 파일에 저장하고, 브라우저가 시작할 때 읽도록 합시다.

```python
DEFAULT_STYLE_SHEET = CSSParser(open("browser.css").read()).parse()
```

이제 브라우저가 웹 페이지를 로드할 때 그 기본 스타일 시트를 적용해 각 요소의 기본 스타일을 설정할 수 있습니다.

```python
def load(self, url):
    # ...
    rules = DEFAULT_STYLE_SHEET.copy()
    style(self.nodes, rules)
    # ...
```

브라우저 스타일 시트는 웹 전체의 기본값입니다. 하지만 각 웹사이트도 `link` 요소로 CSS 파일을 참조함으로써 사이트 전체에 일관된 스타일을 지정하는 데 CSS를 사용할 수 있습니다.

```
<link rel="stylesheet" href="/main.css">
```

필수인 `rel` 속성은 이 링크가 스타일 시트임을 식별해 주고,[^17] `href` 속성에는 스타일 시트의 URL이 들어 있습니다. 그림 2처럼 이 링크들을 모두 찾아 스타일 시트를 내려받고 적용해야 합니다.

![그림 2: 웹 페이지를 위해 스타일 시트 같은 관련 자원을 불러오는 브라우저.](styles-http-2.gif)

*그림 2: 웹 페이지를 위해 스타일 시트 같은 관련 자원을 불러오는 브라우저.*

앞으로 몇 장에 걸쳐 비슷한 작업을 할 것이므로, 조금 일반화해서 트리를 노드의 리스트로 바꾸는 재귀 함수를 작성합시다.

```python
def tree_to_list(tree, list):
    list.append(tree)
    for child in tree.children:
        tree_to_list(child, list)
    return list
```

나중을 위해 이 헬퍼를 HTML 트리와 레이아웃 트리 양쪽에서 동작하도록 작성했습니다. Python의 리스트 컴프리헨션과 함께 `tree_to_list`를 사용하면 링크된 각 스타일 시트의 URL을 가져올 수 있습니다.[^18]

```python
def load(self, url):
    # ...
    links = [node.attributes["href"]
             for node in tree_to_list(self.nodes, [])
             if isinstance(node, Element)
             and node.tag == "link"
             and node.attributes.get("rel") == "stylesheet"
             and "href" in node.attributes]
    # ...
```

그런데 이 스타일 시트 URL들은 보통 완전한 URL이 아닙니다. _상대 URL_ 이라고 불리는 것인데, 다음과 같은 형태일 수 있습니다.[^19]

- 스킴, 호스트, 경로 등을 지정하는 보통의 URL

- 슬래시로 시작하지만 기존 스킴과 호스트를 재사용하는 호스트 상대 URL

- 슬래시로 시작하지 않으며 파일 이름처럼 해석되는 경로 상대 URL

- "`//`" 뒤에 완전한 URL이 오며 기존 스킴을 사용해야 하는 스킴 상대 URL

스타일 시트를 내려받으려면 각 상대 URL을 완전한 URL로 변환해야 합니다.

```python
class URL:
    def resolve(self, url):
        if "://" in url: return URL(url)
        if not url.startswith("/"):
            dir, _ = self.path.rsplit("/", 1)
            url = dir + "/" + url
        if url.startswith("//"):
            return URL(self.scheme + ":" + url)
        else:
            return URL(self.scheme + "://" + self.host + \
                       ":" + str(self.port) + url)
```

또한 초기 웹 아키텍처 때문에, 상대 URL 안의 상위 디렉터리(`..`)를 해석하는 것은 브라우저의 책임입니다.

```python
class URL:
    def resolve(self, url):
        if not url.startswith("/"):
            dir, _ = self.path.rsplit("/", 1)
            while url.startswith("../"):
                _, url = url.split("/", 1)
                if "/" in dir:
                    dir, _ = dir.rsplit("/", 1)
            url = dir + "/" + url
```

이제 브라우저는 링크된 각 스타일 시트를 요청하고 그 규칙들을 `rules` 리스트에 추가할 수 있습니다.

```python
def load(self, url):
    # ...
    for link in links:
        style_url = url.resolve(link)
        try:
            body = style_url.request()
        except:
            continue
        rules.extend(CSSParser(body).parse())
```

`try`/`except`는 내려받기에 실패한 스타일 시트를 무시하지만, 여러분 코드의 버그를 감출 수도 있으니 무언가 이상하다면 잠시 제거해 보세요.

### 더 알아보기

각 브라우저 엔진에는 저마다의 브라우저 스타일 시트가 있습니다([Chromium](https://source.chromium.org/chromium/chromium/src/+/master:third_party/blink/renderer/core/html/resources/html.css), [WebKit](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/css/html.css), [Gecko](https://searchfox.org/mozilla-central/source/layout/style/res/html.css)). 그 차이를 극복하기 위해 [리셋 스타일 시트](https://developer.mozilla.org/en-US/docs/Web/CSS/all)가 자주 사용됩니다. 이것이 동작하는 이유는, 우리 브라우저에서와 마찬가지로 웹 페이지 스타일 시트가 브라우저 스타일 시트보다 우선하기 때문입니다. 다만 실제 브라우저는 그렇게 되도록 [우선순위를 손봅니다](https://www.w3.org/TR/2011/REC-CSS2-20110607/cascade.html#cascading-order).[^20]

## 캐스케이딩

이제 웹 페이지에는 몇 개든 스타일 시트가 적용될 수 있습니다. 그리고 두 규칙이 같은 요소에 적용될 수 있으므로 규칙의 순서가 중요합니다. 순서가 어떤 규칙이 우선하는지, 언제 한 규칙이 다른 규칙을 덮어쓰는지를 결정합니다.

CSS에서 올바른 순서를 _캐스케이드 순서(cascade order)_ 라고 하며, 이는 규칙의 선택자를 기준으로 하되 파일 순서를 동점 처리 기준으로 삼습니다. 이 체계 덕분에 더 구체적인 규칙이 더 일반적인 규칙을 덮어쓸 수 있어서, 브라우저 스타일 시트, 사이트 전체 스타일 시트, 그리고 어쩌면 특정 웹 페이지를 위한 특별 스타일 시트가 모두 공존할 수 있습니다.

우리 브라우저에는 태그 선택자밖에 없으므로 캐스케이드 순서는 그저 그 개수를 세면 됩니다.

```python
class TagSelector:
    def __init__(self, tag):
        # ...
        self.priority = 1

class DescendantSelector:
    def __init__(self, ancestor, descendant):
        # ...
        self.priority = ancestor.priority + descendant.priority
```

그러면 규칙의 캐스케이드 순서는 그 우선순위 그대로입니다.

```python
def cascade_priority(rule):
    selector, body = rule
    return selector.priority
```

이제 `style`을 호출할 때 다음과 같이 규칙을 정렬해야 합니다.

```python
def load(self, url):
    # ...
    style(self.nodes, sorted(rules, key=cascade_priority))
    # ...
```

`rules`는 정렬하기 전에는 파일 순서로 되어 있다는 점에 주의하세요. Python의 `sorted` 함수는 우선순위가 같은 항목들의 상대 순서를 유지하므로, 파일 순서가 마땅히 그래야 하듯 동점 처리 기준으로 작용합니다.

다 됐습니다. 우리 웹 브라우저에 CSS를 추가했습니다! 물론 배경색에 한해서지만요. 하지만 웹 디자인에는 그 이상의 것이 있습니다. 예를 들어 배경색을 바꾼다면 전경색도 바꾸고 싶어질 텐데, 그것이 CSS `color` 속성입니다. 그런데 함정이 있습니다. `color`는 텍스트에 영향을 주는데, 텍스트 노드를 선택할 방법은 없습니다. 어떻게 동작할 수 있을까요?

### 더 알아보기

웹 페이지는 [대체 스타일 시트](https://developer.mozilla.org/en-US/docs/Web/CSS/Alternative_style_sheets)를 제공할 수도 있고, 일부 브라우저는 기본 스타일 시트에서 대체 스타일 시트로 전환하는 (잘 알려지지 않은) 방법을 제공합니다. CSS 표준은 웹사이트에 사용자 지정 스타일 시트를 설정하는 [사용자 스타일](https://userstyles.org)도 허용하는데, 그 우선순위는 브라우저 스타일 시트와 웹사이트 제공 스타일 시트 [사이](https://www.w3.org/TR/css-cascade/#cascade-origin)입니다.

## 상속되는 스타일

CSS에서 텍스트 스타일이 동작하는 방식을 _상속(inheritance)_ 이라고 합니다. 상속이란 어떤 노드가 특정 속성의 값을 갖고 있지 않으면 대신 부모의 값을 사용한다는 뜻입니다. 여기에는 텍스트 노드도 포함됩니다. 어떤 속성은 상속되고 어떤 속성은 상속되지 않는데, 이는 속성에 따라 다릅니다. 배경색은 상속되지 않지만 텍스트 색과 그 밖의 폰트 속성들은 상속됩니다.

네 가지 폰트 속성에 대해 상속을 구현합시다. `font-size`, (`italic`을 위한) `font-style`, (`bold`를 위한) `font-weight`, 그리고 `color`입니다.

```python
INHERITED_PROPERTIES = {
    "font-size": "16px",
    "font-style": "normal",
    "font-weight": "normal",
    "color": "black",
}
```

이 딕셔너리의 값들은 각 속성의 기본값입니다. 그다음 실제 상속 코드를 `style` 함수에 추가하겠습니다. 명시적인 규칙이 상속을 덮어써야 하므로, 이 코드는 다른 루프들 _앞에_ 와야 합니다.

```python
def style(node, rules):
    # ...
    for property, default_value in INHERITED_PROPERTIES.items():
        if node.parent:
            node.style[property] = node.parent.style[property]
        else:
            node.style[property] = default_value
    # ...
```

폰트 크기 상속에는 반전이 있습니다. 웹 페이지는 폰트 크기로 백분율을 사용할 수 있습니다. `h1 { font-size: 150% }`는 제목을 주변 텍스트보다 50% 크게 만듭니다. 그런데 만약 `h1` 태그 안에 `code` 요소가 있다면, 그 요소도 `font-size`로 `150%` 값을 상속받을까요? 설마 나머지 제목 텍스트보다 또 50% 커져서는 안 되겠죠?

실제로 브라우저는 폰트 크기 백분율을 상속되기 전에 절대 픽셀 단위로 해석합니다. 이를 "계산된 스타일(computed style)"이라고 합니다.[^21]

```python
def style(node, rules):
    # ...
    if node.style["font-size"].endswith("%"):
        # ...

    for child in node.children:
        style(child, rules)
```

백분율 크기를 해석하는 데는 까다로운 예외 사례가 딱 하나 있습니다. 루트 `html` 요소의 백분율 크기입니다. 이 경우 백분율은 기본 폰트 크기를 기준으로 합니다.[^22]

```python
def style(node, rules):
    # ...
    if node.style["font-size"].endswith("%"):
        if node.parent:
            parent_font_size = node.parent.style["font-size"]
        else:
            parent_font_size = INHERITED_PROPERTIES["font-size"]
        node_pct = float(node.style["font-size"][:-1]) / 100
        parent_px = float(parent_font_size[:-2])
        node.style["font-size"] = str(node_pct * parent_px) + "px"
```

이 처리가 스타일 값의 모든 출처가 다뤄진 뒤에(그래서 우리는 최종 `font-size` 값을 다루게 됩니다), 그러나 재귀하기 전에(그래서 모든 자식이 부모의 `font-size`가 픽셀 값으로 해석되었다고 가정할 수 있습니다) 일어난다는 점에 주의하세요.

### 더 알아보기

페이지에 스타일을 주는 일은 느릴 수 있어서, 실제 브라우저는 자손 선택자를 위한 [블룸 필터](https://bugs.webkit.org/show_bug.cgi?id=53880), 단순 선택자를 위한 [인덱스](https://source.chromium.org/chromium/chromium/src/+/refs/tags/93.0.4532.3:third_party/blink/renderer/core/css/style-calculation.md), 그리고 다양한 형태의 [공유](https://hacks.mozilla.org/2017/08/inside-a-super-fast-css-engine-quantum-css-aka-stylo/)와 [병렬화](https://blog.rust-lang.org/2017/11/14/Fearless-Concurrency-In-Firefox-Quantum.html) 같은 기법을 사용합니다. 어떤 종류의 공유는 메모리 사용량을 줄이는 데도 중요합니다. 계산된 스타일 시트는 어마어마하게 커질 수 있으니까요!

## 폰트 속성

이제 이 폰트 속성들을 모두 구현했으니, 레이아웃이 그것들을 사용하도록 바꿉시다! 그러면 기본 텍스트 스타일을 브라우저 스타일 시트로 옮길 수 있습니다.

```css
a { color: blue; }
i { font-style: italic; }
b { font-weight: bold; }
small { font-size: 90%; }
big { font-size: 110%; }
```

브라우저는 `BlockLayout`의 `word` 메서드에서 폰트 정보를 찾습니다. 이 메서드가 노드의 `style` 필드를 사용하도록 바꿔야 하고, 그러려면 노드 자체를 넘겨야 합니다.

```python
class BlockLayout:
    def recurse(self, node):
        if isinstance(node, Text):
            for word in node.text.split():
                self.word(node, word)
        else:
            # ...

    def word(self, node, word):
        weight = node.style["font-weight"]
        style = node.style["font-style"]
        if style == "normal": style = "roman"
        size = int(float(node.style["font-size"][:-2]) * .75)
        font = get_font(size, weight, style)
        # ...
```

`font-style`의 경우 CSS의 "normal"을 Tk의 "roman"으로 옮겨야 하고, `font-size`의 경우 CSS 픽셀을 Tk 포인트로 변환해야 한다는 점에 주의하세요.

텍스트 색에는 배관 작업이 조금 더 필요합니다. 먼저 색을 읽어 현재 `line`에 저장해야 합니다.

```python
def word(self, node, word):
    color = node.style["color"]
    # ...
    self.line.append((self.cursor_x, word, font, color))
    # ...
```

그러면 `flush` 메서드가 그것을 `line`에서 `display_list`로 복사합니다.

```python
def flush(self):
    # ...
    metrics = [font.metrics() for x, word, font, color in self.line]
    # ...
    for rel_x, word, font, color in self.line:
        # ...
        self.display_list.append((x, y, word, font, color))
    # ...
```

그 `display_list`는 `paint`에서 그리기 명령으로 변환됩니다.

```python
def paint(self):
    # ...
    if self.layout_mode() == "inline":
        for x, y, word, font, color in self.display_list:
            cmds.append(DrawText(x, y, word, font, color))
```

이제 `DrawText`에는 `color` 인자가 필요하고, 그것을 `create_text`의 `fill` 매개변수로 넘겨야 합니다.

```python
class DrawText:
    def __init__(self, x1, y1, text, font, color):
        # ...
        self.color = color

    def execute(self, scroll, canvas):
        canvas.create_text(
            # ...
            fill=self.color)
```

휴! 서로 맞물린 변경이 많았으니 전부 테스트해서 잘 동작하는지 확인하세요. 이제 [이 장의 웹 버전](https://browser.engineering/styles.html)에서 링크가 파란색으로 보일 것이고, 나머지 텍스트도 약간 밝아졌다는 것을 알아차릴 수 있을 것입니다.[^23] 또한 이제 텍스트 색을 명시적으로 설정하고 있으니 배경색도 명시적으로 설정해야 합니다.[^24]

```python
class Browser:
    def __init__(self):
        # ...
        self.canvas = tkinter.Canvas(
            # ...
            bg="white",
        )
        # ...
```

이 변경들로 인해 `BlockLayout`에서 특정 태그를 처리하던 코드, 즉 `style`, `weight`, `size` 속성과 `open_tag`, `close_tag` 메서드가 모두 쓸모없어졌습니다. 조금 리팩터링해서 없애 봅시다.

```python
class BlockLayout:
    def recurse(self, node):
        if isinstance(node, Text):
            for word in node.text.split():
                self.word(node, word)
        else:
            if node.tag == "br":
                self.flush()
            for child in node.children:
                self.recurse(child)
```

스타일 지정은 웹 페이지 작성자가 자신의 웹 페이지에 스타일을 줄 수 있게 해 줄 뿐 아니라, 브라우저 코드를 단순한 스타일 시트로 옮겨 주기도 합니다. 그리고 그것은 큰 개선입니다. 스타일 시트는 더 단순하고 수정하기도 쉽습니다. 이렇게 코드를 데이터로 바꾸면 때로는 새로운 형식을 유지 관리해야 하지만, 브라우저는 어차피 지원해야 하는 형식인 CSS를 재사용할 수 있습니다.

물론 스타일 지정에는 이 책의 홈페이지를 보기 좋게 렌더링해 주는 근사한 이점도 있습니다(그림 3). 배경이 더 이상 회색이 아니고 링크에 색이 생긴 것을 눈여겨보세요.

## 연습문제

**6-1 _폰트_.** 요소에서 어떤 폰트를 사용할지 지정하는 상속 속성인 `font-family` 속성을 구현하세요. `<code>` 요소 안의 텍스트가 `Courier` 같은 보기 좋은 고정 폭 폰트를 사용하게 만드세요. 폰트 캐시를 조심하세요.

**6-2 _너비/높이_.** 블록 레이아웃에 `width`와 `height` 속성 지원을 추가하세요. 이 값들은 레이아웃 객체의 너비나 높이를 직접 설정하는 픽셀 값일 수도 있고, `auto`라는 단어일 수도 있는데 후자의 경우 기존 레이아웃 알고리즘을 사용합니다.

**6-3 _클래스 선택자_.** 모든 HTML 요소는 `class` 속성을 가질 수 있으며, 그 값은 해당 요소의 클래스들을 공백으로 구분한 목록입니다. `.main` 같은 CSS 클래스 선택자는 `main` 클래스를 가진 모든 요소에 영향을 줍니다. 클래스 선택자를 구현하세요. 클래스 선택자는 태그 선택자보다 우선해야 합니다. 올바르게 구현했다면 이 책의 코드 블록에 구문 강조가 적용된 것을 보게 될 것입니다.

**6-4 _`display`_.** 지금 `layout_mode` 함수는 하드코딩된 블록 요소 목록에 의존합니다. 실제 브라우저에서는 `display` 속성이 이를 제어합니다. 기본값을 `inline`으로 하여 `display`를 구현하고, 블록 요소 목록을 브라우저 스타일 시트로 옮기세요.

**6-5 _단축 속성_.** CSS의 "단축 속성(shorthand property)"은 서로 관련된 여러 CSS 속성을 한 번에 설정합니다. 예를 들어 `font: italic bold 100% Times`는 `font-style`, `font-weight`, `font-size`, `font-family` 속성을 한꺼번에 설정합니다. 파서에 단축 속성을 추가하세요. (연습문제 6-1을 하지 않았다면 `font-family`는 그냥 무시하세요.)

**6-6 _인라인 스타일 시트_.** `<link rel=stylesheet>` 문법은 외부 스타일 시트(자체 HTTP 요청으로 로드되는 것)를 가져올 수 있게 해 줍니다. `<style>` 태그를 통해 HTML의 일부로 스타일 시트를 인라인으로 제공하는 방법도 있는데, 뒤따르는 `</style>` 태그까지의 모든 것이 스타일 시트로 해석됩니다.[^26] 인라인 스타일 시트는 자체 완결적인 예제 웹 페이지를 만드는 데 유용하지만, 더 중요하게는 서버로의 왕복 네트워크 요청 수를 줄여 웹사이트가 더 빨리 로드되게 하는 방법이기도 합니다. 스타일 시트에는 보통 왼쪽 꺾쇠괄호가 들어 있지 않으므로, HTML 파서를 수정하지 않고도 이 기능을 구현할 수 있습니다.

**6-7 _빠른 자손 선택자_.** 지금은 `div div div div div` 같은 선택자를 매칭하는 데 오래 걸릴 수 있습니다. 최악의 경우 *O(nd)* 인데, 여기서 _n_ 은 선택자의 길이이고 _d_ 는 레이아웃 트리의 깊이입니다. 자손 선택자 매칭 코드를 *O(n + d)* 시간에 동작하도록 수정하세요. `DescendantSelector`가 두 개가 아니라 기본 선택자들의 리스트를 저장하게 하면 도움이 될 수 있습니다.

**6-8 _선택자 시퀀스_.** 때로는 태그 _와_ 클래스로 요소를 선택하고 싶습니다. 이는 선택자들을 아무것도 사이에 두지 않고 이어 붙여서 합니다.[^27] 예를 들어 `span.announce`는 `span`과 `.announce` 모두에 매치되는 요소를 선택합니다. 이를 표현하는 새 `SelectorSequence` 클래스를 구현하고 파서가 이를 파싱하도록 수정하세요. 우선순위는 합산하세요.[^28]

**6-9 _`!important`_.** CSS 속성–값 쌍은 `!important` 문법을 사용해 "중요함"으로 표시할 수 있습니다. 다음과 같습니다.

```
#banner a { color: black !important; }
```

이렇게 하면 그 속성–값 쌍은 (같은 블록의 다른 쌍들은 해당하지 않습니다!) 다른 어떤 선택자보다도 (다른 `!important` 속성을 제외하고) 높은 우선순위를 갖게 됩니다. `!important`를 파싱하고 구현하되, 이렇게 표시된 속성–값 쌍에는 보통의 속성–값 쌍보다 10,000 높은 우선순위를 주세요.

**6-10 _`:has` 선택자_.** [`:has` 선택자](https://drafts.csswg.org/selectors-4/#relational)는 자손 선택자의 역입니다. 자손의 존재 여부에 따라 조상에 스타일을 줍니다. `:has` 선택자를 구현하세요. 여러분 구현의 점근적 속도를 분석해 보세요. 요소당 상각 *O(1)* 인 영리한 구현이 있는데, 찾을 수 있겠습니까?[^29]
