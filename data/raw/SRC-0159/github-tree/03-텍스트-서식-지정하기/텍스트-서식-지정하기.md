## 폰트란 무엇인가?

지금까지 우리는 화면에 텍스트를 쓰기 위해 글자 하나와 좌표 두 개를 넘겨 `create_text`를 호출했습니다. 하지만 폰트, 크기, 스타일은 한 번도 지정하지 않았습니다. 그런 것들을 이야기하려면 폰트 객체를 만들어 사용해야 합니다.

_폰트(font)_ 란 정확히 무엇일까요? 옛날에 인쇄공들은 작은 금속 활자를 레일 위에 늘어놓고, 잉크를 묻힌 다음, 종이에 눌러 인쇄면을 만들었습니다(그림 1 참조). 금속 활자는 글자별로 하나씩 상자에 담겨 있어서, e가 담긴 (큰) 상자, x가 담긴 (작은) 상자 같은 식이었습니다. 그 상자들은 다시 케이스(case)에 담겼는데(그림 2 참조), 하나는 _대문자(upper-case)_ 용, 하나는 _소문자(lower-case)_ 용이었습니다. 이 케이스 한 벌을 폰트라고 불렀습니다.[^2] 당연히 더 큰 텍스트를 인쇄하려면 다른 (더 큰) 활자가 필요했으므로 그것은 다른 폰트였습니다. 그리고 폰트를 모아 놓은 것을 _타입(type)_ 이라고 불렀는데, 우리가 타이핑(typing)이라고 부르는 이유가 여기 있습니다. 굵은 글씨나 이탤릭 같은 변형은 그 타입의 "페이스(face)"라고 불렸습니다.

![그림 1: 인쇄소 노동자들을 그린 그림. (Daniel Nikolaus Chodowiecki 작. Wikipedia, 퍼블릭 도메인.)](text-old.jpeg)

![그림 2: 활자 케이스에 담긴 금속 활자와 식자용 스틱. (Willi Heidelbach 작. Wikipedia, CC BY 2.5.)](text-metal.png)

*그림 2: 활자 케이스에 담긴 금속 활자와 식자용 스틱. (Willi Heidelbach 작. [Wikipedia](https://en.wikipedia.org/wiki/File:Metal_movable_type.jpg), [CC BY 2.5](https://creativecommons.org/licenses/by/2.5/deed.en).)*

이 용어들은 인쇄기의 세계, 즉 여러 주조소에서 온 금속 활자가 상자에 담기고 그 상자가 케이스에 담기는 세계를 반영합니다. 반면 우리의 현대 세계에는 드롭다운 메뉴가 있고, 옛 단어들은 더 이상 그것과 들어맞지 않습니다. 이제 "폰트"는 폰트, 서체(typeface), 타입 중 무엇이든 뜻할 수 있고,[^3] 우리는 하나의 폰트가 ("굵게"와 "보통" 같은) 여러 _굵기(weight)_,[^4] ("이탤릭"과 이탤릭이 아닌 것을 가리키는 "로만" 같은) 여러 _스타일(style)_,[^5] 그리고 임의의 _크기(size)_[^6] 를 가진다고 말합니다. 매직 잉크의 세계에 오신 것을 환영합니다.[^7]

그런데 Tk의 _폰트 객체_ 는 폰트의 옛 의미, 즉 크기·스타일·굵기가 고정된 하나의 타입에 대응합니다. 예를 들면 다음과 같습니다.[^8]

```
import tkinter.font
window = tkinter.Tk()
bi_times = tkinter.font.Font(
    family="Times",
    size=16,
    weight="bold",
    slant="italic",
)
```

> **참고**
>
> 여러분의 컴퓨터에는 "Times"가 설치되어 있지 않을 수도 있습니다. `tkinter.font.families()`로 사용 가능한 폰트 목록을 확인하고 다른 것을 고르면 됩니다.

폰트 객체는 `create_text`의 `font` 인자로 넘길 수 있습니다.

```
canvas.create_text(200, 100, text="Hi!", font=bi_times)
```

### 더 알아보기

옛날에 미국의 식자공들은 금속 활자 상자들을 [캘리포니아 잡 케이스](http://www.alembicpress.co.uk/Typecases/CJCCASE.HTM)에 정리해 두었는데, 이는 소문자와 대문자를 한 케이스에 나란히 놓아 식자를 더 쉽게 만들어 주었습니다. 대문자/소문자라는 명칭 자체는 그보다 수백 년 앞선 것입니다.

## 텍스트 측정하기

텍스트는 세로와 가로로 공간을 차지하며, 폰트 객체의 `metrics`와 `measure` 메서드가 그 공간을 측정합니다.[^9]

```
>>> bi_times.metrics()
{'ascent': 15, 'descent': 4, 'linespace': 19, 'fixed': 0}
>>> bi_times.measure("Hi!")
24
```

`metrics` 호출은 텍스트의 세로 치수에 관한 정보를 알려 줍니다(그림 3 참조). `linespace`는 텍스트의 높이이며, 여기에는 "선 위로" 올라가는 `ascent`와 "선 아래로" 내려가는 `descent`가 포함됩니다.[^10] `ascent`와 `descent`는 크기가 다른 단어들이 같은 줄에 놓일 때 중요합니다. 그 단어들은 위쪽이나 아래쪽이 아니라 "선을 따라" 정렬되어야 하기 때문입니다.

![그림 3: 폰트의 다양한 세로 메트릭. 한 폰트의 모든 글리프는 같은 어센트, x-높이, 디센트를 공유하며 공통 베이스라인 위에 배치됩니다. 다만 글리프의 measure(또는 advance)는 서로 다를 수 있습니다.](text-metrics.png)

*그림 3: 폰트의 다양한 세로 메트릭. 한 폰트의 모든 글리프는 같은 어센트, _x_-높이, 디센트를 공유하며 공통 베이스라인 위에 배치됩니다. 다만 글리프의 measure(또는 advance)는 서로 다를 수 있습니다.*

좀 더 깊이 들어가 봅시다. `bi_times`는 크기 16의 Times라는 점을 기억하세요. 그런데 왜 `font.metrics`는 실제 높이가 19픽셀이라고 알려 줄까요? 우선, 크기 16은 16 _포인트_ 를 뜻하며 포인트는 1인치의 72분의 1로 정의됩니다. 16 _픽셀_ 이 아닙니다.[^11] 여러분의 모니터는 아마 1인치당 100픽셀 정도일 것입니다.[^12] 게다가 그 16포인트는 개별 글자가 아니라 그 글자를 새겨 넣었던 금속 블록을 잰 것이므로, 글자 자체는 16포인트보다 _작아야_ 합니다. 실제로 크기 16의 폰트라도 폰트마다 글자 높이가 다릅니다.[^13]

```
>>> tkinter.font.Font(family="Courier", size=16).metrics()
{'fixed': 1, 'ascent': 13, 'descent': 4, 'linespace': 17}
>>> tkinter.font.Font(family="Times", size=16).metrics()
{'fixed': 0, 'ascent': 14, 'descent': 4, 'linespace': 18}
>>> tkinter.font.Font(family="Helvetica", size=16).metrics()
{'fixed': 0, 'ascent': 15, 'descent': 4, 'linespace': 19}
```

`measure()` 메서드는 좀 더 직접적입니다. 텍스트가 _가로_ 로 몇 픽셀을 차지하는지 알려 줍니다. 물론 이는 텍스트에 따라 달라지는데, 글자마다 너비가 다르기 때문입니다.[^14]

```
>>> bi_times.measure("Hi!")
24
>>> bi_times.measure("H")
13
>>> bi_times.measure("i")
5
>>> bi_times.measure("!")
7
>>> 13 + 5 + 7
25
```

이 정보를 이용해 페이지에 텍스트를 배치할 수 있습니다. 예를 들어 "Hello, world!"라는 텍스트를 두 조각으로 나눠 그리되 "world!"를 이탤릭으로 하고 싶다고 합시다. 두 개의 폰트를 사용합시다.

```
font1 = tkinter.font.Font(family="Times", size=16)
font2 = tkinter.font.Font(family="Times", size=16, slant='italic')
```

이제 `(200, 200)`에서 시작해 텍스트를 배치할 수 있습니다.

```
x, y = 200, 200
canvas.create_text(x, y, text="Hello, ", font=font1)
x += font1.measure("Hello, ")
canvas.create_text(x, y, text="world!", font=font2)
```

"Hello,"와 "world!"가 올바르게 정렬되고 두 번째 단어가 이탤릭으로 표시되는 것이 보일 것입니다.

안타깝게도 이 코드에는 버그가 있는데, 예제 텍스트를 잘 골라서 가려져 있을 뿐입니다. "world!"를 "overlapping!"으로 바꿔 보면 두 단어가 겹칩니다. `create_text`에 넘기는 좌표 `x`와 `y`가 Tk에게 텍스트의 _중심_ 을 어디에 놓을지 알려 주기 때문입니다. "Hello, world!"에서 잘 동작한 것은 "Hello,"와 "world!"의 길이가 같았기 때문입니다!

다행히 넘기는 좌표의 의미는 설정할 수 있습니다. `anchor` 인자를 `"nw"`, 즉 텍스트의 "북서쪽" 모서리로 설정하면, 우리가 준 좌표를 텍스트의 왼쪽 위 모서리로 취급하라고 Tk에 지시할 수 있습니다.

```
x, y = 200, 225
canvas.create_text(x, y, text="Hello, ", font=font1, anchor='nw')
x += font1.measure("Hello, ")
canvas.create_text(
    x, y, text="overlapping!", font=font2, anchor='nw')
```

`draw` 함수를 수정해 `anchor`를 `"nw"`로 설정하세요. 이전 장에서는 모든 중국어 글자의 너비가 같았기 때문에 그럴 필요가 없었습니다.

폰트 메트릭이 헷갈린다면, 그런 사람이 여러분만은 아닙니다! 2012년 미시간주 대법원은 [Stand Up for Democracy v. Secretary of State](https://publicdocs.courts.mi.gov/opinions/final/sct/20120803_s145387_157_standup-op.pdf) 사건을 심리했는데, 이는 궁극적으로 주민투표 발의의 유효성을 다투는 사건이었지만 그 핵심은 폰트 크기의 정의였습니다. 법원은 (올바르게도) 폰트 크기란 글자를 새겨 넣었던 금속 블록의 크기이지 글자 자체의 크기가 아니라고 판결했습니다.

## 단어 단위로

[2장](https://browser.engineering/graphics.html)에서 `layout` 함수는 텍스트를 한 글자씩 순회하다가 공간이 부족해지면 다음 줄로 넘어갔습니다. 각 글자가 대체로 단어 그 자체인 중국어에는 그것이 적절합니다. 하지만 영어에서는 단어 중간에서 다음 줄로 넘어갈 수 없습니다. 대신 텍스트를 한 단어씩 배치해야 합니다.[^15]

```python
def layout(text):
    # ...
    for word in text.split():
        # ...
    return display_list
```

중국어 글자와 달리 단어는 크기가 제각각이므로 각 단어의 너비를 측정해야 합니다.

```python
import tkinter.font

def layout(text):
    font = tkinter.font.Font()
    # ...
    for word in text.split():
        w = font.measure(word)
    # ...
```

여기서는 Tk의 기본 폰트를 사용하기로 했습니다. 이제 텍스트를 `cursor_x`에 그린다면 그 오른쪽 끝은 `cursor_x + w`가 됩니다. 그 위치가 페이지의 오른쪽 가장자리를 넘어갈 수 있는데, 그럴 때는 다음 줄로 넘겨 공간을 만들어야 합니다.

```python
def layout(text):
    for word in text.split():
        # ...
        if cursor_x + w > WIDTH - HSTEP:
            cursor_y += font.metrics("linespace") * 1.25
            cursor_x = HSTEP
```

이 코드 블록은 `for` 루프의 내부만 보여 준다는 점에 주의하세요. `layout`의 나머지 부분은 그대로 두어야 합니다. 또한 `metrics`를 인자와 함께 호출하고 있는데, 이렇게 하면 지정한 메트릭만 바로 반환합니다. 마지막으로, `y`를 증가시킬 때 linespace에 1.25를 곱한다는 점에 주의하세요. 이 곱셈을 없애 보면 줄 간격이 너무 좁아서 텍스트가 읽기 어려워지는 것을 볼 수 있습니다.[^16] 그래서 줄 사이에 "행간(line spacing)" 또는 "레딩(leading)"[^17]을 넣는 것이 일반적입니다. 25%의 행간은 흔히 쓰이는 값입니다.

이제 `cursor_x`와 `cursor_y`가 단어의 _시작_ 위치를 가리키므로, 디스플레이 리스트에 추가하고 `cursor_x`가 단어의 끝을 가리키도록 갱신합니다.

```python
def layout(text):
    for word in text.split():
        # ...
        display_list.append((cursor_x, cursor_y, word))
        cursor_x += w + font.measure(" ")
```

`cursor_x`를 `w`가 아니라 `w + font.measure(" ")`만큼 증가시키는데, 단어 사이에 공백을 두고 싶기 때문입니다. `split()` 호출이 모든 공백을 제거했으므로 이렇게 다시 넣어 주는 것입니다. 다만 `if` 조건에서는 `w`에 공백을 더하지 않는데, 한 줄의 마지막 단어 뒤에는 공백이 필요 없기 때문입니다.

### 더 알아보기

단어 중간에서 줄을 나누는 것을 하이픈 처리(hyphenation)라고 하며, [`hyphens` CSS 속성](https://drafts.csswg.org/css-text-3/#hyphens-property)으로 켤 수 있습니다. 최신 기술은 [Knuth–Liang 하이픈 처리 알고리즘](http://www.tug.org/docs/liang/liang-thesis.pdf)인데, 단어 조각 사전을 이용해 가능한 하이픈 위치의 우선순위를 매깁니다. 처음에 CSS 명세는 이 알고리즘과 [호환되지 않았지만](https://news.ycombinator.com/item?id=19472922), 최근의 [`text-wrap-style` 속성](https://drafts.csswg.org/css-text-4/#propdef-text-wrap-style)이 그 문제를 해결했습니다.

## 텍스트에 스타일 입히기

지금은 페이지의 모든 텍스트가 하나의 폰트로 그려집니다. 하지만 웹 페이지는 때때로 `<b>`와 `<i>` 태그를 사용해 텍스트를 **굵게** 또는 _이탤릭_ 으로 지정합니다. 이를 지원하면 좋겠지만, 지금 코드는 그러기 어렵게 되어 있습니다. `layout` 함수는 입력으로 페이지의 텍스트만 받으므로 굵게 태그와 이탤릭 태그가 어디에 있는지 전혀 알지 못합니다.

`lex`를 바꿔서 _토큰_ 의 리스트를 반환하게 합시다. 여기서 토큰은 (태그 바깥의 연속된 글자를 나타내는) `Text` 객체이거나 (태그의 내용을 나타내는) `Tag` 객체입니다. `Text`와 `Tag` 클래스를 작성해야 합니다.[^18]

```python
class Text:
    def __init__(self, text):
        self.text = text

class Tag:
    def __init__(self, tag):
        self.tag = tag
```

이제 `lex`는 텍스트를 `Text`와 `Tag` 객체로 모아야 합니다.[^19]

```python
def lex(body):
    out = []
    buffer = ""
    in_tag = False
    for c in body:
        if c == "<":
            in_tag = True
            if buffer: out.append(Text(buffer))
            buffer = ""
        elif c == ">":
            in_tag = False
            out.append(Tag(buffer))
            buffer = ""
        else:
            buffer += c
    if not in_tag and buffer:
        out.append(Text(buffer))
    return out
```

여기서 `text` 변수의 이름을 `buffer`로 바꿨는데, 이제 이 변수가 사용되기 전의 텍스트나 태그 내용을 담고 있기 때문입니다. 이 이름은 루프가 끝났을 때 버퍼에 남은 텍스트가 있는지, 그리고 그것을 어떻게 처리할지 확인해야 한다는 점도 상기시켜 줍니다. 여기서 `lex`는 쌓인 텍스트를 `Text` 객체로 내보냅니다. 이렇게 하면 꺾쇠괄호를 한 번도 만나지 못하더라도 텍스트 토큰을 반환하게 됩니다. 하지만 `Hi!<hr`처럼 끝나지 않은 태그는 버려집니다.[^20]

`Text`와 `Tag`가 비대칭이라는 점에 주의하세요. `lex`는 빈 `Text` 객체는 만들지 않지만 빈 `Tag` 객체는 만듭니다. 빈 `Tag` 객체는 HTML 코드 `<>`를 나타내는 반면, 빈 `Text` 객체는 아무 내용도 없음을 나타내기 때문입니다.

`lex`를 수정했으므로 이제 `layout`에 페이지의 텍스트뿐 아니라 그 안의 태그도 함께 넘기게 되었습니다. 따라서 `layout`은 텍스트가 아니라 토큰을 순회해야 합니다.

```python
def layout(tokens):
    # ...
    for tok in tokens:
        if isinstance(tok, Text):
            for word in tok.text.split():
                # ...
    # ...
```

`layout`은 태그 토큰을 살펴보고 페이지가 지시하는 대로 폰트를 바꿀 수도 있습니다. 굵기와 스타일 지원부터 시작합시다. 그에 대응하는 변수 두 개를 둡니다.

```python
weight = "normal"
style = "roman"
```

이 변수들은 굵게와 이탤릭의 여는 태그와 닫는 태그를 만났을 때 바뀌어야 합니다.

```python
if isinstance(tok, Text):
    # ...
elif tok.tag == "i":
    style = "italic"
elif tok.tag == "/i":
    style = "roman"
elif tok.tag == "b":
    weight = "bold"
elif tok.tag == "/b":
    weight = "normal"
```

이 코드는 `<b>bold</b>`와 `<i>italic</i>` 텍스트뿐 아니라 `<b><i>bold italic</i></b>` 텍스트도 올바르게 처리한다는 점에 주의하세요.[^21]

`style`과 `weight` 변수는 폰트를 고르는 데 사용됩니다.

```python
if isinstance(tok, Text):
    for word in tok.text.split():
        font = tkinter.font.Font(
            size=16,
            weight=weight,
            slant=style,
        )
        # ...
```

폰트는 `layout`에서 계산되지만 `draw`에서 사용되므로, 디스플레이 리스트의 각 항목에 사용된 폰트를 추가해야 합니다.

```python
if isinstance(tok, Text):
    for word in tok.text.split():
        # ...
        display_list.append((cursor_x, cursor_y, word, font))
```

디스플레이 리스트 항목의 이 추가 폰트 필드를 받아서 사용하도록 `draw`도 반드시 갱신하세요.

### 더 알아보기

_이탤릭_ 폰트는 "[챈서리 핸드(chancery hand)](https://en.wikipedia.org/wiki/Chancery_hand)"라고 불리는 필기체 스타일을 흉내 내기 위해 이탈리아에서 개발되었습니다(그래서 그런 이름이 붙었습니다). 이탤릭이 아닌 폰트는 로마 기념비의 글자를 흉내 냈다고 해서 _로만(roman)_ 이라고 부릅니다. 잘 알려지지 않은 세 번째 선택지도 있는데, 로만 폰트처럼 생겼지만 기울어져 있는 [오블리크(oblique) 폰트](https://en.wikipedia.org/wiki/Oblique_type)입니다.

## Layout 객체

이 모든 태그를 다루다 보니 `layout`은 지역 변수가 많고 제어 흐름도 복잡한, 꽤 커다란 함수가 되었습니다. 이는 무언가가 함수가 아니라 클래스가 될 자격이 있다는 신호입니다.

```python
class Layout:
    def __init__(self, tokens):
        self.display_list = []
```

그러면 `layout`의 모든 지역 변수는 `Layout`의 필드가 됩니다.

```python
self.cursor_x = HSTEP
self.cursor_y = VSTEP
self.weight = "normal"
self.style = "roman"
```

기존 `layout`의 핵심은 토큰에 대한 루프이며, 그 루프의 본문을 `Layout`의 메서드로 옮길 수 있습니다.

```python
def __init__(self, tokens):
    # ...
    for tok in tokens:
        self.token(tok)

def token(self, tok):
    if isinstance(tok, Text):
        for word in tok.text.split():
            # ...
    elif tok.tag == "i":
        self.style = "italic"
    # ...
```

사실 `isinstance(tok, Text)` 분기의 본문은 별도의 메서드로 옮길 수 있습니다.

```python
def word(self, word):
    font = tkinter.font.Font(
        size=16,
        weight=self.weight,
        slant=self.style,
    )
    w = font.measure(word)
    # ...
```

이제 모든 것이 `Browser`의 옛 `layout` 함수 밖으로 옮겨졌으므로, 그 함수는 `Layout`을 호출하는 코드로 대체할 수 있습니다.

```python
class Browser:
    def load(self, url):
        body = url.request()
        tokens = lex(body)
        self.display_list = Layout(tokens).display_list
        self.draw()
```

이런 큰 리팩터링을 할 때는 조금씩 진행하는 것이 중요합니다. 한꺼번에 전부 바꾸는 편이 더 효율적으로 보일 수 있지만, 그 효율에는 실패의 위험이 따릅니다. 너무 많은 일을 한꺼번에 하려다가 혼란에 빠져 리팩터링 전체를 포기하게 될 수 있습니다. 그러니 다음으로 넘어가기 전에 잠시 시간을 내어 브라우저가 여전히 잘 동작하는지 확인하세요.

어쨌든 이 리팩터링은 모든 텍스트 처리 코드를 별도의 메서드로 분리했고, 주된 `token` 함수는 태그 이름에 따라 분기하기만 하면 되게 되었습니다. 이 새롭고 깔끔한 구조를 활용해 태그를 더 추가해 봅시다. 폰트 굵기와 스타일이 동작하니, 타이포그래피 정교함의 다음 관문은 크기입니다. 폰트 크기를 바꾸는 간단한 방법 하나는 `<small>` 태그와, 이제는 사용이 권장되지 않는 그 자매 태그 `<big>`입니다.[^22]

폰트 스타일과 굵기를 다뤄 본 경험에 비추어 보면, `Layout`의 `size` 필드를 조정하는 간단한 접근을 떠올릴 수 있습니다. 이 필드는 다음과 같이 시작합니다.

```python
self.size = 12
```

이 변수는 폰트 객체를 만드는 데 사용됩니다.

```python
font = tkinter.font.Font(
    size=self.size,
    weight=self.weight,
    slant=self.style,
)
```

그리고 이 변수를 갱신함으로써 `<big>`과 `<small>` 태그에서 크기를 바꿀 수 있습니다.

```python
def token(self, tok):
    # ...
    elif tok.tag == "small":
        self.size -= 2
    elif tok.tag == "/small":
        self.size += 2
    elif tok.tag == "big":
        self.size += 4
    elif tok.tag == "/big":
        self.size -= 4
```

깨알 같은 주의 문구를 넣듯이 문단 전체를 `<small>`로 감싸 보면서, 새로 얻은 타이포그래피의 자유를 만끽해 보세요.

### 더 알아보기

`<b>`, `<i>`, `<big>`, `<small>`은 모두 CSS 이전 시대인 초기 웹에서 유래한 것들입니다. 요즘은 CSS로 요소의 모습을 바꿀 수 있으므로, `<b>`나 `<small>`처럼 시각적인 태그 이름은 선호되지 않습니다. 그렇지만 `<b>`, `<i>`, `<small>`은 여전히 [겉모습과 무관한 의미](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-small-element)를 조금 갖고 있습니다.

## 크기가 다른 텍스트

`<small>a</small><big>A</big>`처럼 폰트 크기를 섞기 시작하면 폰트 크기 코드의 문제를 금방 알아차리게 됩니다. 텍스트가 마치 빨랫줄에 걸린 것처럼 위쪽을 기준으로 정렬됩니다. 하지만 영어 텍스트는 보통 보이지 않는 _베이스라인_ 을 기준으로 모든 글자가 정렬된다는 것을 알고 계실 겁니다.

이를 어떻게 고칠지 생각해 봅시다. 더 큰 텍스트를 위로 올리면 이전 줄과 겹칠 것이므로, 더 작은 텍스트를 아래로 내려야 합니다. 즉 작은 텍스트의 세로 위치는 큰 텍스트가 `token`을 통과한 _다음에_ 계산되어야 합니다. 그런데 작은 텍스트가 루프를 먼저 통과하므로, 텍스트 줄에 대해 _2단계_ 알고리즘이 필요합니다. 첫 단계에서는 어떤 단어가 그 줄에 들어갈지 파악하고 그 _x_ 위치를 계산하며, 두 번째 단계에서는 단어들을 세로로 정렬하고 그 _y_ 위치를 계산합니다(그림 4 참조).

![그림 4: 여러 폰트가 섞여 있을 때 줄이 배치되는 방식. 모든 단어는 공통 베이스라인을 기준으로 그려집니다. 줄 전체의 어센트와 디센트는 그 줄에 있는 모든 단어의 최대 어센트와 최대 디센트로 결정되며, 줄의 앞뒤에 레딩이 더해집니다.](text-line.png)

*그림 4: 여러 폰트가 섞여 있을 때 줄이 배치되는 방식. 모든 단어는 공통 베이스라인을 기준으로 그려집니다. 줄 전체의 어센트와 디센트는 그 줄에 있는 모든 단어의 최대 어센트와 최대 디센트로 결정되며, 줄의 앞뒤에 레딩이 더해집니다.*

첫 번째 단계부터 시작합시다. 한 줄에는 여러 태그에서 온 텍스트가 들어가므로, 만들어지는 중인 줄을 저장할 필드가 `Layout`에 필요합니다. 그 필드 `line`은 리스트가 될 것이고, `word`는 단어를 디스플레이 리스트가 아니라 그 리스트에 추가하게 됩니다. `line`의 항목들은 _x_ 위치는 갖지만 _y_ 위치는 갖지 않는데, _y_ 위치는 첫 단계에서 계산되지 않기 때문입니다.

```python
class Layout:
    def __init__(self, tokens):
        # ...
        self.line = []
        # ...
    
    def word(self, word):
        # ...
        self.line.append((self.cursor_x, word, font))
        # ...
```

새로 만든 `line` 필드는 본질적으로 버퍼로, 단어들이 배치되기 전까지 잠시 머무는 곳입니다. 두 번째 단계는 한 줄을 다 처리했을 때 그 버퍼를 비우는 것입니다.

```python
class Layout:
    def word(self, word):
        # ...
        if self.cursor_x + w > WIDTH - HSTEP:
            self.flush()
```

버퍼가 늘 그렇듯이, 모든 토큰을 처리한 뒤에도 버퍼가 비워지도록 해야 합니다.

```python
class Layout:
    def __init__(self, tokens):
        # ...
        self.flush()
```

이 새로운 `flush` 함수에는 세 가지 책임이 있습니다.

1. 단어들을 베이스라인에 맞춰 정렬해야 합니다(그림 5 참조).

2. 그 모든 단어를 디스플레이 리스트에 추가해야 합니다.

3. `cursor_x`와 `cursor_y` 필드를 갱신해야 합니다.

단계별로 살펴보면 다음과 같습니다.

> 🔗 대화형 위젯: [lab3-baselines.html](https://browser.engineering/widgets/lab3-baselines.html)

![그림 5: 한 줄의 단어들을 정렬하기.](example3-words-align.png)

*그림 5: 한 줄의 단어들을 정렬하기.*

단어들이 "선 위에" 놓이기를 원하므로, 그 선이 어디에 있어야 하는지 계산하는 것부터 시작합시다. 그것은 그 줄에서 가장 키가 큰 단어에 따라 달라집니다.

```python
def flush(self):
    if not self.line: return
    metrics = [font.metrics() for x, word, font in self.line]
    max_ascent = max([metric["ascent"] for metric in metrics])
```

그러면 베이스라인은 `self.cursor_y`보다 `max_ascent`만큼 아래에 있습니다. 정확히는 레딩을 고려해 조금 더 아래입니다.[^23]

```python
baseline = self.cursor_y + 1.25 * max_ascent
```

이제 선의 위치를 알았으니, 각 단어를 그 선을 기준으로 배치하고 디스플레이 리스트에 추가할 수 있습니다.

```python
for x, word, font in self.line:
    y = baseline - font.metrics("ascent")
    self.display_list.append((x, y, word, font))
```

`y`가 베이스라인에서 시작해 그 단어의 어센트만큼만 _위로_ 올라간다는 점에 주목하세요. 이제 `cursor_y`는 가장 깊은 디센더를 수용할 수 있도록 `baseline` 아래로 충분히 내려가야 합니다.

```python
max_descent = max([metric["descent"] for metric in metrics])
self.cursor_y = baseline + 1.25 * max_descent
```

마지막으로 `flush`는 `Layout`의 `cursor_x`와 `line` 필드를 갱신해야 합니다.

```python
self.cursor_x = HSTEP
self.line = []
```

이제 텍스트 크기가 섞여 있어도 모든 텍스트가 선을 따라 정렬됩니다. 게다가 이 새로운 `flush` 함수는 다른 줄바꿈 작업에도 편리합니다. 예를 들어 HTML에서 `<br>` 태그[^24]는 현재 줄을 끝내고 새 줄을 시작합니다.

```python
def token(self, tok):
    # ...
    elif tok.tag == "br":
        self.flush()
```

마찬가지로 문단은 `<p>`와 `</p>` 태그로 정의되므로 `</p>` 역시 현재 줄을 끝냅니다.

```python
def token(self, tok):
    # ...
    elif tok.tag == "/p":
        self.flush()
        self.cursor_y += VSTEP
```

여기서는 문단 사이에 약간의 간격을 만들기 위해 `cursor_y`에 조금 더 더했습니다.

## 폰트 캐싱

스타일이 적용된 텍스트를 구현하고 나면, (macOS를 쓰고 있지 않다면[^25]) [이 장](http://browser.engineering/text.html)처럼 큰 웹 페이지에서 우리 브라우저가 [이전 장](https://browser.engineering/graphics.html)에 비해 눈에 띄게 느려졌다는 것을 아마 알아차렸을 것입니다. 텍스트 레이아웃, 특히 각 단어를 측정하는 부분이 꽤 느리기 때문입니다.[^26]

안타깝게도 텍스트 측정을 크게 빠르게 만들기는 어렵습니다. 가변 폭 폰트와 힌팅·커닝 같은 복잡한 폰트 기능 때문에 텍스트 측정에는 꽤 복잡한 계산이 필요할 수 있습니다. 하지만 큰 웹 페이지에서는 어떤 단어들이 아주 많이 등장하기 마련입니다. 예를 들어 이 장에는 "the"라는 단어가 200번 넘게 나옵니다. 이런 단어들을 매번 다시 측정하는 대신 한 번만 측정하고 그 결과를 캐시할 수 있습니다. 보통의 영어 텍스트에서는 이것만으로도 대개 상당한 속도 향상이 있습니다.

캐싱은 워낙 좋은 아이디어라서 대부분의 텍스트 라이브러리는 이미 이를 구현하고 있으며, 보통 각 `Font` 객체 안에 텍스트 측정 결과를 캐시합니다. 그런데 우리의 `text` 메서드는 단어마다 새 `Font` 객체를 만들기 때문에 캐싱이 효과가 없습니다. 캐싱이 동작하게 하려면 새로 만드는 대신 가능한 한 `Font` 객체를 재사용해야 합니다.

캐시는 전역 `FONTS` 딕셔너리에 저장하겠습니다.

```python
FONTS = {}
```

이 딕셔너리의 키는 크기/굵기/스타일의 세 값 조합이고, 값은 `Font` 객체입니다.[^27] 캐싱 로직 자체는 새로운 `get_font` 함수에 넣을 수 있습니다.

```python
def get_font(size, weight, style):
    key = (size, weight, style)
    if key not in FONTS:
        font = tkinter.font.Font(size=size, weight=weight,
            slant=style)
        label = tkinter.Label(font=font)
        FONTS[key] = (font, label)
    return FONTS[key][0]
```

그러면 `word` 메서드는 `Font` 객체를 직접 만드는 대신 `get_font`를 호출할 수 있습니다.

```python
class Layout:
    def word(self, word):
        font = get_font(self.size, self.weight, self.style)
        # ...
```

이제 같은 단어는 같은 폰트를 사용하게 되고, 텍스트 측정은 캐시에 적중하게 됩니다.

### 더 알아보기

중국어 같은 문자 체계를 위한 폰트는 크기가 수 메가바이트에 이를 수 있어서, 보통 디스크에 저장해 두었다가 필요할 때만 메모리에 불러옵니다. 그래서 폰트 로딩이 느리고 캐싱은 더욱 중요해집니다. 브라우저는 텍스트를 측정하고, 셰이핑하고, 렌더링하는 데도 광범위한 캐시를 둡니다. 웹 페이지에는 텍스트가 많기 때문에, 이러한 캐시는 렌더링 속도를 높이는 가장 중요한 요소 중 하나로 밝혀졌습니다.

## 연습문제

**3-1 _가운데 정렬 텍스트_.** [이 책 웹사이트](https://browser.engineering/text.html)의 페이지 제목은 가운데 정렬되어 있습니다. `<h1 class="title">`과 `</h1>` 사이의 텍스트에 대해 여러분의 브라우저도 똑같이 하도록 만드세요. 줄마다 길이가 다르므로 각 줄을 개별적으로 가운데 정렬해야 합니다.[^28]

**3-2 _위 첨자_.** `<sup>` 태그 지원을 추가하세요. 이 태그 안의 텍스트는 더 작아야 하고(아마 보통 텍스트 크기의 절반쯤), 위 첨자의 위쪽이 보통 글자의 위쪽과 맞도록 배치되어야 합니다.

**3-3 _소프트 하이픈_.** Python에서 `\N{soft hyphen}`으로 쓰는 소프트 하이픈 문자는, 텍스트 렌더러가 하이픈을 넣고 단어를 줄 사이에서 나눌 수 있는(반드시 그래야 하는 것은 아닌) 자리를 나타냅니다. 이에 대한 지원을 추가하세요.[^29] 어떤 단어가 줄 끝에 들어가지 않으면 그 단어에 소프트 하이픈이 있는지 확인하고, 있다면 단어를 줄 사이에서 나누세요. 한 단어에 소프트 하이픈이 여러 개 있을 수 있다는 점을 기억하고, 단어를 나눌 때는 반드시 하이픈을 그려 주세요. "super­cali­fragi­listic­expi­ali­docious"라는 단어가 좋은 테스트 사례입니다.

**3-4 _스몰 캡_.** `<abbr>` 요소가 텍스트를 스몰 캡으로 렌더링하게 만드세요. `<abbr>` 태그 안에서 소문자는 작고, 대문자 형태이며, 굵게 그려져야 하고, 그 밖의 문자(대문자, 숫자 등)는 보통 폰트로 그려져야 합니다.

**3-5 _서식이 지정된 텍스트_.** `<pre>` 태그 지원을 추가하세요. 보통의 문단과 달리 `<pre>` 태그 안의 텍스트는 줄을 자동으로 바꾸지 않으며, 공백이나 줄바꿈 같은 공백 문자가 그대로 보존됩니다. `Courier New`나 `SFMono` 같은 고정 폭 폰트도 사용하세요. `<pre>` 태그 안에서 태그가 정상적으로 동작하도록 하세요. `<pre>` 안의 일부 텍스트를 굵게 만들 수 있어야 합니다. [연습문제 1-4](https://browser.engineering/http.html#exercises)도 함께 하면 결과가 가장 좋습니다.

[^28]: 초기 HTML에는 정확히 이 일을 하는 `<center>` 태그가 있었지만, 요즘은 가운데 정렬을 보통 CSS의 `text-align` 속성으로 합니다. 이 연습문제의 접근 방식은 물론 표준적이지 않으며 학습 목적일 뿐입니다.

[^29]: HTML 엔티티에 관한 [연습문제 1-4](https://browser.engineering/http.html#exercises)를 풀었다면, 소프트 하이픈으로 확장되는 `&shy;` 엔티티 지원도 추가하고 싶을 수 있습니다.
