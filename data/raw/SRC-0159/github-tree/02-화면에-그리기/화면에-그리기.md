웹 브라우저는 웹 페이지를 내려받기만 하는 것이 아니라 그 페이지를 사용자에게 보여 주기도 해야 합니다. 21세기에 그것은 곧 그래픽 애플리케이션을 뜻합니다.[^1] 그래서 이 장에서는 우리 브라우저에 그래픽 사용자 인터페이스를 달아 보겠습니다.

## 창 만들기

데스크톱과 노트북 컴퓨터는 창, 버튼, 마우스 같은 _데스크톱 환경_ 을 제공하는 운영체제를 실행합니다. 그래서 책임이 둘로 나뉩니다. 프로그램은 자신의 창을 제어하고, 데스크톱 환경은 화면을 제어합니다. 따라서 다음과 같이 동작합니다.

- 프로그램이 새 창을 요청하면 실제로 그것을 표시하는 것은 데스크톱 환경입니다.

- 프로그램이 자신의 창에 그림을 그리면 데스크톱 환경이 그것을 화면에 올립니다.

- 데스크톱 환경이 클릭과 키 입력을 프로그램에 알려 주면, 프로그램은 그에 반응해 자신의 창을 다시 그립니다.

이 모든 것을 직접 처리하는 일은 다소 번거롭기 때문에, 프로그램들은 보통 이러한 단계를 단순화해 주는 _그래픽 툴킷_ 을 사용합니다. Python에는 `tkinter`라는 Python 패키지 안에 Tk라는 그래픽 툴킷이 함께 들어 있습니다.[^2] 사용법은 아주 간단합니다.

```python
import tkinter
window = tkinter.Tk()
tkinter.mainloop()
```

> **설치**
>
> 보통 Tk는 Python과 함께 배포되므로 이미 설치되어 있을 가능성이 큽니다. 하지만 일부 Linux 배포판에서는 `python3-tk` 같은 이름의 별도 패키지를 설치해야 할 수도 있습니다.

여기서 `tkinter.Tk()`는 데스크톱 환경에 창을 만들어 달라고 요청하고, 그 창에 그림을 그리는 데 사용할 수 있는 객체를 반환합니다. `tkinter.mainloop()` 호출은 다음과 같은 모습의 반복문에 진입합니다.[^3]

```
while True:
    for evt in pendingEvents():
        handleEvent(evt)
    drawScreen()
```

![그림 1: 이벤트 처리 주기의 흐름도.](graphics-cycle-2.gif)

*그림 1: 이벤트 처리 주기의 흐름도.*

여기서 `pendingEvents`는 먼저 데스크톱 환경에 최근의 마우스 클릭이나 키 입력을 요청하고, 그다음 `handleEvent`가 여러분의 애플리케이션을 호출해 상태를 갱신하며, 마지막으로 `drawScreen`이 창을 다시 그립니다. 이 _이벤트 루프_ 패턴(그림 1 참조)은 웹 브라우저부터 비디오 게임에 이르기까지 많은 애플리케이션에서 흔히 쓰입니다. 복잡한 그래픽 애플리케이션에서 모든 이벤트가 결국은 처리되고 화면도 결국은 갱신되도록 보장해 주기 때문입니다.

### 더 알아보기

여러분은 아마 데스크톱 컴퓨터에서 브라우저를 작성하고 있겠지만, 많은 사람들은 휴대폰이나 태블릿 같은 모바일 기기로 웹에 접속합니다. 모바일 기기에도 여전히 화면과 렌더링 루프가 있고, 이 책에서 다루는 대부분의 것들이 그대로 존재합니다.[^4]

다만 짚어 둘 만한 차이가 몇 가지 있습니다. 애플리케이션은 보통 전체 화면으로 실행되며, 한 번에 하나의 애플리케이션만 화면에 그립니다. 마우스는 없고 가상 키보드만 있어서 주된 상호작용 방식은 터치입니다. 데스크톱에는 없는 "시각 뷰포트(visual viewport)"라는 개념도 있는데, 이는 "데스크톱 전용" 사이트와 "모바일 대응" 사이트, 그리고 핀치 줌을 모두 수용하기 위한 것입니다.[^5] 또한 화면의 픽셀 밀도는 훨씬 높지만 전체 화면 해상도는 대체로 더 낮습니다. 이 모든 차이를 지원하는 일은 할 수는 있지만 상당한 작업량을 요구합니다. 이 책은 일부 연습문제를 제외하면 그 구현을 더 깊이 다루지는 않겠습니다.

또한 기기가 배터리로 동작하기 때문에 전력 효율이 훨씬 더 중요한 반면, 중앙 처리 장치(CPU)와 메모리는 성능이 상당히 떨어지고 처리 능력도 낮습니다. 그래서 그래픽 처리 장치(GPU)를 최대한 활용하는 것이 훨씬 더 중요해집니다. 느린 CPU 때문에 좋은 성능을 내기가 더 어렵기 때문입니다. 모바일 브라우저는 만만치 않습니다!

## 창에 그리기

우리 브라우저는 웹 페이지의 텍스트를 _캔버스_ 에 그릴 것입니다. 캔버스는 원, 선, 텍스트를 그릴 수 있는 직사각형 모양의 Tk 위젯입니다. 예를 들어 Tk로 캔버스를 다음과 같이 만들 수 있습니다.[^6]

```
window = tkinter.Tk()
canvas = tkinter.Canvas(window, width=800, height=600)
canvas.pack()
```

첫 줄은 창을 만들고, 둘째 줄은 그 창 안에 `Canvas`를 만듭니다. Tk가 캔버스를 어디에 표시할지 알 수 있도록 창을 인자로 넘깁니다. 나머지 인자들은 캔버스의 크기를 정의합니다. 저는 800 × 600을 골랐는데, 옛날 모니터에서 흔했던 크기이기 때문입니다.[^7] 셋째 줄은 캔버스를 창 안에 배치하는 Tk 특유의 코드입니다. Tk에는 버튼이나 대화 상자 같은 위젯도 있지만 우리 브라우저는 그것들을 쓰지 않겠습니다. 우리에게는 겉모습에 대한 더 세밀한 제어가 필요한데, 캔버스가 바로 그것을 제공하기 때문입니다.[^8]

정리해 두기 위해 이 코드를 클래스 안에 넣읍시다.

```python
WIDTH, HEIGHT = 800, 600

class Browser:
    def __init__(self):
        self.window = tkinter.Tk()
        self.canvas = tkinter.Canvas(
            self.window, 
            width=WIDTH,
            height=HEIGHT
        )
        self.canvas.pack()
```

캔버스를 만들었으면 캔버스에 도형을 그리는 메서드를 호출할 수 있습니다. `load` 안에서 그렇게 해 봅시다. `load`는 새로 만든 `Browser` 클래스 안으로 옮기겠습니다.

```python
class Browser:
    def load(self, url):
        # ...
        self.canvas.create_rectangle(10, 20, 400, 300)
        self.canvas.create_oval(100, 100, 150, 150)
        self.canvas.create_text(200, 150, text="Hi!")
```

이 코드를 실행하려면 `Browser`를 만들고 `load`를 호출한 다음 Tk의 `mainloop`를 시작하면 됩니다.

```python
if __name__ == "__main__":
    import sys
    Browser().load(URL(sys.argv[1]))
    tkinter.mainloop()
```

그림 2처럼 캔버스의 왼쪽 위 모서리 근처에서 시작해 가운데에서 끝나는 직사각형, 그 직사각형 안의 원, 그리고 원 옆의 "Hi!"라는 텍스트가 보여야 합니다.

![그림 2: 직사각형, 원, 텍스트가 있는 예상 예제 출력.](graphics-example.png)

Tk의 좌표에서 _x_ 는 왼쪽에서 오른쪽으로, _y_ 는 위에서 아래로 향합니다. 다시 말해 화면 아래쪽일수록 _y_ 값이 _더 큽니다_. 수학에서 익숙한 것과는 반대입니다. 위 좌표들을 이리저리 바꿔 보면서 각 인자가 무엇을 가리키는지 알아보세요.[^9]

### 더 알아보기

Tk 캔버스 위젯은 우리가 여기서 사용하는 것보다 훨씬 강력합니다. [튜토리얼](https://tkdocs.com/tutorial/canvas.html)에서 볼 수 있듯이, 캔버스에 그린 개별 요소를 움직이거나 각 요소의 클릭 이벤트를 수신하는 등의 일이 가능합니다. 이 책에서는 그런 기능을 사용하지 않는데, 여러분이 직접 구현하는 방법을 알려 드리고 싶기 때문입니다.

## 텍스트 배치하기

이 캔버스에 간단한 웹 페이지를 그려 봅시다. 지금까지 우리 브라우저는 웹 페이지 소스 코드를 한 글자씩 훑으면서 (태그가 아닌) 텍스트를 콘솔 창에 출력했습니다. 이제는 그 대신 글자들을 캔버스에 그리려고 합니다.

먼저 이전 장의 `show` 함수를 `lex`[^10]라고 부를 함수로 바꿉시다. 이 함수는 HTML 문서의 텍스트 내용을 출력하지 않고 그냥 _반환합니다_.

```python
def lex(body):
    text = ""
    # ...
    for c in body:
        # ...
        elif not in_tag:
            text += c
    return text
```

그러면 `load`가 그 텍스트를 한 글자씩 그리게 됩니다.

```python
def load(self, url):
    # ...
    for c in text:
        self.canvas.create_text(100, 100, text=c)
```

이 코드를 실제 웹 페이지로 시험해 봅시다. 언뜻 이해하기 어려운 이유로,[^11] 원숭이에 관한 중국 고전 소설인 [西游记(_서유기_)의 첫 번째 장](https://browser.engineering/examples/xiyouji.html)으로 시험해 보겠습니다. 이 URL[^12]을 `request`, `lex`, `load`에 차례로 통과시켜 보세요. 창의 왼쪽 위 모서리에서 살짝 안쪽으로 들어간 자리에 검은 픽셀 덩어리가 크게 뭉쳐 있는 것이 보일 것입니다.

왜 글자가 아니라 덩어리일까요? 물론 모든 글자를 같은 위치에 그리고 있어서 전부 겹치기 때문입니다! 이를 고쳐 봅시다.

```python
HSTEP, VSTEP = 13, 18
cursor_x, cursor_y = HSTEP, VSTEP
for c in text:
    self.canvas.create_text(cursor_x, cursor_y, text=c)
    cursor_x += HSTEP
```

`cursor_x`와 `cursor_y` 변수는 마치 워드 프로세서에 텍스트를 입력하듯이 다음 글자가 놓일 자리를 가리킵니다. 13과 18이라는 매직 넘버는 여러 값을 시도해 보고 가장 읽기 좋아 보이는 것을 고른 것입니다.[^13]

이제 텍스트가 왼쪽에서 오른쪽으로 한 줄을 이룹니다. 하지만 캔버스 너비가 800픽셀이고 글자당 13픽셀이므로 한 줄에는 약 60글자밖에 들어가지 않습니다. 소설을 읽으려면 그보다 더 많이 필요하므로, 화면 가장자리에 다다르면 텍스트를 _줄바꿈_ 해야 합니다.

```python
for c in text:
    # ...
    if cursor_x >= WIDTH - HSTEP:
        cursor_y += VSTEP
        cursor_x = HSTEP
```

이 코드는 `cursor_x`가 787픽셀을 넘어가면 `cursor_y`를 늘리고 `cursor_x`를 초기화합니다.[^14][^15] 그 과정은 그림 3에 나와 있습니다. 이런 식으로 텍스트를 줄바꿈하면 한 줄 이상을 읽을 수 있게 됩니다.

이 개념을 보여 주는 위젯이 있습니다.

### 더 알아보기

영어 텍스트에서는 (적어도 하이픈 처리 없이는) 단어 중간에서 다음 줄로 넘길 수 없지만, 중국어에서는 여러 글자로 이루어진 단어라도 그것이 기본 동작입니다. 예를 들어 "스위치"를 뜻하는 开关은 "켜기"를 뜻하는 开과 "끄기"를 뜻하는 关으로 이루어져 있지만, 开 다음에서 줄을 바꿔도 아무 문제가 없습니다. 이 기본 동작은 word-break CSS 속성으로 바꿀 수 있습니다. `break-all`은 어디에서든 줄바꿈을 허용하고, `auto-phrase`는 开关 같은 중국어나 일본어 단어·구 안에서는 줄바꿈이 일어나지 않게 합니다. 여기서 "auto"는 단어를 저자가 지정하는 것이 아니라 자동으로 감지한다는 뜻인데, 흔히 [단어 빈도 표](https://github.com/unicode-org/icu/blob/master/icu4c/source/data/brkitr/dictionaries/cjdict.txt)를 바탕으로 [동적 계획법을 사용해](https://unicode-org.github.io/icu/userguide/boundaryanalysis/break-rules.html#details-about-dictionary-based-break-iteration) 이루어집니다.

## 텍스트 스크롤하기

스크롤은 페이지 좌표(이 텍스트는 _페이지_ 위쪽에서 132픽셀 떨어져 있다)와 화면 좌표(60픽셀만큼 아래로 스크롤했으므로 이 텍스트는 _화면_ 위쪽에서 72픽셀 떨어져 있다) 사이에 한 겹의 간접 층을 끼워 넣습니다. 그림 5를 보세요. 일반적으로 브라우저는 페이지 좌표를 기준으로 페이지를 _배치(layout)_ 하고, 즉 페이지의 모든 것이 어디에 놓일지 결정하고, 그다음 화면 좌표를 기준으로 페이지를 _래스터화(raster)_, 즉 모든 것을 그립니다.[^16]

![그림 5: 페이지 좌표와 화면 좌표의 차이.](graphics-coords-2.gif)

*그림 5: 페이지 좌표와 화면 좌표의 차이.*

우리 브라우저도 똑같이 나눌 것입니다. 지금은 `load`가 각 글자의 위치를 계산하는 일과 그리는 일, 즉 레이아웃과 렌더링을 모두 하고 있습니다. 대신 각 글자의 위치를 계산해 저장하는 `layout` 함수와, 저장된 위치를 바탕으로 각 글자를 그리는 별도의 `draw` 함수를 두기로 합시다. 이렇게 하면 `layout`은 페이지 좌표로 동작하고, 화면 좌표를 신경 써야 하는 것은 `draw`뿐입니다.

`layout`부터 시작합시다. 각 글자마다 `canvas.create_text`를 호출하는 대신, 위치와 함께 리스트에 추가하겠습니다. `layout`은 `Browser`의 어떤 것에도 접근할 필요가 없으므로 독립적인 함수로 둘 수 있습니다.

```python
def layout(text):
    display_list = []
    cursor_x, cursor_y = HSTEP, VSTEP
    for c in text:
        display_list.append((cursor_x, cursor_y, c))
        # ...
    return display_list
```

이렇게 만들어진, 표시할 것들의 목록을 _디스플레이 리스트_ 라고 부릅니다.[^17] `layout`은 전적으로 페이지 좌표에 관한 것이므로, 스크롤을 지원하기 위해 여기서 바꿀 것은 아무것도 없습니다.

디스플레이 리스트가 계산되고 나면 `draw`가 그것을 순회하며 각 글자를 그려야 합니다. `draw`는 캔버스에 접근해야 하므로 `Browser`의 메서드로 만듭니다.

```python
class Browser:
    def draw(self):
        for x, y, c in self.display_list:
            self.canvas.create_text(x, y, text=c)
```

이제 `load`는 `layout`을 호출한 다음 `draw`를 호출하기만 하면 됩니다.

```python
class Browser:
    def load(self, url):
        body = url.request()
        text = lex(body)
        self.display_list = layout(text)
        self.draw()
```

이제 스크롤을 추가할 수 있습니다. 얼마나 스크롤했는지를 나타내는 필드를 추가합시다.

```python
class Browser:
    def __init__(self):
        # ...
        self.scroll = 0
```

그러면 페이지 좌표 `y`는 화면 좌표로 `y - self.scroll`이 됩니다.

```python
def draw(self):
    for x, y, c in self.display_list:
        self.canvas.create_text(x, y - self.scroll, text=c)
```

`scroll` 값을 바꾸면 이제 페이지가 위아래로 스크롤됩니다. 그런데 _사용자_ 는 어떻게 `scroll`을 바꿀까요?

대부분의 브라우저는 위아래 방향키를 누르거나, 스크롤 휠을 돌리거나, 스크롤바를 끌거나, 화면에 터치 제스처를 하면 페이지를 스크롤합니다. 단순하게 가기 위해 아래쪽 방향키만 구현합시다.

Tk에서는 함수를 키에 _바인딩_ 할 수 있는데, 이는 그 키를 눌렀을 때 그 함수를 호출하라고 Tk에 지시하는 것입니다. 예를 들어 아래쪽 방향키에 바인딩하려면 다음과 같이 씁니다.

```python
def __init__(self):
    # ...
    self.window.bind("<Down>", self.scrolldown)
```

여기서 `self.scrolldown`은 _이벤트 핸들러_, 즉 아래쪽 방향키가 눌릴 때마다 Tk가 호출할 함수입니다.[^18] 이 함수가 할 일은 `scroll`을 증가시키고 캔버스를 다시 그리는 것뿐입니다.

```python
SCROLL_STEP = 100

def scrolldown(self, e):
    self.scroll += SCROLL_STEP
    self.draw()
```

이것을 시험해 보면 스크롤할 때 모든 텍스트가 두 번씩 그려지는 것을 알게 될 것입니다. 새 텍스트를 그리기 전에 옛 텍스트를 지우지 않았기 때문입니다. `canvas.delete`를 호출해 옛 텍스트를 지웁시다.

```python
def draw(self):
    self.canvas.delete("all")
    # ...
```

이제 스크롤이 동작할 것입니다!

### 더 알아보기

디스플레이 리스트를 저장해 두면 스크롤이 빨라집니다. 스크롤할 때마다 브라우저가 `layout`을 다시 하지 않아도 되기 때문입니다. 현대 브라우저는 [여기서 한 걸음 더 나아가](https://hacks.mozilla.org/2017/10/the-whole-web-at-maximum-fps-how-webrender-gets-rid-of-jank/), JavaScript나 사용자 상호작용으로 웹 페이지가 바뀌더라도 디스플레이 리스트의 상당 부분을 그대로 유지합니다.

일반적으로 스크롤은 웹 페이지에서 가장 흔한 사용자 상호작용입니다. 그래서 실제 브라우저들은 스크롤을 빠르게 만드는 데 _어마어마한_ 시간을 투자해 왔습니다. 그 방법들 중 몇 가지는 이 책의 뒷부분에서 더 살펴보겠습니다.

## 더 빠른 렌더링

상호작용이 매끄럽게 느껴지려면 애플리케이션은 페이지 내용을 빠르게 다시 그려야 하고,[^19] 사용자가 답답해하지 않도록 클릭과 키 입력에도 빠르게 반응해야 합니다. "매끄럽게 느껴진다"는 말은 좀 더 정확하게 표현할 수 있습니다. 브라우저 같은 그래픽 애플리케이션은 대개 화면의 새로 고침 빈도, 즉 _프레임 레이트_ 와 같은 속도, 그리고/또는 고정된 60Hz로 다시 그리는 것을 목표로 삼습니다.[^20] 이는 브라우저가 뒤처지지 않으려면 모든 작업을 1/60초, 즉 16ms 안에 끝내야 한다는 뜻입니다. 그래서 16ms를 애플리케이션의 _애니메이션 프레임 예산_ 이라고 부릅니다.

그런데 우리 브라우저의 스크롤은 꽤 느립니다.[^21] 왜 그럴까요? 알고 보니 `create_text` 안에서 글자의 모양에 관한 정보를 불러오는 데 시간이 좀 걸립니다. 스크롤 속도를 높이려면 (동시에 화면의 픽셀이 항상 올바른지도 보장하면서) 그 일을 꼭 필요할 때만 하도록 해야 합니다.

실제 브라우저는 이를 위해 상당히 까다로운 최적화를 많이 하지만, 우리 브라우저에서는 간단한 개선 하나로 만족합시다. 화면 밖에 있는 글자는 그리지 않는 것입니다.

```python
for x, y, c in self.display_list:
    if y > self.scroll + HEIGHT: continue
    if y + VSTEP < self.scroll: continue
    # ...
```

첫 번째 `if` 문은 보이는 창 아래쪽에 있는 글자를 건너뛰고, 두 번째는 그 위쪽에 있는 글자를 건너뜁니다. 두 번째 `if` 문에서 `y + VSTEP`은 글자의 아래쪽 가장자리인데, 보이는 창에 절반만 걸쳐 있는 글자도 그려야 하기 때문입니다.

이제 스크롤이 기분 좋게 빨라졌을 것이고, 바라건대 16ms 애니메이션 프레임 예산에 가까워졌을 것입니다.[^22] 그리고 `layout`과 `draw`를 나눠 두었기 때문에, 이 최적화를 구현하는 데 `layout`은 전혀 손댈 필요가 없었습니다.

### 더 알아보기

웹 페이지의 모든 상호작용이 애니메이션은 아니라는 점도 기억해 두어야 합니다. 마우스 클릭 같은 이산적인(discrete) 동작도 있습니다. 연구에 따르면 이산적인 동작에는 보통 100ms 안에만 반응하면 충분하며, 그 문턱 아래에서는 대부분의 사람이 이산적인 동작의 속도를 감지하지 못합니다. 이는 60Hz 정도보다 느리면 꽤 눈에 띄는 스크롤 같은 상호작용과는 매우 다릅니다. 이 둘의 차이는 사람의 마음이 움직임(애니메이션)과 이산적인 동작을 처리하는 방식의 차이, 그리고 뇌가 그런 동작을 결정하고 실행하고 그 결과를 이해하는 데 걸리는 시간과 관련이 있습니다.

## 연습문제

**2-1 _줄바꿈_.** `layout`이 줄바꿈 문자를 만나면 현재 줄을 끝내고 새 줄을 시작하도록 바꾸세요. _y_ 를 `VSTEP`보다 더 크게 늘려서 문단이 나뉘는 듯한 느낌을 주세요. _서유기_ 에는 시가 군데군데 들어 있는데, 이제 그것을 알아볼 수 있게 될 것입니다.

**2-2 _마우스 휠_.** 위쪽 방향키를 눌렀을 때 위로 스크롤하는 기능을 추가하세요. 페이지 맨 위보다 더 위로는 스크롤되지 않게 하세요. 그런 다음 마우스 휠로 스크롤할 때 발생하는 `<MouseWheel>` 이벤트에 바인딩하세요.[^24] 해당 이벤트 객체에는 얼마나, 어느 방향으로 스크롤할지 알려 주는 `event.delta` 값이 있습니다. 안타깝게도 macOS와 Windows는 `event.delta` 객체의 부호가 반대이고 크기 단위도 다르며, Linux에서는 스크롤에 `<Button-4>`와 `<Button-5>` 이벤트를 사용합니다.[^25]

**2-3 _크기 조절_.** 브라우저 창의 크기를 조절할 수 있게 만드세요. 그러려면 `canvas.pack`에 [`fill`과 `expand` 인자를 넘기고](https://web.archive.org/web/20201111222645id_/http://effbot.org/tkinterbook/pack.htm), 창 크기가 바뀔 때 발생하는 `<Configure>` 이벤트를 호출하고 바인딩하세요. 창의 새 너비와 높이는 이벤트 객체의 `width`, `height` 필드에서 얻을 수 있습니다. 창 크기가 바뀌면 줄바꿈 위치도 달라져야 하므로 `layout`을 다시 호출해야 한다는 점을 잊지 마세요.

**2-4 _스크롤바_.** 브라우저가 마지막 디스플레이 리스트 항목보다 더 아래로 스크롤되지 않게 하세요.[^26] 화면 오른쪽 가장자리에 파란색 직사각형 스크롤바를 그리세요. 그림 5처럼 스크롤바의 크기와 위치가 브라우저가 볼 수 있는 전체 문서의 어느 부분인지를 반영하도록 하세요. 문서 전체가 화면에 들어간다면 스크롤바를 숨기세요.

**2-5 _이모지_.** 브라우저에 이모지 지원을 추가하세요 😀. 이모지도 문자이므로 `create_text`로 그릴 수 있지만 결과가 그리 좋지 않습니다. 대신 [OpenMoji 프로젝트](https://openmoji.org)로 가서 ["웃는 얼굴"](https://openmoji.org/library/#emoji=1F600) 이모지를 PNG 파일로 내려받고, 16 × 16 픽셀로 크기를 조절한 다음 브라우저와 같은 폴더에 저장하세요. Tk의 `PhotoImage` 클래스로 이미지를 불러오고 `create_image` 메서드로 캔버스에 그리세요. 사실 OpenMoji 라이브러리 전체를 내려받으면(오른쪽 위의 "Get OpenMojis" 버튼을 찾으세요) 페이지에 쓰인 어떤 이모지든 찾아볼 수 있습니다.

**2-6 _`about:blank`_.** 현재는 잘못된 형식의 URL이 들어오면 브라우저가 죽습니다. 사용자가 오류를 고칠 수 있도록 오류에서 복구해 빈 페이지를 보여 주는 편이 훨씬 낫습니다. 이를 위해 그냥 빈 페이지를 렌더링하는 특수 URL `about:blank` 지원을 추가하고, 잘못된 형식의 URL은 자동으로 `about:blank`인 것처럼 렌더링되게 하세요.

**2-7 _다른 텍스트 방향_.** 모든 언어가 왼쪽에서 오른쪽으로 읽고 배치되는 것은 아닙니다. 아랍어, 페르시아어, 히브리어가 오른쪽에서 왼쪽으로 쓰는 언어의 좋은 예입니다. 브라우저에 명령줄 플래그를 두어 이에 대한 기본적인 지원을 구현하세요.[^27] 영어 문장은 여전히 왼쪽에서 오른쪽으로 배치되어야 하지만, 화면의 오른쪽에서부터 늘어나야 합니다(무슨 말인지 확인하려면 [이 예제](https://browser.engineering/examples/example2-rtl.html)를 좋아하는 브라우저에서 열어 보세요).[^28]
