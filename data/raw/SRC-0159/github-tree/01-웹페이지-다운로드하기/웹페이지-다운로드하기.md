웹 브라우저는 URL로 식별되는 정보를 표시합니다. 그리고 그 첫 단계는 URL을 이용해 인터넷 어딘가에 있는 서버에 연결하고 정보를 내려받는 것입니다.

## 서버에 연결하기

인터넷 브라우징은 URL에서 시작합니다.[^1] URL은 브라우저가 방문해야 할 특정 웹 페이지를 식별하는 짧은 문자열입니다.

```
http://example.org/index.html
```

*그림 1: URL의 문법. 여기서 `http`는 스킴, `example.org`는 호스트 이름, `/index.html`은 경로입니다.*

URL은 세 부분으로 이루어집니다(그림 1 참조). 스킴은 정보를 _어떻게_ 가져올지 알려 주고, 호스트 이름은 _어디서_ 가져올지 알려 주며, 경로는 _어떤_ 정보를 가져올지 알려 줍니다. URL에는 포트, 쿼리, 프래그먼트 같은 선택적인 부분도 있는데, 이는 뒤에서 살펴보겠습니다.

브라우저는 URL을 출발점 삼아 웹 페이지를 내려받는 과정을 시작할 수 있습니다. 브라우저는 먼저 로컬 운영체제(OS)에게 _호스트 이름_ 이 가리키는 _서버_ 와 연결해 달라고 요청합니다. 그러면 OS는 _도메인 네임 시스템_(DNS) 서버와 통신하여[^2] `example.org` 같은 호스트 이름을 `93.184.216.34` 같은 _목적지 IP 주소_ 로 변환합니다.[^3] 다음으로 OS는 _라우팅 테이블_ 이라는 것을 사용해 그 목적지 IP 주소와 통신하기에 어떤 하드웨어가 가장 적합한지(예를 들어 무선인지 유선인지) 결정하고, 디바이스 드라이버를 통해 전선이나 공중으로 신호를 내보냅니다.[^4] 이 신호는 일련의 _라우터_[^5] 들이 받아서 다시 전달하는데, 각 라우터는 메시지가 결국 목적지에 닿을 수 있도록 보낼 방향을 가장 알맞게 선택합니다.[^6] 메시지가 서버에 도달하면 연결이 만들어집니다. 어쨌든 요점은, 브라우저가 OS에게 "이봐, `example.org`와 연결해 줘"라고 말하면 OS가 그렇게 해 준다는 것입니다.

많은 시스템에서는 다음과 같이 `telnet` 프로그램을 사용해 이런 종류의 연결을 만들어 볼 수 있습니다.[^7]

```
telnet example.org 80
```

(참고: 회색 테두리가 보인다면, 그 코드는 예시일 뿐이며 실제로 우리 브라우저 코드의 _일부가 아니라는_ 뜻입니다.)

> **설치**
>
> `telnet`을 직접 설치해야 할 수도 있습니다. 기본적으로 꺼져 있는 경우가 많습니다. Windows에서는 제어판에서 [프로그램 및 기능 / Windows 기능 켜기 또는 끄기로 이동](https://www.lifewire.com/what-is-telnet-2626026)하면 되고, 이후 재부팅이 필요합니다. 실행하면 무언가를 출력하는 대신 화면을 지우지만, 그 점만 빼면 정상적으로 동작합니다. macOS에서는 `telnet` 대신 `nc -v` 명령을 사용할 수 있습니다.
>
> ```
> nc -v example.org 80
> ```
>
> 출력은 조금 다르지만 동작 방식은 같습니다. 대부분의 Linux 시스템에서는 패키지 관리자를 통해 `telnet`이나 `nc`를 설치할 수 있으며, 보통 패키지 이름은 `telnet`과 `netcat`입니다.

다음과 같은 출력이 나올 것입니다.

```
Trying 93.184.216.34...
Connected to example.org.
Escape character is '^]'.
```

이는 OS가 호스트 이름 `example.org`를 IP 주소 `93.184.216.34`로 변환했고 그 주소에 연결할 수 있었다는 뜻입니다.[^8] 이제 `example.org`와 대화할 수 있습니다.

### 더 알아보기

URL 문법은 [RFC 3986](https://tools.ietf.org/html/rfc3986)에 정의되어 있는데, 그 첫 번째 저자는 팀 버너스리입니다. 놀랄 일도 아니죠! 두 번째 저자는 로이 필딩으로, HTTP 설계에 핵심적으로 기여했으며 자신의 [박사 학위 논문](https://ics.uci.edu/~fielding/pubs/dissertation/fielding_dissertation_2up.pdf)에서 웹의 REST(Representational State Transfer) 아키텍처를 설명한 것으로도 잘 알려져 있습니다. 이 논문은 REST 덕분에 웹이 어떻게 탈중앙화된 방식으로 성장할 수 있었는지를 설명합니다. 오늘날 많은 서비스가 이러한 원칙을 따르는 "RESTful API"를 제공하고 있지만, 그 개념에 대해 [약간의 혼란](https://twobithistory.org/2020/06/28/rest.html)이 있는 것도 사실입니다.

## 정보 요청하기

연결되고 나면 브라우저는 _경로_ 를 알려 주는 방식으로 서버에 정보를 요청합니다. 경로란 `/index.html`처럼 URL에서 호스트 이름 다음에 오는 부분입니다. 요청의 구조는 그림 2에 나와 있습니다. `telnet`에 이것을 입력해 시험해 보세요.

```
GET /index.html HTTP/1.0
Host: example.org
```

*그림 2: 주석을 붙인 HTTP GET 요청. 첫 줄에서 `GET`은 메서드, `/index.html`은 경로, `HTTP/1.0`은 HTTP 버전이며, 둘째 줄에서 `Host`는 헤더 이름, `example.org`는 그 값입니다.*

여기서 `GET`이라는 단어는 브라우저가 정보를 받고 싶다는 뜻이고,[^9] 그다음에 경로가 오며, 마지막에는 브라우저가 [HTTP](https://developer.mozilla.org/en-US/docs/Web/HTTP) 1.0 버전을 사용한다는 사실을 호스트에게 알려 주는 `HTTP/1.0`이라는 단어가 옵니다. HTTP에는 여러 버전이 있습니다([0.9, 1.0, 1.1, 2.0, 3.0](https://medium.com/platform-engineer/evolution-of-http-69cfe6531ba0)). HTTP 1.1 표준은 keep-alive 같은 유용한 기능을 다양하게 추가했지만, 단순함을 위해 우리 브라우저는 그런 기능을 쓰지 않겠습니다. HTTP 2.0도 구현하지 않을 것입니다. 이는 1._x_ 계열보다 훨씬 복잡하고, 크고 복잡한 웹 애플리케이션을 위한 것인데 어차피 우리 브라우저는 그런 애플리케이션을 실행할 수 없기 때문입니다.

첫 줄 다음의 각 줄에는 _헤더_ 가 하나씩 들어 있으며, 헤더는 이름(`Host` 같은)과 값(`example.org` 같은)을 가집니다. 헤더마다 의미가 다른데, 예를 들어 `Host` 헤더는 서버에게 당신이 그 서버를 무엇이라고 생각하고 있는지 알려 줍니다.[^10] 보낼 수 있는 헤더는 이 밖에도 아주 많지만, 지금은 `Host`만 사용하겠습니다.

마지막으로 헤더들 다음에는 빈 줄이 하나 옵니다. 이 빈 줄은 헤더 입력이 끝났다는 것을 호스트에게 알려 줍니다. 따라서 `telnet`에 빈 줄을 입력하면(요청의 두 줄을 입력한 뒤 Enter를 두 번 누르면) `example.org`로부터 응답을 받게 됩니다.

### 더 알아보기

HTTP/1.0은 [RFC 1945](https://tools.ietf.org/html/rfc1945)에, HTTP/1.1은 [RFC 2616](https://tools.ietf.org/html/rfc2616)에 표준화되어 있습니다. HTTP는 이해하고 구현하기 쉽도록 설계되어 어떤 종류의 컴퓨터든 손쉽게 채택할 수 있었습니다. `telnet`에 HTTP를 직접 입력할 수 있는 것도 우연이 아닙니다! HTTP가 이메일용 단순 메일 전송 프로토콜([SMTP](https://en.wikipedia.org/wiki/Simple_Mail_Transfer_Protocol))처럼 평문과 줄바꿈을 사용하는 "줄 기반 프로토콜"인 것도 우연이 아닙니다. 결국 이 모든 방식은 초기 컴퓨터가 줄 단위 텍스트 입력만 가능했던 데서 비롯되었습니다. 실제로 최초의 두 브라우저 중 하나는 [줄 모드 UI](https://en.wikipedia.org/wiki/Line_Mode_Browser)를 가지고 있었습니다.

## 서버의 응답

서버의 응답은 그림 3에 있는 줄로 시작합니다.

```
HTTP/1.0 200 OK
```

*그림 3: 주석을 붙인 HTTP 응답의 첫 줄. `HTTP/1.0`은 버전, `200`은 응답 코드, `OK`는 응답 설명입니다.*

이는 호스트 역시 `HTTP/1.0`을 사용한다는 것을 확인해 주며, 요청이 "OK"(숫자 코드로는 200)였다고 판단했다는 뜻입니다. `404 Not Found`는 익숙하실 텐데, 이것도 또 다른 숫자 코드와 응답이며 `403 Forbidden`이나 `500 Server Error`도 마찬가지입니다. 이런 코드는 아주 많고, 꽤 깔끔한 체계로 정리되어 있습니다.[^11]

- 100번대는 정보성 메시지입니다.

- 200번대는 성공을 뜻합니다.

- 300번대는 후속 조치(보통은 리다이렉트)를 요청합니다.

- 400번대는 잘못된 요청을 보냈다는 뜻입니다.

- 500번대는 서버가 요청을 잘못 처리했다는 뜻입니다.

서버와 브라우저 중 누구의 잘못인지 알려 주기 위해 오류 코드를 두 묶음(400번대와 500번대)으로 나눈 것은 정말 기발한 발상입니다.[^12] 전체 코드 목록은 [위키백과](https://en.wikipedia.org/wiki/List_of_HTTP_status_codes)에서 볼 수 있으며, 새로운 코드도 이따금 추가됩니다.

`200 OK` 줄 다음에는 서버가 자신의 헤더를 보냅니다. 제가 시험해 봤을 때는 다음과 같은 헤더를 받았습니다(여러분이 받는 것과는 다를 것입니다).

```
Age: 545933
Cache-Control: max-age=604800
Content-Type: text/html; charset=UTF-8
Date: Mon, 25 Feb 2019 16:49:28 GMT
Etag: "1541025663+gzip+ident"
Expires: Mon, 04 Mar 2019 16:49:28 GMT
Last-Modified: Fri, 09 Aug 2013 23:54:35 GMT
Server: ECS (sec/96EC)
Vary: Accept-Encoding
X-Cache: HIT
Content-Length: 1270
Connection: close
```

여기에는 _엄청나게_ 많은 정보가 들어 있습니다. 요청한 정보에 관한 것(`Content-Type`, `Content-Length`, `Last-Modified`), 서버에 관한 것(`Server`, `X-Cache`), 브라우저가 이 정보를 얼마나 오래 캐시해야 하는지에 관한 것(`Cache-Control`, `Expires`, `Etag`), 그 밖에도 온갖 것들이 있습니다. 지금은 넘어가겠습니다.

헤더 다음에는 빈 줄이 오고, 그 뒤에 [HTML](https://developer.mozilla.org/en-US/docs/Web/HTML) 코드 뭉치가 이어집니다. 이를 서버 응답의 _본문(body)_ 이라고 하며, 브라우저는 `Content-Type` 헤더가 `text/html`이라고 알려 주기 때문에 이것이 HTML임을 압니다. 웹 페이지의 내용 자체를 담고 있는 것이 바로 이 HTML 코드입니다.

HTTP 요청/응답 트랜잭션은 그림 4에 정리되어 있습니다. 이제 수동으로 연결하는 방식에서 Python으로 넘어가 봅시다.

### 더 알아보기

위키백과에는 HTTP [헤더](https://en.wikipedia.org/wiki/List_of_HTTP_header_fields)와 [응답 코드](https://en.wikipedia.org/wiki/List_of_HTTP_status_codes)의 훌륭한 목록이 있습니다. ## Python으로 하는 Telnet

지금까지 우리는 `telnet`을 사용해 다른 컴퓨터와 통신했습니다. 그런데 `telnet`은 사실 꽤 단순한 프로그램이어서, 같은 일을 프로그래밍으로 할 수 있습니다. URL에서 호스트 이름과 경로를 뽑아내고, _소켓_ 을 만들고, 요청을 보내고, 응답을 받아야 합니다.[^13]

URL 파싱부터 시작합시다. URL을 파싱하면 `URL` 객체를 반환하도록 만들고, 파싱 코드는 생성자 안에 넣겠습니다.

```python
class URL:
    def __init__(self, url):
        # ...
```

`__init__` 메서드는 클래스 생성자를 위한 Python 특유의 문법이고, 어떤 메서드에서든 항상 첫 번째 매개변수로 넣어야 하는 `self` 매개변수는 C++나 Java의 `this`에 해당합니다.

먼저 스킴부터 시작합시다. 스킴은 `://`로 URL의 나머지 부분과 구분됩니다. 우리 브라우저는 `http`만 지원하므로, 그 점도 함께 검사합시다.

```python
class URL:
    def __init__(self, url):
        self.scheme, url = url.split("://", 1)
        assert self.scheme == "http"
```

이제 호스트와 경로를 분리해야 합니다. 호스트는 첫 번째 `/` 앞에 오고, 경로는 그 슬래시와 그 뒤의 모든 것입니다.

```python
class URL:
    def __init__(self, url):
        # ...
        if "/" not in url:
            url = url + "/"
        self.host, url = url.split("/", 1)
        self.path = "/" + url
```

(이 코드처럼 `# ...`이 들어간 코드 블록이 보이면, 기존 메서드나 블록에 코드를 추가한다는 뜻입니다.) `split(s, n)` 메서드는 문자열을 `s`가 처음 `n`번 나타나는 지점에서 분리합니다. 여기서 호스트 이름과 경로 사이의 슬래시를 처리하는 로직이 조금 까다롭다는 점에 주의하세요. 그 (선택적인) 슬래시는 경로의 일부입니다.

이제 `URL`이 `host`와 `path` 필드를 갖게 되었으니, 그 URL의 웹 페이지를 내려받을 수 있습니다. 이 일은 `request`라는 새 메서드에서 하겠습니다.

```python
class URL:
    def request(self):
        # ...
```

Python에서는 메서드에 항상 `self` 매개변수를 써야 한다는 점에 주의하세요. 앞으로는 메서드를 정의하는 것을 매번 크게 강조하지 않겠습니다. 아직 존재하지 않는 메서드나 함수 안에 코드가 있는 코드 블록이 보인다면, 그것을 정의하고 있다는 뜻입니다.

웹 페이지를 내려받는 첫 단계는 호스트에 연결하는 것입니다. 운영체제는 이를 위해 "소켓"이라는 기능을 제공합니다. 다른 컴퓨터와 대화하고 싶을 때(무언가를 알려 주든, 그쪽에서 알려 주기를 기다리든) 소켓을 만들면, 그 소켓으로 정보를 주고받을 수 있습니다. 다른 컴퓨터와 대화하는 방법이 여러 가지이므로 소켓에도 몇 가지 종류가 있습니다.

- 소켓에는 _주소 패밀리(address family)_ 가 있는데, 이는 상대 컴퓨터를 어떻게 찾을지 알려 줍니다. 주소 패밀리의 이름은 `AF`로 시작합니다. 우리는 `AF_INET`을 원하지만, 예를 들어 `AF_BLUETOOTH` 같은 것도 있습니다.

- 소켓에는 _타입(type)_ 이 있는데, 이는 앞으로 어떤 종류의 대화가 오갈지를 설명합니다. 타입의 이름은 `SOCK`로 시작합니다. 우리는 각 컴퓨터가 임의의 양의 데이터를 보낼 수 있는 `SOCK_STREAM`을 원하지만, 정해진 크기의 패킷을 주고받는 `SOCK_DGRAM`도 있습니다.[^14]

- 소켓에는 _프로토콜(protocol)_ 이 있는데, 이는 두 컴퓨터가 연결을 맺는 절차를 설명합니다. 프로토콜의 이름은 주소 패밀리에 따라 달라지는데, 우리는 `IPPROTO_TCP`를 원합니다.[^15]

이 모든 옵션을 골라서 다음과 같이 소켓을 만들 수 있습니다.[^16]

```python
import socket

class URL:
    def request(self):
        s = socket.socket(
            family=socket.AF_INET,
            type=socket.SOCK_STREAM,
            proto=socket.IPPROTO_TCP,
        )
```

소켓을 만들었으면 상대 컴퓨터에 연결하라고 지시해야 합니다. 그러려면 호스트와 _포트_ 가 필요합니다. 포트는 사용하는 프로토콜에 따라 달라지는데, 지금은 80이면 됩니다.

```python
class URL:
    def request(self):
        # ...
        s.connect((self.host, 80))
```

이 코드는 `example.org`와 통신하여 연결을 맺고 두 컴퓨터가 데이터를 주고받을 준비를 하게 합니다.

> **참고**
>
> 당연하지만 오프라인 상태라면 이 코드는 동작하지 않습니다. 프록시 뒤에 있거나 그 밖에 좀 더 복잡한 네트워크 환경에 있어도 동작하지 않을 수 있습니다. 해결 방법은 환경에 따라 다릅니다. 프록시를 끄는 것만큼 간단할 수도 있고, 훨씬 더 복잡할 수도 있습니다.

`connect` 호출에 괄호가 두 개 있다는 점에 주의하세요. `connect`는 인자를 하나만 받는데, 그 인자가 호스트와 포트의 쌍입니다. 주소 패밀리마다 인자의 개수가 다르기 때문에 이렇게 되어 있습니다.

### 더 알아보기

Python이 사실상 그대로 구현하고 있는 "소켓" API는 1983년 4.2 BSD Unix를 위해 설계된 원조 "[버클리 소켓](https://en.wikipedia.org/wiki/Berkeley_sockets)" API에서 유래했습니다. 물론 Windows와 Linux는 이 API를 다시 구현했을 뿐이지만, macOS와 iOS는 실제로 BSD Unix에서 물려받은 코드를 [지금도 상당량 사용하고 있습니다](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/KernelProgramming/BSD/BSD.html).

## 요청과 응답

이제 연결이 생겼으니 상대 서버에 요청을 보냅시다. 그러려면 `send` 메서드로 데이터를 보내면 됩니다.

```python
class URL:
    def request(self):
        # ...
        request = "GET {} HTTP/1.0\r\n".format(self.path)
        request += "Host: {}\r\n".format(self.host)
        request += "\r\n"
        s.send(request.encode("utf8"))
```

`send` 메서드는 그냥 요청을 서버로 보냅니다.[^17] 이 코드에는 정확히 지켜야 하는 것이 몇 가지 있습니다. 첫째, 줄바꿈에 `\n` 대신 `\r\n`을 사용하는 것이 매우 중요합니다. 또한 요청 끝에 `\r\n`을 _두 번_ 넣어서 마지막에 빈 줄이 오도록 하는 것도 필수입니다. 이를 잊으면 상대 컴퓨터는 그 줄바꿈이 오기를 계속 기다리고, 여러분은 응답이 오기를 계속 기다리게 됩니다.[^18]

`encode` 호출에도 주목하세요. 데이터를 보낼 때는 여러분이 날것의 비트와 바이트를 보내고 있다는 사실을 기억하는 것이 중요합니다. 그 바이트는 텍스트일 수도, 이미지나 비디오일 수도 있습니다. 반면 Python 문자열은 오직 텍스트를 표현하기 위한 것입니다. `encode` 메서드는 텍스트를 바이트로 변환하며, 반대 방향으로 가는 `decode` 메서드도 있습니다.[^19] Python은 텍스트와 바이트에 서로 다른 타입을 부여하여 조심하라고 일깨워 줍니다.

```
>>> type("text")
<class 'str'>
>>> type("text".encode("utf8"))
<class 'bytes'>
```

`str`과 `bytes`에 관한 오류가 보인다면, 어딘가에서 `encode`나 `decode` 호출을 빠뜨린 것입니다.

서버의 응답을 읽으려면 소켓의 `read` 함수를 쓸 수도 있습니다. 이 함수는 이미 도착한 응답의 일부를 돌려줍니다. 그러면 도착하는 대로 조각들을 모으는 반복문을 작성해야 합니다. 하지만 Python에서는 그 반복문을 감춰 주는 `makefile` 헬퍼 함수를 쓸 수 있습니다.[^20]

```python
class URL:
    def request(self):
        # ...
        response = s.makefile("r", encoding="utf8", newline="\r\n")
```

여기서 `makefile`은 서버로부터 받은 모든 바이트를 담은 파일 비슷한 객체를 반환합니다. 저는 Python에게 그 바이트들을 `utf8` _인코딩_, 즉 바이트를 문자에 대응시키는 방식을 사용해 문자열로 바꾸라고 지시하고 있습니다.[^21] 또한 HTTP의 독특한 줄바꿈 방식도 Python에게 알려 주고 있습니다.

이제 응답을 조각으로 나눠 봅시다. 첫 줄은 상태 줄입니다.[^22]

```python
class URL:
    def request(self):
        # ...
        statusline = response.readline()
        version, status, explanation = statusline.split(" ", 2)
```

여기서 서버의 HTTP 버전이 우리 것과 같은지 _검사하지 않는다는_ 점에 주의하세요. 검사하는 게 좋은 생각처럼 들릴 수도 있지만, 세상에는 HTTP 1.0으로 말을 걸어도 HTTP 1.1로 응답하는 잘못 설정된 서버가 많습니다.[^23]

상태 줄 다음에는 헤더가 옵니다.

```python
class URL:
    def request(self):
        # ...
        response_headers = {}
        while True:
            line = response.readline()
            if line == "\r\n": break
            header, value = line.split(":", 1)
            response_headers[header.casefold()] = value.strip()
```

헤더의 경우 각 줄을 첫 번째 콜론에서 나누어 헤더 이름과 헤더 값의 맵을 채웁니다. 헤더는 대소문자를 구분하지 않으므로 소문자로 정규화합니다.[^24] 또한 HTTP 헤더 값에서 공백은 의미가 없으므로 앞뒤의 여분 공백을 잘라냅니다.

헤더는 온갖 종류의 정보를 나타낼 수 있지만, 그중 몇 가지는 우리가 가져오려는 데이터가 평범하지 않은 방식으로 전송되고 있음을 알려 주기 때문에 특히 중요합니다. 그런 헤더가 없는지 확인합시다.[^25]

```python
class URL:
    def request(self):
        # ...
        assert "transfer-encoding" not in response_headers
        assert "content-encoding" not in response_headers
```

그렇다면 전송된 데이터를 얻는 일반적인 방법은, 헤더 다음의 모든 것을 취하는 것입니다.

```python
class URL:
    def request(self):
        # ...
        content = response.read()
        s.close()
```

우리가 화면에 표시할 것은 본문이므로, 그것을 반환합시다.

```python
class URL:
    def request(self):
        # ...
        return content
```

이제 실제로 응답 본문의 텍스트를 표시해 봅시다.

### 더 알아보기

[`Content-Encoding`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Content-Encoding) 헤더를 사용하면 서버가 웹 페이지를 압축해서 보낼 수 있습니다. 텍스트가 많은 큰 웹 페이지는 압축이 잘 되며, 그 결과 페이지가 더 빨리 로드됩니다. 브라우저는 자신이 지원하는 압축 알고리즘을 나열하기 위해 요청에 [`Accept-Encoding` 헤더](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Accept-Encoding)를 보내야 합니다. [`Transfer-Encoding`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Transfer-Encoding)도 이와 비슷하며, 데이터를 "청크(chunked)"로 나누는 것도 가능하게 해 줍니다. 많은 서버가 이를 압축과 함께 사용하는 것으로 보입니다.

## HTML 표시하기

응답 본문의 HTML 코드는 `http://example.org/index.html`에 접속했을 때 브라우저 창에 보이는 내용을 정의합니다. HTML에 대해서는 앞으로의 장에서 훨씬 더 많이 이야기하겠지만, 지금은 아주 단순하게만 다루겠습니다.

HTML에는 _태그_ 와 _텍스트_ 가 있습니다. 각 태그는 `<`로 시작해 `>`로 끝납니다. 일반적으로 태그는 어떤 내용이 어떤 종류의 것인지를 알려 주고, 텍스트는 실제 내용입니다.[^26] 대부분의 태그는 시작 태그와 끝 태그의 쌍으로 옵니다. 예를 들어 페이지의 제목은 `<title>`과 `</title>`이라는 태그 쌍으로 둘러싸입니다. 각 태그는 꺾쇠괄호 안에 태그 이름(여기서는 `title`)을 가지며, 선택적으로 공백 뒤에 _속성_ 이 따라올 수 있습니다. 그리고 짝이 되는 끝 태그는 `/` 뒤에 태그 이름이 옵니다(속성은 없습니다).

그러니 아주아주 단순한 웹 브라우저를 만들기 위해, 페이지의 HTML을 가져와 그 안의 텍스트는 모두 출력하되 태그는 출력하지 않도록 해 봅시다.[^27] 이 일은 `show`라는 새 함수에서 하겠습니다.[^28]

```python
def show(body):
    in_tag = False
    for c in body:
        if c == "<":
            in_tag = True
        elif c == ">":
            in_tag = False
        elif not in_tag:
            print(c, end="")
```

이 코드는 꽤 복잡합니다. 요청 본문을 한 글자씩 훑어가면서 두 가지 상태를 갖습니다. 현재 꺾쇠괄호 쌍 사이에 있는 `in_tag` 상태와, 그렇지 않은 `not in_tag` 상태입니다. 현재 글자가 꺾쇠괄호이면 상태가 바뀌고, 태그 안에 있지 않은 일반 글자는 출력됩니다.[^29]

이제 `request`와 `show`를 이어 붙이기만 하면 웹 페이지를 로드할 수 있습니다.[^30]

```python
def load(url):
    body = url.request()
    show(body)
```

명령줄에서 `load`를 실행할 수 있도록 다음 코드를 추가하세요.

```python
if __name__ == "__main__":
    import sys
    load(URL(sys.argv[1]))
```

첫 줄은 이 스크립트를 명령줄에서 실행할 때만 동작하는 Python판 `main` 함수입니다. 이 코드는 명령줄에서 첫 번째 인자(`sys.argv[1]`)를 읽어 URL로 사용합니다. `http://example.org/` URL로 이 코드를 실행해 보세요.

```bash
python3 browser.py http://example.org/
```

공식 예제 웹 페이지에 오신 것을 환영한다는 짧은 텍스트가 보일 것입니다. [이 장](http://browser.engineering/http.html)에 대해서도 시험해 볼 수 있습니다!

### 더 알아보기

HTML도 URL이나 HTTP와 마찬가지로 기본적인 수준에서는 파싱하고 표시하기가 매우 쉽도록 설계되었습니다. 그리고 초기에는 HTML의 기능이 아주 적었기 때문에, 여기서 본 것보다 그리 대단하지 않은 코드로도 내용을 쓸 만하게 표시할 수 있었습니다. 우리의 아주 단순하고 기본적인 HTML 파서조차도 이미 [browser.engineering](https://browser.engineering/) 웹사이트의 텍스트를 출력할 수 있습니다.

## 암호화된 연결

지금까지 우리 브라우저는 `http` 스킴을 지원합니다. 꽤 흔한 스킴이죠. 하지만 점점 더 많은 웹사이트가 `https` 스킴으로 옮겨 가고 있고, 많은 웹사이트가 이를 필수로 요구합니다.

`http`와 `https`의 차이는 `https`가 더 안전하다는 것인데, 조금 더 구체적으로 살펴봅시다. `https` 스킴은 좀 더 격식을 갖춰 말하면 HTTP over TLS(Transport Layer Security)로, 브라우저와 호스트 사이의 모든 통신이 암호화된다는 점만 빼면 일반 `http` 스킴과 동일합니다. 이것이 어떻게 동작하는지에는 꽤 많은 세부 사항이 있습니다. 어떤 암호화 알고리즘을 사용하는지, 공통 암호화 키를 어떻게 합의하는지, 그리고 물론 브라우저가 올바른 호스트에 연결하고 있는지 어떻게 확인하는지 같은 것들입니다. 관련된 프로토콜 계층의 차이는 그림 5에 나와 있습니다.

![그림 5: HTTP와 HTTPS의 차이는 TLS 계층이 추가된다는 점입니다.](http-tls-2.gif)

*그림 5: HTTP와 HTTPS의 차이는 TLS 계층이 추가된다는 점입니다.*

다행히 Python의 `ssl` 라이브러리가 이 모든 세부 사항을 대신 구현해 주기 때문에, 암호화된 연결을 만드는 일은 일반 연결을 만드는 것만큼이나 쉽습니다. 이렇게 쉬운 대신 몇 가지 기본 설정을 그대로 받아들이게 되는데, 상황에 따라서는 적절하지 않을 수도 있습니다. 다만 학습 목적으로는 충분합니다.

`ssl`로 암호화된 연결을 만드는 것은 꽤 쉽습니다. 이미 소켓 `s`를 만들어 `example.org`에 연결해 두었다고 합시다. 연결을 암호화하려면 `ssl.create_default_context`로 _컨텍스트_ `ctx`를 만들고, 그 컨텍스트로 소켓 `s`를 _감싸면(wrap)_ 됩니다.

```
import ssl
ctx = ssl.create_default_context()
s = ctx.wrap_socket(s, server_hostname=host)
```

`wrap_socket`이 새로운 소켓을 반환하며, 그것을 다시 `s` 변수에 저장한다는 점에 주의하세요. 원래 소켓으로는 어떤 데이터도 보내고 싶지 않기 때문입니다. 그렇게 하면 암호화되지 않을 뿐 아니라 혼란스럽기도 합니다. `server_hostname` 인자는 올바른 서버에 연결했는지 확인하는 데 사용됩니다. 이 값은 `Host` 헤더와 일치해야 합니다.

> **설치**
>
> macOS에서는 대부분의 웹사이트에 대해 Python의 `ssl` 패키지를 사용하기 전에 ["Install Certificates"라는 프로그램을 실행](https://stackoverflow.com/questions/52805115/certificate-verify-failed-unable-to-get-local-issuer-certificate)해야 합니다.

이 코드를 가져와 `request`에 추가해 봅시다. 먼저 어떤 스킴이 사용되고 있는지 감지해야 합니다.

```python
import ssl

class URL:
    def __init__(self, url):
        self.scheme, url = url.split("://", 1)
        assert self.scheme in ["http", "https"]
        # ...
```

(여기서는 기존의 스킴 파싱 코드를 이 새 코드로 교체해야 한다는 점에 주의하세요. 무엇을 교체해야 하는지는 대개 문맥과 코드 자체를 보면 분명합니다.)

암호화된 HTTP 연결은 보통 포트 80 대신 443을 사용합니다.

```python
class URL:
    def __init__(self, url):
        # ...
        if self.scheme == "http":
            self.port = 80
        elif self.scheme == "https":
            self.port = 443
```

소켓을 만들 때 그 포트를 사용할 수 있습니다.

```python
class URL:
    def request(self):
        # ...
        s.connect((self.host, self.port))
        # ...
```

다음으로 `ssl` 라이브러리로 소켓을 감싸겠습니다.

```python
class URL:
    def request(self):
        # ...
        s.connect((self.host, self.port))
        if self.scheme == "https":
            ctx = ssl.create_default_context()
            s = ctx.wrap_socket(s, server_hostname=self.host)
        # ...
```

이제 브라우저가 HTTPS 사이트에 연결할 수 있을 것입니다.

이왕 하는 김에 사용자 지정 포트 지원도 추가합시다. 포트는 그림 6처럼 URL에서 호스트 이름 뒤에 콜론을 붙여 지정합니다.

```
http://example.org:8080/index.html
```

*그림 6: URL에서 포트가 들어가는 위치. 여기서 `8080`이 포트입니다.*

URL에 포트가 있으면 그것을 파싱해서 사용할 수 있습니다.

```python
class URL:
    def __init__(self, url):
        # ...
        if ":" in self.host:
            self.host, port = self.host.split(":", 1)
            self.port = int(port)
```

사용자 지정 포트는 디버깅에 유용합니다. Python에는 컴퓨터의 파일을 제공하는 데 쓸 수 있는 내장 웹 서버가 있습니다. 예를 들어 다음을 실행하면

```bash
python3 -m http.server 8000 -d /some/directory
```

`http://localhost:8000/`으로 접속했을 때 해당 디렉터리의 모든 파일이 보일 것입니다. 브라우저를 테스트하기에 좋은 방법입니다.

### 더 알아보기

TLS는 꽤 복잡합니다. 자세한 내용은 [RFC 8446](https://tools.ietf.org/html/rfc8446)에서 읽어 볼 수 있지만, 직접 구현하는 것은 권장하지 않습니다. 올바를 뿐 아니라 안전하기까지 한 TLS 구현을 직접 작성하기란 매우 어렵습니다.

이 시점에서 여러분의 프로그램은 어떤 웹 페이지에서도 실행할 수 있을 것입니다. [간단한 예제](https://browser.engineering/examples/example1-simple.html)에 대해서는 다음과 같은 결과가 나와야 합니다.

```
  
    This is a simple
    web page with some
    text in it.
  
```

## 연습문제

**1-1 _HTTP/1.1_.** `request` 함수에서 `Host`와 함께 `Connection` 헤더를 값 `close`로 보내세요. 이제 브라우저는 자신이 `HTTP/1.1`을 사용한다고 선언할 수 있습니다. `User-Agent` 헤더도 추가하세요. 그 값은 무엇이든 상관없으며, 호스트에게 여러분의 브라우저를 알려 주는 역할을 합니다. 앞으로 헤더를 더 쉽게 추가할 수 있도록 만드세요.

**1-2 _파일 URL_.** 브라우저가 로컬 파일을 열 수 있게 해 주는 `file` 스킴 지원을 추가하세요. 예를 들어 `file:///path/goes/here`는 여러분 컴퓨터의 `/path/goes/here` 위치에 있는 파일을 가리켜야 합니다. 또한 URL을 주지 않고 브라우저를 시작하면 컴퓨터의 특정 파일이 열리도록 만드세요. 그 파일을 빠른 테스트에 사용할 수 있습니다.

**1-3 _`data`_.** 또 다른 스킴으로 `data`가 있는데, 이는 HTML 콘텐츠를 URL 자체에 인라인으로 넣을 수 있게 해 줍니다. 실제 브라우저에서 `data:text/html,Hello world!`로 이동해 어떤 일이 일어나는지 확인해 보세요. 여러분의 브라우저에 이 스킴 지원을 추가하세요. `data` 스킴은 테스트를 별도 파일에 넣지 않고도 만들 수 있어서 특히 편리합니다.

**1-4 _엔티티_.** 미만(`&lt;`)과 초과(`&gt;`) 엔티티 지원을 구현하세요. 이들은 각각 `<`와 `>`로 출력되어야 합니다. 예를 들어 HTML 응답이 `&lt;div&gt;`였다면, 브라우저의 `show` 메서드는 `<div>`를 출력해야 합니다. 엔티티 덕분에 웹 페이지는 브라우저가 태그로 해석하지 않게 하면서 이런 특수 문자를 포함할 수 있습니다.

**1-5 _`view-source`_.** `view-source` 스킴 지원을 추가하세요. `view-source:http://example.org/`로 이동하면 렌더링된 페이지 대신 HTML 소스가 보여야 합니다. 이 스킴 지원을 추가하세요. 브라우저는 HTML 파일 전체를 텍스트인 것처럼 출력해야 합니다. 연습문제 1-4도 함께 구현해 두는 것이 좋습니다.

**1-6 _Keep-alive_.** 연습문제 1-1을 구현하되, `Connection: close` 헤더는 보내지 마세요(대신 `Connection: keep-alive`를 보내세요). 소켓에서 본문을 읽을 때는 `Content-Length` 헤더에 주어진 만큼의 바이트만 읽고, 그 뒤에 소켓을 닫지 마세요. 대신 소켓을 저장해 두었다가, 같은 서버에 다른 요청을 할 때 새로 만들지 말고 같은 소켓을 재사용하세요. (`makefile`에 `"rb"` 옵션을 넘겨야 할 수도 있습니다. 그러지 않으면 `Content-Length`가 알려 주는 값이 읽고 있는 문자열의 길이와 맞지 않을 수 있습니다.) 이렇게 하면 흔히 일어나는 같은 서버로의 반복 요청이 빨라집니다.

**1-7 _리다이렉트_.** 300번대 오류 코드는 리다이렉트를 요청합니다. 브라우저가 이를 만나면 `Location` 헤더에 주어진 URL로 새 요청을 보내야 합니다. `Location` 헤더가 완전한 URL일 때도 있지만, 호스트와 스킴을 생략하고 그냥 `/`로 시작할 때도 있습니다(원래 요청과 같은 호스트, 같은 스킴이라는 뜻입니다). 새 URL이 또다시 리다이렉트일 수도 있으니 그 경우도 처리해야 합니다. 다만 리다이렉트 루프에 빠지고 싶지는 않을 테니, 브라우저가 연속으로 따라갈 수 있는 리다이렉트 횟수를 제한하세요. 이 페이지로 되돌아오는 [http://browser.engineering/redirect](http://browser.engineering/redirect) URL과, 좀 더 복잡한 리다이렉트 연쇄를 만드는 [/redirect2](http://browser.engineering/redirect2), [/redirect3](http://browser.engineering/redirect3)로 테스트해 볼 수 있습니다.

**1-8 _캐싱_.** 보통 같은 이미지, 스타일, 스크립트가 여러 페이지에서 사용되므로, 이를 반복해서 내려받는 것은 낭비입니다. 일반적으로 `GET`으로 요청했고 `200` 응답을 받았다면 어떤 HTTP 응답이든 캐시해도 괜찮습니다.[^31] 브라우저에 캐시를 구현하고, 같은 파일을 여러 번 요청해 테스트해 보세요. 서버는 `Cache-Control` 헤더로 캐시를 제어합니다. 이 헤더에 대한 지원을 추가하되, 특히 `no-store`와 `max-age` 값에 대해 구현하세요. `Cache-Control` 헤더에 이 두 가지 외의 값이 들어 있다면 응답을 캐시하지 않는 편이 좋습니다.

**1-9 _압축_.** HTTP 압축 지원을 추가하세요. 여기서 브라우저는 압축된 데이터를 받아도 좋다고 [서버에 알립니다](https://developer.mozilla.org/en-US/docs/Web/HTTP/Content_negotiation). 브라우저는 `Accept-Encoding` 헤더를 값 `gzip`으로 보내야 합니다. 서버가 압축을 지원하면 응답에 값이 `gzip`인 `Content-Encoding` 헤더가 들어 있습니다. 그러면 본문이 압축되어 있습니다. 이 경우에 대한 지원을 추가하세요. 데이터를 압축 해제하려면 `gzip` 모듈의 `decompress` 메서드를 사용하면 됩니다. GZip 데이터는 `utf8`로 인코딩되어 있지 않으므로, `makefile`에 `"rb"`를 넘겨 원시 바이트를 다루세요. 대부분의 웹 서버는 [`chunked`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Headers/Transfer-Encoding)라는 `Transfer-Encoding`으로 압축된 데이터를 보냅니다.[^32] 그에 대한 지원도 추가해야 합니다.

[^29]: `end` 인자는 글자 뒤에 줄바꿈을 출력하지 말라고 Python에 알려 줍니다. 그러지 않으면 줄바꿈이 출력됩니다.

[^30]: `show`와 마찬가지로 이것도 전역 함수입니다.

[^31]: `301`이나 `404` 같은 다른 상태 코드도 캐시할 수 있습니다.

[^32]: 데이터를 압축하는 `Transfer-Encoding`도 몇 가지 있습니다. 흔히 쓰이지는 않습니다.
