# 4장 연습문제 구현

[← 4장 결과물로](결과물.md) · [← 본문으로](HTML-트리-구성하기.md#연습문제)

본문의 연습문제 6개를 모두 구현했습니다. `lab4.py` 는 그대로 두고, 1~3장 연습문제를
이어받아 그 위에 4장 기능을 얹은 `HTMLParser` 와 `Layout` 을 `ex4.py` 에 정의했습니다.

3장까지 만든 배치 기능(가운데 정렬·위 첨자·소프트 하이픈·스몰 캡·`<pre>`)은 토큰
순회에서 **트리 순회로 옮겨** 그대로 살아 있습니다.

## 실행

```bash
python3 ex4.py https://browser.engineering/
python3 ex4.py view-source:https://example.org/     # 4-5 구문 강조
```

## 검증

```bash
python3 test_ex4.py
```

38개 테스트로 확인합니다. 마지막 묶음은 3장까지의 배치 기능이 트리에서도 그대로
도는지 보는 회귀 테스트입니다.

## 구현 내용

| 문제 | 제목 | 구현 위치 | 요점 |
|---|---|---|---|
| 4-1 | 주석 | `skip_comment` | `<!--` 부터 `-->` 까지 통째로 건너뜁니다. 토큰을 아예 만들지 않습니다 |
| 4-2 | 문단 | `auto_close` | `<p>` 가 또 열리면 앞의 것을 닫습니다. `<li>` 도 같되 `<ul>`/`<ol>` 을 만나면 멈춰서 중첩 목록은 유지됩니다 |
| 4-3 | 스크립트 | `read_script` | `<script>` 뒤부터 `</script>` 전까지 통째로 텍스트로 봅니다 (대소문자 무시) |
| 4-4 | 따옴표 속성 | `read_tag`, `get_attributes` | 따옴표 상태를 들고 다녀서 값 안의 공백과 `>` 를 견딥니다 |
| 4-5 | 구문 강조 | `SourceParser` | 파서를 상속해 훑는 규칙은 그대로 쓰고, 결과만 `<pre>` 안에 담습니다. 태그는 보통, 내용은 `<b>` |
| 4-6 | 잘못 중첩 태그 | `close_mis_nested` | 안쪽 서식 태그를 닫고 → 원래 태그를 닫고 → 안쪽 것만 다시 엽니다 |

## 본문의 질문에 대한 답

> 확인해 보세요. `<!-->` 는 주석일까요, 아니면 주석을 시작하기만 하는 걸까요?

**빈 주석입니다.** `<!--` 바로 뒤에 `>` 가 오면 거기서 끝납니다. HTML 명세도 이렇게
보고, `test_empty_comment` 가 이 동작을 확인합니다.

## 설계 메모

**훑기와 트리 쌓기를 분리했습니다.** `parse()` 는 글자를 훑다가 `handle_text` /
`handle_tag` 훅을 부르고, 기본 구현이 트리를 쌓습니다. 4-5 의 `SourceParser` 는 이
훅만 갈아끼워서 주석·스크립트·따옴표 처리를 공짜로 물려받습니다. 강조 결과가
실제 파서와 어긋날 일이 없습니다.

**4-2 는 "멈춤 태그"로 중첩을 지킵니다.** `<li>` 를 열 때 위로 훑어 올라가다가
`<ul>`/`<ol>` 을 만나면 멈춥니다. 그래서 같은 목록 안의 `<li>` 는 형제가 되고,
새 목록 안의 `<li>` 는 중첩이 유지됩니다.

**4-6 은 서식 태그일 때만 개입합니다.** 닫으려는 태그와 그 안쪽에 열린 것들이 모두
서식 태그일 때만 닫았다 다시 엽니다. 그렇지 않으면 평소대로 처리해서, 멀쩡한
문서 구조를 건드리지 않습니다.
