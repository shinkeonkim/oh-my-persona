지금 우리 브라우저는 색이 있는 직사각형과 텍스트만 그릴 수 있습니다. 꽤 심심하죠! 실제 브라우저는 픽셀과 색이 섞이는 방식을 바꾸는 온갖 종류의 _시각 효과_ 를 지원합니다. 그 효과들을 구현하고 동시에 브라우저를 더 빠르게 만들려면 _서피스(surface)_ 를 제어할 수 있어야 합니다. 서피스는 빠른 스크롤, 시각 효과, 애니메이션을 비롯한 많은 브라우저 기능의 바탕이 되는 핵심적인 저수준 기능입니다. 그 제어권을 얻기 위해 Skia 그래픽 라이브러리로 전환하고, 그 내부도 살짝 들여다보겠습니다.

## Skia와 SDL 설치하기

Tkinter는 기본 도형과 입력 처리에는 훌륭하지만 서피스에 대한 제어권을 주지 않고[^1] 대부분의 시각 효과 구현도 없습니다. 직접 구현하면 재미있겠지만 이 책의 범위를 벗어나므로 새 그래픽 라이브러리가 필요합니다. Chromium이 사용하는 라이브러리인 [Skia](https://skia.org)를 쓰겠습니다. Tkinter와 달리 Skia는 입력을 처리하거나 그래픽 창을 만들지 않으므로, [SDL](https://www.libsdl.org/) GUI 라이브러리와 짝지어 쓰겠습니다. 새로운 기능은 물론이고, Skia로 전환하면 그래픽과 래스터화를 더 낮은 수준에서 제어할 수 있게 됩니다.

> **설치**
>
> [Skia](https://kyamagu.github.io/skia-python/)와 [SDL](https://pypi.org/project/PySDL2/)을 설치하는 것부터 시작하세요.[^2]
>
> ```bash
> python3 -m pip install skia-python pysdl2 pysdl2-dll PyOpenGL
> ```
>
> 이 책의 다른 곳에서와 마찬가지로, 먼저 `pip` 패키지를 설치하거나 IDE의 패키지 설치 도구를 써야 할 수도 있습니다. Linux를 쓰고 있다면 OpenGL과 fontconfig 같은 추가 의존성을 설치해야 합니다. 또한 `pysdl2-dll`을 설치하지 못할 수도 있는데, 그렇다면 시스템 패키지 관리자에서 SDL을 찾아야 합니다. 더 자세한 내용은 [`skia-python`](https://kyamagu.github.io/skia-python/)과 [`pysdl2`](https://pypi.org/project/PySDL2/) 웹 페이지를 참고하세요.

설치했으면 브라우저에서 `tkinter` import를 제거하고 다음으로 대체하세요.

```python
import ctypes
import sdl2
import skia
```

`ctypes` 모듈은 Python의 표준 구성 요소입니다. 이를 사용해 Python 타입과 C 타입 사이를 변환하겠습니다. 이 import 중 어느 것이라도 실패한다면 Skia와 SDL이 올바르게 설치되었는지 확인하세요.

### 더 알아보기

[`<canvas>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/canvas) HTML 요소는 Skia나 Tkinter와 비슷한 JavaScript API를 제공합니다. [WebGL](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API)과 결합하면 사실상 SDL과 Skia 전부를 JavaScript로 구현할 수 있습니다. 또는 [Skia를 컴파일](https://skia.org/docs/user/modules/canvaskit/)해 [WebAssembly](https://developer.mozilla.org/en-US/docs/WebAssembly)로 만들어 같은 일을 할 수도 있습니다.

## SDL이 창을 만든다

첫 번째 큰 작업은 창을 만들고 이벤트를 처리하는 데 SDL을 쓰도록 전환하는 것입니다. 브라우저의 메인 루프에는 먼저 SDL을 시작하는 상용구가 조금 필요합니다.

```python
if __name__ == "__main__":
    sdl2.SDL_Init(sdl2.SDL_INIT_EVENTS)
    browser = Browser()
    browser.new_tab(URL(sys.argv[1]))
    # ...
```

다음으로 `Browser` 안에서 Tkinter 창이 아니라 SDL 창을 만들어야 합니다. SDL의 주문은 다음과 같습니다.

```python
class Browser:
    def __init__(self):
        self.sdl_window = sdl2.SDL_CreateWindow(b"Browser",
            sdl2.SDL_WINDOWPOS_CENTERED, sdl2.SDL_WINDOWPOS_CENTERED,
            WIDTH, HEIGHT, sdl2.SDL_WINDOW_SHOWN)
```

창을 만들었으니 이제 그 창으로 보내진 이벤트를 처리해야 합니다. SDL에는 `mainloop`나 `bind` 메서드가 없으므로 직접 구현해야 합니다.

```python
def mainloop(browser):
    event = sdl2.SDL_Event()
    while True:
        while sdl2.SDL_PollEvent(ctypes.byref(event)) != 0:
            if event.type == sdl2.SDL_QUIT:
                browser.handle_quit()
                sdl2.SDL_Quit()
                sys.exit()
            # ...
```

`ctypes`와 `PollEvent`의 세부 사항은 여기서 그리 중요하지 않지만, `SDL_QUIT`은 사용자가 마지막으로 열려 있는 창을 닫을 때 보내지는 이벤트라는 점에 주의하세요. 그것이 호출하는 `handle_quit` 메서드는 그저 창 객체를 정리합니다.

```python
class Browser:
    def handle_quit(self):
        sdl2.SDL_DestroyWindow(self.sdl_window)
```

`tkinter.mainloop` 대신 `mainloop`를 호출하세요.

```python
if __name__ == "__main__":
    # ...
    mainloop(browser)
```

`Browser` 생성자의 모든 `bind` 호출 대신, 클릭이나 타이핑 같은 여러 종류의 이벤트에 대해 그냥 메서드를 직접 호출하면 됩니다. SDL 문법은 다음과 같습니다.

```python
def mainloop(browser):
    while True:
        while sdl2.SDL_PollEvent(ctypes.byref(event)) != 0:
            # ...
            elif event.type == sdl2.SDL_MOUSEBUTTONUP:
                browser.handle_click(event.button)
            elif event.type == sdl2.SDL_KEYDOWN:
                if event.key.keysym.sym == sdl2.SDLK_RETURN:
                    browser.handle_enter()
                elif event.key.keysym.sym == sdl2.SDLK_DOWN:
                    browser.handle_down()
            elif event.type == sdl2.SDL_TEXTINPUT:
                browser.handle_key(event.text.text.decode('utf8'))
```

여러 이벤트 핸들러 메서드의 시그니처를 바꿨습니다. 예를 들어 `handle_click` 메서드는 이제 `MouseButtonEvent` 객체를 받는데, 다행히 그 객체에는 `x`와 `y` 좌표가 들어 있습니다. 반면 `handle_enter`와 `handle_down` 메서드는 인자를 전혀 받지 않는데, 어차피 그 인자를 쓰지 않기 때문입니다. `Browser` 메서드들의 시그니처를 그에 맞게 바꿔야 합니다.

### 더 알아보기

SDL은 게임을 만드는 데 가장 널리 쓰입니다. SDL 사이트에는 SDL로 하는 게임 프로그래밍에 관한 [엄선된 책 목록](https://wiki.libsdl.org/Books)이 있습니다.

## 서피스와 픽셀

이 SDL 호출들의 내부를 들여다봅시다. SDL 창을 만들 때 우리는 SDL에게 _서피스(surface)_, 즉 화면의 픽셀을 나타내는 메모리 덩어리를 할당해 달라고 요청하는 것입니다.[^3] 서피스를 만들고 관리하는 것이 이 장의 큰 초점이 될 것입니다. 오늘날의 큰 화면에서 서피스는 많은 메모리를 차지하므로, 서피스를 잘 다루는 것이 좋은 브라우저 성능에 필수적입니다.

_서피스_ 는 _픽셀_(색을 나타내는 비트)을 그려 넣을 수 있는 그래픽 버퍼의 표현입니다. SDL 창을 만들 때 우리는 암묵적으로 SDL 서피스를 만들었습니다. 이제 Skia가 그릴 서피스도 만들어 봅시다.

```python
class Browser:
    def __init__(self):
        self.root_surface = skia.Surface.MakeRaster(
            skia.ImageInfo.Make(
                WIDTH, HEIGHT,
                ct=skia.kRGBA_8888_ColorType,
                at=skia.kUnpremul_AlphaType))
```

각 픽셀에는 색이 있습니다. "색 타입"을 뜻하는 `ct` 인자를 눈여겨보세요. 이는 이 서피스의 각 픽셀이 _r_ed, _g_reen, _b_lue, _a_lpha 값으로 표현되어야 하며 각각 8비트를 차지해야 함을 나타냅니다. 다시 말해 픽셀은 기본적으로 다음과 같이 정의됩니다.

```
class Pixel:
    def __init__(self, r, g, b, a):
        self.r = r
        self.g = g
        self.b = b
        self.a = a
```

이 `Pixel` 정의는 설명을 위한 예시일 뿐 우리 브라우저의 실제 코드가 아닙니다. SDL과 Skia 내부의 다소 복잡한 코드를 대신 표현한 것입니다.[^4]

빨강, 초록, 파랑 성분으로 색을 정의하는 것은 꽤 표준적이며[^5] 컴퓨터 화면이 동작하는 방식에 대응합니다.[^6] 예를 들어 CSS에서 우리는 `#ffd700`처럼 해시 문자와 16진수 여섯 자리로 임의의 색을 나타내며, 빨강·초록·파랑에 각각 두 자리씩 씁니다.[^7]

```python
def parse_color(color):
    if color.startswith("#") and len(color) == 7:
        r = int(color[1:3], 16)
        g = int(color[3:5], 16)
        b = int(color[5:7], 16)
        return skia.Color(r, g, b)
```

지금까지 본 색들은 이 문법으로 그냥 지정할 수 있습니다.

```python
NAMED_COLORS = {
    "black": "#000000",
    "white": "#ffffff",
    "red":   "#ff0000",
    # ...
}

def parse_color(color):
    # ...
    elif color in NAMED_COLORS:
        return parse_color(NAMED_COLORS[color])
    else:
        return skia.ColorBLACK
```

마주치는 대로 [목록](https://developer.mozilla.org/en-US/docs/Web/CSS/named-color)에서 이름 있는 색을 더 추가할 수 있습니다. 이 책의 데모는 `blue`, `green`, `lightblue`, `lightgreen`, `orange`, `orangered`, `gray`를 사용합니다. 지원하지 않는 색은 검정으로 해석되어 최소한 무언가는 화면에 그려진다는 점에 주의하세요.[^8]

이제 서피스와 색에 대한 이해를 활용해, 크롬과 페이지 콘텐츠를 그릴 Skia 서피스에서 실제로 화면에 나타나는 SDL 서피스로 복사해 봅시다. 두 개의 저수준 라이브러리 사이에서 데이터를 옮기는 것이라 조금 까다롭지만, 사실 우리가 하는 일은 그저 픽셀을 한 곳에서 다른 곳으로 복사하는 것뿐입니다. 먼저 Skia 서피스를 나타내는 바이트 열을 가져옵니다.

```python
class Browser:
    def draw(self):
        # ...
        skia_image = self.root_surface.makeImageSnapshot()
        skia_bytes = skia_image.tobytes()
```

다음으로 그 데이터를 SDL 서피스에 복사해야 합니다. 이를 위해서는 픽셀이 어떤 순서로 저장되어 있는지, 그리고 여러분 컴퓨터의 [엔디언](https://en.wikipedia.org/wiki/Endianness)이 무엇인지 SDL에 알려 주어야 합니다.

```python
class Browser:
    def __init__(self):
        if sdl2.SDL_BYTEORDER == sdl2.SDL_BIG_ENDIAN:
            self.RED_MASK = 0xff000000
            self.GREEN_MASK = 0x00ff0000
            self.BLUE_MASK = 0x0000ff00
            self.ALPHA_MASK = 0x000000ff
        else:
            self.RED_MASK = 0x000000ff
            self.GREEN_MASK = 0x0000ff00
            self.BLUE_MASK = 0x00ff0000
            self.ALPHA_MASK = 0xff000000
```

그러면 `CreateRGBSurfaceFrom` 메서드가 (바이트를 복사하지 않고) 그 데이터를 SDL 서피스로 감쌉니다.

```python
class Browser:
    def draw(self):
        # ...
        depth = 32 # Bits per pixel
        pitch = 4 * WIDTH # Bytes per row
        sdl_surface = sdl2.SDL_CreateRGBSurfaceFrom(
            skia_bytes, WIDTH, HEIGHT, depth, pitch,
            self.RED_MASK, self.GREEN_MASK,
            self.BLUE_MASK, self.ALPHA_MASK)
```

마지막으로, `sdl_surface`에서 `sdl_window`의 서피스로 블리팅(복사)하여 이 모든 픽셀 데이터를 창 자체에 그립니다.[^9]

```python
class Browser:
    def draw(self):
        # ...
        rect = sdl2.SDL_Rect(0, 0, WIDTH, HEIGHT)
        window_surface = sdl2.SDL_GetWindowSurface(self.sdl_window)
        # SDL_BlitSurface is what actually does the copy.
        sdl2.SDL_BlitSurface(sdl_surface, rect, window_surface, rect)
        sdl2.SDL_UpdateWindowSurface(self.sdl_window)
```

이제 Skia 서피스에서 SDL 창으로 복사할 수 있습니다. 마지막 한 단계가 남았습니다. 브라우저를 Skia 서피스에 그려야 합니다.

### 더 알아보기

당연하게 여기지만, [CIELAB](https://en.wikipedia.org/wiki/CIELAB_color_space) 같은 색 표준은 [인간의 시각을 역설계하려는](https://en.wikipedia.org/wiki/Opponent_process) 시도에서 비롯되었습니다. 화면은 인간의 눈에 있는 세 종류의 [원뿔세포](https://en.wikipedia.org/wiki/Cone_cell)에 맞추기 위해 빨강, 초록, 파랑 색 채널을 사용합니다. 이 원뿔세포는 사람마다 다릅니다. [더 많은](https://en.wikipedia.org/wiki/Tetrachromacy#Humans) 사람도 있고 [더 적은](https://en.wikipedia.org/wiki/Color_blindness) 사람도 있습니다(보통 X 염색체로 전달되는 유전적 특성입니다). 게다가 사람마다 원뿔세포 종류의 비율이 다르고, 그 원뿔세포들은 서로 다른 단백질 구조를 사용해 반응하는 초록·빨강·파랑의 정확한 진동수가 다릅니다. 그래서 색에 대한 연구는 소프트웨어, 하드웨어, 화학, 생물학, 심리학이 결합된 분야입니다.

## Skia로 래스터화하기

우리는 Skia 서피스에 텍스트, 직사각형 등을 그리고자 합니다. 서피스의 픽셀에 색을 입혀 그 위에 도형을 그리는 이 단계를 "래스터화(rasterization)"라고 하며, 그래픽 라이브러리의 중요한 임무 중 하나입니다. Skia에서 래스터화는 _캔버스_ API를 통해 이루어집니다. 캔버스는 그저 특정 서피스에 그리는 객체입니다.

```python
class Browser:
    def draw(self, canvas, offset):
        # ...
        canvas = self.root_surface.getCanvas()
        # ...
```

여러 클래스를 Skia의 래스터 API를 쓰도록 바꿔 봅시다.

가장 먼저 할 일은 `rect` 필드를 Skia `Rect` 객체로 바꾸는 것입니다. [7장](https://browser.engineering/chrome.html)에서 도입한 기존 `Rect` 클래스를 없애고 `skia.Rect`를 쓰세요. `Rect`를 생성하던 모든 곳에 대신 `skia.Rect.MakeLTRB`("make left-top-right-bottom")나 `MakeXYWH`("make _x_-_y_-width-height")를 넣으세요. 직사각형의 변(예: `left`)을 검사하던 모든 곳은 Skia `Rect`의 해당 함수(예: `left()`)로 바꾸세요. `containsPoint` 호출도 Skia의 `contains`로 바꾸세요.

특히 `DrawText`와 `DrawLine`은 다음과 같습니다.

```python
class DrawText:
    def __init__(self, x1, y1, text, font, color):
        self.rect = skia.Rect.MakeLTRB(
            x1, y1,
            x1 + font.measureText(text),
            y1 - font.getMetrics().fAscent \
                + font.getMetrics().fDescent)
        # ...

class DrawLine:
    def __init__(self, x1, y1, x2, y2, color, thickness):
        self.rect = skia.Rect.MakeLTRB(x1, y1, x2, y2)
        # ...
```

우리 브라우저의 그리기 명령들은 이 캔버스에서 Skia 메서드를 호출해야 합니다. 선을 그리려면 Skia의 `Path` 객체를 사용합니다.[^10]

```python
class DrawLine:
    def execute(self, scroll, canvas):
        path = skia.Path().moveTo(
            self.rect.left(), self.rect.top() - scroll) \
                .lineTo(self.rect.right(),
                    self.rect.bottom() - scroll)
        paint = skia.Paint(
            Color=parse_color(self.color),
            StrokeWidth=self.thickness,
            Style=skia.Paint.kStroke_Style,
        )
        canvas.drawPath(path, paint)
```

여기 관여하는 단계들을 눈여겨보세요. 먼저 `Path` 객체를 만들고, 그다음 `drawPath`를 호출해 실제로 이 경로를 캔버스에 그립니다. 이 `drawPath` 호출은 두 번째 인자로 `paint`를 받는데, 이는 그리기를 실제로 어떻게 수행할지 정의합니다. 우리는 색을 지정하는 한편, 경로의 내부를 채우는(기본 동작) 대신 경로를 _따라_ 선을 그리고 싶다는 것도 지정해야 합니다. 그러기 위해 스타일을 "stroke"로 설정하는데, 이는 어떤 도형의 테두리를 따라 그리는 것을 가리키는 표준 용어입니다.[^11]

`drawString`으로 텍스트를 그릴 때도 비슷하게 합니다.

```python
class DrawText:
    def execute(self, scroll, canvas):
        paint = skia.Paint(
            AntiAlias=True,
            Color=parse_color(self.color),
        )
        baseline = self.rect.top() - scroll \
            - self.font.getMetrics().fAscent
        canvas.drawString(self.text, float(self.rect.left()),
            baseline, self.font, paint)
```

다시 한번 색을 지정하고 안티에일리어싱된 텍스트를 요청하는 `Paint` 객체를 만든다는 점에 주의하세요.[^12] 텍스트의 내부를 채우고 싶은데 그것이 기본값이므로 "style"은 지정하지 않습니다.

마지막으로 직사각형을 그릴 때는 `drawRect`를 사용합니다.

```python
class DrawRect:
    def execute(self, scroll, canvas):
        paint = skia.Paint(
            Color=parse_color(self.color),
        )
        canvas.drawRect(self.rect.makeOffset(0, -scroll), paint)
```

외곽선을 만들려면 직사각형을 그리되 `Paint`의 `Style` 매개변수를 `Stroke_Style`로 설정하세요.

```python
class DrawOutline:
    def execute(self, scroll, canvas):
        paint = skia.Paint(
            Color=parse_color(self.color),
            StrokeWidth=self.thickness,
            Style=skia.Paint.kStroke_Style,
        )
        canvas.drawRect(self.rect.makeOffset(0, -scroll), paint)
```

Tkinter를 Skia로 대체하고 있으므로 `tkinter.font`도 대체합니다. Skia에서 폰트 객체는 두 부분으로 이루어집니다. 특정 굵기, 스타일, 너비를 가진 서체 패밀리인 `Typeface`와, 특정 크기의 `Typeface`인 `Font`입니다. 데이터와 캐시를 담고 있는 것은 `Typeface`이므로, 캐시해야 할 것도 그것입니다.

```python
def get_font(size, weight, style):
    key = (weight, style)
    if key not in FONTS:
        if weight == "bold":
            skia_weight = skia.FontStyle.kBold_Weight
        else:
            skia_weight = skia.FontStyle.kNormal_Weight
        if style == "italic":
            skia_style = skia.FontStyle.kItalic_Slant
        else:
            skia_style = skia.FontStyle.kUpright_Slant
        skia_width = skia.FontStyle.kNormal_Width
        style_info = \
            skia.FontStyle(skia_weight, skia_width, skia_style)
        font = skia.Typeface('Arial', style_info)
        FONTS[key] = font
    return skia.Font(FONTS[key], size)
```

우리 브라우저에는 폰트 메트릭과 측정도 필요합니다. Skia에서는 이를 `measureText`와 `getMetrics` 메서드가 제공합니다. 우선 모든 `measure` 호출을 `measureText`로 바꾸는 것부터 시작합시다. 예를 들어 `InputLayout`의 `paint` 메서드에서는 다음과 같이 해야 합니다.

```python
class InputLayout:
    def paint(self):
        if self.node.is_focused:
            cx = self.x + self.font.measureText(text)
            # ...
```

`measure` 호출은 여러 다른 레이아웃 객체(`paint`와 `layout` 양쪽), `DrawText`, `Chrome`의 `draw` 메서드, `BlockLayout`의 `text` 메서드, `TextLayout`의 `layout` 메서드에도 있습니다. 전부 `measureText`를 쓰도록 갱신하세요.

또한 `LineLayout`의 `layout` 메서드와 `DrawText`에서 폰트의 `metrics` 메서드를 호출합니다. Skia에서 이 메서드의 이름은 `getMetrics`이며, 어센트와 디센트를 얻으려면 그 결과의 `fAscent`와 `fDescent` 필드가 필요합니다.

중요한 점은 Skia에서 어센트를 음수로 뒤집어야 한다는 것입니다. Skia에서 어센트와 디센트는 아래로 가면 양수이고 위로 가면 음수이므로, 어센트는 보통 음수가 됩니다. Tkinter와 반대죠. Tkinter가 제공하는 `linespace` 필드에 해당하는 것은 없지만, 대신 디센트에서 어센트를 뺀 값을 쓸 수 있습니다.

```python
def linespace(font):
    metrics = font.getMetrics()
    return metrics.fDescent - metrics.fAscent
```

이제 브라우저를 다시 실행할 수 있을 것입니다. 이전 장들과 똑같이 보이고 똑같이 동작하되, 복잡한 페이지에서는 더 빠르게 느껴질 수도 있습니다. Skia와 SDL이 일반적으로 Tkinter보다 빠르기 때문입니다. 이 전환이 쉽게 느껴졌다면, 그것이 바로 디스플레이 리스트를 사용해 그리기 백엔드를 추상화한 덕분입니다!

마지막으로, Skia는 몇 가지 새로운 기능도 제공합니다. 예를 들어 Skia는 `RRect` 객체를 통해 둥근 모서리 직사각형을 기본 지원합니다. `DrawRect`를 `DrawRRect`로 바꿔 이를 구현할 수 있습니다.

```python
class DrawRRect:
    def __init__(self, rect, radius, color):
        self.rect = rect
        self.rrect = skia.RRect.MakeRectXY(rect, radius, radius)
        self.color = color

    def execute(self, scroll, canvas):
        paint = skia.Paint(
            Color=parse_color(self.color),
        )
        canvas.drawRRect(self.rrect, paint)
```

class BlockLayout:

### 더 알아보기

[폰트 래스터화](https://en.wikipedia.org/wiki/Font_rasterization)는 놀랄 만큼 깊이 있는 분야로, 낮은 해상도의 화면에서 폰트를 더 보기 좋게 만들기 위해 [서브픽셀 렌더링](https://en.wikipedia.org/wiki/Subpixel_rendering)이나 [힌팅](https://en.wikipedia.org/wiki/Font_hinting) 같은 기법이 사용됩니다. 다만 이런 기법들은 [고픽셀밀도](https://en.wikipedia.org/wiki/Pixel_density) 화면에서는 훨씬 덜 필요합니다. 언젠가는 모든 화면이 충분히 고밀도가 되어 이런 기법들이 은퇴하게 될 가능성이 큽니다.

## 브라우저 컴포지팅

Skia와 SDL은 방금 우리 브라우저를 더 복잡하게 만들었을 뿐이지만, 이 라이브러리들이 제공하는 저수준 제어권은 중요합니다. 스크롤 같은 흔한 상호작용을 최적화할 수 있게 해 주기 때문입니다.

지금까지는 사용자가 웹 페이지를 스크롤할 때마다 캔버스를 지우고 그 위의 모든 것을 처음부터 다시 래스터화해야 했습니다. 이는 비효율적입니다. 같은 픽셀을 위치만 바꿔서 다시 그리는 것이니까요. 컨텍스트가 복잡하거나 화면이 크면 너무 자주 래스터화하는 것이 눈에 띄는 속도 저하를 만들고 노트북과 모바일의 배터리를 소모합니다. 실제 브라우저는 제가 _브라우저 컴포지팅_ 이라고 부를 기법으로 스크롤을 최적화합니다. 웹 페이지 전체를 숨겨진 서피스에 그려 두고, 관련된 픽셀만 창으로 복사하는 것입니다.

이를 구현하려면 두 개의 새로운 Skia 서피스가 필요합니다. 브라우저 크롬을 위한 서피스와 현재 `Tab`의 콘텐츠를 위한 서피스입니다. 페이지 내용이 바뀔 때만 `Tab` 서피스를 다시 래스터화하면 되고, (예를 들어) 사용자가 주소창에 입력할 때는 그럴 필요가 없습니다. 그리고 `Tab`을 스크롤할 때는 래스터화가 전혀 필요 없습니다. 그저 현재 `Tab` 서피스의 다른 부분을 화면에 복사하기만 하면 됩니다. 그 서피스들을 `chrome_surface`와 `tab_surface`라고 부릅시다.[^14]

```python
class Browser:
    def __init__(self):
        # ...
        self.chrome_surface = skia.Surface(
            WIDTH, math.ceil(self.chrome.bottom))
        self.tab_surface = None
```

`tab_surface`를 곧바로 명시적으로 만들지 않는 이유는, 서피스의 높이가 얼마나 되어야 하는지 알려면 페이지 콘텐츠를 배치해야 하기 때문입니다.

브라우저의 `draw` 메서드도 세 부분으로 나눠야 합니다.

- `raster_tab`은 페이지를 `tab_surface`에 래스터화합니다.

- `raster_chrome`은 브라우저 크롬을 `chrome_surface`에 래스터화합니다.

- `draw`는 크롬 서피스와 탭 서피스를 합성하고 그 결과를 Skia에서 SDL로 복사합니다.[^15]

우선 나누는 것부터 시작합시다.

```python
class Browser:
    def raster_tab(self):
        canvas = self.tab_surface.getCanvas()
        canvas.clear(skia.ColorWHITE)
        # ...

    def raster_chrome(self):
        canvas = self.chrome_surface.getCanvas()
        canvas.clear(skia.ColorWHITE)
        # ...

    def draw(self):
        canvas = self.root_surface.getCanvas()
        canvas.clear(skia.ColorWHITE)
        # ...
```

시작할 때 `tab_surface`를 만들지 않았으므로 `raster_tab`의 맨 위에서 만들어야 합니다.[^16]

```python
import math

class Browser:
    def raster_tab(self):
        tab_height = math.ceil(
            self.active_tab.document.height + 2*VSTEP)

        if not self.tab_surface or \
                tab_height != self.tab_surface.height():
            self.tab_surface = skia.Surface(WIDTH, tab_height)

        # ...
```

페이지의 높이가 바뀌면 탭 서피스를 다시 만들어야 한다는 점에 주의하세요. 여기서 레이아웃 트리의 높이를 기준으로 페이지 경계를 계산하는 방식은, 페이지 요소가 부모의 아래쪽(또는 오른쪽)으로 삐져나올 수 있다면 잘못된 것입니다. 다만 우리 브라우저는 그런 기능을 전혀 지원하지 않습니다.

다음으로 `draw`는 크롬 서피스와 탭 서피스에서 루트 서피스로 복사해야 합니다. 게다가 `tab_surface`를 `chrome.bottom`만큼 아래로, `scroll`만큼 위로 이동시키고, 브라우저 크롬과 겹치지 않는 창 영역으로 잘라 내야 합니다.

```python
class Browser:
    def draw(self):
        # ...
        
        tab_rect = skia.Rect.MakeLTRB(
            0, self.chrome.bottom, WIDTH, HEIGHT)
        tab_offset = self.chrome.bottom - self.active_tab.scroll
        canvas.save()
        canvas.clipRect(tab_rect)
        canvas.translate(0, tab_offset)
        self.tab_surface.draw(canvas, 0, 0)
        canvas.restore()

        chrome_rect = skia.Rect.MakeLTRB(
            0, 0, WIDTH, self.chrome.bottom)
        canvas.save()
        canvas.clipRect(chrome_rect)
        self.chrome_surface.draw(canvas, 0, 0)
        canvas.restore()

        # ...
```

`draw` 호출들을 눈여겨보세요. 이들은 `tab_surface`와 `chrome_surface`를 `root_surface`에 묶여 있는 `canvas`로 복사합니다. `clipRect`와 `translate` 호출이 올바른 부분을 복사하도록 보장합니다.

마지막으로 `Browser`에서 `draw`를 호출하던 모든 곳에서 이제 `raster_tab`이나 `raster_chrome`을 먼저 호출해야 합니다. 예를 들어 `handle_click`에서는 다음과 같이 합니다.

```python
class Browser:
    def handle_click(self, e):
        if e.y < self.chrome.bottom:
            # ...
            self.raster_chrome()
        else:
            # ...
            self.raster_tab()
        self.draw()
```

탭만 바뀌었을 때는 크롬을 다시 그리지 않고, 그 반대도 마찬가지라는 점을 눈여겨보세요. 마찬가지로 `handle_down`에서는 `raster_tab`을 아예 호출할 필요가 없는데, 스크롤은 페이지를 바꾸지 않기 때문입니다.

다만 웹 페이지를 클릭하면 새 페이지로 이동할 수 있으므로, 그것을 감지해 URL이 바뀌었으면 브라우저 크롬을 래스터화해야 합니다.

```python
class Browser:
    def handle_click(self, e):
        if e.y < self.chrome.bottom:
            # ...
        else:
            # ...
            url = self.active_tab.url
            tab_y = e.y - self.chrome.bottom
            self.active_tab.click(e.x, tab_y)
            if self.active_tab.url != url:
                self.raster_chrome()
            self.raster_tab()
```

`Tab`에도 관련된 변경이 몇 가지 있습니다. `Tab`의 `draw` 메서드 이름을 `raster`로 바꿉시다. 그 안에서는 이제 `execute` 메서드에 스크롤 오프셋을 넘기거나 `chrome.bottom`을 고려할 필요가 없습니다. 항상 탭 전체를 탭 서피스에 그리기 때문입니다.

```python
class Tab:
    def raster(self, canvas):
        for cmd in self.display_list:
            cmd.execute(canvas)
```

마찬가지로 각 그리기 명령의 `execute` 메서드에서 `scroll` 매개변수를 제거할 수 있습니다.

```python
class DrawRect:
    def execute(self, canvas):
        paint = skia.Paint(
            Color=parse_color(self.color),
        )
        canvas.drawRect(self.rect, paint)
```

이제 우리 브라우저는 합성 스크롤을 사용하여 스크롤이 더 빠르고 부드러워졌습니다. 이는 모두 이미 래스터화된 콘텐츠를 저장하는 중간 서피스들을 조합해 사용함으로써, 콘텐츠가 실제로 바뀌지 않는 한 다시 래스터화하지 않게 되었기 때문입니다.

### 더 알아보기

실제 브라우저는 여러 상황에 대해 새 서피스를 할당합니다. 가속된 오버플로 스크롤을 구현하거나, 래스터 없이 처리할 수 있는 [transform](https://developer.mozilla.org/en-US/docs/Web/CSS/transform)이나 opacity 같은 특정 CSS 속성의 애니메이션을 구현할 때가 그렇습니다. 또한 CSS의 [`overflow: scroll`](https://developer.mozilla.org/en-US/docs/Web/CSS/overflow)을 통해 임의의 HTML 요소를 스크롤할 수 있게도 해 줍니다. DOM 요소의 기본적인 스크롤은 방금 우리가 구현한 것과 매우 비슷합니다. 하지만 그것을 완전히 일반적으로, 그리고 뛰어난 성능으로 구현하는 것은 _극도로_ 어렵습니다. 스크롤은 아마 브라우저 렌더링 엔진에서 가장 복잡한 기능일 것입니다. 관련된 예외 사례와 미묘한 문제들이 거의 끝이 없습니다.

## 투명도

도형을 빠르게 그리는 것만도 이미 도전인데, 도형이 여러 개면 추가 질문이 생깁니다. 두 도형이 겹칠 때 픽셀은 무슨 색이어야 할까요? 지금까지 우리 브라우저는 불투명한 도형만 다뤘고,[^17] 답은 간단했습니다. 위에 있는 도형의 색을 취하면 됐죠. 하지만 이제는 더 섬세해져야 합니다.

CSS에서 부분적으로 투명한 색을 생각해 봅시다. 이런 색은 16진수 여덟 자리를 쓰며, 마지막 두 자리가 투명도 수준을 나타냅니다. 예를 들어 `#00000080` 색은 50% 투명한 검정입니다. 흰 배경 위에서는 회색으로 보이지만, 주황 배경 위에서는 그림 2와 같이 보입니다.

> **데모**
>
> Test — 주황색 배경 위에 50% 투명한 검은 텍스트

*그림 2: 주황색 배경에 섞여 드는 반투명 검은 텍스트의 예.*

텍스트가 짙은 주황색 계열로 보이는데, 그 색이 50% 검정과 50% 주황을 섞은 것이기 때문입니다. 현실 세계의 많은 물체는 부분적으로 투명합니다. 예를 들어 성에 낀 유리, 구름, 색지 같은 것들이죠. 그것들을 통해 보면 여러 색이 _섞인_ 것을 보게 됩니다. 컴퓨터 화면이 동작하는 이유도 그것입니다. 빨강, 초록, 파랑 빛이 [함께 섞여](https://en.wikipedia.org/wiki/Color_mixing) 우리 눈에는 또 다른 색으로 보이는 것이죠. 디자이너들은 오버레이, 그림자, 툴팁에서 이 효과를 사용하므로[^18] 우리 브라우저도 색 혼합을 지원해야 합니다.

Skia는 파싱된 색의 "alpha" 필드를 설정함으로써 이런 종류의 투명도를 지원합니다.

```python
def parse_color(color):
    # ...
    elif color.startswith("#") and len(color) == 9:
        r = int(color[1:3], 16)
        g = int(color[3:5], 16)
        b = int(color[5:7], 16)
        a = int(color[7:9], 16)
        return skia.Color(r, g, b, a)
    # ...
```

위 예제에 대해 여러분의 브라우저가 짙은 주황색 텍스트를 렌더링하는지 확인하세요. 그것은 브라우저가 실제로 검은색을 배경의 기존 주황색과 섞고 있음을 보여 줍니다.

그런데 CSS로 투명도를 만드는, 미묘하게 다른 또 하나의 방법이 있습니다. 여기서는 그림 3처럼 `opacity` 속성을 사용해 요소 전체에 50% 투명도를 적용합니다.

> **데모**
>
> Test — 주황색 배경 위의 검은 텍스트 전체에 50% 투명도 적용

*그림 3: 주황색 배경 위의 검은 텍스트를, 그다음 조상 요소에 반투명하게 섞어 넣은 예.*

이제 불투명도가 배경과 텍스트 양쪽에 적용되므로 배경이 조금 더 밝아졌습니다. 하지만 텍스트가 이제 짙은 주황색이 아니라 회색이라는 점을 눈여겨보세요. 검은 픽셀과 주황 픽셀이 더 이상 섞이지 않은 것입니다!

그것은 불투명도가 CSS에서 [쌓임 맥락(stacking context)](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_Positioning/Understanding_z_index/The_stacking_context)이라고 부르는 것을 만들어 내기 때문입니다. 지금 대부분의 세부 사항은 중요하지 않지만 연산 순서는 중요합니다. 첫 번째 예에서는 검은 픽셀이 먼저 투명해진 다음 배경과 섞였습니다. 따라서 50% 투명한 검은 픽셀이 주황 픽셀과 섞여 짙은 주황색이 나왔습니다. 두 번째 예에서는 검은 픽셀이 먼저 배경과 섞이고, 그 결과가 투명해졌습니다. 따라서 완전히 검은 픽셀이 완전히 주황인 픽셀을 대체해 순수한 검은 픽셀만 남았고, 그것이 나중에 50% 투명해진 것입니다.

`opacity` 같은 효과를 구현하는 데 필요한 대로 블렌딩을 올바른 순서로 적용하려면 서피스를 더 세심하게 다뤄야 합니다.

### 더 알아보기

대체로 요소는 (`z-index`처럼) 계층과 관련이 있거나 (`mix-blend-mode`처럼) 시각 효과와 관련이 있는 CSS 속성 때문에 [쌓임 맥락을 형성](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_Positioning/Understanding_z_index/The_stacking_context)합니다. 반면 요소를 스크롤 가능하게 만들 수 있는 `overflow` 속성은 쌓임 맥락을 유발하지 않는데, 저는 이것이 실수였다고 생각합니다.[^19] 그 이유는 현대 브라우저 안에서 스크롤이 두 서피스를 어긋나게 배치함으로써 GPU에서 이루어지기 때문입니다. 쌓임 맥락이 없으면 브라우저는 (웹 페이지 구조에 따라) 복잡한 페인트 순서를 가진 여러 독립적인 서피스를 발맞춰 움직여야 스크롤을 구현할 수 있게 될 수도 있습니다. 고정(fixed) 및 스티키(sticky) 위치 요소도 스크롤과의 상호작용 때문에 쌓임 맥락을 형성합니다.

## 블렌딩과 쌓기

연산 순서를 올바르게 처리하기 위해, 브라우저는 블렌딩을 개별 도형이 아니라 서피스의 트리에 적용합니다(그림 4 참조). 개념적으로 각 도형은 자신만의 서피스에 그려진 다음 부모 서피스에 섞여 들어갑니다. 중간 서피스의 구조가 달라지면 서로 다른 시각 효과가 만들어집니다.[^20] 웹 페이지를 래스터화하려면 이 개념적 트리를 상향식으로 순회해야 합니다. 어떤 서피스를 래스터화하려면 먼저 자식 서피스를 포함한 그 내용을 래스터화해야 하고, 그다음 그 내용들이 부모로 섞여 들어가야 합니다.[^21]

![그림 4: 렌더링된 웹 페이지는 사실 여러 서피스를 쌓고 섞은 결과입니다.](visual-effects-surfaces.jpg)

*그림 4: 렌더링된 웹 페이지는 사실 여러 서피스를 쌓고 섞은 결과입니다.*

이 사용 패턴에 맞추기 위해 Skia에서 서피스는 스택을 이룹니다. 스택에 새 서피스를 밀어 넣고, 거기에 무언가를 래스터화하고, 그다음 팝하면 그 아래 서피스와 섞입니다. 래스터화할 때 시각 효과를 적용해야 할 때마다 스택에 새 서피스를 밀어 넣고, 그 효과가 적용될 모든 요소를 래스터화하고 나면 팝하며 섞습니다. 다음과 같습니다.

```
# draw parent
canvas.saveLayer(None, skia.Paint(Alphaf=0.5))
# draw children
canvas.restore()
```

여기서 `saveLayer` 호출은 Skia에게[^22] 모든 자식을 별도의 서피스에 그린 다음 `restore`가 호출되면 부모에 섞으라고 요청합니다. `saveLayer`의 두 번째 매개변수는 블렌딩의 구체적인 종류를 지정하는데, 여기서는 `Alphaf` 매개변수로 50% 불투명도를 요청하고 있습니다.

`saveLayer`와 `restore`는 자식 그리기 연산들을 감싸는 괄호 한 쌍과 같습니다. 즉 우리 디스플레이 리스트는 더 이상 그리기 연산의 선형 시퀀스가 아니라 트리입니다. 그러니 디스플레이 리스트에서 `opacity`를, 다른 그리기 명령들의 시퀀스를 인자로 받는 `Opacity` 명령으로 처리합시다.

```python
class Opacity:
    def __init__(self, opacity, children):
        self.opacity = opacity
        self.children = children
        self.rect = skia.Rect.MakeEmpty()
        for cmd in self.children:
            self.rect.join(cmd.rect)

    def execute(self, canvas):
        paint = skia.Paint(
            Alphaf=self.opacity
        )
        canvas.saveLayer(None, paint)
        for cmd in self.children:
            cmd.execute(canvas)
        canvas.restore()
```

이제 요소가 페인트한 그리기 명령들을 `Opacity`로 감싸서 요소 전체에 투명도를 더할 수 있습니다. 저는 레이아웃 객체에 새 `paint_effects` 메서드를 추가해 이를 하려고 합니다. 이 메서드는 감쌀 그리기 명령들의 리스트를 받습니다.

```python
class BlockLayout:
    def paint_effects(self, cmds):
        cmds = paint_visual_effects(
            self.node, cmds, self.self_rect())
        return cmds
```

`Opacity` 명령을 실제로 만드는 부분은 (다른 객체 타입도 필요로 하기 때문에) 새로운 전역 `paint_visual_effects` 메서드에 넣었습니다.

```python
def paint_visual_effects(node, cmds, rect):
    opacity = float(node.style.get("opacity", "1.0"))

    return [
        Opacity(opacity, cmds)
    ]
```

이제 `paint_tree`에서 `paint_effects`를 호출하도록 바꿔야 하는데, 자식으로 재귀한 _뒤에_, 그리고 `should_paint`가 참일 때만 호출해야 합니다. 이 시각 효과들은 현재 객체뿐 아니라 서브트리 전체의 디스플레이 리스트에 적용되며, "익명" 객체(8장 참조)에는 적용되지 않기 때문입니다.

```python
def paint_tree(layout_object, display_list):
    if layout_object.should_paint():
        cmds = layout_object.paint()
    for child in layout_object.children:
        paint_tree(child, cmds)

    if layout_object.should_paint():
        cmds = layout_object.paint_effects(cmds)
    display_list.extend(cmds)
```

`paint_visual_effects`가 명령 리스트를 받아 또 다른 명령 리스트를 반환한다는 점에 주의하세요. 다만 출력 리스트는 항상 원본 내용을 감싸는 단일 `Opacity` 명령입니다. 이는 이치에 맞습니다. 먼저 명령들을 서피스에 그리고 _그다음_ 부모에 섞을 때 투명도를 적용해야 하니까요.

[Bartosz Ciechanowski의 블로그 글](https://ciechanow.ski/alpha-compositing/)을 강력히 추천합니다. 이 장에서 다룬 여러 개념을 아주 훌륭한 시각 자료로 개괄해 주고, 나아가 Skia 같은 라이브러리가 선과 텍스트를 위한 벡터 그래픽의 래스터 샘플링, 픽셀 배열의 해상도나 방향이 맞지 않을 때의 서피스 보간 같은 기능을 어떻게 구현할지에 대한 내용도 훨씬 많이 담고 있습니다.

## 픽셀 합성하기

이제 잠시 멈추고 불투명도가 내부적으로 어떻게 동작하는지 살펴봅시다. Skia, SDL을 비롯한 많은 색 라이브러리는 각 픽셀마다 네 번째 값인 _알파(alpha)_ 값으로 불투명도를 다룹니다.[^23] 알파가 0이면 픽셀이 완전히 투명하다는 뜻이고(즉 색이 무엇이든 어차피 볼 수 없습니다), 알파가 1이면 완전히 불투명하다는 뜻입니다.

알파를 가진 픽셀이 다른 픽셀과 겹치면 최종 색은 두 색을 섞은 것이 됩니다. 색이 정확히 어떻게 섞이는지는 Skia의 `Paint` 객체가 정의합니다. 물론 Skia는 꽤 복잡하지만, 앞서 소개한 개념적 `Pixel` 클래스의 메서드로 이 페인트 연산들을 Python으로 대략 그려 볼 수 있습니다.

`Alphaf` 매개변수가 있는 `Paint`를 적용하면, Skia가 가장 먼저 하는 일은 각 픽셀에 요청된 불투명도를 더하는 것입니다.

```
class Pixel:
    def alphaf(self, opacity):
        self.a = self.a * opacity
```

거듭 강조하지만 이 코드는 우리 브라우저의 일부가 아닙니다. 그저 Skia가 내부적으로 하는 일을 Python 코드로 설명하는 것뿐입니다.

그 `Alphaf` 매개변수는 한 서피스의 픽셀들에 적용됩니다. 하지만 `saveLayer`를 쓰면 서피스가 두 개가 되고, 그 픽셀들이 모두 정렬되어 있으므로 대응하는 픽셀 쌍을 결합, 즉 _블렌딩_ 해야 합니다.

여기서 용어가 헷갈릴 수 있습니다. "위에 있는" 픽셀이 "아래" 픽셀로 섞여 들어간다고 상상하므로, 위쪽 서피스를 _소스 서피스_ 라고 부르고 그 픽셀을 소스 픽셀이라 하며, 아래쪽 서피스를 _대상(destination) 서피스_ 라고 부르고 그 픽셀을 대상 픽셀이라고 합니다. 이 둘을 결합하는 방법은 여러 가지가 있지만, 웹의 기본값은 "단순 알파 합성(simple alpha compositing)" 또는 _source-over_ 합성이라고 불립니다. Python으로 구현하면 다음과 같습니다.[^24]

```
class Pixel:
    def source_over(self, source):
        new_a = source.a + self.a * (1 - source.a)
        if new_a == 0: return self
        self.r = \
            (self.r * (1 - source.a) * self.a + \
                source.r * source.a) / new_a
        self.g = \
            (self.g * (1 - source.a) * self.a + \
                source.g * source.a) / new_a
        self.b = \
            (self.b * (1 - source.a) * self.a + \
                source.b * source.a) / new_a
        self.a = new_a
```

여기서 대상 픽셀 `self`가 소스 픽셀 `source`를 섞어 넣도록 수정됩니다. 빨강, 초록, 파랑 색 채널에 대한 수식은 동일하며, 기본적으로 알파로 가중치를 준 소스와 대상 색의 평균을 냅니다.[^25] `Alphaf` 매개변수가 있는 `saveLayer`의 전체 동작은 대략 다음과 같다고 상상해 볼 수 있습니다.[^26]

```
for (x, y) in destination.coordinates():
    source[x, y].alphaf(opacity)
    destination[x, y].source_over(source[x, y])
```

source-over 합성은 두 픽셀 값을 결합하는 한 가지 방법입니다. 하지만 유일한 방법은 아닙니다. 원한다면 두 픽셀 값을 결합하는 문자 그대로 어떤 계산이든 작성할 수 있습니다. 흥미로운 효과를 내는 두 가지 계산은 전통적으로 "multiply"와 "difference"라고 불리며 단순한 수학 연산을 사용합니다.

"multiply"는 색 값을 곱합니다.

```
class Pixel:
    def multiply(self, source):
        self.r = self.r * source.r
        self.g = self.g * source.g
        self.b = self.b * source.b
```

그리고 "difference"는 그 절댓값 차이를 계산합니다.

```
class Pixel:
    def difference(self, source):
        self.r = abs(self.r - source.r)
        self.g = abs(self.g - source.g)
        self.b = abs(self.b - source.b)
```

CSS는 [`mix-blend-mode` 속성](https://drafts.fxtf.org/compositing-1/#propdef-mix-blend-mode)을 통해 이들과 그 밖의 많은 블렌딩 모드를[^27] 다음과 같이 지원합니다.

```
<div style="background-color:orange">
    Parent
    <div style="background-color:blue;mix-blend-mode:difference">
        Child
    </div>
    Parent
</div>
```

> Parent

*그림 5: 파란 자식과 주황 부모에 `mix-blend-mode`의 `difference` 값을 적용해 분홍색이 나오는 예.*

여기서 파랑이 주황과 겹치면 분홍이 보입니다. 파랑은 (빨강, 초록, 파랑) 색 채널이 `(0, 0, 1)`이고 주황은 `(1, 0.65, 0)`이므로, "difference" 블렌딩을 하면 결과 픽셀은 `(1, 0.65, 1)`이 되는데 이것이 분홍입니다. 픽셀 수준에서 일어나는 일은 대략 다음과 같습니다.

```
for (x, y) in destination.coordinates():
    source[x, y].alphaf(opacity)
    source[x, y].difference(destination[x, y])
    destination[x, y].source_over(source[x, y])
```

이상해 보이지만, 개념적으로는 대상을 소스에 섞은 다음(이때 알파는 무시됩니다) 소스를 대상 위에 그리는 것입니다(이때는 알파를 고려합니다). 어떤 의미에서 블렌딩은 [두 번 일어나는](https://drafts.fxtf.org/compositing-1/#blending) 셈입니다.

Skia는 [multiply](https://drafts.fxtf.org/compositing-1/#blendingmultiply)와 [difference](https://drafts.fxtf.org/compositing-1/#blendingdifference) 블렌딩 모드를 기본 지원합니다.

```python
def parse_blend_mode(blend_mode_str):
    if blend_mode_str == "multiply":
        return skia.BlendMode.kMultiply
    elif blend_mode_str == "difference":
        return skia.BlendMode.kDifference
    else:
        return skia.BlendMode.kSrcOver
```

그러면 새로운 `Blend` 연산을 정의해 우리 브라우저에서 블렌딩을 지원할 수 있습니다.

```python
class Blend:
    def __init__(self, blend_mode, children):
        self.blend_mode = blend_mode

        self.children = children
        self.rect = skia.Rect.MakeEmpty()
        for cmd in self.children:
            self.rect.join(cmd.rect)

    def execute(self, canvas):
        paint = skia.Paint(
            BlendMode=parse_blend_mode(self.blend_mode),
        )
        canvas.saveLayer(None, paint)
        for cmd in self.children:
            cmd.execute(canvas)
        canvas.restore()
```

`mix-blend-mode`가 설정되었을 때 그것을 적용하려면 `paint_visual_effects`를 간단히 바꾸기만 하면 됩니다.

```python
def paint_visual_effects(node, cmds, rect):
    # ...
    blend_mode = node.style.get("mix-blend-mode")
    
    return [
        Blend(blend_mode, [
            Opacity(opacity, cmds),
        ]),
    ]
```

여기서 연산 순서를 눈여겨보세요. _먼저_ 투명도를 적용하고 _그다음_ 그 결과를 페이지의 나머지 부분에 섞습니다. `Opacity`와 `Blend` 호출을 뒤바꾸면 섞어 넣을 대상이 아무것도 없을 것입니다!

### 더 알아보기

알파는 직관적으로 보일 수 있지만 생각만큼 자명하지 않습니다. 예를 들어 알파의 공동 발명자(이자 Pixar의 공동 창업자)가 쓴 [알파의 역사](http://alvyray.com/Memos/CG/Microsoft/7_alpha.pdf)를 보세요. 게다가 구현 선택지도 여럿 있습니다. 예를 들어 Skia를 포함한 많은 그래픽 라이브러리는 색 채널 하나를 통째로 할당하는 대신 색 채널에 불투명도를 곱해 둡니다. 이 [미리 곱한(premultiplied)](https://limnu.com/premultiplied-alpha-primer-artists/) 표현은 일반적으로 더 효율적입니다. 예를 들어 위의 `source_over`는 마지막에 `self.a`로 나눠야 했는데, 그러지 않으면 결과가 미리 곱한 형태가 되기 때문입니다. 전체적으로 미리 곱한 표현을 쓰면 나눗셈 하나를 아낄 수 있습니다. 알파가 [크기 조절 시 어떻게 동작하는지](https://jcgt.org/published/0004/02/03/paper.pdf)도 자명하지 않습니다.

## 클리핑과 마스킹

"multiply"와 "difference" 블렌딩 모드는 다소 난해해 보일 수 있지만, 블렌딩 모드는 픽셀 단위 연산을 구현하는 유연한 방법입니다. 흔한 사용 사례 하나가 클리핑, 즉 서피스를 주어진 도형과 교차시키는 것입니다. 이를 클리핑이라고 부르는 이유는, 첫 번째 종이 위에 (_마스크_ 라고 불리는) 두 번째 종이를 올려놓고 가위로 마스크의 가장자리를 따라 자르는 것과 같기 때문입니다.

웹에는 콘텐츠를 클리핑하는 온갖 강력한 방법이 있지만,[^28] 가장 흔한 형태는 `overflow` 속성과 관련이 있습니다. 이 속성에는 가능한 값이 많지만,[^29] 여기서는 요소의 경계 밖에 있는 요소 내용을 잘라 내는 `overflow: clip`에 집중합시다.

보통 `overflow: clip`은 자식이 부모 밖으로 삐져나오게 만들 수 있는 `height`나 `rotate` 같은 속성과 함께 쓰입니다. 우리 브라우저는 이런 속성을 지원하지 않지만, `overflow: clip`이 관련되는 예외 사례가 하나 있습니다. 바로 둥근 모서리입니다.[^30] 다음 예를 생각해 봅시다.

![그림 6: 넘치는 텍스트가 둥근 모서리에 의해 잘리지 않는 예.](example11-longword.png)

*그림 6: 넘치는 텍스트가 둥근 모서리에 의해 잘리지 않는 예.*

```
<div 
  style="border-radius:30px;background-color:lightblue;overflow:clip">
    This test text exists here to ensure that the "div" element is
    large enough that the border radius is obvious.
</div>
```

그 HTML은 그림 7과 같이 보입니다.

> **데모**
>
> This test text exists here to ensure that the "div" element is large enough that the border radius is obvious.

*그림 7: `overflow:clip`과 `border-radius`가 적용된 div의 텍스트 자식에서 넘친 부분이 잘려 나가는 예.*

모서리 근처의 글자들이 날카로운 둥근 가장자리를 유지하기 위해 잘려 나간 것을 눈여겨보세요. 그것이 클리핑입니다. `overflow: clip` 속성이 없다면 이 글자들은 온전히 그려질 것입니다.

직관에 반하게도, 우리는 클리핑을 블렌딩 모드로 구현하겠습니다. 새 서피스(마스크)를 만들고, 거기에 둥근 직사각형을 그린 다음, 그것을 요소 내용과 섞을 것입니다. 그런데 우리가 보고 싶은 것은 마스크가 아니라 요소 내용이므로, 이 블렌딩을 할 때 _destination-in_ 합성을 사용하겠습니다.

[Destination-in 합성](https://drafts.fxtf.org/compositing-1/#porterduffcompositingoperators_dstin)은 기본적으로 소스 서피스와 겹치는 대상 서피스의 픽셀을 남기는 것을 뜻합니다. 소스 서피스의 색은 사용되지 않고 알파만 사용됩니다. 우리 경우에 소스 서피스는 둥근 직사각형 마스크이고 대상 서피스는 잘라 내고 싶은 내용이므로, destination-in이 완벽하게 들어맞습니다. 코드로 보면 destination-in은 다음과 같습니다.

```
class Pixel:
    def destination_in(self, source):
        self.a = self.a * source.a
```

이제 `paint_visual_effects`에서 새 레이어를 만들고, 거기에 마스크 이미지를 그린 다음, destination-in 블렌딩으로 요소 내용과 섞어야 합니다.

```python
def paint_visual_effects(node, cmds, rect):
    # ...
    if node.style.get("overflow", "visible") == "clip":
        border_radius = float(node.style.get(
            "border-radius", "0px")[:-2])
        cmds.append(Blend("destination-in", [
            DrawRRect(rect, border_radius, "white")
        ]))

    return [
        Blend(blend_mode, [
            Opacity(opacity, cmds),
        ]),
    ]
```

여기서는 블렌딩 모드로 `destination-in`을 넘기는데, 이는 다소 꼼수이며 실제로 `mix-blend-mode`의 유효한 값은 아니라는 점에 주의하세요.

```python
def parse_blend_mode(blend_mode_str):
    # ...
    elif blend_mode_str == "destination-in":
        return skia.BlendMode.kDstIn
    # ...
```

이 코드는 (그리고 불투명도를 적용한 뒤) `cmds`로 모든 요소 내용을 그린 다음, 마스크 역할을 할 둥근 직사각형을 다른 레이어에 그리고 destination-in 블렌딩으로 요소 내용을 잘라 냅니다. 여기서 저는 둥근 직사각형을 흰색으로 그렸는데, 불투명하기만 하다면 색은 상관없습니다.

이 마스킹 기법이 앞서 설명한 가위를 이용한 물리적 비유와 얼마나 비슷한지 눈여겨보세요. 두 레이어가 두 장의 종이 역할을 하고, destination-in 합성이 가위 역할을 합니다.[^31]

### 더 알아보기

둥근 모서리에는 컴퓨팅에서 [흥미로운 역사](https://www.folklore.org/StoryView.py?story=Round_Rects_Are_Everywhere.txt)가 있습니다. 오늘날 단순한 기능들이 메모리가 제한적이고 하드웨어 부동소수점 연산이 없던 초기 개인용 컴퓨터에서는 [매우 복잡했습니다](https://raw.githubusercontent.com/jrk/QuickDraw/master/RRects.a). 부동소수점 하드웨어와 결국 GPU가 표준이 된 뒤에도 `border-radius` CSS 속성은 2010년 무렵까지 브라우저에 나타나지 않았습니다.[^32] 더 최근에는 애니메이션, 시각 효과, 다중 프로세스 합성, [하드웨어 오버레이](https://en.wikipedia.org/wiki/Hardware_overlay)의 도입으로 둥근 모서리를 구현하기가 꽤 복잡해졌습니다. 예를 들어 `clipRRect` 빠른 경로는 하드웨어 비디오 오버레이나 중첩된 둥근 모서리 클립 같은 경우에는 적용되지 못할 수 있습니다.

## 서피스 사용 최적화하기

이제 우리 브라우저는 올바르게 동작하지만 서피스를 너무 많이 사용합니다. 예를 들어 아무 효과도 필요 없는 텍스트 내용이 든 `div` 하나에 대해 현재 디스플레이 리스트에 18개의 서피스가 할당됩니다. 블렌딩이 전혀 없다면 하나만 있으면 되는데 말이죠!

우리 코드가 한 요소에 대해 만들 수 있는 모든 서피스를 살펴봅시다.

- 최상위 서피스는 _블렌딩 모드_ 를 적용하는 데 사용됩니다. 최상위 서피스이므로 요소를 페이지의 다른 부분과 _격리_ 하기도 해서, 클리핑이 그 요소에만 적용되게 합니다.

- 첫 번째 중첩 서피스는 _불투명도_ 를 적용하는 데 사용됩니다.

- 두 번째 중첩 서피스는 _클리핑_ 을 구현하는 데 사용됩니다.

하지만 모든 요소에 불투명도, 블렌딩 모드, 클리핑이 적용되는 것은 아니므로, 대부분의 경우 그 서피스들을 만들지 않고 건너뛸 수 있습니다. 예를 들어 실제로 불투명도가 적용되지 않는다면 `Opacity`에서 서피스를 만들 이유가 없습니다.

```python
class Opacity:
    def execute(self, canvas):
        paint = skia.Paint(
            Alphaf=self.opacity,
        )
        if self.opacity < 1:
            canvas.saveLayer(None, paint)
        for cmd in self.children:
            cmd.execute(canvas)
        if self.opacity < 1:
            canvas.restore()
```

마찬가지로 `Blend`도 블렌딩이 전혀 없다면 굳이 레이어를 만들 필요가 없습니다. 다만 여기서 로직이 조금 까다롭습니다. `Blend` 연산은 블렌딩을 적용할 뿐 아니라 요소 내용을 격리하기도 하는데, 이는 그 내용이 `overflow`로 클리핑되고 있을 때 중요합니다. 그러니 블렌딩 모드가 없을 때는 `Blend`에서 레이어 만들기를 건너뛰되, 클리핑이 필요할 때는 블렌딩 모드를 특별한 비표준 `source-over` 값으로 설정합시다.

```python
def paint_visual_effects(node, cmds, rect):
    if node.style.get("overflow", "visible") == "clip":
        if not blend_mode:
            blend_mode = "source-over"
        # ...
```

이 값은 기본 source-over 블렌딩 모드로 파싱하겠습니다.

```python
def parse_blend_mode(blend_mode_str):
    # ...
    elif blend_mode_str == "source-over":
        return skia.BlendMode.kSrcOver
    # ...
```

`parse_blend_mode`가 이미 알 수 없는 문자열을 source-over 블렌딩으로 파싱하므로 사실 이는 불필요하지만, 명시적으로 해 두는 것이 좋습니다. 어쨌든 이제 `Blend`는 블렌딩 모드가 넘어오지 않으면 `saveLayer`를 건너뛸 수 있습니다.

```python
class Blend:
    def execute(self, canvas):
        paint = skia.Paint(
            BlendMode=parse_blend_mode(self.blend_mode),
        )
        if self.blend_mode:
            canvas.saveLayer(None, paint)
        for cmd in self.children:
            cmd.execute(canvas)
        if self.blend_mode:
            canvas.restore()
```

이제 `Opacity`와 `Blend`가 정말 필요하지 않을 때 여분의 서피스를 만들지 않고 건너뜁니다. 하지만 여전히 너무 많이 쓰는 경우가 하나 남아 있습니다. `Opacity`와 `Blend`가 서피스를 공유하는 대신 각자 만들 수 있다는 점입니다. 불투명도를 `Blend`에 합쳐서 이를 고칩시다.[^33]

```python
class Blend:
    def __init__(self, opacity, blend_mode, children):
        self.opacity = opacity
        self.blend_mode = blend_mode
        self.should_save = self.blend_mode or self.opacity < 1

        self.children = children
        self.rect = skia.Rect.MakeEmpty()
        for cmd in self.children:
            self.rect.join(cmd.rect)

    def execute(self, canvas):
        paint = skia.Paint(
            Alphaf=self.opacity,
            BlendMode=parse_blend_mode(self.blend_mode),
        )
        if self.should_save:
            canvas.saveLayer(None, paint)
        for cmd in self.children:
            cmd.execute(canvas)
        if self.should_save:
            canvas.restore()
```

이제 `paint_visual_effects`는 다음과 같습니다.

```python
def paint_visual_effects(node, cmds, rect):
    # ...

    if node.style.get("overflow", "visible") == "clip":
        # ...
        cmds.append(Blend(1.0, "destination-in", [
            DrawRRect(rect, border_radius, "white")
        ]))

    return [Blend(opacity, blend_mode, cmds)]
```

클립용 `Blend`에는 불투명도를 `1.0`으로 지정했다는 점에 주의하세요.

## 연습문제

**11-1 _필터_.** `filter` CSS 속성은 그레이스케일이나 블러 같은 여러 종류의 더 [복잡한 효과](https://developer.mozilla.org/en-US/docs/Web/CSS/filter)를 지정할 수 있게 해 줍니다. 구현하기 재미있고, `blur` 같은 일부는 Skia에 내장 지원이 있습니다. `blur`를 구현하세요. 투명도, 클리핑, 블렌딩 같은 다른 효과에 대해 블러가 언제 일어나는지 신중히 생각해 보세요.

**11-2 _히트 테스팅_.** `border-radius`가 있는 요소의 경우, "둥글게 깎여 나간" 모서리 부분을 클릭하면 요소 바깥이지만 그것을 담은 직사각형 안쪽을 클릭하게 될 수 있습니다. 이는 그 요소를 클릭한 것이 되어서는 안 되지만, 지금 우리 브라우저에서는 그렇게 됩니다. 테두리 반지름을 고려하도록 `click` 메서드를 수정하세요.

**11-3 _관심 영역_.** 이제 우리 브라우저는 웹 페이지 전체를 하나의 서피스에 그리므로, ([이 장](http://browser.engineering/visual-effects.html)처럼!) 아주 긴 웹 페이지는 큰 서피스를 만들어 많은 메모리를 사용합니다. 대신 높이가 제한된, 이를테면 `4 * HEIGHT` 픽셀의 "관심 영역"만 그리세요. 관심 영역이 페이지의 어디인지 추적하고, 그중 올바른 부분을 화면에 그리고, 사용자가 그 밖으로 스크롤하려 하면 관심 영역을 다시 래스터화해야 합니다. 관심 영역 바깥에 그리지 않도록 Skia의 `clipRect` 연산을 사용하세요.

**11-4 _오버플로 스크롤_.** `overflow` 속성이 `scroll`로 설정되고 픽셀 단위 `height`가 고정된 요소는 스크롤 가능합니다. (`height`가 지원되도록 연습문제 6-2를 구현하는 것이 좋습니다.) 어떤 형태로든 `overflow: scroll`을 구현하세요. 다음과 같은 사용자 상호작용을 권합니다. 사용자가 스크롤 가능한 요소 안을 클릭해 포커스를 준 다음, 방향키를 눌러 위아래로 스크롤할 수 있게 하는 것입니다. [_레이아웃 오버플로_](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_Flow_Layout/Flow_Layout_and_Overflow)를 추적해야 합니다. 추가 도전으로, 다른 스크롤 가능한 요소 안에 중첩된 스크롤 가능한 요소도 지원하도록 해 보세요.

**11-5 _터치 입력_.** 요즘은 (물론 모든 모바일 화면은 물론이고) 많은 데스크톱 화면이 터치와 멀티터치 입력을 지원합니다. 그리고 SDL에는 이를 지원하는 [API](https://wiki.libsdl.org/SDL2/SDL_MultiGestureEvent)가 있습니다. `click`의 터치 입력 변형을 구현하세요.[^35]

[^25]: 예를 들어 소스 픽셀의 알파가 1이면 결과는 그냥 소스 픽셀의 색이고, 0이면 결과는 배경 픽셀의 색입니다.

[^26]: 실제로 개별 픽셀을 메모리로 읽어 들여 이렇게 조작하는 것은 느리므로, Skia 같은 라이브러리는 그렇게 하기 편하게 만들어 두지 않았습니다. (Skia 캔버스에는 `peekPixels`와 `readPixels` 메서드가 있어서 가끔 쓰이지만 이런 용도로는 아닙니다.)

[^27]: 이 블렌딩 모드 중 상당수는 Photoshop이나 GIMP 같은 다른 그래픽 편집 프로그램에도 [공통적으로](https://en.wikipedia.org/wiki/Blend_modes) 있습니다. ["닷지"와 "번"](https://en.wikipedia.org/wiki/Dodging_and_burning) 같은 일부는 아날로그 사진 시절까지 거슬러 올라가는데, 그때 사진가들은 이미지의 일부를 다른 부분보다 더 노출시켜 밝기를 조절했습니다.

[^28]: CSS의 [`clip-path` 속성](https://developer.mozilla.org/en-US/docs/Web/CSS/clip-path)은 곡선으로 마스크 모양을 지정할 수 있게 해 주고, [`mask` 속성](https://developer.mozilla.org/en-US/docs/Web/CSS/mask)은 대신 마스크로 쓸 이미지 URL을 지정할 수 있게 해 줍니다.

[^29]: 예를 들어 `overflow: scroll`은 스크롤바를 추가하고 요소를 스크롤 가능하게 만들며, `overflow: hidden`은 `overflow: clip`과 비슷하지만 미묘하게 다릅니다.

[^30]: 기술적으로 클리핑은 브라우저 창 너비보다 긴 단어 하나가 있을 때도 우리 브라우저와 관련이 있습니다. [여기](https://browser.engineering/examples/example11-longword.html)에 예제가 있는데, 시각적으로는 그림 6과 같습니다.

[^31]: 우리 브라우저가 클리핑하려는 것이 둥근 직사각형뿐이라면, Skia는 실제로 특화된 `clipRRect` 연산을 제공합니다. 이는 destination-in 블렌딩보다 효율적인데, 다른 명령들이 그려지는 동안 적용되므로 클리핑된 영역 바깥의 것은 아예 그리지 않고 건너뛸 수 있기 때문입니다. 이를 위해서는 Skia의 각 _셰이더_, 즉 GPU 프로그램에 특화된 코드가 필요하므로 몇몇 흔한 도형에 대해서만 가능합니다. Destination-in 블렌딩이 더 일반적입니다.

[^32]: 지원이 없다고 해서 웹 개발자들이 `border-radius`가 지원되기 전에 사이트에 둥근 모서리를 넣는 것을 멈추지는 않았습니다. 그렇게 하는 영리한 방법이 여럿 있는데, [2008년의 한 영상](https://css-tricks.com/video-screencasts/24-rounded-corners/)이 몇 가지를 소개합니다.

[^33]: 이는 불투명도에는 통하지만 [블러](https://developer.mozilla.org/en-US/docs/Web/CSS/filter-function/blur())처럼 "픽셀을 움직이는" 필터에는 통하지 않습니다. 그런 필터는 부모 서피스로 섞일 때가 아니라 클리핑 전에 적용되어야 합니다. 그렇지 않으면 블러의 가장자리가 날카롭지 않게 됩니다.

[^34]: [_Computer Graphics: Principles and Practice_](https://en.wikipedia.org/wiki/Computer_Graphics:_Principles_and_Practice)도 있는데, 그러고 보니 저는(여기서 말하는 건 크리스입니다) 젊은 시절(1992년쯤)에 이 책을 샀던 기억이 납니다. 그때는 (어셈블리어로!) 선과 다각형을 래스터화하는 것 이상으로 나아가지 못했습니다. 요즘은 Skia와 Python 몇 줄이면 같은 일을, 그리고 그 이상을 할 수 있습니다.

[^35]: 터치 입력을 잘 구현하는 방법에 대한 힌트를 얻으려면 [7장](https://browser.engineering/chrome.html)의 "더 알아보기" 블록을 다시 살펴보는 것이 좋습니다.
