지금까지 레이아웃은 여는 태그와 닫는 태그를 각각 독립적으로 처리하는 선형 과정이었습니다. 하지만 웹 페이지는 트리이고, 실제로 그렇게 보입니다. 테두리와 배경은 시각적으로 서로 안에 중첩됩니다. 이를 지원하기 위해 이 장에서는 _트리 기반 레이아웃_ 으로 전환하겠습니다. 여기서는 그리기에 앞서 요소의 트리를 _레이아웃 객체_ 의 트리로 변환합니다. 그 과정에서 배경을 도입해 웹 페이지를 더 다채롭게 만들 것입니다.

## 레이아웃 트리

지금 우리 브라우저는 요소의 여는 태그와 닫는 태그를 따로 배치합니다. 두 태그 모두 `cursor_x`나 `cursor_y` 같은 전역 상태를 수정하지만 그 외에는 서로 연결되어 있지 않고, 너비와 높이처럼 요소 전체에 관한 정보는 아예 계산되지 않습니다. 그래서 요소 뒤에 배경을 그리기가 꽤 어렵고, 더 복잡한 시각 효과는 말할 것도 없습니다. 그래서 웹 브라우저는 레이아웃을 다르게 구조화합니다.

브라우저에서 레이아웃이란 _레이아웃 트리_ 를 만들어 내는 일입니다. 이 트리의 노드는 _레이아웃 객체_ 이고, 각 객체는 HTML 요소와 연결되며[^1] 저마다 크기와 위치를 갖습니다. 브라우저는 HTML 트리를 순회하며 레이아웃 트리를 만들고, 각 레이아웃 객체의 크기와 위치를 계산한 다음, 마지막으로 각 레이아웃 객체를 화면에 그립니다.

기존 `Layout` 클래스가 어떻게 사용되는지 살펴보는 것부터 시작합시다.

```python
class Browser:
    def load(self, url):
        # ...
        self.display_list = Layout(self.nodes).display_list
        #...
```

여기서 `Layout` 객체는 잠깐 만들어졌다가 버려집니다. 대신 이것을 `Browser`의 필드에 저장해 레이아웃 트리의 시작점으로 삼읍시다.

```python
class Browser:
    def load(self, url):
        # ...
        self.document = Layout(self.nodes)
        self.document.layout()
        self.display_list = self.document.display_list
        #...
```

`Layout` 생성자의 이름을 `layout` 메서드로 바꿨다는 점에 주의하세요. 이렇게 하면 레이아웃 객체를 만드는 일과 실제로 배치하는 일을 별개의 단계로 나눌 수 있습니다. 이제 생성자는 넘겨받은 노드를 저장하기만 합니다.

```python
class Layout:
    def __init__(self, node):
        self.node = node
```

아직까지는 트리라고 할 것이 없고 `Layout` 객체 하나만 있을 뿐입니다. 이를 트리로 만들려면 자식과 부모 포인터를 추가해야 합니다. 이전 형제를 가리키는 포인터도 추가하겠습니다. 나중에 크기와 위치를 계산할 때 유용하기 때문입니다.

```python
class Layout:
    def __init__(self, node, parent, previous):
        self.node = node
        self.parent = parent
        self.previous = previous
        self.children = []
```

그런데 이제 `parent`와 `previous` 객체를 요구하게 되면서 `Browser` 안에서 `Layout` 객체를 만들기가 까다로워졌습니다. 레이아웃 트리의 루트에는 당연히 부모가 있을 수 없기 때문입니다. 이를 바로잡기 위해 레이아웃 트리의 루트 역할을 할 두 번째 종류의 레이아웃 객체를 추가하겠습니다.[^2] 저는 그 루트를 문서 자체라고 생각하므로 `DocumentLayout`이라고 부르겠습니다.

```python
class DocumentLayout:
    def __init__(self, node):
        self.node = node
        self.parent = None
        self.children = []

    def layout(self):
        child = Layout(self.node, self, None)
        self.children.append(child)
        child.layout()
        self.display_list = child.display_list
```

이 새로운 `layout` 메서드에서 흥미로운 점을 하나 짚어 봅시다. 이 메서드의 역할은 자식 레이아웃 객체를 _만들고_ 그다음 그들의 `layout` 메서드를 _재귀적으로_ 호출하는 것입니다. 이는 트리를 구성할 때 흔히 쓰이는 패턴이며, 이 책 전반에 걸쳐 자주 보게 될 것입니다.

이제 `load` 안에서 `DocumentLayout` 객체를 만들면 트리를 만들게 됩니다. 아주 짧은 트리, 그루터기에 가까운 트리("문서"와 그 아래의 HTML 요소뿐)이지만 어쨌든 트리입니다!

그런데 이제 `DocumentLayout`이 생겼으니, 덜 모호하도록 `Layout`의 이름도 바꿉시다. 저는 `BlockLayout`이라는 이름이 마음에 드는데, 궁극적으로 이것이 문단이나 제목 같은 텍스트 블록을 나타내기를 바라기 때문입니다.

```python
class BlockLayout:
    # ...
```

`DocumentLayout` 안의 `Layout` 생성자 호출도 반드시 이름을 바꾸세요. 늘 그렇듯 이 모든 리팩터링을 마친 뒤 브라우저를 시험해 모든 것이 여전히 잘 동작하는지 확인하세요.

레이아웃 트리는 웹 개발자가 접근할 수 없으므로 표준화되지 않았고, 그 구조는 브라우저마다 다릅니다. 심지어 이름조차 다릅니다! Chrome은 이를 [레이아웃 트리](https://developers.google.com/web/updates/2018/09/inside-browser-part3), Safari는 [렌더 트리](https://webkit.org/blog/114/webcore-rendering-i-the-basics/), Firefox는 [프레임 트리](https://wiki.mozilla.org/Gecko:Key_Gecko_Structures_And_Invariants)라고 부릅니다.

## 블록 레이아웃

지금까지 우리는 텍스트 레이아웃에 집중해 왔고, 텍스트는 줄 단위로 가로로 배치됩니다.[^3] 하지만 웹 페이지는 사실 제목, 문단, 메뉴처럼 세로로 차곡차곡 쌓이는 더 큰 블록들로 구성됩니다. 이런 종류의 레이아웃 지원을 브라우저에 추가해야 하는데, 그 방법은 이미 만들어 둔 레이아웃 트리를 확장하는 것입니다.

핵심 아이디어는 (루트에 `DocumentLayout`이 있는) `BlockLayout` 객체들의 트리를 갖는 것입니다. 그중 일부는 텍스트를 담은 잎 블록을 나타내며, 이미 구현한 방식대로 자신의 내용을 배치합니다. 하지만 `BlockLayout` 자식을 가지는 새로운 중간 `BlockLayout`도 생길 것이고, 이들은 자식들을 세로로 쌓습니다. (예시는 그림 1에 있습니다. 그 위의 위젯으로 블록 레이아웃이 어떻게 서로 다른 시각적 결과를 만들어 내는지 직접 만져 볼 수 있습니다.)

> 🔗 대화형 위젯: [layout-container-example.html](https://browser.engineering/widgets/layout-container-example.html?embed=true)

![그림 1: HTML 트리와 그에 대응하는 레이아웃 트리의 예.](layout-tree-2.gif)

*그림 1: HTML 트리와 그에 대응하는 레이아웃 트리의 예.*

이러한 중간 `BlockLayout` 자식들을 만들려면 다음과 같은 루프를 사용할 수 있습니다.

```python
class BlockLayout:
    def layout_intermediate(self):
        previous = None
        for child in self.node.children:
            next = BlockLayout(child, self, previous)
            self.children.append(next)
            previous = next
```

이 메서드의 이름을 `layout_intermediate`라고 지었는데, 이는 여러분이 곧바로 코드에 추가한 뒤 기존 `recurse` 메서드와 비교해 볼 수 있게 하기 위해서입니다.

이 코드는 까다로우니 꼼꼼히 읽어 보세요. 여기에는 두 개의 트리가 관여합니다. `node`와 `child`가 가리키는 HTML 트리, 그리고 `self`, `previous`, `next`가 가리키는 레이아웃 트리입니다. 두 트리의 구조가 비슷해서 헷갈리기 쉽습니다. 하지만 이 코드가 HTML 트리로부터 레이아웃 트리를 구성한다는 점을 기억하세요. 그래서 (HTML 트리의) `node.children`에서 읽고 (레이아웃 트리의) `self.children`에 씁니다.

이제 요소를 배치하는 방법이 두 가지가 되었습니다. `recurse`와 `flush`를 호출하는 방법과, 이 `layout_intermediate` 함수를 쓰는 방법입니다. 레이아웃 객체가 어느 쪽을 써야 하는지 판단하려면 그 HTML 노드가 어떤 종류의 내용을 담고 있는지 알아야 합니다. _인라인_ 텍스트와 `<b>` 같은 텍스트 관련 태그인지, 아니면 `<p>`나 `<h1>` 같은 _블록_ 인지 말입니다. 어느 쪽인지 계산하는 `layout_mode` 메서드를 추가합시다.

```python
class BlockLayout:
    def layout_mode(self):
        if isinstance(self.node, Text):
            return "inline"
        elif any([isinstance(child, Element) and \
                  child.tag in BLOCK_ELEMENTS
                  for child in self.node.children]):
            return "block"
        elif self.node.children:
            return "inline"
        else:
            return "block"
```

여기서 `BLOCK_ELEMENTS` 목록은 예상하시는 그대로, 블록과 컨테이너를 나타내는 모든 태그의 목록입니다.[^4]

```python
BLOCK_ELEMENTS = [
    "html", "body", "article", "section", "nav", "aside",
    "h1", "h2", "h3", "h4", "h5", "h6", "hgroup", "header",
    "footer", "address", "p", "hr", "pre", "blockquote",
    "ol", "ul", "menu", "li", "dl", "dt", "dd", "figure",
    "figcaption", "main", "div", "table", "form", "fieldset",
    "legend", "details", "summary"
]
```

우리의 `layout_mode` 메서드는 까다로운 경우 하나를 처리해야 합니다. 어떤 노드가 `<p>` 요소 같은 블록 자식과 텍스트 노드나 `<b>` 요소 같은 텍스트 자식을 동시에 갖는 경우입니다. 이는 웹 개발자 쪽의 일종의 오류라고 보는 편이 아마 가장 나을 것입니다. 그리고 [4장](https://browser.engineering/html.html)의 암묵적 태그와 마찬가지로, 이 상황을 이해할 수 있게 만들어 주는 복구 메커니즘이 필요합니다. 저는 이 경우 블록 모드를 사용하기로 했습니다.[^5]

이제 `BlockLayout`은 자신의 HTML 노드의 `layout_mode`에 따라 어떤 종류의 레이아웃을 할지 결정할 수 있습니다.

```python
class BlockLayout:
    def layout(self):
        mode = self.layout_mode()
        if mode == "block":
            previous = None
            for child in self.node.children:
                next = BlockLayout(child, self, previous)
                self.children.append(next)
                previous = next
        else:
            self.cursor_x = 0
            self.cursor_y = 0
            self.weight = "normal"
            self.style = "roman"
            self.size = 12

            self.line = []
            self.recurse(self.node)
            self.flush()
```

마지막으로, 이제 `BlockLayout`이 자식을 가질 수 있으므로 `layout` 메서드는 그 자식들이 다시 자신의 자식을 구성할 수 있도록 `layout`을 재귀적으로 호출해야 하고, 그런 식으로 계속 이어져야 합니다.

```python
class BlockLayout:
    def layout(self):
        # ...
        for child in self.children:
            child.layout()
```

이제 우리 브라우저는 `BlockLayout` 객체들의 트리 전체를 구성합니다. `Browser`의 `load` 메서드에서 `print_tree`로 이 트리를 볼 수 있습니다. 이 장처럼 큰 웹 페이지는 크고 복잡한 레이아웃 트리를 만들어 낸다는 것을 알게 될 것입니다! 이제 이 `BlockLayout` 객체들 각각이 페이지 위 어딘가에 크기와 위치를 갖게 해야 합니다.

### 더 알아보기

CSS에서 레이아웃 모드는 [`display` 속성](https://developer.mozilla.org/en-US/docs/Web/CSS/display)으로 설정합니다. `inline`이나 `block` 같은 가장 오래된 CSS 레이아웃 모드는 부모가 아니라 자식에 설정되는데, 그 때문에 [익명 블록 박스(anonymous block boxes)](https://developer.mozilla.org/en-US/docs/Web/CSS/Visual_formatting_model#anonymous_boxes) 같은 골치 아픈 문제가 생깁니다. `inline-block`, `flex`, `grid` 같은 더 새로운 속성들은 부모에 설정되므로 이런 종류의 오류를 피할 수 있습니다.

## 크기와 위치

[이전 장](https://browser.engineering/html.html)에서 `Layout` 객체는 웹 페이지 전체를 담당했으므로, 그냥 페이지 맨 위에서 시작해 내용을 배치하기만 하면 됐습니다. 이제는 서로 다른 문단을 담은 여러 개의 `BlockLayout` 객체가 있으므로 조금 다르게 해야 합니다. 각 레이아웃 객체마다 크기와 위치를 독립적으로 계산해야 합니다.

각 레이아웃 객체 타입에 `x`, `y`, `width`, `height` 필드를 추가합시다.

```python
class BlockLayout:
    def __init__(self, node, parent, previous):
        # ...
        self.x = None
        self.y = None
        self.width = None
        self.height = None
```

`DocumentLayout`에도 똑같이 하세요. 이제 이 필드들을 사용하도록 `layout` 메서드를 갱신해야 합니다.

`cursor_x`와 `cursor_y`부터 시작합시다. 이들이 페이지 위의 절대 위치를 나타내는 대신, `BlockLayout`의 `x`와 `y`를 기준으로 한 상대 위치가 되게 합시다. 그러면 `layout`과 `flush` 양쪽에서 `HSTEP`, `VSTEP` 대신 `0`에서 시작해야 합니다.

```python
class BlockLayout:
    def layout(self):
        else:
            self.cursor_x = 0
            self.cursor_y = 0

    def flush(self):
        # ...
        self.cursor_x = 0
        # ...
```

이 필드들이 이제 상대 위치이므로, 디스플레이 리스트를 계산할 때 `flush`에서 블록의 `x`와 `y` 위치를 더해 주어야 합니다.

```python
class BlockLayout:
    def flush(self):
        # ...
        for rel_x, word, font in self.line:
            x = self.x + rel_x
            y = self.y + baseline - font.metrics("ascent")
            self.display_list.append((x, y, word, font))
        # ...
```

마찬가지로 줄을 바꾸기 위해 `cursor_x`를 `WIDTH`와 비교할 수는 없습니다. `cursor_x`는 상대 위치인데 `WIDTH`는 절대 위치이기 때문입니다. 대신 `cursor_x`가 블록의 `width`에 도달하면 줄을 바꾸겠습니다.

```python
class BlockLayout:
    def word(self, word):
        # ...
        if self.cursor_x + w > self.width:
            # ...
        # ...
```

이제 이 `x`, `y`, `width` 필드를 계산하는 문제가 남았습니다. `BlockLayout`은 문단이나 제목 같은 텍스트 블록을 나타내며 세로로 차곡차곡 쌓인다는 점을 떠올려 봅시다. 즉 각 블록은 부모의 왼쪽 가장자리에서 시작해 부모를 가로질러 끝까지 갑니다.[^6]

```python
class BlockLayout:
    def layout(self):
        self.x = self.parent.x
        self.width = self.parent.width
        # ...
```

레이아웃 객체의 세로 위치는 이전 형제가 있는지에 따라 달라집니다. 있다면 그 바로 뒤에서 시작하고, 없다면 부모의 위쪽 가장자리에서 시작합니다.

```python
class BlockLayout:
    def layout(self):
        if self.previous:
            self.y = self.previous.y + self.previous.height
        else:
            self.y = self.parent.y
        # ...
```

마지막으로 높이는 조금 까다롭습니다. 다른 블록들을 담는 `BlockLayout`은 모든 자식을 담을 수 있을 만큼 커야 하므로, 그 높이는 자식들의 높이의 합이어야 합니다.

```python
class BlockLayout:
    def layout(self):
        # ...
        if mode == "block":
            self.height = sum([
                child.height for child in self.children])
```

반면 텍스트를 담는 `BlockLayout`에는 자식이 없습니다. 대신 자신의 모든 텍스트를 담을 수 있을 만큼 커야 하는데, 그 값은 `cursor_y`에서 편리하게 읽어 올 수 있습니다.[^7]

```python
class BlockLayout:
    def layout(self):
        # ...
        else:
            self.height = self.cursor_y
```

이 규칙들은 충분히 단순해 보이지만, 여기에는 설명해야 할 미묘한 점이 있습니다. `x` 위치를 생각해 봅시다. 어떤 블록의 `x` 위치를 계산하려면 그 부모 블록의 `x` 위치가 _이미_ 계산되어 있어야 합니다. 따라서 블록의 `x`는 자식들의 `x`보다 먼저 계산되어야 합니다. 즉 `x` 계산은 재귀적인 `layout` 호출 _앞에_ 와야 합니다.

반면 요소의 `height` 필드는 자식들의 높이에 의존합니다. 그러니 `x`는 재귀 호출 _앞에_ 계산되어야 하지만 `height`는 _뒤에_ 계산되어야 합니다. 마찬가지로 블록의 `y` 위치는 이전 형제의 `y` 위치에 의존하므로, 재귀적인 `layout` 호출은 첫 번째 형제부터 시작해 리스트를 앞에서부터 순회해야 합니다.

즉 `layout` 메서드는 다음 순서로 단계를 수행해야 합니다(그림 2 참조).

- `layout`이 호출되면 먼저 `parent`와 `previous` 레이아웃 객체로부터 읽어 `width`, `x`, `y` 필드를 계산합니다.

- 다음으로 각 자식 요소마다 자식 레이아웃 객체를 만듭니다.

- 그다음 자식 레이아웃 노드들의 `layout` 메서드를 호출해 재귀적으로 배치합니다.

- 마지막으로 `layout`은 자식 레이아웃 객체들로부터 읽어 `height` 필드를 계산합니다.

이 단계들이 실제로 동작하는 모습을 이 위젯에서 볼 수 있습니다.

> 🔗 대화형 위젯: [lab5-propagate.html](https://browser.engineering/widgets/lab5-propagate.html)

이런 종류의 의존성 추론은 레이아웃에, 그리고 더 넓게는 트리에 대한 모든 종류의 계산에 매우 중요합니다. 연산 순서를 잘못 잡으면 어떤 레이아웃 객체가 아직 계산되지 않은 값을 읽으려 하게 되고, 브라우저에 버그가 생깁니다. 이 의존성 문제는 [16장](https://browser.engineering/invalidation.html)에서 다시 다룰 것이며, 그때는 훨씬 더 중요해집니다.

`DocumentLayout`에도 레이아웃 코드가 조금 필요하지만, 문서는 항상 같은 자리에서 시작하므로 꽤 단순합니다.

```python
class DocumentLayout:
    def layout(self):
        # ...
        self.width = WIDTH - 2*HSTEP
        self.x = HSTEP
        self.y = VSTEP
        child.layout()
        self.height = child.height
```

내용 주위에 여백이 조금 있다는 점에 주의하세요. 좌우에 `HSTEP`, 위아래에 `VSTEP`입니다. 이는 텍스트가 창의 맨 가장자리에 부딪혀 잘리지 않게 하기 위한 것입니다.

어쨌든 이제 모든 크기와 위치가 올바르게 계산되었으니, 우리 브라우저는 페이지의 모든 텍스트를 제자리에 표시할 것입니다.

### 더 알아보기

형식적으로 이런 트리 위의 계산은 [속성 문법(attribute grammar)](https://en.wikipedia.org/wiki/Attribute_grammar)으로 기술할 수 있습니다. 속성 문법 엔진은 서로 다른 속성들 사이의 의존 관계를 분석하여 트리를 순회할 올바른 순서를 정하고 각 속성을 계산합니다.

## 재귀적으로 그리기

이제 우리 `layout` 메서드는 꽤 많은 일을 하고 있습니다. 크기와 위치를 계산하고, 자식 레이아웃 객체를 만들고, 그 자식들을 재귀적으로 배치하고, 텍스트를 화면에 그릴 수 있도록 디스플레이 리스트를 모읍니다. 조금 지저분하니, 잠시 시간을 내어 이 중 한 부분, 즉 디스플레이 리스트 부분만 떼어 냅시다. 그러면서 레이아웃 트리를 거슬러 올라갈 때마다 디스플레이 리스트 내용을 계속 복사하는 일도 그만둘 수 있습니다.

이를 위한 가장 편리한 방법은 각 레이아웃 객체에 `paint` 함수를 추가하고, 그 반환값이 해당 객체의 디스플레이 리스트 항목들이 되게 하는 것이라고 생각합니다. 그러면 모든 레이아웃 객체에 대해 `paint`를 재귀적으로 호출하는 별도의 `paint_tree` 함수를 두면 됩니다.

```python
def paint_tree(layout_object, display_list):
    display_list.extend(layout_object.paint())

    for child in layout_object.children:
        paint_tree(child, display_list)
```

`DocumentLayout`에는 그릴 것이 없습니다.

```python
class DocumentLayout:
    def paint(self):
        return []
```

이제 `DocumentLayout`의 `display_list` 필드를 계산하던 줄은 삭제해도 됩니다.

`BlockLayout` 객체의 경우에는 `recurse`와 `flush` 동안 계산한 `display_list` 필드를 복사해 와야 합니다.[^8]

```python
class BlockLayout:
    def paint(self):
        return self.display_list
```

이제 브라우저는 `paint_tree`를 사용해 자신의 `display_list` 변수를 모을 수 있습니다.

```python
class Browser:
    def load(self, url):
        # ...
        self.display_list = []
        paint_tree(self.document, self.display_list)
        self.draw()
```

보세요. 우리 브라우저가 이제 근사한 트리 기반 레이아웃을 사용합니다! 여기서 잠시 멈추고 테스트와 디버깅을 해 보시기를 권합니다. 트리 기반 레이아웃은 강력하지만 복잡하고, 우리는 곧 기능을 더 추가할 것입니다. 튼튼한 기초가 편안한 집을 만듭니다.

### 더 알아보기

레이아웃 트리는 [그래픽 사용자 인터페이스(GUI) 프레임워크](https://book.huihoo.com/debian-gnu-linux-desktop-survival-guide/Widget_Tree.html)에서 흔히 쓰이지만, 제약 기반 레이아웃처럼 레이아웃을 구조화하는 다른 방법도 있습니다. TeX의 [박스와 글루(boxes and glue)](https://www.overleaf.com/learn/latex/Articles/Boxes_and_Glue%3A_A_Brief%2C_but_Visual%2C_Introduction_Using_LuaTeX)와 iOS의 [오토 레이아웃](https://developer.apple.com/library/archive/documentation/UserExperience/Conceptual/AutolayoutPG/index.html)이 이 대안적 패러다임의 두 가지 예입니다.

## 배경

브라우저는 레이아웃 트리를 많이 활용하는데,[^9] 그중 단순하면서도 시각적으로 인상적인 사용 사례 하나가 배경 그리기입니다.

배경은 직사각형이므로, 우리의 첫 번째 과제는 디스플레이 리스트에 직사각형을 넣는 것입니다. 지금 디스플레이 리스트는 화면에 그릴 단어들의 목록이지만, 대신 이를 _명령(command)_ 의 목록으로 개념화할 수 있습니다. 지금은 명령의 종류가 하나뿐이고요. 이제 두 종류의 명령을 원합니다.

```python
class DrawText:
    def __init__(self, x1, y1, text, font):
        self.top = y1
        self.left = x1
        self.text = text
        self.font = font
    
class DrawRect:
    def __init__(self, x1, y1, x2, y2, color):
        self.top = y1
        self.left = x1
        self.bottom = y2
        self.right = x2
        self.color = color
```

이제 `BlockLayout`은 그리려는 각 단어마다 `DrawText` 객체를 추가해야 하지만, 인라인 모드일 때만 그렇습니다.[^10]

```python
class BlockLayout:
    def paint(self):
        cmds = []
        if self.layout_mode() == "inline":
            for x, y, word, font in self.display_list:
                cmds.append(DrawText(x, y, word, font))
        return cmds
```

하지만 배경을 그리기 위해 `DrawRect` 명령을 추가할 수도 있습니다. (코드 예제에 쓰이는) `pre` 태그에 회색 배경을 넣어 봅시다.

```python
class BlockLayout:
    def paint(self):
        # ...
        if isinstance(self.node, Element) and self.node.tag == "pre":
            x2, y2 = self.x + self.width, self.y + self.height
            rect = DrawRect(self.x, self.y, x2, y2, "gray")
            cmds.append(rect)
        # ...
```

이 코드가 `DrawText` 객체를 추가하는 루프 _앞에_ 오도록 하세요. 배경은 그 텍스트 _아래에_ 그려져야 합니다. 또한 `paint_tree`가 서브트리로 재귀하기 전에 `paint`를 호출하므로, 서브트리도 우리가 원하는 대로 이 배경 위에 그려진다는 점에 주의하세요.

디스플레이 리스트가 채워졌으니 이제 각 그래픽 명령을 그려야 합니다. 이를 위해 `execute` 메서드를 추가합시다. `DrawText`에서는 `create_text`를 호출합니다.

```python
class DrawText:
    def execute(self, scroll, canvas):
        canvas.create_text(
            self.left, self.top - scroll,
            text=self.text,
            font=self.font,
            anchor='nw')
```

`execute`가 스크롤 양을 매개변수로 받는다는 점에 주의하세요. 이렇게 하면 각 그래픽 명령이 관련된 좌표 변환을 스스로 수행합니다. `DrawRect`도 `create_rectangle`로 똑같이 합니다.

```python
class DrawRect:
    def execute(self, scroll, canvas):
        canvas.create_rectangle(
            self.left, self.top - scroll,
            self.right, self.bottom - scroll,
            width=0,
            fill=self.color)
```

`create_rectangle`은 기본적으로 1픽셀의 검은 테두리를 그리는데, 배경에는 그것을 원하지 않으므로 반드시 `width=0`을 넘기세요.

여전히 화면 밖의 그래픽 명령은 건너뛰고 싶으므로, 언제 건너뛸지 알 수 있도록 `DrawText`에 `bottom` 필드를 추가합시다.

```python
def __init__(self, x1, y1, text, font):
    # ...
    self.bottom = y1 + font.metrics("linespace")
```

이제 브라우저의 `draw` 메서드는 `top`과 `bottom`만 보고 어떤 명령을 `execute`할지 결정합니다.

```python
class Browser:
    def draw(self):
        self.canvas.delete("all")
        for cmd in self.display_list:
            if cmd.top > self.scroll + HEIGHT: continue
            if cmd.bottom < self.scroll: continue
            cmd.execute(self.scroll, self.canvas)
```

코드 조각이 들어 있는 페이지, 예를 들어 [이 장](https://browser.engineering/layout.html) 같은 페이지에서 브라우저를 시험해 보세요. 각 코드 조각이 회색 배경으로 구분되어 보일 것입니다.

트리 기반 레이아웃의 또 다른 귀여운 이점이 있습니다. 이제 페이지 전체의 높이를 기록하게 되었습니다. 브라우저는 이를 이용해 맨 아래를 지나쳐 스크롤되지 않게 할 수 있습니다.

```python
def scrolldown(self, e):
    max_y = max(self.document.height + 2*VSTEP - HEIGHT, 0)
    self.scroll = min(self.scroll + SCROLL_STEP, max_y)
    self.draw()
```

페이지 위아래에 `VSTEP`만큼의 여백이 있으므로 `2*VSTEP`을 쓴다는 점에 주의하세요. 이 레이아웃으로 [browser.engineering 홈페이지](https://browser.engineering/)가 이제 조금 더 나아 보입니다. 그림 3을 보세요.

이것이 트리 기반 레이아웃의 기본입니다! 사실 다음 두 장에서 보게 되겠지만, 이는 브라우저에서 레이아웃 트리가 맡는 중심 역할의 일부에 지나지 않습니다. 하지만 그 이야기로 넘어가기 전에 브라우저에 스타일 지정 기능을 좀 추가해야 합니다.

## 연습문제

**5-1 _링크 바_.** 이 책의 웹 버전에서 각 장의 위아래에는 장 이름을 알려 주고 이전/다음 링크를 제공하는 회색 바가 있습니다. 이는 `<nav class="links">` 태그로 감싸여 있습니다. 실제 브라우저가 그러하듯 여러분의 브라우저도 이 링크 바에 옅은 회색 배경을 주도록 만드세요.

**5-2 _숨겨진 head_.** 여러분의 브라우저는 아마 아직도 방문하는 모든 페이지의 맨 위에 스크립트, 스타일, 페이지 제목을 표시하고 있을 것입니다. `<head>` 요소와 그 내용이 절대 표시되지 않도록 만드세요. 그 요소들은 HTML 트리에는 여전히 있어야 하지만 레이아웃 트리에는 없어야 합니다.

**5-3 _글머리 기호_.** HTML에서 `<li>` 태그인 목록 항목에 글머리 기호를 추가하세요. 목록 항목 자체의 왼쪽에 놓인 작은 사각형으로 만들면 됩니다. 또한 요소 안의 텍스트가 글머리 기호의 오른쪽에 오도록 `<li>` 요소를 들여쓰기하세요.

**5-4 _목차_.** 이 책의 웹 버전에는 각 장 맨 위에 `<nav id="toc">` 태그로 감싸인 목차가 있고, 그 안에는 링크 목록이 들어 있습니다. 그 목록 위에 회색 배경으로 "Table of Contents"라는 텍스트를 추가하세요. 렉서나 파서는 수정하지 마세요.

**5-5 _익명 블록 박스_.** 때때로 어떤 요소는 텍스트 같은 자식과 컨테이너 같은 자식을 섞어 갖습니다. 예를 들어 다음 HTML에서

```
<div><i>Hello, </i><b>world!</b><p>So it began...</p></div>
```

`<div>` 요소에는 자식이 셋 있습니다. `<i>`, `<b>`, `<p>` 요소입니다. 앞의 둘은 텍스트 같은 것이고 마지막은 컨테이너 같은 것입니다. 이는 두 개의 문단, 즉 `<i>`와 `<b>`를 위한 문단 하나와 `<p>`를 위한 문단 하나처럼 보여야 합니다. 여러분의 브라우저가 그렇게 하도록 만드세요. 구체적으로는 `BlockLayout`이 노드 하나가 아니라 형제 노드들의 시퀀스를 받을 수 있도록 수정하세요. 그다음 레이아웃 트리를 구성하는 알고리즘을 수정해, 텍스트 같은 요소들의 연속된 시퀀스가 하나의 `BlockLayout`이 되게 하세요.

**5-6 _런인 제목_.** "런인 제목(run-in heading)"이란 다음 문단의 텍스트의 일부로 그려지는 제목을 말합니다.[^11] `<h6>` 요소를 런인 제목으로 렌더링하도록 브라우저를 수정하세요. 익명 블록 박스에 관한 앞 연습문제를 먼저 구현한 다음, `<h6>` 요소에 대한 특수 처리를 추가해야 합니다.

## 각주

[^1]: `<script>` 같은 요소는 레이아웃 객체를 만들지 않고, 어떤 요소는 여러 개의 레이아웃 객체를 만들지만(`<li>` 요소는 글머리 기호를 위한 것이 하나 더 있습니다!), 대체로는 요소당 레이아웃 객체 하나입니다.

[^2]: 부모로 그냥 `None`을 넘기고 싶지는 않습니다. 이 장 뒷부분에서 보겠지만 루트 레이아웃 객체는 크기와 위치도 다르게 계산하기 때문입니다.

[^3]: 적어도 유럽 언어에서는 그렇습니다!

[^4]: [HTML 리빙 스탠더드](https://html.spec.whatwg.org/multipage/#toc-semantics)에서 가져왔습니다.

[^5]: 실제 브라우저에서 그 복구 메커니즘은 "[익명 블록 박스](https://developer.mozilla.org/en-US/docs/Web/CSS/Visual_formatting_model#anonymous_boxes)"라고 불리며 여기서 설명한 것보다 복잡합니다. 연습문제 5-5를 보세요.

[^6]: [다음 장](https://browser.engineering/styles.html)에서는 작성자가 정의한 스타일 지원을 추가할 텐데, 실제 브라우저에서는 이것이 사용자 지정 너비를 설정하거나 _x_, _y_ 위치 계산 방식을 바꿈으로써 이러한 레이아웃 규칙을 수정합니다.

[^7]: 높이가 `cursor_y`와 같다면 그냥 `cursor_y`의 이름을 `height`로 바꾸면 되지 않을까요? 그래도 잘 동작하겠지만 저는 그러고 싶지 않습니다. 예를 들어 `y` 계산에서 볼 수 있듯이 `height` 필드는 공개 필드로, 다른 레이아웃 객체가 자신의 위치를 계산하기 위해 읽습니다. 그래서 저는 이 필드가 _항상_ 올바른 값을 갖도록 하고 싶습니다. 반면 `cursor_y`는 문단을 배치하는 동안 계속 바뀌므로 때로는 "잘못된" 값을 갖습니다. 이 두 필드를 분리해 두면 `height` 필드를 "너무 일찍" 읽어 잘못된 값을 얻는 고약한 버그들을 통째로 피할 수 있습니다.

[^8]: 그리고 다시 한번, 자식 레이아웃 객체에서 복사해 `BlockLayout`의 `display_list` 필드를 계산하던 줄은 삭제하세요.

[^9]: 예를 들어 [7장](https://browser.engineering/chrome.html)에서는 각 링크의 크기와 위치를 이용해 사용자가 어떤 링크를 클릭했는지 알아낼 것입니다.

[^10]: `BlockLayout` 안의 `display_list` 필드가 아예 `DrawText` 명령을 직접 담게 하면 안 될까요? 그럴 수도 있겠지만, 저는 모든 그리기 명령을 `paint`에서 만드는 편이 더 깔끔하다고 생각합니다.

[^11]: 이 절의 연습문제 제목들이 런인 제목이라고 볼 수 있습니다. 다만 `display: run-in` 속성에 대한 브라우저 지원이 [부실하기](https://caniuse.com/run-in) 때문에 이 책은 실제로 그 속성을 쓰지 않았습니다. 제목이 실제로 다음 문단 안에 포함되어 있는 것입니다.
