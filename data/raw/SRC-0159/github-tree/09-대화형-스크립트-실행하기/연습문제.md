## 구현 내용

| 문제 | 제목 | 구현 위치 | 요점 |
|---|---|---|---|
| 9-1 | `Node.children` | `JSContext.getChildren` | `Element` 만 골라 핸들로 돌려줍니다 |
| 9-2 | `createElement` | `createElement`, `appendChild`, `insertBefore` | 만들면 문서 밖(분리 상태)에 있습니다 |
| 9-3 | `removeChild` | `removeChild`, `detach` | 떼어 낸 서브트리는 다시 붙일 수 있습니다 |
| 9-4 | ID | `update_id_globals` | DOM 이 바뀔 때마다 전역 변수를 맞춥니다 |
| 9-5 | 이벤트 버블링 | `ancestors`, `__dispatch` | 대상 → 조상 순서, `stopPropagation` 으로 멈춤 |
| 9-6 | HTML 직렬화 | `serialize` | 원문이 아니라 **현재** 속성을 씁니다 |
| 9-7 | 스크립트가 추가한 스크립트와 스타일 시트 | `attach_resources`, `detach_resources` | 붙을 때 읽고, 떨어질 때 뺍니다 |

## 설계 메모

**버블링은 파이썬이 사슬을 주고 JS 가 돌립니다.** 조상 목록을 만드는 건 파이썬이
쉽고(`ancestors`), 하나의 `Event` 객체를 여러 핸들러에 넘기며 `stopPropagation`
을 살피는 건 JS 가 자연스럽습니다. 그래서 `__dispatch(handles, type)` 하나로
넘겨 JS 가 순회합니다. `preventDefault` 는 그 결과값으로 돌아옵니다.

**9-4 는 "바뀔 때마다" 가 핵심입니다.** `innerHTML`, `appendChild`,
`removeChild`, `setAttribute` 가 모두 `changed()` 를 지나가고, 거기서 현재
id 목록을 다시 계산해 없어진 전역은 지우고 새 것은 만듭니다. id 가 JS 이름으로
쓸 수 없는 모양(`not-an-identifier`)이거나 `document` 같은 예약어면 건너뜁니다.

**DOM 은 원문이 아니라 문자를 담아야 합니다.** 9-6 을 하면서 드러난 문제입니다.
파서가 `&lt;` 를 그대로 들고 있으면 `innerHTML` 로 읽을 때 `&amp;lt;` 가 됩니다.
글자 마디를 만들 때 실체 참조를 풀도록 고쳤습니다(`<script>` 안은 그대로 둡니다).
화면에도 이제 `&lt;` 가 아니라 `<` 로 나옵니다.

**`#id` 선택자를 더했습니다.** 9-4 로 id 가 JS 이름이 되는데 정작
`querySelectorAll("#id")` 가 조용히 빈 결과를 주면 이상합니다. 6장 선택자
문법에 `IdSelector`(우선순위 100)를 넣어 짝을 맞췄습니다.

**9-7 은 붙는 쪽과 떨어지는 쪽이 짝입니다.** 새로 들어온 서브트리는
`attach_resources` 가 훑어 `<script>` 를 돌리고 `<link>` 를 읽어 옵니다. 나가는
서브트리는 `detach_resources` 가 훑어 그 `<link>` 의 규칙을 목록에서 뺍니다.
스타일시트를 링크 노드별로 따로 들고 있어서 뺄 때 그 규칙만 사라집니다.
