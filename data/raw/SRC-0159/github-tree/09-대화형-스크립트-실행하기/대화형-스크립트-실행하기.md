## DukPy 설치하기

JavaScript 인터프리터를 실제로 작성하는 것은 이 책의 범위를 넘어서므로,[^1] 이 장에서는 JavaScript 실행에 `dukpy` 라이브러리를 사용합니다.

[DukPy](https://github.com/amol-/dukpy)는 [Duktape](https://duktape.org)라는 JavaScript 인터프리터를 감싼 것입니다. 가장 유명한 JavaScript 인터프리터는 브라우저에서 쓰이는 것들입니다. SpiderMonkey(Firefox), JavaScriptCore(Safari), V8(Chrome)이죠. 극도로 빠르지만 극도로 복잡하기도 한 이 구현들과 달리, Duktape는 단순하고 확장 가능한 것을 목표로 하며 보통 더 큰 C나 C++ 프로젝트 안에 내장됩니다.[^2]

다른 JavaScript 엔진과 마찬가지로 DukPy는 JavaScript 코드를 실행할 뿐 아니라, 그 코드가 _내보낸(exported)_ Python 함수를 호출할 수 있게도 해 줍니다. 우리는 이 기능을 사용해 JavaScript 코드가 자신이 실행되고 있는 웹 페이지를 수정할 수 있게 하겠습니다.

DukPy를 사용하는 첫 단계는 설치입니다. Windows, macOS, Linux 시스템을 포함해 대부분의 기기에서 다음과 같이 설치할 수 있습니다.

```bash
python3 -m pip install dukpy
```

> **설치**
>
> 정말 오래된 버전의 Python을 쓰고 있다면 먼저 `pip` 패키지를 설치해야 할 수도 있는데, 아마 명령줄 `easy_install`을 사용하게 될 것입니다. 통합 개발 환경(IDE)으로 Python 프로그래밍을 한다면 IDE의 패키지 설치 도구를 써야 할 수도 있습니다. 아무것도 통하지 않는다면 [소스에서](https://github.com/amol-/dukpy) 빌드할 수 있습니다.
>
> Python이 아닌 다른 언어로 따라 하고 있다면 이 장을 건너뛰어야 할 수도 있습니다. 다만 `dukpy`가 사용하는 `duktape` 라이브러리에 직접 바인딩해 보는 방법도 있습니다.

DukPy를 올바르게 설치했는지 확인하려면 다음을 실행해 보세요.

```
import dukpy
dukpy.evaljs("2 + 2")
```

첫 줄에서 오류가 난다면 DukPy 설치에 실패했을 가능성이 큽니다.[^3] 둘째 줄에서 오류나 세그먼테이션 폴트가 난다면 Duktape 컴파일이 실패했거나 여러분의 시스템을 지원하지 않을 수 있으니 더 파고들어 디버깅해야 할 수도 있습니다.

> **참고**
>
> JavaScript 전문가 여러분께 알립니다. DukPy는 `let`, `const`나 화살표 함수 같은 최신 문법을 구현하지 않습니다. 이 책의 미학에 맞게, 세기 전환기의 구식 JavaScript를 사용하셔야 합니다.

## JavaScript 코드 실행하기

위 테스트는 DukPy에서 JavaScript 코드를 어떻게 실행하는지 보여 줍니다. 그냥 `evaljs`를 호출하면 됩니다! 이 새로 얻은 지식을 우리 브라우저에 써먹어 봅시다.

웹에서 JavaScript는 `<script>` 태그 안에 있습니다. 보통 `<script>` 태그에는 CSS 파일과 비슷하게 JavaScript 파일을 가리키는 상대 URL이 담긴 `src` 속성이 있습니다. `<script>` 태그는 시작 태그와 끝 태그 사이에 JavaScript 소스 코드를 직접 담을 수도 있지만, 그것은 구현하지 않겠습니다.[^4]

이 스크립트들을 찾아 내려받는 일은 CSS에서 했던 것과 비슷합니다. 먼저 모든 스크립트를 찾아야 합니다.

```python
class Tab:
    def load(self, url, payload=None):
        # ...
        scripts = [node.attributes["src"] for node
                   in tree_to_list(self.nodes, [])
                   if isinstance(node, Element)
                   and node.tag == "script"
                   and "src" in node.attributes]
        # ...
```

다음으로 모든 스크립트를 실행합니다.

```python
def load(self, url, payload=None):
    # ...
    for script in scripts:
        script_url = url.resolve(script)
        try:
            body = script_url.request()
        except:
            continue
        print("Script returned: ", dukpy.evaljs(body))
    # ...
```

이 코드는 스타일 지정과 레이아웃보다 먼저 실행되어야 합니다. 시험해 보려면 `script` 태그가 있는 간단한 웹 페이지를 만드세요.

```
<script src=test.js></script>
```

그다음 `test.js`에 아주 간단한 스크립트를 작성하세요. 아마 다음과 같이요.

```
var x = 2
x + x
```

브라우저를 그 페이지로 보내면 다음이 보일 것입니다.

```
Script returned: 4
```

여러분의 브라우저가 처음으로 JavaScript를 실행한 것입니다!

### 더 알아보기

사실 실제 브라우저는 페이지 전체를 파싱한 뒤가 아니라, 브라우저가 `<script>` 태그를 _파싱하자마자_ JavaScript 코드를 실행합니다. 적어도 그것이 기본 동작이고, [여러 옵션](https://html.spec.whatwg.org/multipage/scripting.html#the-script-element)이 있습니다. 우리 브라우저가 하는 일은 실제 브라우저가 [`defer`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/script#attr-defer) 속성이 설정되었을 때 하는 일입니다. 기본 동작은 효율적으로 구현하기가 [훨씬 더 까다롭습니다](https://developer.mozilla.org/en-US/docs/Glossary/speculative_parsing).

## 함수 내보내기

지금 우리 브라우저는 스크립트의 마지막 표현식을 그냥 출력할 뿐이지만, 실제 브라우저에서는 스크립트가 출력하려면 `console.log` 함수를 호출해야 합니다. 이를 지원하려면 Python의 함수를 JavaScript로 _내보내야_ 합니다. 앞으로 많은 함수를 내보낼 텐데, `Tab` 객체를 새 메서드로 어지럽히지 않도록 이 코드는 새로운 `JSContext` 클래스에 넣읍시다.

```python
class JSContext:
    def __init__(self):
        self.interp = dukpy.JSInterpreter()

    def run(self, code):
        return self.interp.evaljs(code)
```

DukPy의 `JSInterpreter` 객체는 모든 JavaScript 변수의 값을 저장하며, 여러 JavaScript 조각을 실행하면서 그것들 사이에 변수 값과 그 밖의 상태를 공유할 수 있게 해 줍니다.

이 새로운 `JSContext` 객체는 페이지를 로드하는 동안 만듭니다.

```python
class Tab:
    def load(self, url, payload=None):
        # ...
        self.js = JSContext()
        for script in scripts:
            # ...
            self.js.run(body)
```

모든 스크립트에 하나의 `JSContext`를 쓰는 부수적인 이점으로, 이제 스크립트 두 개를 실행하면서 한쪽이 정의한 변수를 다른 쪽이 사용할 수 있습니다. 예를 들어 다음과 같은 페이지에서요.

```
<script src=a.js></script>
<script src=b.js></script>
```

`a.js`가 "`var x = 2;`"이고 `b.js`가 "`console.log(x + x)`"라고 합시다. 변수 `x`는 `a.js`에서 설정되었지만 `b.js`에서 사용됩니다. 실제 웹 브라우저에서 이는 흔한 일인데, 한 스크립트가 다른 스크립트가 호출하려는 라이브러리 함수를 정의할 수 있기 때문입니다.

이제 JavaScript가 바깥 세계와 상호작용할 수 있도록 DukPy는 함수를 JavaScript로 "내보낼" 수 있게 해 줍니다. 예를 들어 Python의 `print` 함수를 다음과 같이 내보낼 수 있습니다.

```python
class JSContext:
    def __init__(self):
        # ...
        self.interp.export_function("log", print)
```

내보낸 함수는 DukPy의 `call_python` 함수를 사용해 JavaScript에서 호출할 수 있습니다. 예를 들면 다음과 같습니다.

```
call_python("log", "Hi from JS")
```

이 JavaScript 코드가 실행되면 DukPy는 JavaScript 문자열 `"Hi from JS"`를 Python 문자열로 변환하고,[^5] 그 Python 문자열을 우리가 내보낸 `print` 함수에 넘깁니다. 그러면 `print`가 그 문자열을 출력합니다.

우리가 궁극적으로 원하는 것은 `call_python` 함수가 아니라 [`console.log`](https://developer.mozilla.org/en-US/docs/Web/API/console/log) 함수이므로, `console` 객체를 정의하고 거기에 `log` 속성을 부여해야 합니다. 이는 _JavaScript에서_ 할 수 있습니다.

```javascript
console = { log: function(x) { call_python("log", x); } }
```

JavaScript에 그리 익숙하지 않다면[^6] 설명하자면, 이 코드는 `console`이라는 변수를 정의하는데 그 값은 `log` 속성을 가진 객체 리터럴이고, 그 `log`의 값은 `call_python`을 호출하는 함수입니다. 브라우저와 JavaScript 사이의 상호작용이 그림 1에 나와 있습니다.

![그림 1: 브라우저는 JavaScript를 평가할 수 있고, JavaScript 코드는 다시 브라우저를 호출할 수 있습니다.](scripts-calls-2.gif)

*그림 1: 브라우저는 JavaScript를 평가할 수 있고, JavaScript 코드는 다시 브라우저를 호출할 수 있습니다.*

이 JavaScript 코드를 우리의 "JavaScript 런타임"이라고 부를 수 있습니다. 사용자 코드를 실행하기 전에 먼저 실행하므로, `runtime.js` 파일에 넣어 두고 `JSContext`가 만들어질 때, 사용자 코드를 실행하기 전에 실행합시다.

```python
RUNTIME_JS = open("runtime.js").read()

class JSContext:
    def __init__(self):
        # ...
        self.interp.evaljs(RUNTIME_JS)
```

이제 JavaScript 파일에 `console.log("Hi from JS!")`를 넣고 브라우저에서 실행하면 터미널에 출력이 보일 것입니다. `console.log`를 여러 번 호출할 수도 있습니다.

한 걸음 물러서서 보면, 우리 브라우저에서 JavaScript를 실행할 때 우리는 JavaScript 인터프리터를 구현한 C 코드, 특정 JavaScript 함수를 구현한 Python 코드, Python API를 JavaScript답게 보이도록 감싸는 JavaScript 런타임, 그리고 물론 JavaScript로 된 사용자 코드를 섞어 쓰고 있습니다. 여기에는 복잡함이 정말 많습니다!

### 더 알아보기

스크립트가 오래 실행되거나 무한 루프에 빠지면 우리 브라우저는 멈춰서 사용자에게 전혀 반응하지 않게 됩니다. 이는 JavaScript의 단일 스레드 의미론과 작업 기반의 [실행 완료 스케줄링(run-to-completion scheduling)](https://en.wikipedia.org/wiki/Run_to_completion_scheduling)의 결과입니다. [Web Workers](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API) 같은 일부 API는 제한적인 멀티스레딩을 허용하지만, 그 스레드들은 DOM에 접근할 수 없습니다.

## 충돌 처리하기

JavaScript 코드의 충돌은 디버깅하기 답답합니다. 나쁜 코드를 작성해서, 또는 다음과 같이 명시적으로 예외를 던져서 충돌을 일으킬 수 있습니다.

```
throw Error("bad");
```

웹 페이지가 충돌하는 JavaScript를 실행하면 브라우저는 그 충돌을 무시해야 합니다. 웹 페이지가 우리 브라우저를 죽일 수 있어서는 안 됩니다! 다음과 같이 구현할 수 있습니다(그리고 `run`의 호출 지점이 스크립트를 넘기도록 바꿔야 합니다).

```python
class JSContext:
    def run(self, script, code):
        try:
            return self.interp.evaljs(code)
        except dukpy.JSRuntimeError as e:
            print("Script", script, "crashed", e)
```

하지만 이 장을 진행하다 보면 또 다른 종류의 충돌도 만나게 됩니다. 바로 우리 JavaScript 런타임 자체의 충돌입니다. 그것은 우리 코드이니 무시할 수 없습니다. 이런 충돌을 디버깅하는 일은 골칫거리입니다. 기본적으로 DukPy는 역추적(backtrace)을 보여 주지 않고, 런타임 코드가 충돌하는 내보낸 함수를 호출하면 더욱 혼란스러워집니다.

이런 충돌에 도움이 되는 요령 몇 가지를 알려 드립니다. 먼저, 어떤 JavaScript 함수 안에서 충돌이 난다면 그 함수의 본문을 다음과 같이 감싸세요.

```
function foo() {
    try {
        // ...
    } catch(e) {
        console.log("Crash in function foo()", e.stack);
        throw e;
    }
}
```

이 코드는 모든 예외를 잡아서 스택 트레이스를 출력한 뒤 다시 던집니다. 반대로 내보낸 함수 안에서 충돌이 나고 있다면 Python 쪽에서 그 함수를 감싸야 합니다.

```
class JSContext:
    def foo(self, arg):
        try:
            # ...
        except:
            import traceback
            traceback.print_exc()
            raise
```

이런 문제를 디버깅하는 일은 쉽지 않습니다. Python과 JavaScript 사이를 오가는 이 모든 호출이 꽤 복잡해지기 때문입니다. 이런 버그가 어렵기 _때문에_, 고치려 들기 전에 체계적으로 접근해 정보를 많이 모으는 것이 값진 일입니다.

### 더 알아보기

초기 웹 브라우저의 JavaScript 디버깅 지원이 딱 이 정도였습니다! 오늘날의 정교한 개발자 도구는 조금씩 모여 만들어졌습니다. Microsoft의 [Script Debugger](https://en.wikipedia.org/wiki/Microsoft_Script_Debugger)가 JavaScript용 단계별 디버거를 도입했고,[^7] [Firebug](https://hacks.mozilla.org/2017/10/saying-goodbye-to-firebug/)가 JS 콘솔과 네트워크 탭을, WebKit의 [Web Inspector](https://webkit.org/blog/5718/10-years-of-web-inspector/)가 "검사" 버튼과 DOM 뷰를 도입했습니다. 이 기능들은 워낙 유용해서 금세 [표준이 되었고](https://blog.chromium.org/2018/09/10-years-of-chrome-devtools.html) 이제는 모든 브라우저 엔진의 핵심 부분이 되었습니다.

## 핸들 반환하기

지금까지 JavaScript 평가는 재미있지만 쓸모가 없습니다. JavaScript가 페이지 자체를 전혀 수정할 수 없기 때문입니다. (출력 말고는 아무것도 할 수 없다면 JavaScript를 실행할 이유가 무엇일까요? 브라우저의 콘솔 출력을 누가 본단 말입니까?) JavaScript가 페이지를 수정할 수 있게 해야 합니다.

JavaScript는 통틀어 DOM API라고 불리는 방대한 메서드 집합을 호출해 웹 페이지를 조작합니다. DOM API는 크고 계속 커지고 있으므로, 전부는커녕 대부분도 구현하지 않겠습니다. 하지만 몇 가지 핵심 함수만으로도 전체 API의 주요 요소를 보여 줄 수 있습니다.

- `querySelectorAll`은 선택자에 매치되는 모든 요소를 반환합니다.

- `getAttribute`는 어떤 속성에 대한 요소의 값을 반환합니다.

- `innerHTML`은 요소의 내용을 새 HTML로 대체합니다.

우리는 이 API들의 단순화된 버전을 구현하겠습니다.[^8]

`querySelectorAll`부터 시작합시다. 먼저 함수를 내보냅니다.

```python
class JSContext:
    def __init__(self):
        # ...
        self.interp.export_function("querySelectorAll",
            self.querySelectorAll)
        # ...
```

JavaScript에서 `querySelectorAll`은 `document` 객체의 메서드이므로, JavaScript 런타임에 `document`를 정의해야 합니다.

```javascript
document = { querySelectorAll: function(s) {
    return call_python("querySelectorAll", s);
}}
```

Python 쪽에서 `querySelectorAll`은 먼저 선택자를 파싱하고 그다음 매치되는 요소들을 찾아 반환해야 합니다. 선택자를 파싱하기 위해 `CSSParser`의 `selector` 메서드를 호출하겠습니다.[^9]

```python
class JSContext:
    def querySelectorAll(self, selector_text):
        selector = CSSParser(selector_text).selector()
```

다음으로 매치되는 모든 요소를 찾아 반환해야 합니다. 그러려면 `JSContext`가 `Tab`에, 구체적으로는 그 `nodes` 필드에 접근할 수 있어야 합니다. 그러니 `JSContext`를 만들 때 `Tab`을 넘깁시다.

```python
class JSContext:
    def __init__(self, tab):
        self.tab = tab
        # ...

class Tab:
    def load(self, url, payload=None):
        # ...
        self.js = JSContext(self)
        # ...
```

이제 `querySelectorAll`은 선택자에 매치되는 모든 노드를 찾을 것입니다.

```python
def querySelectorAll(self, selector_text):
    # ...
    nodes = [node for node
             in tree_to_list(self.tab.nodes, [])
             if selector.matches(node)]
```

마지막으로 그 노드들을 JavaScript로 되돌려 주어야 합니다. 다음과 같이 해 보고 싶을 수 있습니다.

```python
def querySelectorAll(self, selector_text):
    # ...
    return nodes
```

하지만 이렇게 하면 오류가 납니다.[^10]

```
_dukpy.JSRuntimeError: EvalError:
Error while calling Python Function:
TypeError('Object of type Element is not JSON serializable')
```

DukPy가 하려는 말은, `querySelectorAll`이 반환하는 `Element` 객체를 어떻게 다뤄야 할지 전혀 모르겠다는 것입니다. 그도 그럴 것이 `Element` 클래스는 JavaScript가 아니라 Python에만 존재하니까요!

Python 객체는 브라우저의 Python 쪽에 머물러야 하므로, JavaScript 코드는 어떤 간접적인 방식으로 그것을 참조해야 합니다. 저는 간단한 숫자 식별자를 사용하겠는데, 이를 _핸들(handle)_ 이라고 부르겠습니다(그림 2 참조).[^11]

![그림 2: JavaScript의 Node 객체와 브라우저의 Element/Text 객체 사이의 관계는 핸들을 통해 유지됩니다.](scripts-handles-2.gif)

*그림 2: JavaScript의 `Node` 객체와 브라우저의 `Element`/`Text` 객체 사이의 관계는 핸들을 통해 유지됩니다.*

핸들과 노드의 대응 관계를 추적해야 합니다. 노드를 핸들에 대응시키는 `node_to_handle` 자료 구조와 그 반대로 가는 `handle_to_node` 맵을 만듭시다.

```python
class JSContext:
    def __init__(self, tab):
        # ...
        self.node_to_handle = {}
        self.handle_to_node = {}
        # ...
```

이제 `querySelectorAll` 핸들러는 각 노드에 핸들을 할당하고 그 핸들들을 대신 반환할 수 있습니다.

```python
def querySelectorAll(self, selector_text):
    # ...
    return [self.get_handle(node) for node in nodes]
```

`get_handle` 함수는 핸들이 아직 없으면 새로 만들어야 합니다.

```python
class JSContext:
    def get_handle(self, elt):
        if elt not in self.node_to_handle:
            handle = len(self.node_to_handle)
            self.node_to_handle[elt] = handle
            self.handle_to_node[handle] = elt
        else:
            handle = self.node_to_handle[elt]
        return handle
```

이제 `querySelectorAll` 핸들러는 `[1, 3, 4, 7]` 같은 것을 반환하고, 각 숫자는 요소에 대한 핸들입니다. DukPy는 이를 문제없이 JavaScript 객체로 변환할 수 있습니다. 물론 JavaScript 쪽에서 `querySelectorAll`은 숫자 뭉치가 아니라 `Node` 객체들의 리스트를 반환해야 합니다.[^12] 그러니 핸들을 감싸는 `Node` 객체를 런타임에 정의합시다.[^13]

```javascript
function Node(handle) { this.handle = handle; }
```

이 `Node` 객체들은 `querySelectorAll`의 래퍼에서 만듭니다.[^14]

```javascript
document = { querySelectorAll: function(s) {
    var handles = call_python("querySelectorAll", s);
    return handles.map(function(h) { return new Node(h) });
}}
```

### 더 알아보기

초기 브라우저는 `querySelectorAll`을 제공하지 않고 `getElementById`와 `getElementsByTagName`만 제공했으며, `querySelectorAll`의 [가장 초기 버전](https://simonwillison.net/2003/Mar/25/getElementsBySelector/)들은 [JavaScript로 다시 구현한 것](https://johnresig.com/blog/selectors-in-javascript/)이었습니다. 특히 인기 있고 영향력 있던 [jQuery 라이브러리](https://jquery.org)에서 그랬죠. 하지만 브라우저는 CSS 선택자를 _이미_ 구현하고 있으니, 그 구현을 JavaScript에 직접 노출하는 것이 당연히 합리적입니다.

## 핸들 감싸기

이제 `Node`가 몇 개 생겼는데, 이것들로 무엇을 할 수 있을까요?

간단한 DOM 메서드 하나가 `getAttribute`인데, 이는 `Node` 객체의 메서드로 HTML 속성의 값을 가져올 수 있게 해 줍니다. `getAttribute`를 구현하는 것은 `querySelectorAll`과 반대의 문제를 푸는 일입니다. JavaScript 쪽의 `Node` 객체를 받아서 Python으로 실어 보내야 합니다.

해법은 `querySelectorAll`과 비슷합니다. `Node` 객체 자체를 보내는 대신 그 핸들을 보냅니다.

```javascript
Node.prototype.getAttribute = function(attr) {
    return call_python("getAttribute", this.handle, attr);
}
```

Python 쪽에서 `getAttribute` 함수는 핸들과 속성이라는 두 개의 인자를 받습니다.

```python
class JSContext:
    def getAttribute(self, handle, attr):
        elt = self.handle_to_node[handle]
        attr = elt.attributes.get(attr, None)
        return attr if attr else ""
```

속성이 지정되어 있지 않으면 `get` 메서드가 `None`을 반환하고, DukPy는 이를 JavaScript의 `null`로 변환한다는 점에 주의하세요. 이 함수를 `getAttribute`라는 이름으로 내보내는 것을 잊지 마세요.

이제 텍스트 영역을 위한 간단한 글자 수 세기 함수를 구현하기에 충분한 DOM API를 갖췄습니다.

```
inputs = document.querySelectorAll('input')
for (var i = 0; i < inputs.length; i++) {
    var name = inputs[i].getAttribute("name");
    var value = inputs[i].getAttribute("value");
    if (value.length > 100) {
        console.log("Input " + name + " has too much text.")
    }
}
```

다만 이상적으로는 사용자가 입력 상자에 입력할 때마다 글자 수를 갱신하면 좋겠습니다. 그러려면 키를 누를 때마다 JavaScript를 실행해야 합니다. 다음으로 그것을 구현해 봅시다.

### 더 알아보기

DOM의 `Node` 객체는 브라우저의 `Element` 노드에 대응합니다. 그래서 이들은 JavaScript 객체의 _속성(property)_ 과 HTML _속성(attribute)_ 을 모두 가집니다. 둘은 헷갈리기 쉬운데, 설상가상으로 많은 DOM 객체 프로퍼티가 attribute 값을 자동으로 [_반영(reflect)_](https://html.spec.whatwg.org/multipage/common-dom-interfaces.html#reflecting-content-attributes-in-idl-attributes)합니다. 예를 들어 `Node` 객체의 `id` 프로퍼티는 그 바탕이 되는 `Element`의 [`id` 속성](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/id)에 대한 읽기·쓰기 접근을 제공합니다. 아주 편리하고, 여기저기서 `setAttribute`와 `getAttribute`를 호출하지 않아도 되게 해 줍니다. 다만 이 반영은 특정 필드에만 적용됩니다. 임의로 만든 JavaScript 프로퍼티를 설정한다고 해서 그에 대응하는 HTML 속성이 생기지는 않으며, 그 반대도 마찬가지입니다.

## 이벤트 처리

브라우저는 웹 페이지를 로드하자마자 JavaScript 코드를 실행하지만, 그 코드는 흔히 사용자 동작에 _반응해서_ 페이지를 바꾸고 싶어 합니다.

동작 방식은 이렇습니다. 사용자가 페이지와 상호작용할 때마다 브라우저는 _이벤트_ 를 발생시킵니다. 각 이벤트에는 `change`, `click`, `submit` 같은 타입이 있고 _대상 요소_ 에서 발생합니다. `addEventListener` 메서드는 JavaScript가 그 이벤트에 반응할 수 있게 해 줍니다. `node.addEventListener('click', func)`는 `node`에 해당하는 요소가 `click` 이벤트를 발생시킬 때마다 `func`가 실행되도록 설정합니다. 기본적으로 Tk의 `bind`와 같되 브라우저 안에서 동작하는 것입니다. 그림 3을 보세요. 이것을 구현해 봅시다.

![그림 3: 이벤트가 발생하면 브라우저가 JavaScript를 호출합니다.](scripts-events-2.gif)

*그림 3: 이벤트가 발생하면 브라우저가 JavaScript를 호출합니다.*

이벤트를 발생시키는 것부터 시작합시다. `dispatch_event` 메서드를 만들고 이벤트가 발생할 때마다 호출하겠습니다. 여기에는 우선 페이지를 클릭할 때마다가 포함됩니다.

```python
class Tab:
    def click(self, x, y):
        # ...
        elif elt.tag == "a" and "href" in elt.attributes:
            self.js.dispatch_event("click", elt)
            # ...
        elif elt.tag == "input":
            self.js.dispatch_event("click", elt)
            # ...
        elif elt.tag == "button":
            self.js.dispatch_event("click", elt)
            # ...
        # ...
```

둘째로, 입력 영역의 값을 갱신하기 전입니다.

```python
class Tab:
    def keypress(self, char):
        if self.focus:
            self.js.dispatch_event("keydown", self.focus)
            # ...
```

마지막으로, 폼을 제출할 때 실제로 서버에 요청을 보내기 전입니다.

```python
def submit_form(self, elt):
    self.js.dispatch_event("submit", elt)
    # ...
```

여기까지는 좋습니다. 그런데 `dispatch_event` 메서드는 무엇을 해야 할까요? 이 메서드는 `addEventListener`로 넘겨진 리스너들을 실행해야 하므로, 그 리스너들이 어딘가에 저장되어 있어야 합니다. 리스너는 JavaScript 함수이므로 그 데이터를 JavaScript 쪽, 즉 런타임의 변수에 두어야 합니다. 그 변수를 `LISTENERS`라고 부르겠습니다. 핸들과 이벤트 타입으로 조회할 것이므로, 핸들을 이벤트 타입에서 리스너 리스트로 가는 딕셔너리에 대응시키게 만듭시다.

```javascript
LISTENERS = {}

Node.prototype.addEventListener = function(type, listener) {
    if (!LISTENERS[this.handle]) LISTENERS[this.handle] = {};
    var dict = LISTENERS[this.handle];
    if (!dict[type]) dict[type] = [];
    var list = dict[type];
    list.push(listener);
}
```

이벤트를 디스패치하려면 다음과 같이 `LISTENERS` 배열에서 타입과 핸들을 조회해야 합니다.

```javascript
Node.prototype.dispatchEvent = function(type) {
    var handle = this.handle;
    var list = (LISTENERS[handle] && LISTENERS[handle][type]) || [];
    for (var i = 0; i < list.length; i++) {
        list[i].call(this);
    }
}
```

`dispatchEvent`가 함수의 `call` 메서드를 사용한다는 점에 주의하세요. 이 메서드는 함수 안에서 `this`의 값을 설정합니다. JavaScript에서 표준적으로 그러하듯, 저는 그것을 이벤트가 발생한 노드로 설정하고 있습니다.

이벤트가 발생하면 브라우저는 Python에서 `dispatchEvent`를 호출합니다.

```python
class JSContext:
    def dispatch_event(self, type, elt):
        handle = self.node_to_handle.get(elt, -1)
        self.interp.evaljs(
            EVENT_DISPATCH_JS, type=type, handle=handle)
```

여기서 `EVENT_DISPATCH_JS` 상수는 새 이벤트를 디스패치하는 JavaScript 코드 문자열입니다.

```python
EVENT_DISPATCH_JS = \
    "new Node(dukpy.handle).dispatchEvent(dukpy.type)"
```

그래서 Python 쪽에서 `dispatch_event`가 호출되면 JavaScript 쪽에서 `dispatchEvent`가 실행되고, 그것이 다시 모든 이벤트 리스너를 실행합니다. 이 코드 조각의 `dukpy` JavaScript 객체는 `evaljs`에 넘긴 이름 붙은 `type`과 `handle` 인자를 저장합니다.

이 모든 이벤트 처리 장치를 갖췄으니, 입력 영역이 바뀔 때마다 글자 수를 갱신할 수 있습니다.

```javascript
function lengthCheck() {
    var name = this.getAttribute("name");
    var value = this.getAttribute("value");
    if (value.length > 100) {
        console.log("Input " + name + " has too much text.")
    }
}
```

```javascript
var inputs = document.querySelectorAll("input");
for (var i = 0; i < inputs.length; i++) {
    inputs[i].addEventListener("keydown", lengthCheck);
}
```

`lengthCheck`가 `dispatchEvent`가 설정한 대로 실제로 바뀐 입력 요소를 참조하기 위해 `this`를 사용한다는 점에 주의하세요.

여기까지는 좋습니다. 다만 이상적으로는 길이 검사가 콘솔에 출력하는 대신 웹 페이지 자체에 경고를 추가하면 좋겠습니다. 그러려면 페이지를 읽을 뿐 아니라 수정도 할 수 있어야 합니다.

### 더 알아보기

JavaScript는 [1995년에 처음 등장했습니다](https://auth0.com/blog/a-brief-history-of-javascript/). Netscape Navigator의 일부로서요. 그 이름은 [Java](https://en.wikipedia.org/wiki/Java_(programming_language)) 언어와의 유사성을 나타내려고 고른 것이고, 문법이 Java스러운 것도 그 때문입니다. 하지만 겉모습 아래에서 JavaScript는 Java보다 훨씬 동적인 언어인데, 웹의 점진적 향상 메커니즘이라는 역할에 어울리는 특성입니다. 예를 들어 (`Element` 같은 내장 객체를 포함한) 어떤 객체의 어떤 메서드나 프로퍼티든 언제든지 동적으로 재정의할 수 있습니다. 덕분에 브라우저 간 차이를 [폴리필](https://developer.mozilla.org/en-US/docs/Glossary/Polyfill)해서, 다른 JavaScript 코드가 보기에 내장 기능처럼 보이는 기능을 추가할 수 있습니다.

## DOM 수정하기

지금까지는 읽기 전용 DOM 메서드를 구현했습니다. 이제 페이지를 바꾸는 메서드가 필요합니다. 완전한 DOM API는 그런 메서드를 많이 제공하지만, 단순함을 위해 `innerHTML`만 구현하겠습니다. 사용법은 다음과 같습니다.

```
node.innerHTML = "This is my <b>new</b> bit of content!";
```

다시 말해 `innerHTML`은 노드 객체의 _프로퍼티_ 이며, 그 필드가 수정될 때 실행되는 _세터(setter)_ 를 가집니다. 그 세터는 반드시 문자열이어야 하는 새 값을 받아, 그것을 HTML로 파싱하고, 새로 파싱된 HTML 노드들을 원래 노드의 자식으로 만듭니다.

JavaScript 쪽부터 시작해 이를 구현해 봅시다. JavaScript에는 세터를 정의하는 잘 알려지지 않은 `Object.defineProperty` 함수가 있는데, DukPy도 이를 지원합니다.

```javascript
Object.defineProperty(Node.prototype, 'innerHTML', {
    set: function(s) {
        call_python("innerHTML_set", this.handle, s.toString());
    }
});
```

`innerHTML_set`에서는 HTML 문자열을 파싱해야 합니다. 이는 생각보다 까다로운 것으로 드러납니다. 우리 브라우저의 HTML 파서는 이런 문서 조각이 아니라 HTML 문서 전체를 파싱하도록 만들어졌기 때문입니다. 편의를 위한 그럴듯한 꼼수로,[^15] HTML을 `html`과 `body` 요소로 감싸겠습니다.

```python
def innerHTML_set(self, handle, s):
    doc = HTMLParser("<html><body>" + s + "</body></html>").parse()
    new_nodes = doc.children[0].children
```

`innerHTML_set` 함수를 내보내는 것을 잊지 마세요. `body` 요소의 모든 자식을 뽑아낸다는 점에 주의하세요. `innerHTML_set` 호출 하나가 여러 노드를 한꺼번에 만들 수 있기 때문입니다. 이제 이 새 노드들을 `innerHTML_set`이 호출된 요소의 자식으로 만들어야 합니다.

```python
def innerHTML_set(self, handle, s):
    # ...
    elt = self.handle_to_node[handle]
    elt.children = new_nodes
    for child in elt.children:
        child.parent = elt
```

파싱된 자식 노드들의 부모 포인터를 갱신하는 이유는, 그러지 않으면 그 포인터들이 파싱을 돕기 위해 우리가 추가한 가짜 `body` 요소를 가리키게 되기 때문입니다.

다 된 것처럼 보일 수 있지만, 시험해 보면 스크립트가 `innerHTML_set`을 호출해도 아무 일도 일어나지 않는다는 것을 알게 됩니다. HTML 트리는 바꿨지만 레이아웃 트리나 디스플레이 리스트를 다시 만들지 않았으므로 브라우저가 여전히 옛 페이지를 보여 주고 있기 때문입니다.

페이지가 바뀔 때마다 `render`를 호출해 렌더링을 갱신해야 합니다.[^16]

```python
class JSContext:
    def innerHTML_set(self, handle, s):
        # ...
        self.tab.render()
```

## 이벤트 기본 동작

지금까지는 이벤트가 발생하면 브라우저가 리스너를 실행하고, 그다음 _또한_ 그 이벤트에 대해 평소에 하는 일, 즉 _기본 동작(default action)_ 을 수행합니다. 이제 JavaScript 코드가 그 기본 동작을 _취소_ 할 수 있게 하고 싶습니다.

여기에는 몇 단계가 필요합니다. 우선 이벤트 리스너는 인자로 _이벤트 객체_ 를 받아야 합니다. 그 객체에는 `preventDefault` 메서드가 있어야 합니다. 그 메서드가 호출되면 기본 동작이 일어나지 않아야 합니다.

먼저 이벤트 객체가 필요합니다. 다시 JavaScript 런타임으로 갑시다.

```javascript
function Event(type) {
    this.type = type
    this.do_default = true;
}

Event.prototype.preventDefault = function() {
    this.do_default = false;
}
```

`preventDefault`가 호출되었는지 기록하는 `do_default` 필드를 눈여겨보세요. 이제 `dispatchEvent`에 이벤트 타입만이 아니라 `Event` 객체를 넘기게 됩니다.

```javascript
Node.prototype.dispatchEvent = function(evt) {
    var type = evt.type;
    // ...
    for (var i = 0; i < list.length; i++) {
        list[i].call(this, evt);
    }
    // ...
    return evt.do_default;
}
```

Python에서는 이제 `dispatchEvent`에 넘길 `Event`를 만들어야 합니다.

```python
EVENT_DISPATCH_JS = \
    "new Node(dukpy.handle).dispatchEvent(new Event(dukpy.type))"
```

또한 `dispatchEvent`가 `evt.do_default`를 반환한다는 점에 주의하세요. 이는 JavaScript에서 표준일 뿐 아니라 Python에서 이벤트를 디스패치할 때도 유용한데, Python의 `dispatch_event`가 그 불리언 값을 자신의 호출자에게 반환할 수 있기 때문입니다.

```python
class JSContext:
    def dispatch_event(self, type, elt):
        # ...
        do_default = self.interp.evaljs(
            EVENT_DISPATCH_JS, type=type, handle=handle)
        return not do_default
```

이렇게 하면 이벤트가 발생할 때마다 브라우저가 `dispatch_event`의 반환값을 확인해서 `True`이면 멈출 수 있습니다. `click` 메서드에 그런 곳이 세 군데 있습니다.

```python
class Tab:
    def click(self, x, y):
        while elt:
            # ...
            elif elt.tag == "a" and "href" in elt.attributes:
                if self.js.dispatch_event("click", elt): return
                # ...
            elif elt.tag == "input":
                if self.js.dispatch_event("click", elt): return
                # ...
            elif elt.tag == "button":
                if self.js.dispatch_event("click", elt): return
                # ...
            # ...
         # ...
```

그리고 `submit_form`에 한 군데 있습니다.

```python
class Tab:
    def submit_form(self, elt):
        if self.js.dispatch_event("submit", elt): return
```

`keypress`에도 한 군데 있습니다.

```python
class Tab:
    def keypress(self, char):
        if self.focus:
            if self.js.dispatch_event("keydown", self.focus): return
```

이제 우리 글자 수 세기 코드가 사용자의 폼 제출을 막을 수 있습니다. 제출이 허용되는지 여부를 추적하는 전역 변수를 사용하고, 제출이 시도되면 그 변수를 확인해 필요하면 제출을 취소하면 됩니다.

```javascript
var allow_submit = true;

function lengthCheck() {
    // ...
    allow_submit = value.length <= 100;
    if (!allow_submit) {
        // ...
    }
}

var form = document.querySelectorAll("form")[0];
form.addEventListener("submit", function(e) {
    if (!allow_submit) e.preventDefault();
});
```

이렇게 하면 댓글이 너무 길 때 폼을 제출하는 것이 불가능해집니다!

음… 이 브라우저에서는 불가능하죠. 하지만 (한 장 전의 우리 브라우저처럼) JavaScript를 실행하지 않는 브라우저도 있으므로 서버 쪽에서도 길이를 확인해야 합니다.

```python
def add_entry(params):
    if 'guest' in params and len(params['guest']) <= 100:
        ENTRIES.append(params['guest'])
```

브라우저가 JavaScript를 실행해 주리라고 의존해서는 안 되고, 사실 의존할 수도 없다는 점에 주의하세요. 브라우저는 우리의 대리인이 아니라 사용자의 대리인이기 때문입니다. 이상적으로 웹 페이지는 JavaScript 없이도 올바르게 동작하되 JavaScript가 있으면 더 잘 동작하도록 작성되어야 합니다. 이를 [점진적 향상(progressive enhancement)](https://en.wikipedia.org/wiki/Progressive_enhancement)이라고 하며, 브라우저가 이미 할 수 있는 일을 JavaScript로 다시 만들지 않는다는 뜻입니다.

마무리하며 한 가지 생각을 덧붙이자면, 우리 방명록에 이제 JavaScript 코드가 조금 들어갔지만 여전히 대부분은 HTML, CSS, 폼 요소를 비롯한 표준 웹 기능으로 이루어져 있습니다. 이런 식으로 JavaScript는 웹을 대체하는 것이 아니라 확장합니다. 이는 최근 세상을 떠난 [Adobe Flash](https://www.adobe.com/products/flashplayer/end-of-life.html)나 그 이전의 [Java 애플릿](https://en.wikipedia.org/wiki/Java_applet)과 대조적입니다. 그것들은 입력과 렌더링을 스스로 처리하는 자체 완결적인 플러그인이었습니다.

### 더 알아보기

검색 엔진은 끊임없이 웹을 [크롤링](https://en.wikipedia.org/wiki/Web_crawler)하며 찾을 수 있는 모든 웹 페이지를 [색인](https://en.wikipedia.org/wiki/Search_engine_indexing)합니다. 초창기에 색인은 그저 HTML을 불러와 파싱하고 정보를 뽑아내는 일이었습니다. 하지만 요즘 많은 [단일 페이지 앱](https://en.wikipedia.org/wiki/Single-page_application) 사이트는 JavaScript를 사용해 사이트를 전체 내용으로 ["하이드레이션"](https://en.wikipedia.org/wiki/Hydration_(web_development))[^18]합니다. 그런 사이트에서는 하이드레이션이 일어나기 전까지 사이트의 정보가 JavaScript 자료 구조 안에 숨겨져 있습니다. 그래서 검색 엔진은 색인 과정에서 HTML을 파싱하는 것뿐 아니라 JavaScript도 실행하고 (스타일 시트도 로드) 해야 합니다. 다시 말해 색인 시스템은 (예를 들어 [헤드리스 Chrome](https://chromium.googlesource.com/chromium/src/+/lkgr/headless/README.md) 같은) 브라우저를 사용합니다. 웹 생태계에서 브라우저가 등장하는 또 하나의 자리인 셈입니다.

## 요약

이제 우리 브라우저는 웹사이트를 대신해 JavaScript 애플리케이션을 실행합니다. 방대한 DOM API 중 단 네 개의 메서드만 지원하지만, 그것만으로도 다음을 보여 줍니다.

- 스크립트가 페이지 이벤트에 반응할 수 있도록 이벤트 리스너를 붙이기

## 연습문제

**9-1 _`Node.children`_.** JavaScript `Node`의 [`children`](https://developer.mozilla.org/en-US/docs/Web/API/Element/children) 프로퍼티 지원을 추가하세요. `Node.children`은 노드의 직계 `Element` 자식들을 배열로 반환합니다. `Text` 자식은 포함되지 않습니다.[^19]

**9-2 _`createElement`_.** [`document.createElement`](https://developer.mozilla.org/en-US/docs/Web/API/Document/createElement) 메서드는 새 요소를 만드는데, 이 요소는 `Node`의 [`appendChild`](https://developer.mozilla.org/en-US/docs/Web/API/Node/appendChild)와 [`insertBefore`](https://developer.mozilla.org/en-US/docs/Web/API/Node/insertBefore) 메서드로 문서에 _붙일_ 수 있습니다. `innerHTML`과 달리 파싱이 관여하지 않습니다. 이 세 메서드를 모두 구현하세요.

**9-3 _`removeChild`_.** `Node`의 [`removeChild`](https://developer.mozilla.org/en-US/docs/Web/API/Node/removeChild) 메서드는 주어진 자식을 떼어 내고 그것을 반환하여, 그 자식과 그 서브트리를 _분리된_ 상태로 되돌립니다. (그다음 `appendChild`나 `insertBefore`로 다른 곳에 _다시 붙이거나_ 삭제할 수 있습니다.) 이 메서드를 구현하세요. Python 쪽에서도 서브트리를 제거해야 하므로 이 메서드는 구현하기가 더 어렵습니다.

**9-4 _ID_.** HTML 요소에 `id` 속성이 있으면 그 요소를 가리키는 JavaScript 변수가 미리 정의됩니다. 그래서 페이지에 `<div id="foo"></div>`가 있으면 그 노드를 참조하는 `foo`라는 변수가 있게 됩니다.[^20] 이를 여러분의 브라우저에 구현하세요. (`innerHTML` 등으로) 노드가 추가되고 제거되는 경우도 반드시 처리하세요.

**9-5 _이벤트 버블링_.** 지금은 `a`(앵커) 요소에 `click` 핸들러를 붙일 수 있지만 다른 요소에는 붙일 수 없습니다. 이를 고치세요. 마주치게 될 문제 하나는, 어떤 요소를 클릭하면 그 모든 조상도 클릭하게 된다는 점입니다. 웹에서 이런 종류의 문제는 [_이벤트 버블링_](https://developer.mozilla.org/en-US/docs/Learn/JavaScript/Building_blocks/Events#event_bubbling)으로 처리됩니다. 어떤 요소에서 이벤트가 발생하면 그 요소뿐 아니라 조상들에서도 리스너가 실행됩니다. 이벤트 버블링을 구현하고, 리스너가 이벤트 객체의 `stopPropagation`을 호출해 이벤트가 트리 위로 버블링되는 것을 멈출 수 있게 하세요. 링크 클릭이 여전히 동작하는지 다시 확인하고, `preventDefault`가 여전히 링크 클릭이 실제로 링크를 따라가는 것을 성공적으로 막는지도 확인하세요.

**9-6 _HTML 직렬화_.** [`innerHTML`](https://developer.mozilla.org/en-US/docs/Web/API/Element/innerHTML)에서 읽으면 HTML 소스 코드를 담은 문자열이 반환되어야 합니다. 그 소스 코드는 요소의 _현재_ 속성을 반영해야 합니다. 예를 들면 다음과 같습니다.

```
element.innerHTML = '<span id=foo>Chris was here</span>';
element.id = 'bar';
console.log(element.innerHTML);
// Prints "<span id=bar>Chris was here</span>":
```

`innerHTML`을 게터로 하여 이 동작을 구현하세요. `outerHTML`도 구현하세요. 이는 자식뿐 아니라 요소 자체까지 포함한다는 점에서 `innerHTML`과 다릅니다.

**9-7 _스크립트가 추가한 스크립트와 스타일 시트_.** `innerHTML` API는 문서에 `<script>`나 `<link>` 요소를 추가할 수 있지만, 현재 우리 브라우저는 그런 일이 일어나도 그것들을 로드하지 않습니다. 이를 고치세요. 마찬가지로 `<link>` 요소가 문서에서 제거되면 그 스타일 시트도 전역 목록에서 제거되어야 합니다. 그것도 구현하세요.[^21]
