# 16장 연습문제 구현

[← 16장 결과물로](결과물.md) · [← 본문으로](이전-계산-재사용하기.md#연습문제)

본문의 연습문제 10개를 모두 구현했습니다. `lab16.py` 는 그대로 두고,
1~15장 연습문제를 이어받아 그 위에 16장 기능을 얹은 것을 `ex16.py` 와
`ex16_sdl.py` 에 두었습니다.

16장 본문 기능(`ProtectedField`, 의존성, 더티 플래그, 증분 스타일)도 함께
들어 있습니다.

## 실행

```bash
python3 server10ex.py               # 다른 터미널에서
python3 ex16_sdl.py http://localhost:8000/
```

창 모서리를 끌어 크기를 바꿀 수 있습니다(16-5).

## 검증

```bash
python3 test_ex16.py
```

77개 테스트로 확인합니다. 무효화는 "얼마나 적게 다시 하는가"가 핵심이므로,
다시 계산한 노드 수를 세어 확인합니다.

## 구현 내용

| 문제 | 제목 | 구현 위치 | 요점 |
|---|---|---|---|
| 16-1 | 요소 비우기 | `JSContext.replaceChildren` | 인자가 없으면 자식을 모두 뗍니다 |
| 16-2 | 레이아웃 단계 보호하기 | `ProtectedField` | 스타일이 바뀌면 배치가 더러워집니다 |
| 16-3 | 자식 옮기기 | `JSContext.replaceChildren` | 옛 부모에서 빼고 새 부모에 붙입니다 |
| 16-4 | `style` 을 위한 자손 플래그 | `mark_style_dirty`, `style_incremental` | 더러운 가지만 훑습니다 |
| 16-5 | 브라우저 크기 조절 | `Tab.resize`, `Browser.handle_resize` | 미디어 쿼리도 함께 다시 봅니다 |
| 16-6 | 자식 매칭하기 | `reconcile_children` | 이미 있던 레이아웃 객체를 다시 씁니다 |
| 16-7 | `previous` 무효화 | `reconcile_children` | 앞 형제가 바뀐 것만 다시 배치 |
| 16-8 | `:hover` 의사 클래스 | `Tab.hover` | 들어온 곳과 나간 곳만 다시 스타일링 |
| 16-9 | `ProtectedField` 없애기 | `FieldStore` | 필드 객체를 하나도 만들지 않습니다 |
| 16-10 | `paint` 최적화하기 | `paint_tree_cached` | 지난 프레임의 명령을 그대로 씁니다 |

## 설계 메모

**16-9 를 파이썬에서 푸는 방법.** 본문이 말하듯 노드마다 필드 객체를 수십 개씩
만드는 것은 실제 브라우저에는 너무 비쌉니다. 파이썬에는 매크로가 없으니,
객체 대신 **주인 하나에 딕셔너리 세 개**(값·더티 집합·의존 관계)를 두고 필드를
이름으로 가리키는 `FieldStore` 를 만들었습니다. 필드를 가리켜야 할 때는
`(저장소, 이름)` 튜플을 그때그때 만들었다 버립니다 — 오래 남지 않습니다.
`FieldStore` 는 `__slots__` 를 써서 인스턴스 딕셔너리조차 없습니다.
`test_same_semantics_as_protected_field` 가 두 구현이 같은 답을 내는지 봅니다.

**16-4 의 핵심은 "위로 알린다"입니다.** 노드를 더럽힐 때 조상들에게
`has_dirty_style_descendants` 를 세워 둡니다. 그러면 스타일 단계는 깨끗한 가지를
만나는 즉시 되돌아설 수 있습니다. 다만 **부모의 스타일이 바뀌면 자식도 다시**
봐야 합니다 — 상속 속성이 있기 때문입니다. `style_incremental` 이 노드를 다시
스타일링할 때마다 자식들을 더럽히는 이유입니다.

**DOM 을 건드릴 때 표시는 건드리기 *전에* 합니다.** `appendChild` 같은
메서드는 안에서 곧바로 다시 스타일링을 부릅니다. 그 뒤에 표시하면 이미 지나간
뒤라 새 노드가 스타일 없이 남습니다. 그래서 ex16 의 DOM 메서드들은 `super()`
를 부르기 전에 `mark_style_dirty` 를 합니다.

**16-6 과 16-7 은 한 함수로 풀립니다.** 둘 다 "노드 목록에 맞춰 레이아웃 자식을
맞추는" 문제입니다. `reconcile_children` 이 이미 있는 것은 그대로 쓰고, 새 노드만
새로 만들고, **앞 형제가 바뀐 것**만 다시 배치할 목록에 올립니다. 그래서 목록
끝에 붙이면 손대는 자식이 하나뿐이고, 앞에 끼워 넣으면 둘뿐입니다.

**16-10 은 디스플레이 리스트를 상자마다 캐시합니다.** 상자마다 지난번에 만든
명령 목록을 들고 있다가, 자기도 자손도 더럽지 않으면 그대로 내놓습니다.
`mark_paint_dirty` 가 뿌리까지 길을 내 두므로, 한 곳이 바뀌어도 그 가지만
다시 그립니다. `test_content_is_still_complete_after_a_partial_repaint` 가
부분 재그리기 뒤에도 화면이 온전한지 확인합니다.

**16-8 은 이미 있던 것을 이어 붙였습니다.** `:hover` 선택자 자체는 14장에서
만들어 두었습니다. 16장에서 더한 것은 **무효화**입니다. 마우스가 들어온 요소와
나간 요소 둘만 더럽히므로, 문서 전체를 다시 스타일링하지 않습니다.
