# 12장 연습문제 구현

[← 12장 결과물로](결과물.md) · [← 본문으로](작업과-스레드-스케줄링.md#연습문제)

본문의 연습문제 8개를 모두 구현했습니다. `lab12.py`·`runtime12.js` 는 그대로 두고,
1~11장 연습문제를 이어받아 그 위에 12장 기능을 얹은 것을 `ex12.py`(스케줄링 알맹이),
`ex12_sdl.py`(창과 스레드), `runtime12ex.js` 에 두었습니다.

12장 본문 기능(작업 큐, 메인/브라우저 스레드, 커밋, `setTimeout`, 비동기
`XMLHttpRequest`, `requestAnimationFrame`, 트레이싱)도 함께 들어 있습니다.

## 실행

```bash
python3 server10ex.py               # 다른 터미널에서
python3 ex12_sdl.py http://localhost:8000/
```

## 검증

```bash
python3 test_ex12.py
```

58개 테스트로 확인합니다. 시간에 기대는 대신 작업 고리를 손으로 돌려
결정적으로 확인합니다.

## 구현 내용

| 문제 | 제목 | 구현 위치 | 요점 |
|---|---|---|---|
| 12-1 | `setInterval` | `setInterval`, `dispatch_setinterval` | 콜백 안에서 취소하는 경우까지 |
| 12-2 | 작업 타이밍 | `Task.name`, `Task.run` | 이름은 `task_code.__name__` 에서 |
| 12-3 | 시계 기반 프레임 타이밍 | `FrameScheduler` | 고정 지연이 아니라 절대 마감 |
| 12-4 | 스케줄링 | `TaskQueue.next_task` | 우선순위 + 굶기지 않기 |
| 12-5 | 스레드 기반 로딩 | `parallel_fetch`, `Tab.load_resources` | 병렬로 받고 소스 순서로 처리 |
| 12-6 | 네트워킹 스레드 | `NetworkThread` | 비동기 요청은 여기서 |
| 12-7 | 최적화된 스케줄링 | `FrameTimeEstimator` | 실제 박자를 재서 목표를 조정 |
| 12-8 | 래스터·그리기 스레드 | `RasterDrawThread` | 그리는 동안 입력을 받는다 |

## 설계 메모

**12-3 은 "밀리지 않게"가 핵심입니다.** 프레임이 끝난 뒤 33ms 를 세면 실제 박자는
`작업 시간 + 33ms` 가 되어 계속 느려집니다. 절대 마감을 두고 거기까지 남은
시간만 기다리면 작업이 얼마나 걸렸든 박자가 유지됩니다. 마감을 놓쳤으면 지난
만큼을 박자 단위로 건너뛰어 다시 맞춥니다. `test_fixed_delay_would_drift` 가
두 방식을 나란히 놓고 비교합니다.

**12-7 은 12-3 과 한 몸입니다.** 페이지가 무거워 프레임마다 80ms 가 걸린다면
33ms 목표는 지킬 수 없습니다. 그때 계속 따라잡으려 하면 CPU 만 태우고 박자는
들쭉날쭉해집니다. 최근 프레임 시간의 평균을 목표로 삼으면 **일관되게** 느려집니다.
그래서 `FrameScheduler` 가 목표 대신 추정기를 씁니다.

**12-4 의 굶주림 방지는 "몇 번 밀렸나"로 셉니다.** 우선순위가 높은 작업이 계속
들어오면 타이머 작업은 영영 못 돕니다. 작업마다 밀린 횟수를 세어 두고, 한계를
넘으면 우선순위를 제치고 먼저 태웁니다.

**12-5 는 받는 순서와 쓰는 순서를 나눕니다.** 네트워크는 병렬로 열되, 결과는
스레드가 끝난 뒤 **원래 목록 순서대로** 처리합니다. 그래야 나중에 도착한
스타일시트가 앞선 것을 이기지 않습니다.
`test_stylesheets_apply_in_source_order` 가 일부러 첫 번째를 느리게 만들어
확인합니다.

**12-8 은 SDL 이 스레드 안전하지 않다는 점 때문에 반만 옮깁니다.** 그리는 일은
래스터 스레드가 하고, 다 그린 그림을 **화면에 올리는 일**만 주 스레드가 합니다.
`needs_blit` 이벤트가 둘 사이의 신호입니다.

**바탕을 갈아 끼우는 방식을 이어 갑니다.** 11장의 `install_backend()` 와 같이,
`install_runtime()` 이 앞 장의 `JSContext` 이름을 12장 것으로 바꿔 끼웁니다.
그래서 9~10장에서 만든 DOM API·쿠키·CORS 가 그대로 살아 있는 채로 타이머와
비동기 요청만 더해집니다.
