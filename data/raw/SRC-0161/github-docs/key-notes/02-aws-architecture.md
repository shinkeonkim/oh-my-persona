## 1. AWS 글로벌 인프라 구성 요소

| 구성 요소 | 정의 | 특징 | 예시 |
|---|---|---|---|
| **AWS 리전 (Region)** | 전 세계에 분산된 **물리적 위치**의 클러스터 | 지리적으로 분리, 데이터 주권/규정 준수에 사용 | `ap-northeast-2` (서울), `us-east-1` (버지니아 북부) |
| **가용 영역 (AZ)** | 리전 내 **하나 이상의 데이터센터** | 독립 전력·냉각·네트워킹, 리전당 최소 3개 이상 | `ap-northeast-2a`, `ap-northeast-2b` |
| **엣지 로케이션 (Edge Location)** | CloudFront/Route 53용 **콘텐츠 캐시 지점** | 리전보다 훨씬 많음, 최종 사용자와 가까움 | 전 세계 400+ 위치 |
| **로컬 존 (Local Zone)** | 대도시 근처 **저지연 확장** | 소수 서비스 지원, 리전에 연결됨 | LA, 라스베가스 등 |
| **웨이브렝스 (Wavelength)** | **5G 네트워크 엣지** | 모바일 사용자 초저지연 | 통신사 5G 존 |
| **아웃포스트 (Outposts)** | 온프레미스에 설치되는 **AWS 인프라 랙** | 하이브리드, 온프레미스에서 AWS API 사용 | 고객 데이터센터 내 |

### 개수 관계 (반복 출제)
```
Edge Locations > Availability Zones > Regions
```
- **엣지 로케이션이 리전보다 훨씬 많다** ✅
- **가용 영역이 리전보다 많다** ✅ (각 리전에 여러 AZ)
- 리전이 AZ보다 많다 ❌ (역방향 함정)
- 엣지 로케이션은 AZ와 다르다 ✅ (엣지는 콘텐츠 캐시용)

## 3. 배포 모델 (Deployment Models)

| 모델 | 설명 | 사용 사례 |
|---|---|---|
| **온프레미스 (On-premises)** | 로컬 인프라만 사용 | 규정/레거시 유지 |
| **클라우드 (Cloud / Cloud-native)** | AWS 클라우드만 사용 | 신규 스타트업, 클라우드 우선 |
| **하이브리드 (Hybrid)** | 온프레미스 + 클라우드 | 마이그레이션 중, Outposts 사용 |

### 마이그레이션 방향 매트릭스
| 출발 → 도착 | 명칭 |
|---|---|
| 온프레미스 → 하이브리드 | **온프레미스에서 하이브리드로** (일부만 이전) |
| 온프레미스 → 클라우드 | **온프레미스에서 클라우드 네이티브로** (완전 이전) |
| 하이브리드 → 클라우드 | 하이브리드에서 클라우드 네이티브로 |

### 배포 모델 결정 힌트
- 문제에 "**Outposts** 사용" 언급 → **하이브리드**
- "**로컬 데이터센터 유지 + AWS 일부**" → **하이브리드**
- "**모든 워크로드를 AWS로**" → **클라우드 네이티브**
- "**규정 때문에 온프레미스 유지**" → **하이브리드** (일부 AWS와 연결 시)

## 4. Multi-AZ vs Multi-Region — 시험 필수 구별

| 목적 | 정답 |
|---|---|
| **단일 리전 내 고가용성 / 내결함성** | **Multi-AZ** |
| **글로벌 사용자 저지연** | **Multi-Region** |
| **자연 재해 (지역 전체) 대비** | **Multi-Region** (DR) |
| **AZ 내 데이터센터 장애 대비** | Multi-AZ로 충분 |
| **RDS 고가용성 자동 페일오버** | **Multi-AZ RDS** |
| **글로벌 콘텐츠 배포 (저지연)** | CloudFront (엣지) 또는 Multi-Region |

**Multi-AZ의 실제 이점**:
- 자동 페일오버
- 동기식 복제 (RDS)
- 독립 전력망 + 네트워크
- 단일 AZ 장애에도 서비스 유지

**Multi-Region의 이점**:
- 지역 전체 재해 대비
- 글로벌 저지연
- 데이터 주권 (특정 국가 저장)

## 5. 하이브리드 확장 서비스 (Outposts / Local Zones / Wavelength)

### AWS Outposts
- **온프레미스에 물리적으로 설치되는 AWS 인프라**
- EC2, EBS, S3, RDS, EKS 등 사용 가능
- **온프레미스에서 AWS API/도구를 동일하게 사용**
- 대표 사용 사례:
  - 규정 준수로 온프레미스 유지 필요
  - 저지연이 필요한 온프레미스 시스템 (공장, 병원)
  - 데이터 주권 요구
- **하이브리드 배포 모델**로 분류

### AWS Local Zones
- 대도시 근처 소규모 AWS 확장
- 리전에 연결됨
- 저지연 애플리케이션 (미디어, 게임)

### AWS Wavelength
- 5G 통신사 네트워크 엣지에 배포
- 초저지연 모바일 애플리케이션

### 3자 구별 요약
| 목적 | 서비스 |
|---|---|
| 온프레미스에 AWS 자체를 놓기 | **Outposts** |
| 대도시에서 짧은 지연 | **Local Zones** |
| 5G 모바일 사용자 초저지연 | **Wavelength** |

## 7. 오답 패턴 (Distractor Traps)

- ❌ "**엣지 로케이션이 가용 영역**이다" → 별개 개념 (엣지는 CDN용)
- ❌ "**AWS 리전이 가용 영역보다 많다**" → 반대. AZ가 리전보다 많음
- ❌ "**AWS 리전이 엣지 로케이션보다 많다**" → 반대. 엣지 로케이션이 훨씬 많음
- ❌ "**CloudFront가 인프라 물리적 위치**" → CloudFront는 서비스, 물리 위치는 리전
- ❌ "**엣지 로케이션에 EC2 배포**" → 엣지는 컴퓨팅 호스팅 X, CDN 캐시 전용
- ❌ "**Fargate가 온프레미스**" → Fargate는 서버리스 컨테이너 (클라우드)
- ❌ "**단일 AZ가 고가용성 제공**" → 다중 AZ 필요
- ❌ "**단일 리전이 글로벌 배포**" → 다중 리전 필요
- ❌ "**Snowmobile로 하이브리드 아키텍처**" → Snowmobile은 물리 데이터 이전용
- ❌ "**Local Zones = 온프레미스**" → Local Zones는 AWS 소유 대도시 확장

## 8. Amazon Connect / AWS Artifact 함정 주의

이 폴더에서 오답 선택지로 자주 등장하는 서비스:
- **Amazon Connect**: **고객 센터 (콜센터) 서비스** — 인프라 아님
- **AWS Artifact**: **규정 준수 문서 다운로드** 서비스 — 인프라 아님
- **AWS Organizations**: 다중 계정 관리 — 인프라 아님
- **AWS DataSync**: 데이터 전송 서비스 — 인프라 아님

이 서비스들은 문제에 "인프라 위치" 관련 문구가 있으면 **모두 오답**.

## 9. 시험 대비 팁

1. **개수 부등식** `Edge > AZ > Region` 완벽 암기
2. **"동일 지리, 다른 위치, 독립 전력망"** = **Multi-AZ** (반사적으로 답하기)
3. **"전 세계 저지연"** = **Multi-Region** 또는 **CloudFront**
4. **"온프레미스에 AWS"** = **Outposts** (항상)
5. **"자연 재해 대비"** — 문제가 "지역 전체"면 Multi-Region, "AZ 하나 장애"면 Multi-AZ
6. **하이브리드**의 정의: **온프레미스 + AWS 두 환경 모두** — 한쪽만 있으면 하이브리드 아님
7. Region은 **물리적 위치**, AZ는 **하나 이상의 데이터센터**, Edge는 **CDN 캐시** — 이 정의 그대로 암기
